## 한 줄 요약

WandEnhancer는 Wand 애플리케이션의 로컬 클라이언트 파일을 수정해 구성과 화면 동작을 확장하는 제3자 도구다.
독립 게임 실행기나 Wand의 공식 제품이 아니며, README는 교육·연구·로컬 상호운용 목적을 명시한다.
화면 조정, 사용자 스크립트, 선택형 Remote Web Panel 등이 소개되어 있지만 서버 권한을 얻는 도구로 설명해서는 안 된다.[1]

## 설정 화면 밖의 동작을 바꾼다는 의미

일반적인 테마 설정은 프로그램이 마련한 선택지를 바꾸는 일이다.
이 프로젝트는 선택한 Wand 설치 폴더의 파일 자체에 패치를 적용한다.
따라서 사용 경험의 확장과 함께 원본 보관, 버전 변화, 실패 후 복구라는 문제가 따라온다.
단순한 브라우저 북마크나 외부 리모컨과 달리 설치된 클라이언트의 상태를 바꾸는 프로그램이라는 점이 출발점이다.[1][2]

README는 기본 .NET 패처에 업데이트 조회나 원격 측정 네트워크 코드가 없다고 설명한다.
그러나 Wand 자체는 온라인 애플리케이션이고, 빌드 도구는 의존성을 내려받으며, 선택형 원격 패널은 LAN의 HTTP/WebSocket 서버와 Wand API/CDN 자료를 사용한다.
기본 패처가 오프라인이라는 문장을 전체 사용 과정에 네트워크가 없다는 말로 바꾸면 범위가 달라진다.
빌드 시 선택할 수 있는 GitHub 릴리스 알림도 별도 경로다.[1]

## 원본 보관과 수정 상태를 다루는 코드

대표 구현인 `Enhancer.cs`는 앱 자료를 담은 `app.asar`, 압축 밖의 `app.asar.unpacked`, 각각의 백업, 미완료 표식을 구별한다.
ASAR는 Electron 계열 앱에서 여러 파일을 묶는 아카이브 형식으로 이해하면 된다.
패치 시작 시 대상 프로세스를 종료하려고 시도하고 미완료 표식을 만든 뒤, 백업이 없으면 생성하고 있으면 원본 상태를 다시 복원하는 흐름이 나타난다.[2]

그 다음 자료를 풀어 선택한 변경과 원격 패널·사용자 스크립트 처리를 연결하고 다시 패키징한다.
성공 경로에서는 미완료 표식을 지우며 예외가 발생하면 되돌리기를 시도한다.
여기서 중요한 것은 백업 파일의 존재와 패치 완료 판정이 같지 않다는 점이다. `IsPatched`는 백업뿐 아니라 미완료 표식이 없는지도 확인한다.
파일 하나가 남아 있다는 사실만으로 성공을 판단하지 않으려는 구조다.[2]

복구 코드가 있다고 무조건 복원이 보장되는 것은 아니다. `RollbackQuietly`는 최선의 복구를 시도하되 실패를 로그에 남기고, 명시적 `Restore`는 백업이 불완전하면 예외를 낸다.
원본이 사라지거나 권한 문제가 생긴 상황까지 자동으로 해결했다고 해석할 수 없다.
이 글에서도 실제 설치 파일을 바꾸거나 복원 성공을 확인하지 않았다.[2]

## 예시로 따라가는 흐름

공식 README의 `hello.js`는 사용자 스크립트가 클라이언트 화면 안에서 어떻게 동작하는지 보여준다.
예제 입력은 대화상자가 나타날 때 로그를 남기는 짧은 JavaScript 파일이다.
여기서는 이 예제를 읽어 동작 순서를 설명하며 패치를 실행한 결과를 제시하지 않는다.
사용자 스크립트 경로는 Remote Web Panel 패치의 렌더러 주입 기능을 재사용한다고 안내되어 있다.[1]

스크립트는 먼저 전역 플래그를 확인한다.
같은 코드가 실행 때 여러 번 호출될 수 있으므로 한 번 설치한 관찰자를 중복해서 등록하지 않기 위한 장치다.
이후 `MutationObserver`로 화면 요소의 변화를 관찰하고, 아직 표시를 붙이지 않은 대화상자를 찾으면 `data-seen` 속성을 설정하고 로그를 남긴다.
입력 파일을 추가하는 행위와 실제 화면에서 관찰자가 등록되는 시점이 다르다는 사실을 이 예제에서 읽을 수 있다.[1]

예상되는 관찰 대상은 대화상자가 열릴 때의 로그와 중복 등록 여부다.
이는 예제의 의도를 설명한 것이지 특정 로그가 실제로 출력됐다는 보고가 아니다.
사람이 확인할 부분은 스크립트가 무엇에 접근하는지, 반복 실행에도 상태가 망가지지 않는지, 클라이언트 업데이트 뒤 선택자가 여전히 의미 있는지다.
README는 스크립트가 화면 DOM 전체와 Node의 `require`에 접근하고 Wand와 같은 권한으로 실행된다고 경고한다.
화면 장식 코드처럼 보여도 신뢰할 수 없는 파일을 넣으면 안 되는 이유가 여기에 있다.[1]

## 원격 패널과 배포 파일에서 생기는 경계

Remote Web Panel은 같은 로컬 네트워크의 휴대전화에서 기능을 조작하는 선택형 기능이다.
문서는 포트 `3223`의 평문 HTTP를 사용하며 페어링 코드가 없다고 명시한다.
그 포트에 접근할 수 있는 사람은 패널을 보고 활성 trainer를 제어할 수 있으므로, 신뢰한 LAN 또는 VPN으로 범위를 제한하고 인터넷에 직접 공개하지 말라고 안내한다.
베어러 토큰을 프로토콜에 포함하지 않는다는 설명과 접속자 인증이 있다는 주장은 서로 다르다.[1]

배포 경로도 특히 주의해야 한다.
조회한 README 기준 공식 Releases는 릴리스 설명만 제공하고 미리 빌드된 실행 파일을 배포하지 않는다.
프로젝트 이름을 이용한 가짜 영상과 악성 다운로드를 경고하며, 직접 소스를 검토하고 자기 빌드 산출물을 사용하도록 안내한다.
이름이나 아이콘이 같다고 공식 바이너리로 간주할 수 없다.
또한 서명되지 않은 프로그램에 대한 보안 경고를 이 문서가 무시하라고 권하는 것은 아니다.[1]

원본 클라이언트의 이용 조건과 제3자 도구의 Apache-2.0 라이선스도 별개다.
클라이언트 수정은 본인 소유 또는 명시적으로 허가된 환경의 연구 범위로 한정하고, 다른 사람의 시스템이나 서비스 권한을 바꾸는 용도로 확대해서는 안 된다.
프로젝트의 로컬 상호운용 목적 설명만으로 모든 사용 방식의 적법성과 안정성이 보장되지는 않는다.[1]

## 정리

WandEnhancer는 클라이언트의 로컬 파일과 화면 동작을 확장하는 패처다.
기능 목록보다 수정·백업·복원 경로, 사용자 스크립트 권한, 원격 패널의 접근 범위를 먼저 이해해야 한다.
