## 한 줄 요약

OpenStock은 외부 시장 데이터와 차트를 한 화면에 연결하는 주식 정보 웹 앱이다.
종목을 검색하고 개인 관심 목록에 저장하며 기업 정보·뉴스·차트를 확인하는 역할이다.
매매 주문을 넣는 증권 중개 서비스가 아니고 금융 조언을 제공하지 않는다고 README가 구분한다.
AI 관련 기능도 있지만 전체 앱의 중심은 데이터를 가져와 사용자별 화면으로 구성하는 데 있다.[1]

## 종목을 찾는 것과 기억해 두는 것

관심 종목을 매번 검색하는 대신 목록에 저장해 두고 상세 화면을 오가는 작은 상황을 떠올릴 수 있다.
이때 필요한 것은 현재 가격뿐 아니라 로그인한 사람이 누구인지, 어떤 종목을 저장했는지와 그 정보를 어디에 유지하는지다.
OpenStock은 Better Auth로 사용자 인증을 처리하고 MongoDB에 관심 목록을 저장하며 외부 서비스로 시세와 기업 정보를 채운다.[1]

Finnhub는 종목과 프로필·시장 뉴스 등의 데이터 공급원이고 TradingView는 차트·열지도와 시장 위젯을 제공한다.
위젯은 다른 서비스가 제공하는 화면 일부를 앱에 넣는 방식이다.
두 제공자를 조합하므로 검색에서 종목이 발견되는 것과 해당 종목의 차트가 같은 범위로 표시되는 것은 별개일 수 있다.
README는 무료 위젯의 시장 제한과 지연 가능성을 따로 안내한다.[1]

## 앱이 저장하는 정보와 가져오는 정보

관심 목록은 사용자별 저장 데이터다.
반면 차트와 뉴스의 원천은 외부 서비스다.
외부 제공자의 응답·요금제·갱신 간격이 달라지면 화면에서 볼 수 있는 내용도 달라진다.
프로젝트가 공개되어 있다는 사실만으로 실시간 데이터 이용권까지 함께 제공되지는 않는다.
README의 소개에 나오는 실시간이라는 표현은 구성과 공급자 조건을 함께 읽어야 한다.[1]

선택 기능으로는 여러 출처의 감성 정보를 보여주는 카드, 가입 이벤트에 따른 AI 맞춤 환영 메일과 일정에 따른 뉴스 요약 메일이 있다.
감성 카드는 기존 시세 공급원을 대체하지 않는다.
AI 문구 생성이나 소셜 정보 요약이 주가 예측의 정확성을 증명하는 것도 아니다.
기능 이름보다 어떤 서비스에서 가져온 어떤 종류의 값인지 구분해 읽는 편이 안전하다.[1]

메일 기능에는 이벤트·예약 작업을 처리하는 Inngest와 메일 전송 설정이 필요하다.
README는 로컬 구성에서 메일 자격증명을 생략하면 앱 자체는 시작하지만 관련 메일은 비활성화된다고 설명한다.
따라서 화면을 읽는 핵심 앱과 선택적인 자동 발송 기능의 준비 조건을 나눌 수 있다.[1]

## 예시로 따라가는 흐름

로그인한 사용자가 공개 종목 하나를 검색해 관심 목록에 넣고 나중에 다시 여는 상황을 가정하자.
이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
입력은 선택한 종목 기호와 기업명이다.
대표 코드 `addToWatchlist`는 먼저 `requireUserId`로 사용자 식별자를 얻고 데이터베이스에 연결한다.
저장 조건에는 사용자 ID와 대문자로 정리한 종목 기호가 함께 들어간다.
같은 종목이 이미 있다면 새 행을 계속 추가하는 대신 갱신하고, 없다면 만드는 upsert 방식이다.[2]

저장 뒤에는 모든 페이지의 사이드바에서 목록을 다시 반영할 수 있도록 레이아웃 경로를 재검증한다.
목록 조회 함수는 사용자 ID로 항목을 찾고 추가 시각의 역순으로 정렬한다.
사람이 확인할 부분은 로그인한 사용자의 목록인지, 같은 종목을 반복 추가했을 때 중복이 생기지 않는지, 화면의 갱신과 실제 저장 상태가 일치하는지다.
이 저장 흐름은 주식을 사거나 외부 계좌에 주문을 전달하지 않는다.
관심 목록 추가라는 작은 동작에 인증·저장·화면 캐시 갱신이 함께 필요하다는 점을 보여준다.[2]

## 빈 목록이 항상 저장 항목 없음은 아니다

대표 코드에서 추가·삭제 실패는 오류를 던지지만 조회 실패는 오류를 기록하고 빈 배열을 반환한다.
포함 여부 검사 실패도 `false`를 반환한다.
이 때문에 빈 목록이나 비활성 버튼만 보고 데이터가 정말 없는지, 조회 도중 문제가 있었는지까지 구분할 수는 없다.
정상 경로를 읽는 것과 장애 상황에서 사용자가 받는 신호를 검토하는 것은 다른 질문이다.[2]

이 원고에서는 개별 서버 작업이 사용자 ID를 조회하는 부분을 확인했을 뿐, 전체 인증과 권한 경계를 보안 감사한 것은 아니다.
화면이 보호된다고 소개하는 문장만으로 모든 API가 같은 수준으로 점검되었다고 주장하지 않는다.
실제 공개 운영 전에는 인증 설정, 데이터베이스 접근과 외부 API 오류 처리까지 별도로 확인해야 한다.

## 데이터 제공 조건과 공개 운영 조건

README는 Node.js 20 이상, MongoDB 연결과 Finnhub 키를 사전 조건으로 제시한다.
무료 데이터는 지연되거나 호출 한도가 있을 수 있고, 설정에는 시간 단위 캐시 갱신과 더 자주 갱신하는 모드의 차이도 나온다.
따라서 화면의 가격만 보고 즉시 거래 가능한 시세나 정확한 현재가로 단정하지 않아야 한다.[1]

환경 변수에 비밀을 넣는다고 모두 서버 안에 숨겨지는 것은 아니다.
README는 `NEXT_PUBLIC_` 이름의 값이 브라우저에 노출된다고 경고한다.
공개 가능한 설정과 사적인 API 키·데이터베이스 비밀번호를 분리해야 한다.
로컬 예제 설정을 인터넷 운영 환경에 그대로 복사하는 것은 적절한 검증을 대신하지 않는다.[1]

프로젝트는 AGPL-3.0을 명시한다.
수정·배포·네트워크 서비스 제공 시 해당 라이선스의 소스 제공 의무 등을 검토해야 하며, 외부 시장 데이터의 이용 약관은 코드 라이선스와 별도다.
무료로 코드에 접근할 수 있다는 문장을 운영 비용이나 모든 데이터의 자유로운 재배포 허가로 넓혀 해석하면 안 된다.[1]

## 정리

OpenStock은 시장 정보를 모아 개인 관심 목록과 연결하는 웹 앱이다.
관심 목록은 앱의 저장 데이터이고 시세·차트는 외부 제공자의 조건을 따르며, 거래나 투자 판단을 대신하지 않는다.
