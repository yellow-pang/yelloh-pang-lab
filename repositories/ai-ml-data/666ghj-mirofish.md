## 한 줄 요약

MiroFish는 입력 문서와 질문을 바탕으로 가상 참여자들을 구성하고 상호작용을 시뮬레이션해 보고서를 만드는 다중 에이전트 응용이다.
여기서 에이전트는 성격과 기억, 행동 규칙을 부여받은 가상 참여자다.
README는 이를 예측 엔진으로 소개하지만 시뮬레이션 결과가 실제 미래를 정확하게 맞힌다는 사실과는 구분해야 한다.
여러 가능한 전개를 생성하는 기능과 현실 예측의 검증은 다른 문제다.[1]

## 자료에서 가상 사회를 만드는 과정

입력은 자연어 요구와 출발 자료다.
README는 자료 분석 보고서나 이야기처럼 초기 정보를 제공하고 무엇을 알고 싶은지 설명하는 방식을 제시한다.
입력 문장을 곧바로 하나의 답변으로 줄이는 대신 등장 주체, 관계, 성격과 기억을 구성해 상호작용 환경을 만드는 것이 특징이다.
소설의 인물 관계를 설정한 뒤 ‘다른 사건이 생기면 누가 어떻게 반응할까’를 탐색하는 상황으로 이해할 수 있다.[1]

전체 흐름은 그래프 구성, 환경 설정, 시뮬레이션, 보고서 생성과 후속 대화로 나뉜다.
그래프는 개체를 점으로, 관계를 연결선으로 표현하는 구조다.
자료에서 관계와 기억을 추출한 다음 참여자 프로필과 설정을 만들고, 두 플랫폼의 병렬 시뮬레이션과 시간에 따른 기억 갱신을 진행한다고 설명한다.
보고서 이후에도 가상 참여자나 ReportAgent와 대화하는 경로가 있다.[1]

## 관계를 만들기 전에 ‘종류’를 정한다

대표 구현 `ontology_generator.py`는 어떤 개체 종류와 관계 종류를 사용할지 설계하는 서비스를 담는다.
온톨로지는 여기서 세계를 분류하는 규칙표라고 이해하면 된다.
코드의 모델 지침은 텍스트와 시뮬레이션 요구를 분석해 `entity_types`, `edge_types`, `analysis_summary`가 있는 JSON을 반환하도록 한다.
JSON은 프로그램이 일정한 구조로 읽을 수 있는 데이터 표현이다.[2]

이 지침은 사회적 상호작용에 참여할 수 있는 사람이나 조직을 개체로 삼고 ‘여론’, ‘감정’, ‘주제’ 같은 추상 개념을 행위 주체로 만들지 않도록 요구한다.
관계에는 어떤 종류의 개체에서 어떤 종류로 이어지는지 `source_targets`를 명시한다.
따라서 모델이 그럴듯한 인물 이름을 많이 만드는 것만으로 환경 설계가 끝나지 않는다.
누가 행위자이고 어떤 연결이 허용되는지를 먼저 정한다.[2]

구체적 유형 외에 `Person`과 `Organization` 같은 포괄 유형을 두는 지침도 있다.
자료에 나타나는 모든 사람과 조직이 미리 정한 세부 유형에 들어맞지는 않기 때문이다.
이름 표기 변환과 속성·관계 정규화 코드가 포함된 점은 모델 출력을 뒤의 그래프 처리에 맞추려는 장치다.
다만 출력 구조를 맞추는 검사는 입력 자료가 현실을 올바르게 대표하는지 검증하는 것과 다르다.[2]

## 예시로 따라가는 흐름

공개된 창작 설정에 등장하는 인물들이 새로운 사건에 반응하는 상황을 탐색한다고 가정하자.
이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
입력은 권리가 확보된 이야기 자료와 ‘사건 이후 인물 관계가 어떻게 달라질 수 있는가’라는 요구다.
먼저 자료에 등장하는 주체와 관계의 종류를 정한다.
이때 사건의 분위기나 주제를 인물처럼 취급하지 않고, 행동할 수 있는 주체와 그 사이의 관계를 구분하는 것이 대표 구현에서 읽은 준비 단계다.[1][2]

이 구조를 바탕으로 참여자의 성격과 기억을 구성하고 상호작용을 진행한 뒤 ReportAgent가 결과를 보고서로 정리하는 것이 README의 흐름이다.
사람이 확인할 부분은 원문에 없는 성격이 추가됐는지, 중요한 인물이 누락됐는지, 초기 관계와 질문이 시뮬레이션에 제대로 반영됐는지다.
마지막 보고서를 읽을 때에는 ‘입력 자료에서 확인한 사실’, ‘모델이 보충한 설정’, ‘가상 환경에서 발생한 사건’을 분리해야 한다.
후속 대화에서 가상 인물이 자세히 답한다고 해서 원작이나 실제 인물의 의도가 새로 확인되는 것은 아니다.
보고서의 설득력과 외부 사실성은 따로 판단할 대상이다.

## 외부 API와 예측 표현의 한계

README는 OpenAI SDK 형식의 LLM API와 Zep Cloud 키를 요구한다.
따라서 소스코드를 로컬에 두더라도 기본 안내를 완전 오프라인 도구로 읽을 수 없다.
출발 자료와 대화·기억이 어느 외부 서비스로 전달되는지 확인하고 공개하거나 전송할 권한이 있는 자료를 선택해야 한다.
비공개 정보와 실제 개인의 민감한 자료를 가상 환경이라는 이유로 가볍게 넣어서는 안 된다.[1]

모델 사용량이 높을 수 있어 처음에는 작은 회차의 시뮬레이션으로 시작하라는 경고도 있다.
에이전트가 많거나 회차가 길면 여러 요청이 발생하므로 파일 크기만으로 비용을 예상하기 어렵다.
Node.js와 Python, 패키지 관리 도구의 요구사항도 구분되어 있으며 화면과 백엔드가 함께 필요한 애플리케이션이다.[1]

README의 ‘모든 것을 예측한다’는 문장은 비전과 소개 문구다.
이 조사에서는 실제 사건을 대상으로 오차를 평가하거나 반복 실험의 안정성을 확인하지 않았다.
가상 참여자의 반응을 실제 설문 결과, 투자 판단 근거 또는 확정된 사회 전망으로 취급하면 안 된다.
코드의 온톨로지 지침이 사회적 상호작용을 중심으로 설계됐다는 점도 모든 분야의 현상을 동일하게 모델링하는 범용 검증을 뜻하지 않는다.[1][2]

프로젝트에는 AGPL-3.0이 적용된다.
특히 수정한 프로그램을 네트워크를 통해 사용자와 상호작용하도록 제공하는 경우에는 LICENSE 13조의 해당 소스 제공 조건을 확인해야 한다.
외부 API 사용 약관과 프로그램 코드의 라이선스는 서로 다른 조건이므로, 공개 소스라는 소개만으로 수정판의 배포나 서비스 제공이 제한 없이 허용된다고 보아서는 안 된다.[3]

## 정리

MiroFish는 자료를 가상 행위자와 관계로 재구성해 여러 전개를 탐색하는 시스템이다.
초기 설정과 모델 해석이 결과에 들어가므로 보고서를 실제 관측이나 검증된 미래 사실과 분리해 읽어야 한다.
