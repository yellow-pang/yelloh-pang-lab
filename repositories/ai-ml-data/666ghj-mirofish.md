## 한 줄 요약

MiroFish는 문서와 질문을 바탕으로 여러 AI 에이전트가 상호작용하는 가상 상황을 만들고 시뮬레이션 보고서를 생성하는 프로젝트이다.[1]

## 이 Repository는 무엇인가?

에이전트는 성격·기억·행동 규칙을 부여받은 가상 참여자를 뜻하며, 이들의 상호작용으로 상황 전개를 살펴보는 방식을 제시한다.[1]

프로젝트는 이를 예측 엔진으로 소개하지만, README의 비전과 시나리오 실험 기능은 실제 미래를 정확히 맞힌다는 검증 결과와 구분해야 한다.[1]

### 자료 확인 범위

2026-09-27에 공개 README와 아래에 인용한 공식 파일을 확인한 기본 초안이다.
설치·실행 시험이나 성능 검증을 한 문서는 아니다.
개인적인 Star 이유와 평가, 사용 후기는 직접 작성할 수 있도록 비워두었다.

## 주요 기능

- 자료에서 출발 정보를 추출하고, 개체 관계와 기억을 그래프로 구성한 뒤 참여자별 성격과 설정을 만드는 흐름을 설명한다.[1]
- 시뮬레이션 단계에는 두 플랫폼의 병렬 진행, 자연어 요구사항 해석과 시간에 따른 기억 갱신이 포함된다.[1]
- 결과를 해석하는 ReportAgent의 보고서 생성뿐 아니라 가상 참여자나 ReportAgent와 대화하는 후속 탐색을 제공한다.[1]

## 어떻게 동작하는가?

```text
문서 등 초기 자료와 자연어 시나리오 요구 입력.
↓
관계 그래프·참여자 설정 생성 후 상호작용 시뮬레이션.
↓
보고서 생성과 가상 참여자에 대한 추가 질문.
```

이 흐름은 공식 문서의 그래프 구성·환경 설정·시뮬레이션·보고서·후속 대화 단계를 요약한 것이며, 모든 결과를 현실의 관측값으로 해석해서는 안 된다.[1]

### 확인한 파일 구성

- 루트 `package.json`은 `frontend`와 `backend`의 준비·시작 작업을 구분하고, 개발 시 두 프로세스를 함께 시작하는 구성을 선언한다.[2]
- `backend/pyproject.toml`은 Python 백엔드의 의존성과 개발 검사 도구를 선언하고 `app`을 배포 패키지 대상으로 지정한다.[3]

## 어떤 기술을 사용하는가?

- `OASIS`·`CAMEL`: 다중 에이전트 시뮬레이션을 뒷받침하며 백엔드 의존성에 `camel-oasis`와 `camel-ai`가 포함된다.[1][3]
- `Flask`: Python 백엔드의 웹 프레임워크로 선언되어 있다.[3]
- `OpenAI` SDK 형식의 모델 API와 `Zep Cloud`: README가 필수 키를 요구하는 외부 연동이며 백엔드 의존성에도 포함된다.[1][3]

## 실제로 어디에 사용할 수 있는가?

- 공개 소설이나 창작 설정을 입력하여 가상 인물의 상호작용과 여러 이야기 전개를 탐색하는 개인 실험을 할 수 있다.[1]
- 공개 자료로 가정한 시나리오를 구성하고, 참여자 설정·기억·보고서가 이어지는 다중 에이전트 설계를 학습할 수 있다.[1]

## 왜 주목할 만한가?

학습 관점에서는 보고서를 최종 파일로만 끝내지 않고, 시뮬레이션 이후에도 참여자와 보고서 담당 에이전트에 질문할 수 있도록 흐름을 연결한 점이 특징이다.[1]

## 장점

- 자료 입력부터 관계 구성, 시뮬레이션과 보고서까지의 단계를 구분하여 제시한다.[1]
- 소스 기반 구성과 Docker 구성을 모두 안내하고, 화면과 백엔드의 실행 작업을 분리한다.[1][2]

## 단점 / 주의점

- Node.js 18 이상과 Python 3.11 이상·3.13 미만을 요구하며, 모델 API 및 Zep Cloud 키가 필요하므로 완전 오프라인 도구로 볼 수 없다.[1][2][3]
- README는 모델 사용량이 클 수 있어 처음에는 40회 미만의 시뮬레이션으로 시작하도록 안내하므로 API 사용량과 비용 확인이 필요하다.[1]
- AGPL-3.0 라이선스가 적용되며 외부 API 연동을 전제로 하므로 공개하거나 전송할 권한이 있는 자료를 대상으로 사용 범위를 정해야 한다.[1][4]
- 이 초안은 현실 예측의 정확도를 검증하지 않았다. 가상 참여자의 반응을 실제 조사 결과나 검증된 투자 근거와 동일시하지 않아야 한다.
