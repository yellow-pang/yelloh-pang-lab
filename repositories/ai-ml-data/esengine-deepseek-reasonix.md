## 한 줄 요약

Reasonix는 파일을 읽고 수정하며 도구를 호출하는 로컬 코딩 에이전트 엔진이다.
이름에 DeepSeek가 들어가지만 확인한 README는 DeepSeek를 기본 제공 구성 중 하나로 설명하고 다른 호환 모델 연결도 허용한다.
터미널, 데스크톱, 브라우저와 편집기 연결이 같은 로컬 엔진을 사용하는 구조다.
모델 자체를 배포하거나 학습하는 저장소가 아니라 모델과 개발 도구 사이의 실행 환경이다.[1]

## 먼저 1.x와 2.x를 구분해야 한다

확인한 공식 README는 `studio` 브랜치의 2.x 문서다.
기존 초안의 `main-v2` 중심 소개와 달리 현재 문서는 안정 유지보수 계열인 1.x와 개발 중인 프리릴리스 2.x를 나누어 설명한다. 1.x는 버그·호환성·업데이트·보안 수정을 계속 받지만 핵심 구조를 확장하지 않는다고 하고, 2.x는 새로운 구조를 개발하는 계열이라고 한다.
이 글의 기능 설명은 실제 읽은 studio 문서를 기준으로 한다.[1]

같은 명령 이름을 사용한다고 설치 경로가 모두 같은 버전을 뜻하지는 않는다.
README의 npm 설치 안내는 1.x에 속하고 Studio 릴리스는 2.x로 표시된다.
편집기 확장이 로컬 CLI를 시작하는 경로도 별도로 소개된다.
사용하려는 화면보다 먼저 어느 계열의 엔진과 문서를 보고 있는지 확인해야 설정과 기능 기대가 섞이지 않는다.[1]

## 오래 실행할수록 필요한 문맥과 통제

장기 코딩 작업은 한 번의 답변이 아니라 조사, 수정, 명령 실행과 재검토를 반복한다.
Reasonix는 시작 시 안정된 환경 요약을 넣고 오래된 도구 출력을 줄인 뒤 요약 압축을 수행하는 문맥 관리를 소개한다.
모델 요청 앞부분을 자주 바꾸지 않도록 하는 캐시 인식 설계도 강조한다.
캐시는 반복되는 입력을 재사용하는 구조지만 이 글은 특정 비용 절감률이나 속도를 직접 확인하지 않았다.[1]

모델과 도구 설정은 `reasonix.toml`에서 선언한다.
README는 실행 모델과 계획 모델을 별도 세션으로 조합할 수 있다고 설명하고 MCP 및 확장 프로토콜을 통해 외부 기능을 연결한다고 한다.
MCP는 외부 도구·프롬프트·자료를 연결하는 규약이며 확장 sidecar는 엔진 옆에서 별도 프로세스로 동작하는 구성 요소다.
사용자 화면이 늘어나더라도 모델 요청과 도구 권한은 엔진의 설정에서 따로 다룬다.[1]

공식 Guide는 명령줄 옵션, 프로젝트 설정, 사용자 설정, 기본값의 우선순위를 제시한다.
단 모든 필드가 프로젝트에서 덮어써지는 것은 아니다.
제공자 설정은 `api_key_env`로 비밀값의 이름을 가리키고 실제 키는 전역 Reasonix 환경 파일에 둔다.
프로젝트의 일반 `.env`와 모델 키를 보관하는 영역을 구분한다는 점이 중요하다.[2]

## 예시로 따라가는 흐름

README의 `main.go`에 있는 TODO를 구현하라는 예제를 읽어보자.
입력은 프로젝트와 구체적인 수정 요청이다.
엔진은 설정된 제공자와 모델을 사용해 파일을 조사하고 필요한 도구 호출을 이어간다.
이 글은 명령을 실행한 결과가 아니라 공식 사용 예제를 바탕으로 작업의 경계를 설명한다.
요청이 코딩이라고 해서 모든 셸 명령과 파일 경로에 일괄 권한이 생기는 것은 아니다.[1][2]

Guide에 따르면 도구 호출에는 거부·확인·허용 규칙과 기본 정책이 적용된다.
파일을 읽은 뒤 수정하려는 단계에서 승인 규칙이 맞는지 확인하고, 승인된 경우에도 파일 도구의 쓰기 경로는 작업 공간 경계 안인지 검사된다.
사람이 검토할 결과는 변경된 코드뿐 아니라 실행한 명령과 출력, 수정 범위가 요청에 맞는지다.
자동 실행 모드를 썼다고 명시적인 거부 규칙까지 사라지는 것으로 읽으면 안 된다.
반대로 Ask 모드는 승인 후 쓰기가 가능한 모드이지 읽기 전용 모드는 아니다.
이런 차이를 알아야 ‘분석만 요청했는데 승인 후 수정이 진행됐다’는 상황을 정확하게 판단할 수 있다.[2]

## 승인 정책과 실제 격리의 차이

Guide는 Permissions를 허용하거나 물어보는 정책, Sandbox를 강제되는 기능 경계로 구분한다.
전용 파일 도구는 기본 작업 공간 밖의 경로를 거부하고 심볼릭 링크와 상위 경로 이동을 해석하도록 설명한다.
셸은 운영체제 샌드박스가 가능할 때 그 안에서 실행하며 macOS의 Seatbelt와 Linux의 bubblewrap 경로가 제시된다.
승인 버튼 하나로 모든 격리 조건을 설명할 수는 없다.[2]

특히 Windows에서는 운영체제 수준의 Bash 샌드박스를 제공하지 않는다는 명시적 주의가 있다.
전용 파일 도구의 경로 제한은 유지되지만 승인된 셸은 사용자 권한으로 격리 없이 동작한다.
따라서 동일한 설정 이름을 사용해도 플랫폼별 보안 경계가 같다고 단정하면 안 된다.
네트워크 허용과 읽기 금지 경로 역시 실제 적용 상태를 확인해야 한다.[2]

세션 전용 임시 디렉터리는 연속 명령 사이에 파일을 전달하는 데 쓰이지만 영구 저장소가 아니다.
프로세스 재시작 후 재개에서 임시 파일이 복원된다고 가정하지 말라는 안내가 있다.
오랫동안 실행할 수 있는 에이전트라 해도 작업 결과, 세션 기록과 임시 산출물의 수명은 서로 다르다.[2]

## 정리

Reasonix의 중심은 여러 화면에서 사용할 수 있는 코딩 실행 엔진과 문맥·권한 관리다.
버전 계열과 플랫폼별 격리 경계를 구분해야 하며 장기 실행 가능성이 무제한 권한이나 자동 정답을 뜻하지는 않는다.
