## 한 줄 요약

WeKnora는 문서를 모아 검색하고 답변·작업·위키로 활용하는 지식 관리 프레임워크다.
문서를 저장하는 폴더나 언어 모델 하나를 뜻하지 않는다.
README는 같은 지식 기반을 RAG 질의응답, 여러 단계의 Agent 작업과 위키 구성에 재사용한다고 설명한다.
Agent는 질문에 답하는 데서 더 나아가 도구를 선택하고 여러 작업을 이어서 수행하는 실행 주체다.[1]

## 자료가 많아졌을 때 생기는 세 가지 질문

공개 학습 문서가 여러 개 쌓이면 “이 조건은 어디에 설명되어 있는가”, “관련 자료를 모아 비교해 달라”, “핵심 개념을 서로 연결해 정리해 달라”는 요청이 생길 수 있다.
각각 필요한 처리가 다르다.
WeKnora의 RAG는 관련 원문을 찾아 답하는 데, Agent는 도구와 여러 단계를 잇는 데, Wiki는 연결된 페이지로 지식을 정리하는 데 초점을 둔다.
별도 자료를 계속 복사하기보다 같은 지식 기반을 출발점으로 삼는 구조다.[1]

RAG는 검색 증강 생성이라고 하며, 모델이 기억한 내용만으로 답하는 대신 관련 문서 조각을 찾아 참고하게 하는 방식이다.
문서 파싱은 PDF·표·이미지 등을 읽을 수 있는 내용으로 바꾸는 과정이고, 임베딩은 의미를 검색할 수 있게 수치 표현으로 바꾸는 과정이다.
두 과정에서 생긴 누락이 이후 검색과 답변에도 영향을 줄 수 있으므로 파일 업로드 성공을 내용 이해 성공으로 간주하면 안 된다.[1]

## 하나의 질문에도 여러 처리 단계가 있다

대표 파일 `session_knowledge_qa.go`의 `KnowledgeQA`는 먼저 사용할 지식 기반과 모델을 정하고 검색 대상을 구성한다.
질문 문자열만 모델에 바로 보내는 함수가 아니다.
사용자·세션·검색 범위, 결과 임곗값과 재정렬 설정 등을 모아 이후 파이프라인에 전달한다.
임곗값은 어느 점수 이상의 검색 결과를 채택할지 정하는 기준이고, 재정렬은 찾은 후보를 질문과의 관련성에 따라 다시 평가하는 단계다.[2]

코드는 검색할 지식 범위가 있거나 웹 검색이 켜진 경우 RAG 경로를 조립한다.
이 경로에는 질문 이해, 문서 조각 병렬 검색, 재정렬, 병합, 상위 결과 필터링과 대화 메시지 구성이 순서대로 들어간다.
검색 범위와 웹 검색이 모두 없으면 별도의 일반 대화 경로가 선택된다.
화면에 답변이 나왔다는 것만으로 문서 검색을 거쳤다고 단정할 수 없는 이유다.[2]

RAG와 일반 대화 경로 모두 기억 회상 단계를 포함할 수 있지만 문서 검색 단계는 다르다.
이 차이를 알아야 사용자의 이전 대화에서 가져온 정보와 업로드 문서를 근거로 한 답변을 구별할 수 있다.
출처 표시는 검토를 돕는 장치이지 답변의 모든 문장이 정확하다는 보증은 아니다.[1][2]

## 예시로 따라가는 흐름

공개 장비 설명서 PDF 두 개를 개인 학습용 지식 기반에 올리고 “두 모델의 보관 온도 조건은 어떻게 다른가”라고 묻는 상황을 가정하자.
이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
입력은 문서와 질문, 선택한 지식 기반이다.
문서 처리로 만든 검색 자료를 사용할 수 있는 상태에서 질문이 들어오면 대표 코드가 검색 대상과 답변 모델을 정하고 RAG 파이프라인을 선택한다.
검색 후보는 재정렬·병합·필터링을 거쳐 답변용 메시지에 들어가도록 구성된다.[1][2]

사람은 결과에서 두 문서가 모두 참고되었는지, 표의 온도 단위와 각주가 빠지지 않았는지, 보관 조건을 사용 조건과 혼동하지 않았는지 원문과 대조해야 한다.
만약 지식 기반 선택이 빠지고 웹 검색도 꺼져 있다면 일반 대화 경로가 될 수 있으므로 유창한 답변만 보고 업로드한 자료를 읽었다고 믿어서는 안 된다.
결과 이벤트에는 참조와 답변 조각, 완료 상태가 전달되도록 설계되어 있다.
최종 답변의 완료와 충분한 근거 확보도 별개다.
이 사례의 목적은 예상 성능을 주장하는 것이 아니라 입력 범위가 검색 경로와 검토 대상에 어떻게 영향을 주는지 보여주는 것이다.[2]

## 답변에서 도구 실행으로 넘어갈 때

README의 Agent는 Skill과 MCP 도구, 샌드박스 및 로컬 브라우저 연결을 사용한다.
Skill은 반복 작업을 위한 지침 묶음이고 MCP는 외부 도구 연결 규약이다.
샌드박스는 실행 영역을 분리하는 장치지만 그 안에서 가능한 명령과 접근할 파일·네트워크 범위까지 자동으로 무해해지는 것은 아니다.
README는 특정 버전의 샌드박스 명령이 `root`로 실행된다고 명시한다.
높은 권한을 다루므로 문서 검색만 사용할 때와 다른 검토가 필요하다.[1]

로컬 브라우저 연결은 사용자의 Chrome·Edge를 조작하는 방식으로 소개되며, 이미 로그인한 브라우저의 권한이 연결될 수 있다.
문서에 있는 로그인 인계나 일시 정지 기능을 읽고 실제 접근 범위를 정해야 한다.
공유 지식 기반과 외부 MCP를 활성화할 때도 어떤 자료를 어떤 도구에 내보내는지 확인해야 한다.[1]

Wiki는 개념을 추출해 연결된 페이지를 만드는 별도 산출물이다.
문서 검색 결과를 그대로 목록화하는 것과 달리 페이지 내용과 관계를 새로 구성하므로 원문과의 연결을 검토해야 한다.
수정 이력 비교·되돌리기는 교정을 돕지만 생성된 분류와 요약이 사실인지 자동으로 결정해 주지는 않는다.[1]

## 배포 방식과 보호 설정

README는 Docker Compose, Kubernetes, 경량 단일 실행 파일과 데스크톱 경로를 나눈다.
데스크톱 설치 프로그램은 아직 배포하지 않는다고 명시하므로 다운로드 가능한 완제품으로 소개하면 안 된다.
모델과 벡터 검색·파일 저장소를 선택할 수 있지만 선택한 외부 모델로 데이터가 전송되는지와 비용은 별도로 확인해야 한다.[1]

로그인 기능이 있어도 서비스를 인터넷에 직접 노출하지 않고 사설망, 방화벽과 접근 제어를 사용하라는 경고가 있다.
MIT 라이선스는 공개 코드의 사용 조건일 뿐 운영상의 보안 보증이 아니다.
많은 기능을 켜는 것보다 검색·모델·도구별 권한을 필요한 수준으로 제한하고 처리 기록을 점검하는 준비가 중요하다.[1]

## 정리

WeKnora는 같은 자료를 검색 답변·다단계 작업·위키로 활용하는 플랫폼이다.
검색 범위를 지정하는 일과 실행 도구의 권한을 정하는 일을 나누고 최종 산출물은 원문과 비교해야 한다.
