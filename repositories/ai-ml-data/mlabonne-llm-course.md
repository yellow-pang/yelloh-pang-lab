## 한 줄 요약

LLM Course는 대규모 언어 모델의 개념·연구·앱 개발을 공부할 때 필요한 자료와 실습을 연결한 공개 학습 경로다.
모델을 자체 제공하는 서버나 완성된 학습 프레임워크가 아니라 로드맵과 외부 노트북을 연결하는 출발점이다.[1]

## 모델을 만드는 공부와 사용하는 공부

LLM이라는 주제 안에서도 수학 기초, 모델 개선, 애플리케이션 배포는 필요한 지식이 다르다.
README는 선택적인 Fundamentals, 모델을 만드는 Scientist, 모델 기반 앱을 만드는 Engineer로 경로를 나눈다.
모든 링크를 순서대로 읽기보다 목표에 맞는 지식의 층을 선택할 수 있게 한 구성이다.[1]

## 저장소 문서와 외부 실습의 관계

README의 Notebooks 표는 저자의 글과 Colab으로 연결되며 미세조정, 양자화 같은 주제를 나눈다.
미세조정은 기존 모델을 추가 데이터에 맞추는 작업이고, 양자화는 모델 수치를 더 적은 정밀도로 표현하는 방법이다.
학습 데이터로 모델을 바꾸는 과정과 저장 표현을 줄이는 과정은 같은 작업이 아니다.[1][2]

대표 자료로 연결된 저자의 `Introduction to Weight Quantization`을 읽었다.
이미 학습한 가중치를 변환하는 PTQ와 학습 과정에 양자화를 넣는 QAT를 구분하고, GPT-2 예제로 PTQ를 설명한다.
가중치는 모델이 학습한 수치이며, 낮은 정밀도로 표현하면 메모리를 줄일 수 있지만 오차도 생길 수 있다.[2]

## 예제에서 확인하는 양자화의 동작

원문의 `absmax_quantize`는 텐서의 절댓값 최댓값으로 배율을 구하고, 값을 반올림해 INT8로 표현한다.
함께 계산하는 복원값은 배율을 되돌린 근사치이므로 원래 값과 항상 같지 않다.
이어 zero-point 방식과 이상치 문제를 다루면서 저장 크기뿐 아니라 표현 오차를 읽도록 구성한다.[2]

현재 루트 트리에는 README와 이미지 자료가 중심이며 노트북 파일은 확인되지 않았다.
따라서 원문의 과거 GitHub 노트북 링크를 현재 저장소에 존재하는 실습 파일로 간주하면 안 된다.
본문 예제와 현재 README가 제공하는 Colab 연결을 구분해 읽어야 한다.[1][2]

## 가상 학습 시나리오

작은 언어 모델도 메모리를 많이 쓰는 이유가 궁금한 학습자를 가정한다.
양자화 입문 글에서 데이터 타입을 먼저 읽고, 원래 텐서와 복원 텐서를 비교하는 실습 계획을 세울 수 있다.[1][2]
기대하는 학습 결과는 모델 이름 암기가 아니라 메모리 절약과 수치 오차가 함께 생기는 이유에 대한 설명이다.
노트북 실행, 모델 다운로드, 생성 품질 비교는 별도 실습이며 이 조사에서는 수행하지 않았다.

## 무료 자료와 실행 비용을 구분한다

강좌가 무료라는 것과 Colab·RunPod 같은 실행 자원이 무제한 무료라는 것은 다르다.[1]
모델·데이터 접근 권한, GPU 메모리와 라이브러리 버전은 선택한 노트북별로 확인해야 한다.
양자화 글은 정밀도 감소의 품질 저하 가능성을 설명하므로 더 작은 모델 표현이 언제나 같은 답을 낸다고 해석하지 않는다.[2]
저장소는 Apache-2.0이며, 외부 기사·모델·데이터까지 같은 조건으로 묶는 허가는 아니다.[3]

## 직접 읽어볼 순서

1. README 첫머리의 세 경로에서 모델 연구와 앱 개발 중 목표를 정한다.[1]
2. Notebooks의 Quantization에서 연결된 입문 글로 이동해 자료의 위치와 실습 환경을 구분한다.[1]
3. 원문의 PTQ/QAT 비교와 absmax 예제를 읽고 어떤 값이 근사되는지 확인한다.[2]
