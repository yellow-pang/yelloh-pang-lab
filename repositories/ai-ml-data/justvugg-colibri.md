## 한 줄 요약

Colibrì는 대형 MoE 모델의 필요한 부분을 저장장치에서 읽어 계산하도록 설계한 C 기반 로컬 AI 추론 엔진이다.[1]

## 이 Repository는 무엇인가?

MoE는 여러 전문가 모듈 중 일부를 선택해 계산하는 모델 방식이며, Colibrì는 선택된 전문가의 가중치를 필요할 때 불러온다.[1]

이미 학습한 모델로 답을 계산하는 추론 도구인 동시에 저장장치·메모리·CPU·GPU의 배치를 실험하는 공개 연구 프로젝트이다.[1]

## 주요 기능

- VRAM·RAM·디스크를 하나의 계층으로 다루고, 반복해서 쓰는 전문가를 캐시에 보관하며 다음 계층의 데이터를 미리 읽는다.[1]
- 공통 전면 도구인 `coli`가 모델 설정에 맞는 엔진을 골라 터미널 대화, API 서버와 웹 대시보드를 제공한다.[1]
- Brio 모드는 자유로운 문장 생성 대신 주어진 선택지의 확률과 불확실성을 나타내는 엔트로피를 반환한다.[1]

## 어떻게 동작하는가?

```text
지원 모델의 가중치와 해당 엔진, 저장 공간 및 사용 가능한 메모리를 준비한다.
↓
모델 설정에 맞는 엔진이 전문가를 선택하고 메모리 또는 저장장치에서 필요한 가중치를 가져와 계산한다.
↓
대화 응답을 터미널·HTTP API·웹 화면으로 제공하고 배치·성능 정보를 확인한다.
```

메모리 계층 배치는 모델의 정밀도나 전문가 선택 의미를 몰래 바꾸지 않는다는 설계 원칙을 따르지만, 속도는 장치와 작업에 따라 달라진다.[1]

### 확인한 파일 구성

- README의 구성 설명에서 `c/colibri.c`는 GLM 계열 엔진, `c/expert_store.h`는 전문가 캐시, `c/openai_server.py`는 HTTP 연결 계층이다.[1]
- `pyproject.toml`은 `coli` 명령을 `colibri.cli:main`에 연결하고 모델 변환·정답 비교·벤치마크용 선택 의존성을 구분한다.[2]

## 어떤 기술을 사용하는가?

- `C`는 추론 엔진의 구현 언어이며, 모델별 엔진은 공통 헤더의 파일 읽기·토큰 처리·캐시 기능을 공유한다.[1]
- `Python`은 실행 도구와 API 연결 계층에 사용되고 패키지 manifest는 Python 3.10 이상을 요구한다.[1][2]

## 실제로 어디에 사용할 수 있는가?

- 개인 장치에서 지원 모델의 전문가 캐시와 디스크 읽기가 추론에 미치는 영향을 학습할 수 있다.[1]
- 제한된 선택지를 평가하는 Brio와 일반 문장 생성의 입출력 차이를 비교하는 학습 소재로 사용할 수 있다.[1]

## 왜 주목할 만한가?

학습 관점에서는 모델 전체가 빠른 메모리에 들어가는지만 보지 않고, 매 단계 필요한 가중치의 이동과 재사용을 실행 설계의 중심에 놓은 점이 관찰점이다.[1]

## 장점

- 모델별 계산 구현과 여러 엔진이 공유하는 저장·캐시 기능을 분리해 구조를 살펴볼 수 있다.[1]
- 하드웨어·캐시 상태·품질을 함께 기록하는 측정 원칙과 최적화가 오히려 느려지는 조건도 공개한다.[1]

## 단점 / 주의점

- 작은 실행 파일이 작은 모델 저장 공간을 뜻하지 않으며, README의 GLM-5.2 예시는 약 372 GB 가중치와 별도 RAM을 요구한다.[1]
- C 엔진의 의존성 설명을 실행 도구 전체에 적용하면 안 되며, 런처·API 계층에는 Python이 필요하다.[1]
- 엔진은 Apache 2.0이고 모델 가중치 조건은 별도이며, 속도 보장은 없고 패키지 분류도 Beta이다.[1][2]

## 정리

Colibrì는 전문가 가중치를 메모리와 저장장치 사이에 배치하며 대형 모델을 계산하는 로컬 추론 엔진이다.[1] 모델별 형식과 자원 요구가 다르고, 실행 가능 여부와 실용적인 응답 속도는 구별해야 한다.[1]
