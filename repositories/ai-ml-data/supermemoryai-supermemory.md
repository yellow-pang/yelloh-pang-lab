## 한 줄 요약

Supermemory는 대화에서 얻은 사실과 문서를 저장하고 다음 AI 요청에 필요한 문맥을 돌려주는 기억·검색 계층이다.
직접 모든 질문에 답하는 모델이 아니라 AI 앱이 참고할 정보를 공급한다.
README는 API, 여러 AI 도구의 플러그인, MCP와 로컬 실행 제품을 함께 소개한다.
공개 저장소에 있는 연동 코드와 소개된 전체 기억 엔진의 범위는 구분해 읽어야 한다.[1]

## 기억과 문서 검색은 무엇이 다른가

문서 검색은 질문에 관련된 설명을 찾아오는 일이다.
기억은 사용자가 어떤 방식을 선호하고 최근 무엇을 바꾸었는지처럼 시간에 따라 달라지는 사실을 유지하는 일이다.
README는 이사한 뒤 새 거주지가 이전 거주지 정보를 대체하는 예로 차이를 설명한다.
과거 대화를 그대로 쌓는 것과 현재 유효한 사실을 추리는 것은 같은 작업이 아니다.[1]

Supermemory는 대화에서 사실을 추출하고 변경·모순·만료를 다루며 프로필을 만든다고 소개한다.
프로필의 `static`은 비교적 오래 유지되는 정보, `dynamic`은 최근 문맥을 표현한다.
‘자동 기억’이라는 설명을 모든 문장이 정확히 해석되고 어떤 오류도 남지 않는다는 보증으로 볼 수는 없다.
기억의 원문과 최신성, 저장 범위는 실제 결과에서 확인해야 할 대상이다.[1]

문서 검색과 기억 검색을 함께 하는 hybrid 모드도 있다.
여기서 혼합이라는 말은 프로젝트가 설명하는 RAG와 Memory를 함께 조회한다는 의미다.
RAG는 관련 자료를 검색해 생성 모델에 제공하는 방식이다.
문서의 일반 지식과 사용자별 선호를 함께 돌려주면 앱은 같은 자료를 바탕으로도 맥락에 맞는 답변을 구성할 수 있다.
최종 답변을 만드는 모델의 판단까지 자동으로 검증해 주는 것은 아니다.[1]

## 정보는 어느 공간에 들어가는가

API 예제의 `containerTag`는 사용자나 프로젝트별 정보를 구분하는 표지다.
아무 태그 없이 대화를 섞기보다 저장과 조회에 같은 범위를 지정하는 것이 중요하다.
하지만 태그 이름만 붙였다고 접근 권한 검사가 완성되는 것은 아니다.
인증된 계정, 앱의 사용자와 조회할 공간 사이의 관계를 함께 설정해야 한다.[1][2]

실제로 확인한 MCP 서버 안내는 매 HTTP 요청에서 OAuth 토큰을 검증하고 활성 공간을 인증된 조직 ID와 사용자 ID의 조합으로 관리한다고 설명한다.
MCP는 AI 클라이언트가 외부 도구와 자료를 사용하는 연결 규약이다.
MCP 프로토콜 세션은 유지하지 않지만 활성 공간 같은 앱 상태는 별도 저장소에 유지한다는 점이 특징이다.
‘세션 없음’이 모든 상태가 없다는 뜻은 아니다.[2]

## 예시로 따라가는 흐름

루트 README의 공식 API 예제는 “사용자가 TypeScript와 함수형 패턴을 선호한다”는 내용을 `user_123` 태그로 저장한 뒤 프로그래밍 방식에 대한 질문과 같은 태그로 프로필을 요청한다.
입력은 대화 내용과 저장 범위, 조회 질문이다.
서비스가 이를 사실과 프로필로 정리하면 앱은 장기 정보·최근 문맥 및 관련 검색 결과를 받아 다음 모델 요청에 넣을 수 있다.
코드 주석의 반환 예시는 문서의 설명이며 이 조사에서 저장 요청을 보내 얻은 결과가 아니다.[1]

같은 정보를 MCP로 조회할 때에는 활성 공간의 선택 규칙도 살펴야 한다.
공식 MCP 문서의 우선순위는 호출에 명시한 `containerTag`, 계정에 저장된 활성 공간, 기본 공간이다.
한 번의 명시적 태그 지정은 그 호출에만 적용되고 계정의 활성 공간을 바꾸지 않는다.
따라서 사람이 확인할 부분은 기억이 존재하는가뿐 아니라 어느 공간을 보고 있는가다.
다른 공간에서 찾았다고 정보를 잊었다고 결론 내릴 수 없고, 한번 임시로 조회한 공간이 다음 호출에도 계속 적용된다고 가정해서도 안 된다. `list_memories`가 원본 문서 ID를 함께 제공한다는 설명은 추출된 사실을 출처와 대조할 읽기 경로를 보여준다.[2]

## 도구 이름과 실행 표면을 구분한다

루트 README는 기억·회상·문맥 주입을 `memory`, `recall`, `context` 중심으로 설명한다.
반면 확인한 MCP 앱 문서는 모델에 보이는 `search_memory`, `get_profile`, `add_memory`와 문서 조회 도구를 구체적으로 나열한다.
두 안내를 같은 호출 이름 목록으로 섞기보다 사용자 수준의 기능 소개와 현재 앱의 도구 표면을 구분해 읽어야 한다.[1][2]

또한 공간 선택기나 업로드 폼처럼 화면을 여는 도구와 앱 내부에서만 사용하는 도구가 분리되어 있다. `set-active-tag`처럼 활성 공간을 저장하는 기능은 앱 전용 도구로 설명되어 있다.
이 구분은 모델이 보는 기능 목록과 사람이 화면에서 할 수 있는 행동이 반드시 같지 않다는 사례다.
연결만 성공했다고 모든 도구와 인터랙티브 화면의 호환성까지 검증된 것은 아니다.[2]

## 로컬 실행과 외부 전송의 경계

README는 로컬 서버의 저장 디렉터리와 같은 API를 쓰는 구성을 소개한다.
하지만 모델 제공자를 외부 서비스로 선택하면 로컬 서버를 실행해도 모델 요청은 외부로 나갈 수 있다.
Ollama를 통한 오프라인 구성을 별도로 안내하므로 ‘로컬’이라는 한 단어로 저장과 처리의 모든 경계를 판단하지 않아야 한다.
MCP 앱의 기본 API URL도 원격 서비스로 기재되어 있다.[1][2]

자동 기억은 원래 대화보다 오래 남는 정보를 만들 수 있다.
어떤 사실을 저장할지, 잘못된 사실을 어떻게 지울지, 동기화하는 문서의 권한을 어디까지 허용할지 정해야 한다.
벤치마크 순위와 지연 수치는 README의 주장으로 이 글에서는 재현하지 않았다.
공개 저장소의 MIT 라이선스는 고지 보존 등의 조건을 정하지만 외부 서비스의 요금·처리 정책과 로컬 배포물 전체의 이용 조건을 그 파일 하나로 판단할 수는 없다.[1][3]

## 정리

Supermemory는 기억과 문서를 다음 대화의 문맥으로 돌려주는 계층이다.
