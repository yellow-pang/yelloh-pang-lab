## 한 줄 요약

Marin은 기반 모델을 만드는 연구 프로그램이자 소프트웨어 플랫폼이다.
완성된 모델로 대화하는 앱만 제공하는 것이 아니라 데이터 준비부터 학습과 평가까지의 과정을 다룬다.
기반 모델은 여러 과제에 활용할 수 있도록 폭넓게 학습한 모델을 말한다.
README는 데이터 선정·변환·필터링·토큰화·사전학습·후속학습·평가를 범위로 소개하며 실패한 실험도 개발 기록에 포함한다는 원칙을 밝힌다.[1]

## 모델 파일 밖에 남아야 하는 정보

학습된 가중치를 공개해도 어떤 데이터를 어떤 비율로 섞고 어떤 설정으로 계산했는지 알 수 없다면 같은 과정을 이해하기 어렵다.
Marin의 특징은 최종 파일뿐 아니라 그 파일을 만드는 과정과 결정도 공개한다는 것이다.
README에는 공개 모델, 데이터 혼합 파이프라인, 학습 설정과 실험 보고서로 가는 경로가 함께 있다.
이는 저장소를 실행 라이브러리와 연구 기록의 두 관점에서 읽어야 하는 이유다.[1]

특정 모델의 성능을 소개한 문장은 저자들이 정한 평가 묶음에서의 결과다.
모델 하나가 모든 과제에서 우월하다는 근거나 이 원고에서 재현한 결과로 쓰지 않는다.
현재 진행하는 대규모 연구와 작은 튜토리얼이 한 저장소에 함께 있다는 사실도 각각의 계산 요구가 같다는 뜻은 아니다.

## 단계의 의존 관계를 코드로 표현한다

Marin 실험은 서로 의존하는 여러 단계로 정의된다.
문장은 먼저 토큰으로 바뀌어야 학습 입력이 된다.
토큰화는 글을 모델이 다루는 조각과 번호로 변환하는 작업이다.
README는 토큰화 단계와 학습 단계를 만든 뒤 선행 작업이 먼저 실행되도록 연결하는 예제를 보여준다.
여기서 실행 순서는 코드의 줄 번호만이 아니라 어떤 결과를 다른 단계가 필요로 하는가에 의해 결정된다.[1]

`tokenized`가 돌려주는 lazy handle은 지금 바로 데이터를 모두 내려받아 계산했다는 뜻이 아니라 나중에 만들 결과를 가리킨다.
실제 실행기가 의존 관계를 풀고 준비 작업을 실행한다.
이 구분 덕분에 실험 계획을 표현하는 부분과 자원을 사용하는 시점을 나눠 읽을 수 있다.
학습 모델, optimizer와 데이터 비율도 인자로 드러난다.
optimizer는 예측 오차에 따라 모델의 매개변수를 어떻게 조정할지 정하는 규칙이다.[1][2]

대표 튜토리얼에서는 CPU·GPU·TPU별 자원과 배치 크기를 하나의 `DEVICES` 표로 지정한다.
배치는 한 번에 처리하는 학습 묶음이다.
장치 선택은 같은 파일에서 바뀌지만 장치를 바꾸면 메모리·실행 환경·비용까지 자동으로 같아지는 것은 아니다.
여러 자원 경로를 한 실험 표현으로 다룬다는 의미에 가깝다.[2]

## 예시로 따라가는 흐름

공식 `train_tiny_model.py`의 기본 선택은 CPU와 TinyStories다.
입력은 선택한 데이터셋 이름, 장치와 실행 버전이다. `dataset` 함수는 원시 텍스트 자료인 TinyStories나 WikiText에서는 작은 표본을 토큰화하도록 정의하고, FineWeb-Edu 선택에서는 이미 토큰화된 캐시를 사용한다.
다음 `build` 함수가 데이터에 맞는 작은 모델, 학습률·배치·학습 횟수와 출력 체크포인트 경로를 묶어 `train_lm`에 전달한다.
체크포인트는 학습한 매개변수와 다시 이어갈 정보를 저장하는 결과다.[2]

튜토리얼의 기본 동작은 계획을 표시하는 것이며 `--run`을 붙일 때 실제 빌드를 진행하도록 설명되어 있다.
따라서 계획에 체크포인트 경로가 보였다고 파일 생성이 끝난 것은 아니다.
실행을 검토하는 사람은 원시 텍스트를 새로 토큰화하는 경로인지 캐시를 쓰는지, 선택한 장치가 실제로 제공되는지, 결과 버전이 보존용인지 반복 개발용인지 확인해야 한다.
이 글은 해당 공식 예제를 읽은 설명이며 학습을 실행하지 않았다.
코드가 `evals=None`으로 평가를 끄므로 작은 모델 학습이 끝났다는 사실만으로 언어 능력의 성능 수치까지 얻는 예제도 아니다.[2]

## 캐시 버전과 실험 버전이 다른 이유

예제는 공유 데이터 캐시에 명시적 날짜 버전을 붙이고 학습 체크포인트 버전은 전체 실행 옵션에서 결정하도록 한다.
변하는 개발 버전을 모든 공유 데이터에 사용하면 재사용하려던 중간 결과까지 다시 만들 수 있다.
반대로 이미 고정한 결과 이름을 아무 생각 없이 재사용하면 서로 다른 실험을 같은 결과로 착각할 수 있다.
버전은 장식용 꼬리표가 아니라 재사용과 재현을 구분하는 정보다.[2]

코드 주석은 `dev` 버전이 반복 개발에서 매번 다시 빌드되는 용도이고 날짜 버전은 보존할 실행을 고정하는 용도라고 설명한다.
원고를 읽는 단계에서도 실행 명령만 복사하기보다 데이터 버전, 학습 설정과 출력 이름을 함께 적어 보는 편이 구조 이해에 도움이 된다.
다만 이 설명은 예제에서 확인한 규칙이며 저장소의 모든 캐시 구현을 검증했다는 의미는 아니다.[2]

README의 확장 예제는 더 큰 자료와 데이터 혼합, GPU·TPU 규모 확장을 안내한다.
작은 CPU 튜토리얼에서 구조를 읽을 수 있지만 대형 모델의 자원 접근권과 비용은 별개다.
외부 데이터셋의 이용 조건과 내려받는 내용도 코드 라이선스만으로 해결되지 않는다.
데이터 출처와 학습 설정을 공개한다고 해서 그 데이터의 모든 재사용 권리가 동일해지는 것은 아니다.

## 정리

Marin은 모델을 만드는 과정의 데이터·설정·계산 단계를 연결하고 기록하는 플랫폼이다.
