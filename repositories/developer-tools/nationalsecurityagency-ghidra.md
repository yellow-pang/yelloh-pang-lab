## 실행 파일에서 프로그램 구조를 읽는 분석 환경

Ghidra는 컴파일된 프로그램을 분석하는 소프트웨어 역공학 프레임워크다.
역공학은 완성된 프로그램의 동작과 구조를 거꾸로 살펴보는 작업이며, 여기서는 원래 소스코드 대신 실행 파일에 남은 명령·함수·참조 관계를 읽는 데 초점이 있다.
Windows, macOS, Linux에서 사용할 수 있는 분석 도구들을 묶고 여러 프로세서 명령 집합과 실행 파일 형식을 지원한다.[1]

공개 학습용 프로그램의 소스와 실행 파일을 비교한다고 생각해 보자.
소스에는 변수와 조건문이 보이지만 실행 파일에는 기계가 처리하는 명령이 들어 있다.
Ghidra는 이 간격을 살펴볼 수 있도록 명령을 읽기 쉬운 형태로 표현하고, 함수와 호출 관계를 탐색하며, 사람이 이름과 해석을 붙이는 분석 환경을 제공한다.
파일을 열었다는 사실만으로 원래 작성자의 의도까지 자동으로 복원되는 도구는 아니다.[1]

README는 악성 코드 분석과 복잡한 역공학 연구를 위한 확장 가능한 플랫폼이라는 목적을 설명한다.
다만 이 글은 직접 작성했거나 분석 권한이 확인된 프로그램, 공개 학습 자료를 방어적으로 읽는 범위만 다룬다.
접근 통제 우회, 제삼자 제품의 보호 장치 무력화, 공격 코드 제작 절차는 포함하지 않는다.

## 기계 명령·고수준 표현·관계를 함께 보기

디스어셈블은 기계어를 프로세서의 어셈블리 명령으로 읽는 과정이고, 디컴파일은 이를 사람이 이해하기 쉬운 고수준 코드 형태로 재구성하는 과정이다.
Ghidra의 README는 두 기능과 어셈블, 그래프, 스크립팅을 함께 제공한다고 설명한다.
같은 프로그램을 낮은 수준의 명령과 큰 구조의 표현으로 오가며 검토할 수 있다는 뜻이다.[1]

디컴파일된 표현은 원본 소스 파일과 구분해야 한다.
컴파일 과정에서 이름이나 표현 방식이 달라질 수 있으므로 보기 쉬운 결과가 곧 원래 소스의 완전한 복제라는 기대는 적절하지 않다.
따라서 특정 조건의 의미를 조사할 때는 재구성된 코드 한 조각만 읽기보다 함수 경계, 호출 관계, 실제 명령과 서로 맞는지 확인하는 방향으로 접근한다.

스크립트는 사람이 화면에서 반복하는 분석 작업을 코드로 묶는 방법이다.
Ghidra는 Java와 Python을 이용한 사용자 스크립트·확장 구성 요소를 지원한다.
별도 프로그램이 실행 파일을 처음부터 다시 해석하게 하는 대신, Ghidra가 가진 프로그램·함수 모델에 접근하여 필요한 질문을 던질 수 있다는 것이 중요한 차이다.[1][2]

실행 형태도 화면 모드 하나로 고정되지 않는다.
Getting Started는 GUI 모드 외에 명령행 기반의 headless 배치 모드, 협업을 위한 Ghidra Server, Python 환경에서 연결하는 PyGhidra를 구분한다.
headless는 그래픽 창 없이 분석을 진행하는 형태이며, 서버는 여러 사용자가 분석 프로젝트의 변경을 공유하는 구성이다.
이들은 각각 다른 운영 목적을 가지므로 처음부터 모두 필요한 것은 아니다.[3]

## 작은 공식 스크립트로 보는 함수 관계

`PrintFunctionCallTreesScript.java`는 현재 위치의 함수를 누가 호출하는지와 그 함수가 무엇을 호출하는지를 출력하는 공식 예제다.
함수란 프로그램 안에서 특정 작업을 수행하도록 묶은 코드 단위이며, 호출은 한 함수가 다른 함수의 처리를 요청하는 관계다.
이 예제는 분석 결과에 저장된 관계를 꺼내 읽는 작은 출발점이다.[2]

먼저 현재 주소를 포함하는 함수를 `FunctionManager`에서 찾는다.
함수가 없으면 커서가 함수 안에 없다는 메시지를 출력하고 종료한다.
함수가 있으면 `getCallingFunctions`와 `getCalledFunctions`로 들어오는 호출과 나가는 호출을 각각 얻고, 시작 주소를 기준으로 정렬해 이름과 주소를 콘솔에 표시한다.
파일 이름에 Tree가 들어 있어도 코드가 재귀적으로 모든 깊이를 탐색하는 것은 아니며, 선택한 함수의 직접 관계를 출력하는 구성이다.[2]

이 예제는 확장 기능을 이해하는 데 도움이 된다.
스크립트가 프로그램의 실행을 흉내 내거나 새로운 취약점을 판정하는 것이 아니라, 이미 존재하는 분석 모델에 질문하고 결과를 사람이 읽기 좋은 순서로 정리하기 때문이다.
따라서 출력의 완전성은 함수 인식과 참조 관계가 얼마나 잘 분석되어 있는지에도 영향을 받는다.[2]

## 예시로 따라가는 흐름

공식 호출 관계 스크립트의 처리 과정을 문서와 코드로 따라가 보자.
입력은 이메일 주소나 원격 서버가 아니라 Ghidra에서 열어 둔 프로그램과 현재 커서 주소다.
권한이 확인된 학습용 실행 파일의 한 함수 위치를 선택한 상황을 가정하되, 이는 이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
현재 주소가 함수에 속하는지를 먼저 확인하는 것이 이 스크립트의 출발점이다.[2]

함수를 찾으면 들어오는 호출 목록을 읽는다.
여기에는 현재 함수를 부르는 다른 함수들이 들어간다.
다음으로 나가는 호출 목록을 읽어 현재 함수가 다른 어떤 함수를 사용하는지 살펴본다.
각 목록은 주소순으로 정리되어 함수 이름과 시작 위치를 출력하도록 되어 있으므로, 사람은 결과에 나타난 주소를 분석 화면의 위치와 연결해 흐름을 더 따라갈 수 있다.
이번 글에서는 실제 함수 이름이나 출력 목록을 만들어 제시하지 않는다.[2]

출력이 없거나 예상보다 적을 때는 곧바로 호출이 없다고 단정할 일이 아니다.
커서가 올바른 함수에 있는지, 해당 함수와 참조가 분석 모델에 잡혀 있는지, 간접적인 관계를 이 예제만으로 충분히 다루고 있는지 질문해야 한다.
특히 이 코드는 직접 관계를 가져오므로 프로그램 전체의 실행 순서나 모든 경로를 증명하지 않는다.
사례의 끝은 자동 판정이 아니라 다음에 읽을 함수와 확인할 주소를 얻는 지점이다.[2]

## 도구 자체의 보안과 설치 범위

README에는 일부 버전에 알려진 보안 취약점이 있으므로 사용 전 보안 공지를 확인하라는 경고가 있다.
분석 도구 역시 복잡한 입력 파일을 처리하는 프로그램이므로 안전을 당연시할 수 없다.
출처가 불명확한 파일을 조사할 때는 분석 권한뿐 아니라 격리 환경과 자료 취급 방침도 별도로 마련해야 한다.[1]

조회한 README의 배포판 안내는 64비트 JDK 25를 요구하며, 공식 릴리스 압축 파일과 GitHub의 Source Code 다운로드를 구분한다.
전자는 실행 준비가 된 배포물이고 후자는 소스 구성이라는 차이가 있다.
소스에서 빌드하려면 추가 도구가 필요하며 기존 설치 위에 압축을 풀지 말라는 주의도 있다.
이 조건은 확인 시점의 문서 내용으로, 다른 버전에도 그대로 적용된다고 단정하지 않는다.[1]

Getting Started는 업그레이드 전 기존 프로젝트를 백업하라고 안내한다.
분석 프로젝트에는 사람이 붙인 이름과 주석 등 다시 만들기 어려운 작업이 들어갈 수 있으므로 프로그램 파일과 분석 작업의 보관을 구분해야 한다.
스크립트와 확장도 실행 권한을 가진 코드이므로 공식 예제의 존재만으로 임의의 외부 스크립트까지 신뢰할 이유는 없다.[3]

## 정리

Ghidra는 실행 파일을 여러 표현과 관계로 살펴보고 반복 분석을 확장할 수 있는 역공학 환경이다.
분석 결과는 원본 소스의 보증된 복구본이나 자동 보안 판정이 아니며, 권한·입력 안전·사람의 해석을 전제로 한다.
