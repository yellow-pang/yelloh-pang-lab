## 한 줄 요약

Flowsint는 공개 정보를 바탕으로 조사하는 OSINT에서 개체와 개체의 관계를 그래프로 탐색하는 도구다.
OSINT는 공개 출처의 정보를 수집하고 검토하는 활동을 뜻한다.
Flowsint는 검색 결과를 최종 사실로 판결하는 시스템이 아니라, 도메인·IP·웹사이트 같은 자료를 연결하고 확인할 수 있게 돕는 조사 화면과 처리 모듈을 제공한다.[1]

## 검색 결과를 점과 선으로 연결하기

허가받은 실습용 도메인의 구성을 살펴볼 때 도메인 이름, 연결된 IP, 웹사이트 주소를 각각 다른 메모에 적으면 관계를 놓치기 쉽다.
Flowsint는 이들을 개체로 표현하고 관계를 선으로 연결한다.
그래프는 숫자를 그리는 막대그래프가 아니라 대상과 연결 관계를 표현하는 자료 구조다.
README는 시각적 그래프 인터페이스와 자동 enricher를 핵심으로 설명한다.[1]

Enricher는 기존 항목을 입력받아 관련 정보를 보태는 모듈이다.
도메인을 IP로 해석하거나, 웹사이트에서 도메인을 추출하는 등 서로 다른 변환이 나뉘어 있다.
이 구성에서는 어떤 자료를 갖고 출발했고 어떤 처리를 통해 다음 자료를 얻었는지 구분할 수 있다.
다만 그래프에 선이 하나 생겼다고 해서 두 대상의 소유자나 의도가 같다는 결론까지 얻은 것은 아니다.[1][2]

## 하나의 정보 보강이 그래프가 되는 과정

대표 구현인 `domain/to_ip.py`의 `ResolveEnricher`는 입력을 `Domain`, 출력을 `Ip`로 선언한다.
타입은 값의 모양과 종류에 붙인 이름이다.
도메인 문자열과 IP 문자열을 모두 그냥 글자로 취급하지 않고, 다음 모듈이 어떤 자료를 받을 수 있는지 명시하는 역할을 한다.
모듈 이름은 `domain_to_ip`이며 도메인 범주로 등록되어 있다.[2]

`scan`은 입력 도메인 목록을 순회하며 `socket.gethostbyname`으로 주소를 얻는다.
성공하면 `Ip` 객체를 만들고 결과 목록에 추가하며 원래 도메인과 IP의 짝도 별도로 보관한다.
오류는 해당 조사 화면 식별자와 함께 기록한 뒤 다음 입력으로 넘어가도록 작성되어 있다.
따라서 하나의 실패가 곧 전체 결과가 없다는 뜻은 아니고, 빈 결과를 원래 대상이 존재하지 않는다는 증거로 해석해서도 안 된다.[2]

후처리인 `postprocess`는 보관한 짝을 이용해 도메인 노드와 IP 노드를 만들고 `RESOLVES_TO`라는 관계를 연결한다.
그래프 서비스가 없으면 이 부분은 건너뛴다.
조회 결과를 얻는 단계와 화면에 연결 가능한 관계로 저장하는 단계가 분리되어 있음을 보여준다.
또한 이 구현은 `gethostbyname` 호출에 기반하므로 도메인의 모든 DNS 레코드를 포괄적으로 모은다는 주장으로 확대할 수 없다.[2]

프로젝트 전체도 역할을 나눈다. `flowsint-types`는 데이터 형태, `flowsint-enrichers`는 보강 처리, `flowsint-core`는 작업 조정·비밀값 저장·공통 기반, `flowsint-api`는 외부 요청을 받는 API, `flowsint-app`은 사용자 화면을 맡는다.
특정 정보원을 추가하는 일과 화면 자체를 바꾸는 일이 같은 위치에서 처리되지 않는 모듈 구성이다.[1]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
조사 권한이 있는 실습 도메인을 출발 노드로 등록하고 그 도메인이 가리키는 IP 관계만 확인한다고 하자.
이때 입력은 사람의 신상이나 타인의 비공개 자료가 아니라 허가된 도메인 항목이다.
목적도 다른 대상을 무작정 확장 수집하는 것이 아니라, 이미 정한 범위의 연결을 검토하는 데 둔다.[1][3]

`domain_to_ip`의 소스 흐름에서는 입력 도메인의 이름을 주소 해석 함수에 전달한다.
성공한 경우 IP 객체를 반환할 준비를 하면서 도메인과 IP의 짝을 기록한다.
이어 그래프 서비스가 연결되어 있으면 두 노드 사이에 `RESOLVES_TO` 관계를 만든다.
실제 IP 값은 조회 환경과 시점에 달려 있으므로 여기서는 임의의 결과 주소를 제시하지 않는다.
실패한 항목은 로그를 확인해야 하며 성공한 항목과 섞어 해석하지 않아야 한다.[2]

사람이 검토할 결과는 '이 도메인이 이 조회에서 어떤 IP로 해석되었는가'라는 좁은 관계다.
그것만으로 해당 IP를 독점적으로 소유한다거나 같은 IP의 다른 사이트와 조직적 관계가 있다는 결론을 내리지 않는다.
추가 보강을 하더라도 조사 허가 범위와 출처를 다시 확인해야 한다.
그래프의 편리함은 연결을 보는 데 있고, 연결의 의미와 사실 여부를 확정하는 판단은 별도로 남는다.

## 로컬 저장과 안전한 사용은 같은 말이 아니다

README는 조사 자료가 자신의 기기에 저장된다고 설명하지만, 외부 정보원에 대한 조회가 사라진다는 뜻은 아니다.
이번 대표 코드도 운영체제의 주소 해석 기능을 호출한다.
이용하는 모듈과 정보원에 따라 외부 접속·API 키·제공자 조건이 관여할 수 있으므로, 로컬 저장 안내를 완전한 오프라인 동작이나 익명성 보장으로 읽어서는 안 된다.[1][2]

네트워크에 공개할 때는 인증 비밀값, 저장된 API 키의 암호화 키, 데이터베이스 비밀번호를 바꾸고 Host 헤더 허용 목록을 설정하라고 README가 명시한다.
기본 설치 후 첫 계정을 만들도록 안내하며 기본 계정은 없다고 설명한다.
화면이 접속된다는 사실과 조사 자료가 안전하게 보호된다는 사실은 별도로 확인할 조건이다.[1]

윤리 문서는 무단 침입·감시·자료 수집, 신상 공개·협박·괴롭힘, 개인정보 침해 등을 금지한다.
실제 라이선스는 Apache-2.0이며 Hippocratic License는 윤리적 토대를 설명하는 참조라는 구분도 명시되어 있다.
README는 초기 개발 단계이고 테스트 모음이 불완전하다고 밝힌다.
기능 목록이나 대규모 그래프 성능 소개를 실환경 검증 결과로 대신하지 않는 이유다.[1][3]

## 정리

Flowsint는 정보 보강 결과를 개체와 관계로 표현하는 조사 도구다.
도메인 해석 예제는 입력 타입, 조회, 관계 저장이라는 흐름을 보여준다.
그래프의 연결 자체가 결론은 아니며 허가 범위·개인정보·출처와 접근 보안을 사람이 함께 검토해야 한다.
