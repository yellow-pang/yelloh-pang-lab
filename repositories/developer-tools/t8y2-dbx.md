## 한 줄 요약

DBX는 여러 데이터베이스에 연결해 구조와 데이터를 살펴보고, SQL 작성·실행·편집·이동을 수행하는 관리 도구다.
데스크톱과 Web/Docker 경로에 더해 CLI, 내장 AI 도우미, 별도 MCP 서버를 제공하지만, 읽기 전용 조회기만은 아니다.[1]

## 데이터베이스 자체가 아니라 연결하고 조작하는 도구

데이터베이스는 정보를 저장하고 질의하는 시스템이며, DBX는 그 시스템에 접속하는 클라이언트다.
여러 제품의 연결 정보를 관리하고 테이블·열·인덱스 등을 탐색하며, SQL 편집기와 결과 표를 통해 데이터를 확인한다.
SQL은 데이터베이스에 조회나 변경을 요청하는 언어다.[1]

대표 기능에는 입력 중 구문 강조와 자동 완성, 선택한 SQL 실행, 이력과 저장한 SQL, 결과 필터와 내보내기가 있다.
테이블 관계를 그리는 ER 다이어그램과 구조 비교도 제공한다.
반면 셀 편집, 행 삭제, 구조 변경, CSV·Excel 가져오기, 다른 데이터베이스로 전송하는 기능은 저장된 데이터를 실제로 바꿀 수 있다.
결과가 표처럼 보인다는 이유로 안전한 사본이라고 생각해서는 안 된다.[1][2]

## 화면, 실행 계층, AI 연결의 역할

README의 기술 구성은 Tauri 2, Vue 3와 TypeScript, CodeMirror 6 편집기, Rust 기반 데이터베이스 연결 계층이다.
MCP 서버는 별도 배포되며 DBX 데스크톱을 설치했다고 실행 파일이 자동으로 생기는 구조가 아니다.
MCP는 AI 도우미가 외부 기능을 정해진 도구 호출 형태로 이용하는 연결 규약이다.[1][3]

MCP 패키지의 Node.js 부분은 작은 실행기이고, 실제 프로토콜·연결 로딩·쿼리 실행은 Rust 바이너리가 맡는다고 설명한다.
기본 로컬 경로에서는 DBX에 저장한 연결을 재사용하며, 일부 네이티브 연결은 데스크톱을 계속 열어둘 필요가 없다.
다만 테이블을 앱에서 열거나 결과를 앱에 표시하는 도구에는 실행 중인 데스크톱이 필요하다.[3]

지원 목록과 설치 크기를 읽을 때도 조건을 나누어야 한다.
루트 README는 작은 앱과 많은 연결 종류를 강조하지만, MCP 문서는 Agent/JDBC 연결에 해당 에이전트·드라이버·JRE가 필요할 수 있다고 명시한다.
JDBC는 Java 기반 데이터베이스 연결 방식이다.
모든 제품을 추가 구성 없이 동일한 기능으로 다룬다는 뜻은 아니며, 별도 드라이버와 공급자의 라이선스 조건도 확인해야 한다.[1][3]

## 예시로 따라가는 흐름

공식 AI 문서의 예제는 `@orders`와 `@customers`를 지정하고 “최근 30일 고객별 매출 상위 10명을 구하는 SQL만 생성하고 실행하지 말라”고 요청한다.
입력은 자연어 요청뿐 아니라 현재 대화에 연결된 데이터베이스, 스키마와 명시한 테이블이다.
스키마는 테이블·열·관계가 어떻게 구성되는지 알려주는 설명이다.
Ask 모드라면 결과는 검토할 SQL 제안이며, 실제 고객 매출을 조회했다는 뜻은 아니다.[4]

사람은 생성된 SQL의 기간 계산, 테이블 간 연결 열, 빈 값 처리, 대상 데이터베이스와 결과 제한을 확인해야 한다.
반대로 같은 문서의 “최근 7일 일별 주문 수를 읽기 쿼리로 실행하고 급증을 설명하라”는 예제는 실제 자료를 요청하므로 Agent 흐름에 해당한다.
이 경우 AI가 구조와 데이터를 읽는 도구를 반복 호출하고 그 결과를 답변 근거로 사용한다.
답변 문장만이 아니라 어떤 테이블과 필터로 얻은 결과인지 검토할 필요가 있다.[4]

두 사례의 차이는 “AI가 SQL을 쓸 수 있는가”가 아니라 “이번 요청이 실행까지 허락했는가”다.
문서는 Agent 모드에서도 단지 쿼리를 써 달라는 요청이면 실행하지 말아야 한다고 명시한다.
이 원고는 공식 예제를 해설한 것으로, 연결을 만들거나 SQL을 실행하고 결과 행을 얻은 기록은 아니다.[4]

## 쓰기와 삭제의 경계는 여러 층에서 결정된다

DBX의 안전 문서는 데이터베이스 계정 권한, 연결의 읽기 전용 설정, 운영 환경 보호, 위험 동작 확인, AI 규칙, MCP 정책을 별도 층으로 설명한다.
운영 환경 보호는 실제 서비스 데이터를 다루는 연결 또는 특정 데이터베이스를 표시해 쓰기마다 확인을 요구하는 장치다.
이 장치들이 서버의 권한·백업·감사를 대신하지는 않는다.[2]

중요한 예외는 데스크톱과 Web 작업 화면에서 읽기 전용 연결을 명시적으로 1분 또는 5분 동안 쓰기 허용 상태로 풀 수 있다는 점이다.
저장된 읽기 전용 설정은 유지되지만 허용 시간에는 해당 연결의 쓰기가 가능하다.
MCP와 CLI에는 이 작업 화면의 임시 해제가 적용되지 않는다.
따라서 “읽기 전용을 켰다”는 말만으로 현재 모든 진입점의 쓰기 가능 여부를 설명할 수 없다.[2]

AI 문서는 변경 SQL을 먼저 제안하고 동일 연결·동일 데이터베이스·정확히 같은 SQL에 대한 일회 확인을 요구한다고 설명한다.
보호된 운영 데이터베이스에 대해서는 Agent가 자율 쓰기 권한을 받는 대신 편집기로 SQL을 돌려 사람이 확인·실행하도록 한다.
필터가 빠진 UPDATE/DELETE, 테이블 구조를 바꾸는 DDL, 대량 가져오기와 전송은 특히 대상과 영향 범위를 확인할 작업이다.[4][2]

MCP에는 Read only, Data read/write, Full access 모드와 허용 연결 범위가 있다.
Data read/write도 삽입과 유효한 필터가 있는 변경·삭제 등을 수행하므로 “안전 모드”를 “쓰기 없음”으로 번역하면 안 된다.
Full access는 넓은 변경, DDL, TRUNCATE와 데이터 비우기 같은 고위험 범위까지 넓힌다.[3][2]

대표 Rust 정책 구현은 연결 ID와 그룹을 확인하고, 연결·데이터베이스별 실행 규칙도 계산한다.
특정 데이터베이스 규칙이 있는 상황에서 다른 DB를 참조하는 SQL을 거부하는 분기도 있다.
화면에 보이는 모드 이름 하나보다 실제 대상에 적용되는 정책을 확인해야 하며, 분류 코드가 모든 저장 프로시저나 동적 SQL의 부작용을 알아낼 수 있다고 보장하지 않는다.[5][2]

## AI에 보내는 정보와 로컬 저장 정보는 다르다

AI 문서는 모델 문맥에 스키마, SQL, 오류, 제한된 샘플 행과 결과 미리보기가 포함될 수 있다고 설명한다.
Cloud 제공자를 선택하면 전달한 문맥이 그 제공자로 가며, 호환 API·프록시·게이트웨이에도 별도 로깅 조건이 있을 수 있다.
로컬 CLI를 쓴다는 사실만으로 그 모델이나 플러그인의 네트워크 통신까지 사라지지는 않는다.[4]

연결·AI 인증 정보의 로컬 암호화와 질의 결과의 모델 전송은 별개다.
README는 데스크톱의 운영체제 자격 증명 저장소와 Web/Docker의 데이터 디렉터리 키를 구분하고, DB 파일과 키를 함께 백업해야 한다고 설명한다.
같은 볼륨에 데이터와 키가 있으므로 볼륨 전체가 유출된 경우까지 보호하지는 않는다고 명시한다.[1]

Apache-2.0은 코드의 이용·재배포 조건이며 외부 모델이나 서버 사용료를 포함하는 요금제가 아니다.
AI 반복 횟수와 추론 설정을 늘리면 비용·지연이 늘 수 있고 정확성이 보장되지 않는다는 문서의 경고도 함께 읽어야 한다.
이 원고는 실제 청구 요금이나 모델 정확도를 검증하지 않았다.[4][6]
