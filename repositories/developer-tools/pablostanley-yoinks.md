## 한 줄 요약

yoinks는 영상 주소를 붙여 넣고 해상도나 MP3를 고르면, yt-dlp와 ffmpeg를 이용해 파일을 내려받는 터미널용 도구다.
자체 영상 서비스나 새로운 다운로드 엔진이 아니라 기존 도구 앞에 선택 화면을 붙인 프로그램이다.[1][2]

## 주소와 파일 사이의 선택을 줄인다

웹에서 내려받기 버튼을 찾는 대신 터미널 안에서 주소 입력, 형식 선택, 진행 상황 확인을 이어 간다.
README는 YouTube, X/Twitter, Instagram 등 여러 사이트를 소개하지만 실제 지원은 기반 도구인 yt-dlp와 해당 사이트의 상태에 의존한다.
따라서 README의 지원 사이트 수를 모든 주소의 성공 보장으로 읽어서는 안 된다.[1][2]

화면은 Ink를 사용한다. Ink는 React 방식으로 터미널의 글자 화면을 구성하는 라이브러리다.
방향키나 `j/k`, 숫자 키로 형식을 고르고 Enter로 진행하며, 마우스로도 주요 요소를 누를 수 있다.
기본 저장 위치는 `~/Downloads`이고 완료 뒤 파일 경로를 터미널에 남긴다.
여기서 전체 화면은 웹 브라우저가 아니라 실행한 터미널을 뜻한다.[1]

## 화면 뒤의 세 가지 역할

**yoinks는 입력과 선택을 담당한다.** 주소를 조사한 결과에서 영상 높이별 선택지를 만들고 높은 해상도부터 보여준다.
대표 구현은 서로 다른 영상 높이를 최대 여덟 개까지 선택지로 만들며 오디오 전용 항목도 덧붙인다.
화면에 표시되는 용량은 원본 메타데이터의 실제값 또는 추정값을 활용하므로 최종 파일 크기와 같다고 보장하지 않는다.[2]

**yt-dlp는 정보 조회와 실제 다운로드를 담당한다.** `probe` 함수는 `-J`로 영상 정보를 JSON 형태로 받아 제목과 형식 목록을 읽는다.
JSON은 프로그램끼리 구조화된 정보를 주고받는 텍스트 형식이다.
받은 정보는 임시 파일로 보관하고, 다운로드 때 `--load-info-json`으로 재사용해 같은 주소의 정보를 다시 추출하는 일을 줄인다.[2]

**ffmpeg는 영상·음성의 결합과 변환을 담당한다.** 고해상도 영상은 영상과 소리가 별도 파일일 수 있어 합치는 단계가 필요하다.
MP3 선택도 원본 음원을 그대로 저장하는 것과 달리 추출·변환 과정을 거친다.
시스템에서 ffmpeg를 먼저 찾고 `ffmpeg-static`을 대안으로 사용하지만, 둘 다 사용하지 못하면 단일 파일 형식 외의 작업은 제약을 받을 수 있다.[1][2]

## 예시로 따라가는 흐름

본인이 보관할 권한이 있는 공개 영상 주소를 입력하고, 목록에 나타난 1080p 항목을 고른다고 가정하자.
이 주소와 해상도는 이해용 상황이며 실제로 다운로드한 기록이 아니다.
먼저 프로그램은 시스템의 yt-dlp가 작동하는지 확인하고, 없다면 이전에 내려받은 복사본을 찾는다.
둘 다 없을 때 GitHub Releases에서 운영체제·아키텍처에 맞는 실행 파일을 받아 `~/.yoinks/bin`에 둔다.[2]

이후 주소의 메타데이터를 조회하고 영상 높이별 선택지와 MP3 항목을 구성한다.
사용자가 영상 항목을 고르면 해당 높이의 영상과 음성을 요청하되, 일치하는 조합이 없을 때 다른 형식을 선택하는 대체 조건도 yt-dlp에 전달한다.
영상·음성이 분리되어 있으면 다운로드 뒤 ffmpeg 결합 단계로 넘어가며, 프로그램은 전송 진행과 후처리를 구분해 표시한다.
종료 코드가 성공이고 최종 파일 경로가 확인되어야 다운로드 함수가 성공 결과를 반환한다.[2]

결과는 기본 저장 폴더의 미디어 파일과 완료 경로다.
사람은 경로만 볼 것이 아니라 영상이 열리는지, 소리가 있는지, 선택한 품질과 실제 결과가 맞는지 확인해야 한다.
표시된 `mp4`나 추정 용량만으로 모든 기기의 재생 호환성까지 판단할 수는 없다.
중간 취소 시에는 이번 작업에서 감지한 출력 파일과 `.part`, `.ytdl` 파일을 정리하려는 코드가 있으나, 모든 실패 상황의 잔여 파일 제거를 보장하는 테스트 결과는 이번 조사에 포함하지 않았다.[1][2]

## 편의 기능과 미완료 기능을 구분한다

Node.js 18 이상이 필요하며 README에는 전역 설치와 `npx yoinks` 실행 경로가 안내되어 있다.
여기서 `npx`는 영구 전역 설치를 생략하는 선택지이지, 네트워크 다운로드나 로컬 파일 생성을 하지 않는다는 뜻은 아니다.
첫 실행에 별도 실행 파일을 받을 수 있으므로 완전한 오프라인 도구라고 설명할 수도 없다.[1][2]

확인한 커밋의 로드맵에서는 선택 화면을 건너뛰는 `--best`·`--mp3`, 출력 폴더 지정 `-o`, 재생목록 지원, 번들 yt-dlp의 자체 업데이트가 미완료로 표시되어 있다.
특히 실제 정보 조회와 다운로드 모두 `--no-playlist`를 사용한다.
목록 전체를 일괄 보관하거나 정기적인 무인 다운로드를 구성하는 도구로 확대 해석하지 않는 편이 정확하다.[1][2]

다운로드한 yt-dlp를 다시 사용할 때는 버전 명령으로 실행 가능 여부를 확인한다.
확인한 내려받기 함수에는 별도의 체크섬·서명 검증 단계가 보이지 않는다.
이는 악성 파일을 확인했다는 뜻이 아니라, 자동으로 외부 실행 파일을 받아 사용하는 구조와 그 검증 범위를 구분해야 한다는 뜻이다.[2]

## 라이선스와 콘텐츠 권리는 별개다

yoinks 코드는 MIT 라이선스다.
사용·수정·배포를 허용하지만 복사본이나 중요한 부분에 저작권·허가 고지를 포함해야 하며 보증 없이 제공된다.[3]
이 허가는 내려받을 영상의 저작권이나 플랫폼 이용약관을 바꾸지 않는다.
README도 개인 보관용 도구라고 설명하면서 보관할 권리가 있는 콘텐츠만 내려받으라고 명시한다.[1]

읽은 파일에서는 별도 yoinks 서비스 구독이나 API 키 비용을 안내하지 않는다.
그렇다고 영상 서비스 이용권, 네트워크·저장 공간, 기반 도구의 배포 조건까지 모두 무료라고 결론 내릴 수는 없다.
yt-dlp와 ffmpeg의 별도 라이선스 원문은 이번 조사 범위 밖이므로 이 문서의 MIT 설명은 yoinks 코드에 한정한다.[1][3]
