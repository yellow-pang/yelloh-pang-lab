## 서비스와 판단 단계를 연결하는 자동화 플랫폼

n8n은 화면에 처리 단계를 배치하고 선으로 연결해 워크플로를 만드는 자동화 플랫폼이다.
워크플로는 입력을 받아 여러 동작과 판단을 거쳐 결과를 내는 작업 흐름을 뜻한다.
필요한 부분에 JavaScript·Python 코드나 AI 모델·도구를 결합할 수 있지만, n8n 자체가 하나의 언어 모델이거나 설치만으로 목적을 알아서 정하는 에이전트는 아니다.[1]

예를 들어 개인 자료를 받아 형식을 정리하고 조건에 맞는 항목만 후속 작업으로 보내려면 데이터 읽기, 조건 검사, 외부 서비스 호출을 각각 작성해야 한다.
n8n은 이 단계를 노드라는 처리 단위로 보여주고 연결 관계를 관리한다.
화면 편집과 코드를 함께 쓰는 이유는 단순한 연결을 눈으로 이해하면서도 화면의 설정만으로 표현하기 어려운 처리를 추가하기 위해서다.[1]

README는 자체 호스팅과 클라우드 사용을 모두 안내한다.
자체 호스팅은 사용자가 관리하는 서버에서 플랫폼을 운영하는 방식이며, 클라우드는 제공된 서비스를 이용하는 방식이다.
어느 쪽이든 자동화가 연결하는 외부 서비스와 모델은 별도의 구성 요소다.
실행 장소를 바꾸는 것과 각 서비스의 인증·비용·데이터 처리 조건을 없애는 것은 다르다.[1]

## 화면의 노드를 실제 처리 단위로 읽기

n8n의 노드는 데이터를 받아 처리한 뒤 다음 노드로 넘기는 단위다.
README는 기존 연동 기능과 워크플로 템플릿을 활용하고 자체 노드로 확장할 수 있다고 설명한다.
템플릿은 참고할 작업 구조이지 모든 사용자의 계정이나 데이터 형식까지 완성해 놓은 결과는 아니다.
흐름을 이해하려면 각 연결선이 어떤 항목을 전달하고 어느 단계에서 외부 변경을 일으키는지 구분해야 한다.[1]

대표 구현으로 읽은 `IfV2.node.ts`는 조건에 따라 입력을 나누는 If 노드다.
출력 이름은 `true`와 `false`이며, 입력 항목마다 조건을 평가해 두 목록 중 하나에 넣는다.
조건이 참일 때 실행할 일과 그렇지 않을 때 할 일을 화면의 서로 다른 선으로 표현하는 구조다.
필터로 항목을 없애는 동작과 달리 거짓인 항목도 별도 경로로 보낼 수 있다.[2]

조건에는 여러 비교를 묶는 논리와 문자열 대소문자 처리, 자료형 검사 설정이 있다.
자료형은 숫자·문자열처럼 값의 종류를 말한다.
코드에는 자료형 검사 오류에 대한 설명과 해당 입력 항목 위치를 연결하는 처리가 있어, 화면에서 설정한 조건도 실제 입력의 형식에 영향을 받는다는 점을 확인할 수 있다.
텍스트로 온 값을 무조건 숫자로 취급해도 된다고 가정하면 안 된다.[2]

입력과 결과의 관계를 추적하기 위한 `pairedItem`도 사용된다.
이미 연결 정보가 없을 때 원래 항목의 위치를 기록하는 방식이다.
여러 항목이 갈라지는 자동화에서는 결과가 어떤 입력에서 왔는지를 알아야 오류를 되짚을 수 있는데, 노드가 목록을 나누는 기능 외에 그 연결 정보도 다룬다는 점이 드러난다.[2]

## AI 처리도 전체 흐름의 한 단계다

README는 여러 모델 제공자 또는 공개 모델을 연결하고, 다단계 에이전트에 도구 사용과 사람의 승인을 포함할 수 있다고 설명한다.
여기서 에이전트는 모델이 주어진 작업을 수행하며 도구를 선택·사용하도록 구성된 흐름으로 이해할 수 있다.
그러나 모델 선택 기능이 모든 응답의 정확성이나 외부 변경의 적절성을 자동 보증하지는 않는다.[1]

화면에 사람의 승인 단계를 둘 수 있다는 것과 모든 템플릿에 승인이 이미 들어 있다는 것도 다르다.
자료 분류와 외부 게시처럼 결과의 영향이 다른 작업은 연결 구조를 따로 검토해야 한다.
이 글에서 확인한 If 노드는 조건 분기라는 작은 구성 요소이며, 이를 근거로 AI 에이전트 전체의 권한 통제나 실행 품질을 검증했다고 주장하지 않는다.[1][2]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
개인 독서 목록에서 `status`가 `ready`인 항목을 다음 정리 단계로 보내고, 나머지는 검토 대기 경로로 보내는 흐름을 생각해 보자.
입력은 제목과 상태를 가진 항목들의 목록이며, If 노드는 각 항목의 상태 값과 기준 문자열을 비교하도록 구성한다고 가정한다.
외부 계정이나 실제 문서를 읽지 않고 조건 분기의 의미만 설명하는 사례다.[2]

소스의 `execute`는 입력 목록을 순회하면서 해당 항목의 조건을 평가한다.
조건이 참이면 참 목록, 그렇지 않으면 거짓 목록에 원래 항목을 넣고, 마지막에 두 목록을 정해진 순서로 반환한다.
화면에서는 이 두 출력에 각각 다음 단계를 연결해야 한다.
소스의 안내문도 연결되지 않은 분기로 전달된 항목은 이어지는 처리가 없어진다고 경고한다.
따라서 참 경로만 확인하면 대기 자료가 조용히 누락되는 구성을 놓칠 수 있다.[2]

또 하나 볼 부분은 오류다.
현재 구현은 오류가 발생했을 때 `continueOnFail` 설정이 켜져 있으면 해당 항목을 거짓 목록에 넣는다.
그러므로 거짓 분기에 온 항목이 항상 정상적인 비교 결과라고 단정해서는 안 된다.
사용자는 상태 필드가 누락된 항목, 대소문자가 다른 값, 자료형이 예상과 다른 값을 어떻게 처리할지 정하고, 오류 처리 설정과 두 출력의 연결을 함께 점검해야 한다.[2]

이 사례에서 최종 결과는 성공 알림이나 가상의 실행 횟수가 아니라 입력이 두 갈래로 나뉘는 구조다.
실제로 저장·전송하는 노드를 덧붙인다면 그 단계의 권한과 실패 처리를 다시 확인해야 한다.
작은 분기에서도 입력 규약과 예외 처리가 필요하다는 점이 자동화 플랫폼을 읽는 출발점이 된다.

## 공개 소스와 이용 조건의 차이

n8n은 README에서 fair-code와 소스 공개형 프로젝트라고 설명한다.
기본 라이선스는 Sustainable Use License이며 `.ee.` 파일 또는 `.ee` 디렉터리의 소스는 별도 Enterprise License 적용 대상이다.
소스를 볼 수 있다는 사실만으로 모든 기능을 같은 조건으로 재배포하거나 유상 제공할 수 있다고 해석하면 안 된다.[1][3]

기본 라이선스는 사용·수정 목적을 제한하고, 타인에게 배포하거나 제공하는 경우 비상업적 목적의 무상 제공 조건을 명시한다.
또한 조회한 LICENSE는 기본 브랜치 외 브랜치의 내용과 제삼자 구성 요소를 별도로 취급한다.
실제 제공 형태를 결정할 때는 프로젝트 이름 하나가 아니라 사용할 코드의 범위와 라이선스 문구를 확인해야 한다.[3]

자체 호스팅 예시는 플랫폼을 시작하는 방법이지 백업, 공개 접근 통제, 연결한 서비스의 비밀값 관리가 모두 끝났다는 증거가 아니다.
README의 보안·관찰 기능 소개도 각 배포형태에서 어떤 구성이 필요한지까지 이번 조사에서 시험한 것은 아니다.
외부 모델·서비스를 연결할 경우 요청 데이터와 비용은 그 연결의 조건에 따라 따로 검토해야 한다.[1]

## 정리

n8n은 데이터 처리·서비스 연결·AI 작업을 노드와 연결선으로 구성하는 플랫폼이다.
화면이 흐름을 드러내더라도 입력 형식, 예외 경로, 외부 변경 권한과 소스 이용 조건은 별도로 설계하고 확인해야 한다.
