## 한 줄 요약

n8n은 작업 단계를 화면에서 연결하거나 코드를 추가하여 서비스 자동화와 AI 에이전트 흐름을 만드는 플랫폼이다.[1]

## 이 Repository는 무엇인가?

워크플로는 여러 처리 단계를 이어 놓은 작업 흐름이며, n8n은 시각적 캔버스와 사용자 코드를 결합해 이를 구성한다.[1]

사용자 데이터·모델·도구를 연결하는 다단계 AI 작업을 다루고, 자체 호스팅과 클라우드 서비스를 모두 안내한다.[1]

### 자료 확인 범위

2026-09-27에 공개 README와 아래에 인용한 공식 파일을 확인한 기본 초안이다.
설치·실행 시험이나 성능 검증을 한 문서는 아니다.
개인적인 Star 이유와 평가, 사용 후기는 직접 작성할 수 있도록 비워두었다.

## 주요 기능

- 시각적 구성에 JavaScript·Python과 npm 패키지를 더해 화면 설정만으로 표현하기 어려운 처리를 작성할 수 있다.[1]
- 여러 모델 제공자와 공개 모델을 연결하고, AI 작업에 도구 사용과 사람의 승인 단계를 포함할 수 있다.[1]
- 기존 서비스 연결과 워크플로 템플릿을 제공하며, 사용자가 노드라는 개별 처리 단위를 추가하여 기능을 확장할 수 있다.[1]

## 어떻게 동작하는가?

```text
연결할 데이터·서비스·모델을 정하고 시각적 캔버스에 작업 단계를 구성한다.
↓
단계를 연결하고 필요한 곳에 사용자 코드, 도구 사용, 사람의 승인을 추가한다.
↓
자체 호스팅 또는 클라우드 환경에서 구성한 자동화 흐름을 실행한다.
```

위 흐름은 README에 제시된 기능의 개념적 요약이며, 특정 서비스의 인증이나 노드별 입력 형식을 검증한 실행 절차는 아니다.[1]

### 확인한 파일 구성

- 루트 `package.json`은 여러 패키지를 함께 관리하는 모노레포 설정이며, 빌드·검사·테스트 작업을 Turbo로 묶는다.[2]
- `packages/core/package.json`은 핵심 기능 패키지 `n8n-core`를 정의하고, TypeScript 빌드와 Vitest 테스트 설정 및 내부 패키지 의존성을 선언한다.[3]
- `LICENSE.md`는 기본 Sustainable Use License와 Enterprise 적용 파일의 구분을 설명한다.[4]

## 어떤 기술을 사용하는가?

- `Node.js`와 `pnpm`: 루트 manifest에 실행 환경과 패키지 관리 도구로 명시되어 있다.[2]
- `TypeScript`와 `Vitest`: 핵심 패키지에서 코드 빌드·타입 검사와 테스트를 담당하도록 설정되어 있다.[3]
- `Docker`: README가 자체 호스팅을 시작하는 배포 방식으로 제시한다.[1]

## 실제로 어디에 사용할 수 있는가?

- 개인용 서비스 연결을 시각적 단계로 표현하며 자동화의 입력·처리·출력 관계를 학습할 수 있다.[1]
- AI 모델에 도구와 승인 단계를 연결하여 사람이 확인하는 다단계 자동화 흐름을 구성할 수 있다.[1]

## 왜 주목할 만한가?

학습 관점에서는 화면에서 정의한 흐름과 사용자 코드를 결합하면서, AI 처리 역시 같은 작업 흐름 안에 배치하는 방식을 살펴볼 수 있다.[1]

## 장점

- 시각적 편집과 코드 확장을 모두 제공하여 간단한 연결과 별도 처리를 한 흐름에서 표현할 수 있다.[1]
- 모델 선택과 자체 호스팅·클라우드 선택을 각각 제공하므로 한 가지 실행 형태만을 전제로 하지 않는다.[1]

## 단점 / 주의점

- 소스 공개형 fair-code 프로젝트로 Sustainable Use License와 Enterprise License를 사용하며, 재배포·제공에는 목적과 유상 여부 등에 관한 제한이 있다.[1][4]
- `.ee.` 파일과 `.ee` 디렉터리의 코드는 기본 라이선스 대상이 아니므로, 소스가 보인다는 이유만으로 모두 같은 조건으로 사용할 수는 없다.[4]
- 조회한 소스의 루트 manifest는 Node.js 24 이상과 pnpm 12.4.2 이상을 요구하며, 이 조건은 소스 개발 환경과 관련된 선언이다.[2]
