## 한 줄 요약

Nitter는 Twitter/X의 공개 내용을 다른 화면으로 읽도록 하는 대체 웹 프런트엔드다.
프런트엔드는 사용자가 보는 화면을 뜻하지만, Nitter는 요청을 중개하는 백엔드도 함께 둔다.
별도의 소셜 네트워크나 원본 게시물을 보관하는 완전한 기록 저장소가 아니라, 원래 서비스의 자료를 받아 다시 보여주는 구성이다.[1]

## 브라우저 대신 서버가 요청하는 구조

README의 핵심 설명은 클라이언트가 Twitter에 직접 요청하지 않고 모든 요청이 Nitter 백엔드를 거친다는 것이다.
기본 열람에는 JavaScript가 필요하지 않고 광고 없는 화면, 반응형 디자인, 테마와 RSS를 제공한다고 안내한다.
이는 이용자 브라우저와 원본 서비스 사이의 연결 경로를 바꾸는 설계다.
원본 서비스에 대한 직접 노출을 줄인다는 목표와 인터넷 어디에서도 추적되지 않는다는 보장은 구분해야 한다.[1]

사용자는 특정 Nitter 인스턴스에 접속한다.
인스턴스는 누군가 실제로 실행해 공개한 서버 한 개를 뜻한다.
따라서 원본 서비스 대신 어떤 운영자의 서버를 신뢰하는지도 중요한 질문이 된다.
README의 가벼움과 속도 수치는 프로젝트가 제시한 비교이며, 이 문서에서 같은 조건으로 측정한 결과가 아니다.
구조 설명과 성능 주장을 나누어 읽는다.[1]

## 캐시와 RSS가 맡는 일

Nitter는 Redis 또는 Valkey를 캐시로 사용한다.
캐시는 이미 받아 만든 결과를 잠시 보관해 비슷한 요청에 재사용하는 장치다.
설치 설명에서도 캐시 서비스를 별도로 준비하도록 하며, 설정 예제에는 목록 정보와 RSS 조회의 보관 기간이 구분되어 있다.
화면의 내용이 매 요청마다 원본에서 새로 받아온 것이라고 가정할 수 없는 이유다.[1][2]

RSS는 새 글 목록을 피드 리더가 읽을 수 있는 형식이다. `src/routes/rss.nim`에는 검색, 사용자, 탭, 목록 피드용 경로가 나뉘어 있다.
사용자 피드는 요청한 이름과 커서로 캐시 키를 만들고, 사용할 수 있는 캐시가 있으면 그것을 응답한다.
없으면 타임라인 피드를 만들고 저장한 뒤 응답한다.
커서는 다음 묶음의 위치를 나타내는 값으로, 어떤 구간의 결과를 요청했는지 구분하는 데 쓰인다.[3]

설정 파일에는 RSS 전체 스위치와 사용자 글·답글·미디어·글 문서·검색·목록별 스위치가 있다.
라우터도 관련 기능이 꺼져 있으면 403과 'RSS feed is disabled' 메시지를 반환한다.
README가 RSS는 인스턴스별이며 남용 때문에 꺼져 있는 경우가 많다고 설명하는 것과 맞물린다.
기능 소스가 존재한다고 모든 공개 서버에서 그 기능을 쓸 수 있는 것은 아니다.[1][3][2]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
관심 있는 공개 계정의 새 글을 피드 리더에서 읽고 싶은 상황을 생각해 보자.
입력은 운영자를 확인한 Nitter 인스턴스와 계정 이름이다.
피드 요청이 들어오면 사용자 글 RSS 설정을 검사하고, 꺼져 있으면 피드를 만들지 않고 거절한다.
이 경우는 계정이 없다는 뜻이나 브라우저가 고장났다는 뜻과 다르다.[3]

허용된 경우에는 계정 이름과 조회 위치로 캐시를 찾는다.
캐시의 커서가 있으면 준비된 RSS를 응답하고, 그렇지 않으면 타임라인 조회 결과로 피드를 생성해 캐시에 저장한다.
응답에는 `application/rss+xml` 형식과 `Min-Id` 헤더가 사용된다.
실제 피드 항목이나 게시물 내용을 이번 조사에서 받아 확인한 것은 아니므로 예시 결과를 꾸며 넣지 않는다.[3]

응답 처리에는 찾지 못한 대상과 정지된 계정에 대한 오류 분기도 있다.
독자가 확인할 부분은 RSS 활성 여부, 원본 계정 상태, 캐시 때문에 새 글 반영이 늦을 수 있다는 조건이다.
피드가 비어 있거나 접근이 실패했을 때 같은 주소를 반복 요청하기보다 실패 의미를 구분하는 편이 정확하다.
피드 이용 가능성과 공개 게시물의 재배포 권리 역시 별도의 문제다.[1][3][2]

## 원본 서비스와 운영 조건에 의존하는 한계

README는 비공식 API를 사용한다고 명시한다.
개발자 계정이 필요 없다는 소개를 아무 인증 조건이나 제약도 없다는 뜻으로 확장해서는 안 된다.
원본 서비스의 변화와 제한, 인스턴스 설정에 따라 제공 범위가 달라질 수 있다.
계정 시스템과 타임라인 기능은 Roadmap에 적힌 항목도 있으므로 계획을 이미 구현된 사용자 계정 기능으로 소개하지 않는다.[1]

수집한 README 상단에는 2026-08-24 서비스와 저장소의 중단을 요구하는 법적 통지를 받았다는 내용과, 법률 자문 뒤 프로젝트를 계속한다는 갱신 안내가 함께 있다.
이는 제공자가 밝힌 프로젝트 상황이다.
계속한다는 문장만으로 모든 인스턴스의 운영이나 법적 문제가 해결되었다고 해석할 수 없다.
기존 초안의 과거 상태 표기만으로 현재 동작 여부를 단정하지도 않는다.[1]

설정 예제는 외부 접속 주소·포트·HTTPS·캐시 접속값·미디어 URL 서명용 HMAC 키를 담는다.
HMAC은 값이 바뀌지 않았는지 확인할 때 쓰는 서명 방식이며, 예제 키는 반드시 독자적인 난수 값으로 바꾸라는 주석이 있다.
README는 보안과 성능 때문에 역방향 프록시 뒤에서 실행할 것을 안내하고 현재 오류 로그 기능의 한계도 설명한다.
소스 공개만으로 안전한 공개 서버가 완성되는 것은 아니다.[1][2]

## 정리

Nitter는 원본 서비스의 내용을 서버가 중개해 다시 표현하는 읽기용 인터페이스다.
RSS와 캐시는 그 읽기 경로를 확장하지만 인스턴스 설정과 원본 접근에 의존한다.
개인정보 목표, 운영자의 신뢰성, 법적·기술적 지속 가능성은 따로 판단해야 한다.
