## 한 줄 요약

public-apis는 여러 분야의 공개 API를 찾기 위한 공동 편집 목록이다.
API는 프로그램이 다른 서비스에 자료나 기능을 요청할 때 쓰는 접점이다.
이 저장소가 모든 API를 대신 운영하거나 동일한 응답으로 묶어 제공하는 것은 아니다.
목록에서 후보를 찾은 뒤 각 제공자의 문서로 이동하는 출발점에 가깝다.[1]

## 데이터를 구하기 전에 후보를 좁히는 도구

작은 웹 페이지에 동물 사진을 넣고 싶어도 검색 결과만으로는 가입이 필요한지, 브라우저에서 바로 요청할 수 있는지 알기 어렵다.
기능 설명이 비슷한 서비스 사이에서 인증 방식이나 연결 조건이 다를 수도 있다.
이 목록은 분야별 표에 짧은 설명과 인증·HTTPS·CORS 정보를 나란히 놓아 이런 첫 비교를 돕는다.
다만 표는 서비스 계약서나 전체 사용 설명서가 아니라 요약 색인이다.[1][2]

README의 Index에서 Animals, Books, Geocoding, Weather 같은 분류로 이동할 수 있다.
Animals만 보아도 동물에 관한 짧은 사실, 사진, 생태 관측 자료처럼 서로 다른 종류가 섞여 있다.
따라서 같은 분류에 있다는 이유로 대체 가능한 API로 보지 말고, Description에서 실제로 돌려주는 정보가 무엇인지 먼저 확인해야 한다.[1]

## 표의 짧은 칸을 제대로 읽는 방법

`Auth`는 인증 요구 여부를 적는 칸이다.
기여 지침에는 `OAuth`, `apiKey`, `X-Mashape-Key`, `No`, `User-Agent`가 허용되는 값으로 명시되어 있다. `No`는 인증이 필요 없다는 표기이지 이용약관이나 요청 한도까지 없다는 선언이 아니다. `apiKey`라면 비공개 키 문자열이나 토큰을 쓰는 방식으로 설명한다.
항목마다 발급 절차와 안전한 보관 방법은 제공자에게 다시 확인해야 한다.[2]

`HTTPS`는 암호화된 HTTP 연결을 지원하는지, `CORS`는 다른 출처의 웹 페이지에서 요청한 응답을 브라우저가 읽도록 허용하는지를 나타낸다.
CORS는 브라우저의 출처 구분과 관련된 조건이므로 인증과 별개의 질문이다.
기여 지침은 적절한 CORS 구성이 없으면 서버 측 이용만 가능하다고 설명한다.
표에는 `Unknown`도 허용되므로, 모른다는 표시를 지원한다는 뜻으로 읽어서는 안 된다.[2]

현재 README에는 기존 API 목록과 별도로 MCP Servers 구역도 있다.
MCP는 AI 클라이언트가 도구를 호출하도록 연결하는 규약이다.
이 구역은 HTTPS·CORS 대신 `Transport`와 설치 가능한 위치를 적는다. `stdio`는 로컬 하위 프로세스의 표준 입출력, `HTTP`는 네트워크 연결 방식을 가리킨다는 설명이 기여 지침에 있다.
외부 API 주소를 프로그램에서 호출하는 방식과 클라이언트에 도구 서버를 연결하는 방식을 같은 표로 섞지 않는 구성이다.[1][2]

## 목록의 품질을 지키는 장치

`CONTRIBUTING.md`는 이름 정렬, 짧은 설명, 실제 문서 링크 등 항목 작성 규칙을 둔다.
특히 완전히 무료이거나 무료 구간이 있어야 하며, 별도 기기나 서비스 구매가 전제되는 API는 받지 않는다고 설명한다.
그러므로 여기서 말하는 무료는 모든 기능을 무제한으로 무료 이용할 수 있다는 통일된 보장이 아니다.
무료 구간의 범위는 각 서비스마다 다르게 남는다.[2]

목록을 검사하는 스크립트도 있다.
스크립트 안내는 README 형식 검사와 링크 검사를 별도로 소개하고, 링크가 많아 검사 시간이 걸리면 중복 링크만 확인하는 옵션을 제공한다.
이런 도구는 문서 유지 관리의 보조 장치다.
링크가 열리는지와 API가 기대한 데이터를 정확하게 반환하는지는 다른 검증이므로, 목록의 검사 통과를 실제 연동 시험으로 대체할 수 없다.[3]

`scripts/validate/links.py`의 `find_links_in_file`은 README에서 `## Index`를 찾은 뒤 그 이후 내용을 링크 추출 대상으로 삼는다.
중복 검사는 URL 끝의 슬래시를 제거한 값을 비교한다.
문서에 링크가 많다는 사실만 확인하는 것이 아니라 검사할 구역과 중복 기준을 코드로 정한 사례이며, 상단 소개의 모든 링크까지 같은 범위로 검사한다고 해석하면 안 된다.[4]

## 예시로 따라가는 흐름

Animals 표의 `Cat Facts` 항목을 읽는 상황을 예로 들 수 있다.
이는 목록에 실제로 있는 항목을 따라 읽는 예시이며 API 호출 결과를 재현한 것이 아니다.
같은 이름의 항목이 둘 있고 설명도 Daily cat facts와 Random cat facts로 다르다.
무작위 사실이 필요한 독자는 Description으로 먼저 후보를 좁힌 다음 해당 행의 Auth·HTTPS·CORS를 함께 읽어야 한다.
이름만 복사하면 서로 다른 제공자를 혼동할 수 있다.[1]

표에서 `catfact.ninja`로 연결된 행은 무작위 고양이 사실을 설명하며 `No`, `Yes`, `Yes`로 표시되어 있다.
여기서 얻는 중간 결과는 '이 목록에는 인증 없이 HTTPS와 CORS를 지원하는 후보로 기록되어 있다'는 판단까지다.
아직 요청 주소, 응답 필드, 언어, 호출 한도를 확인한 것은 아니다.
다음 단계는 표의 문서 링크로 이동해 필요한 조건을 확인하는 것이며, 그 외부 문서는 이번 조사에서 직접 검토한 범위에 포함하지 않았다.[1]

이 읽기 흐름의 결과물은 동작하는 고양이 정보 앱이 아니라 후보와 확인 질문의 묶음이다.
브라우저 페이지에서 쓸지 서버에서 요청할지, 무료 이용 범위 안에서 필요한 요청량을 감당할지, 실패했을 때 어떤 화면을 보여줄지는 개발자가 결정할 부분이다.
목록의 몇 개 열로 후보를 빠르게 줄일 수 있지만 그 간결함 때문에 생략된 조건도 있다는 점을 끝까지 유지해서 읽어야 한다.

## 링크 모음과 서비스 보증 사이의 경계

README 상단에는 특정 API 묶음에 대한 소개가 있고, 그 아래 공동 편집 목록과 MCP 항목이 이어진다.
상단의 통합 계정·대시보드·키 설명을 목록 전체의 공통 계약으로 확장하면 안 된다.
저장소에 나란히 실린 별도 서비스들은 각각의 인증·요금·운영 조건을 갖는다.
이번 글 역시 표의 모든 서비스가 현재 응답하는지 확인했다는 의미가 아니다.[1]

등록 지침과 실제 제공 조건은 시간이 지나며 어긋날 수 있다.
무료 구간이나 인증 방식이 바뀌면 README의 요약도 갱신이 필요하다.
중요한 연동에서는 목록에 적힌 사실을 최종 근거로 삼기보다, 후보 제공자의 현재 문서와 약관을 확인하는 단계가 필요하다.
제공자 응답의 품질이나 데이터의 재배포 권리는 이 저장소의 문서 검사만으로 판정되지 않는다.[2][3]

## 정리

public-apis의 역할은 다양한 외부 API를 찾고 첫 조건을 비교하도록 돕는 것이다.
API 실행 환경이나 모든 서비스의 통합 SDK가 아니다.
짧은 표를 출발점으로 사용하되 실제 사용 결정은 각 제공자의 상세 문서로 이어져야 한다.

## 자료 확인 범위

2026-09-27에 수집된 공식 README의 소개·분류·Animals 표, 기여 지침, 검사 스크립트 안내와 루트 구성을 확인했다.
전체 API를 호출하거나 프로젝트를 설치·실행하지 않았으며, 표의 값은 수집한 문서의 표기 기준이다.
