## 설치하는 프로그램이 아니라, 기술 자료로 들어가는 주간 입구

`ruanyf/weekly`는 중국어 기술 주간지 ‘科技爱好者周刊’의 공개 원고 저장소다.
README는 매주 공유할 만한 기술 내용을 기록하고 금요일에 발행한다고 소개한다.
기사·소프트웨어·학습 자료를 Issue로 제안하는 경로와 연도별·월별 목차가 함께 있다.
어떤 기능을 설치해 실행하는 개발 도구라기보다, 관심 있는 주제를 발견하고 원문으로 이동하기 위한 읽기 자료다.[1]

기술 정보를 찾을 때 어려운 일은 검색 결과를 많이 얻는 것만이 아니다.
처음 보는 도구가 무엇을 하는지, 긴 글을 읽을 만한지, 어디에서 원래 설명을 찾을지 판단하는 데도 시간이 든다.
이 주간지는 자료에 짧은 소개와 링크를 붙여 그 첫 단계를 돕는 형태다.
이를 큐레이션이라고 부를 수 있다.
여러 정보를 선별하고 맥락을 덧붙여 독자에게 건네는 방식이다.[2]

이런 형태의 출발점은 저자가 직접 설명한 적도 있다.
2018년의 15호에서 저자는 Hacker News, GitHub, RSS 구독, 소셜 미디어를 주요 정보원으로 들고, 흥미로운 내용을 기록하던 개인 노트를 공개한 것이라고 말한다.
이는 그 시점에 밝힌 설명이며, 현재 모든 항목이 같은 경로로 수집되거나 자동으로 수집된다는 뜻은 아니다.[3]

## 목차, 한 호의 편집, 원문 링크가 맡는 역할

### 날짜는 자료를 다시 찾는 좌표가 된다

README의 목차는 연도와 월 아래에 호수·제목·본문 파일을 연결한다.
예를 들어 2026년 9월 항목에서 413호를 선택하면 `docs/issue-413.md`로 이동한다.
본문을 한 페이지에 모두 쌓아 놓는 대신 시작점과 개별 원고를 나눈 구성이다.[1]

이 방식에서는 제목이 관심을 끄는 호를 고를 수도 있고, 특정 시기에 어떤 이야기가 실렸는지 거슬러 올라갈 수도 있다.
다만 호수의 제목 하나가 그 안에 있는 모든 자료를 설명하지는 않는다.
413호의 제목은 React Native에 관한 글이지만, 같은 호 안에는 HTML, JavaScript, 지도, Python 도구 등 다른 주제도 들어 있다.
제목만 읽고 자신의 관심 분야와 무관하다고 판단하면 놓치는 자료가 생길 수 있다.[2]

### 한 호 안에도 서로 다른 종류의 글이 있다

413호에는 표지 이미지와 대표 논평 뒤에 기술 동향, 기사, 도구, 자료, 이미지, 발췌문, 인용문 등의 구획이 이어진다.
중국어 제목으로는 `文章`이 기사, `工具`가 도구, `资源`이 자료에 해당한다.
각 구획이 수행하는 일이 다르므로 처음부터 끝까지 같은 방식으로 읽을 필요는 없다.[2]

긴 대표 논평은 저자가 어떤 주장을 하는지 읽는 부분이다.
기사 항목은 다른 사람이 쓴 글의 주제와 원문을 안내한다.
도구 항목은 소프트웨어가 무엇을 하는지 짧게 소개하고 프로젝트로 연결한다.
따라서 논평의 결론, 외부 기사의 요약, 도구의 기능 소개를 모두 동일한 수준의 검증된 사실로 묶어 읽지 않는 것이 중요하다.[2]

### 제보와 출처를 따라갈 수 있는 흔적을 남긴다

README는 기사·소프트웨어·자료를 Issue로 제출하도록 안내한다.
GitHub Issue는 여기서 버그 보고서만을 뜻하지 않고 독자가 자료를 제안하는 공개 게시물 역할도 한다.[1]

413호의 도구·자료 일부에는 제보자 표시와 해당 Issue 링크가 붙는다.
예를 들어 Lyrimuse 항목에는 macOS 가사 도구라는 소개와 제보 표시가 함께 있다.
이런 표시는 해당 자료가 어떤 경로로 소개됐는지 확인할 단서이지, 그 도구의 품질이나 안전성을 보증하는 인증은 아니다.[2]

## 예시로 따라가는 흐름

웹 페이지의 기본 HTML 문서를 어떻게 구성하는지 알고 싶은 독자를 가정해 보자.
이것은 이해를 위한 독서 상황이며, 아래 자료 탐색은 실제 확인한 413호의 항목에 근거한다.
프로그램을 실행해 결과를 만드는 사례가 아니라, **관심 질문 → 소개문 → 원문 → 판단할 질문**으로 이어지는 사례다.[1][2]

첫째, README의 2026년 9월 목차에서 413호를 연다.
본문의 `文章` 구획 첫 항목은 ‘我的 HTML 模板文件’이며 영어 자료라는 표시가 있다.
소개문은 HTML 템플릿의 각 줄이 어떤 역할을 하는지 설명하는 글이라고 안내하고, Vale.Rocks의 `My HTML Boilerplate`로 연결한다.
독자는 여기서 제목, 언어, 주제라는 세 가지 단서로 더 읽을지 결정할 수 있다.[2]

둘째, 연결된 저자의 원문 도입부를 읽는다.
Boilerplate는 여러 문서에서 반복해서 사용하는 기본 골격을 뜻한다.
해당 저자는 자신의 HTML 문서를 만들 때 기본 구조이자 참고 자료로 쓰는 틀을 소개하며, 개인의 선택이 강하게 반영된 것이라고 명시한다.
주간지의 짧은 소개만 보면 보편적인 정답처럼 느껴질 수 있지만, 원문에서는 개인이 유지하는 템플릿이라는 성격을 확인할 수 있다.[4]

셋째, 확인된 코드 앞부분에서 `<!doctype html>`, 문서 언어를 나타내는 `lang`, 문자 인코딩을 적는 `charset`, 제목과 스타일시트 연결 같은 항목을 살펴볼 수 있다.
이 단계의 산출물은 복사해서 바로 배포한 웹사이트가 아니라, 원문에서 더 확인할 항목의 목록이다.
예를 들면 “이 설정이 내 문서에도 필요한가”, “예제의 언어와 설명 문구를 그대로 써도 되는가”라는 질문이다.[4]

이번 조사에서는 연결된 원문의 도입부와 코드 앞부분까지만 확인했다.
추출 결과가 중간에서 끊겼고 추가 조회도 막혀 전체 해설을 검토하지 못했다.
따라서 각 설정의 최신 브라우저 지원이나 전체 템플릿의 적절성까지 검증했다고 할 수 없다.
주간지에서 좋은 자료를 발견하는 일과 그 자료를 끝까지 읽어 적용 조건을 확인하는 일이 별개의 단계라는 점은 이 사례에서도 드러난다.

마지막으로 읽기 기록에는 ‘413호에서 발견’, ‘원문의 저자는 개인 템플릿으로 소개’, ‘세부 설정은 추가 확인’처럼 출처와 판단 범위를 나누어 남길 수 있다.
짧은 추천문을 자신의 결론으로 바꾸기 전에, 원문에서 확인한 부분과 아직 확인하지 못한 부분을 나누는 것이다.

## 읽을 때 남겨 두어야 할 거리

자료의 시점부터 구분해야 한다.
README에 목차가 남아 있다고 해서 오래된 도구의 가격·지원 환경·설치 방법이 지금도 같다는 뜻은 아니다.
예를 들어 15호는 2018년의 기록이고, 413호는 2026년 목차에 연결된 기록이다.
과거 글을 읽을 때는 당시의 소개를 현재 제품 설명으로 바꾸어 받아들이지 않아야 한다.[1][3]

저자의 의견에도 같은 구분이 필요하다.
413호의 React Native 논평은 특정 소식을 계기로 기술의 미래에 대한 강한 해석을 전개한다.
그런 논평이 수록되어 있다는 사실은 확인했지만, 그 전망을 이 원고의 기술적 결론으로 채택한 것은 아니다.
관련 사실을 판단하려면 논평이 가리키는 당사자의 발표와 다른 자료를 별도로 읽어야 한다.[2]

본문이 중국어 중심이라는 점도 읽기 조건이다.
외부 기사에는 영어 표시가 붙기도 하므로, 중국어 소개를 번역했다고 연결된 원문까지 읽은 것은 아니다.
낯선 고유명사나 기술 용어는 소개문과 원문을 대조하는 편이 뜻을 잘못 받아들일 가능성을 줄인다.[2]

발행 주기도 절대적인 약속으로 해석하지 않는 편이 맞다.
README는 금요일 발행을 안내하지만, 확인한 413호 첫머리에는 연휴 휴간 공지가 있다.
또한 저장소의 원고가 공개되어 있다는 이유만으로 연결된 글·이미지·프로그램까지 같은 재사용 조건을 가진다고 가정할 수 없다.
이 조사에서는 외부 항목 전체의 라이선스나 재배포 허용 범위를 확인하지 않았다.[1][2]

## 직접 읽어볼 자료

1. [공식 README와 연도별 목차](https://github.com/ruanyf/weekly/blob/master/README.md)

   발행 안내와 제보 경로를 먼저 확인하고, 관심 연도·월에서 한 호를 고른다.
   최신 제목만 훑는 것과 과거의 기술 관심사를 찾아 읽는 것이 다른 독서 경로임을 볼 수 있다.[1]

2. [413호 실제 원고](https://github.com/ruanyf/weekly/blob/master/docs/issue-413.md)

   대표 논평과 `文章`·`工具` 구획을 비교해 읽는다.
   HTML 템플릿 소개에서 원문 링크를 찾고, 일부 도구 항목에서 제보자와 Issue가 어떻게 표시되는지도 확인한다.[2]

3. [15호: 주간지의 정보원에 관한 저자 설명](https://github.com/ruanyf/weekly/blob/master/docs/issue-15.md)

   첫머리의 정보원 목록과 개인 노트 공개에 관한 설명을 읽는다.
   현재 편집 방식을 추측하기보다 저자가 당시 어떤 출발점을 설명했는지 확인하는 자료다.[3]

4. [413호가 연결한 원저자의 HTML 템플릿 글](https://vale.rocks/posts/html-boilerplate)

   주간지 소개문과 원문의 자기 설명을 비교한다.
   이번에 확인한 범위는 도입부와 코드 앞부분이며, 전체 코드 설명과 적용 조건은 원문에서 추가로 읽어야 한다.[4]

## 정리

`ruanyf/weekly`는 기술 자료를 대신 실행하거나 성능을 평가해 주는 도구가 아니다.
시간별 목차와 짧은 소개를 통해 낯선 주제의 원문으로 들어가게 하는 주간 기록이다.
읽기의 결과는 추천 목록을 그대로 받아들이는 데 있지 않고, 흥미로운 항목을 찾은 뒤 소개자의 해석과 원래 자료를 구분하는 데 있다.[1][2]

## 자료 확인 범위

2026-09-27 기준 README의 소개·목차 구조, 루트 구성, 413호 본문, 15호의 정보원 설명, 연결된 HTML 글의 도입부와 코드 앞부분을 읽었다.
외부 링크 전체를 점검하지 않았으며, 소개된 소프트웨어를 설치하거나 실행하지 않았다.
HTML 원문의 전체 본문 추가 확보는 차단되어 확인 범위에서 제외했다.
