## 한 줄 요약

개발자의 실제 경험과 생각이 담긴 글·발표를 주제별로 찾도록 정리한 한국어 중심 링크 모음이다.
설치하는 개발 도구나 자동 품질 평가기가 아니라 사람이 제안하고 분류하는 읽기 자료다.[1]

## 검색 결과보다 경험을 먼저 찾는 목록

문법을 아는 것과 설계 선택의 이유를 이해하는 것은 다르다.
README는 저자의 고유한 경험·생각·노하우를 선정 기준으로 삼고, 일반적인 문법 설명이나 저작권 위반 자료는 제외한다고 설명한다.
별도 웹사이트 goquality.dev에서 재평가한 목록도 안내하므로 GitHub의 기존 분류, 대기열과 웹사이트를 완전히 같은 목록으로 보면 안 된다.[1]

## 제안에서 분류로 이어지는 구조

기여자는 루트 README의 Queue 아래에 링크를 추가해 Pull Request로 제안한다.
Queue는 검증 뒤 카테고리로 옮기는 대기 공간이며, 이름이 올라왔다는 사실만으로 선정이 끝난 것은 아니다.[1]

대표 파일 `고퀄리티 컨텐츠 모음/1. 개발 일반/README.md`는 개발 문화, 소프트웨어 설계, 제품 개발 후기, 테스트/TDD로 나뉜다.
설계 안에서도 객체지향, DDD, 함수형 프로그래밍을 다시 나누므로 넓은 관심사를 구체적인 질문으로 좁힐 수 있다.
이 구조의 핵심은 추천문을 자동 생성하는 알고리즘이 아니라 Markdown 제목과 원문 링크다.[2]

## 한 항목을 원문까지 따라가면

개발 문화 항목에 연결된 Twelve-Factor App은 서비스형 애플리케이션의 개발·배포 방법론이다.[2][3]
원문은 종속성의 명시적 선언, 환경에 저장하는 설정, 빌드와 실행의 분리 등을 각각 독립된 원칙으로 설명한다.
따라서 목록은 학습 입구이며 실제 주장의 적용 범위와 이유는 연결된 원문에서 읽어야 한다.[3]

## 가상 읽기 시나리오

개인 웹앱을 다른 컴퓨터에서도 실행하려는 초보자를 가정한다.
개발 일반 분류에서 Twelve-Factor App으로 이동해 종속성과 설정 항목을 먼저 읽고, 자신의 실행 환경 차이를 메모하는 흐름을 생각할 수 있다.[2][3]
이때 산출물은 설치된 프로그램이 아니라 문제와 관련된 원문 목록 및 읽기 노트다.
한 원칙을 모든 프로그램에 그대로 적용하기보다는 원문이 서비스형 앱을 대상으로 한다는 조건부터 확인한다.[3]

## 목록을 사용할 때의 주의점

선정 기준은 운영자의 편집 기준이지 모든 링크의 정확성이나 최신성을 보증하는 시험 결과가 아니다.[1]
외부 글의 작성 시점, 사용 버전, 삭제·이동 여부는 읽는 시점에 다시 확인해야 한다.
저장소 LICENSE는 MIT이며 저작권·허가 고지의 보존을 요구한다.[4]
목록의 라이선스만으로 연결된 모든 글과 영상의 복제 권한까지 생기는 것은 아니다.

## 직접 읽어볼 순서

1. 루트 README의 선정 기준과 Queue 규칙을 비교한다. 제안 자료와 분류 자료의 차이를 확인하는 입구다.[1]
2. 개발 일반 파일에서 자신의 질문에 맞는 하위 제목을 고른다. 처음부터 전체를 읽는 강의 순서는 아니다.[2]
3. Twelve-Factor 원문에서 대상 독자와 설정·종속성 항목을 읽는다. 큐레이션과 실제 방법론의 역할을 구분한다.[3]
