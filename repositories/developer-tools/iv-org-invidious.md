## 영상 서비스 앞에 놓이는 다른 웹 화면

Invidious는 YouTube를 위한 공개 대체 프런트엔드다.
프런트엔드는 사용자가 검색하고 영상을 고르는 화면과 상호작용 부분을 뜻한다.
README는 광고·추적 없는 이용, JavaScript 없이 사용하는 화면, 별도 구독과 가져오기·내보내기 기능을 소개한다.
자체 영상 원본을 모두 보유한 독립 영상 플랫폼이나 모든 영상 접근을 보장하는 우회 서비스와는 다르다.[1]

사용자는 공개 인스턴스를 골라 이용하거나 직접 호스팅할 수 있다.
인스턴스는 같은 소프트웨어를 별도의 운영자가 실제로 실행하는 서버다.
따라서 프로젝트 소스가 공개되어 있다는 사실, 특정 인스턴스가 현재 연결된다는 사실, 그 운영자를 신뢰할 수 있다는 사실은 서로 다른 문제다.
README도 제3자가 운영하는 인스턴스에 대한 책임을 분리한다.[1]

이 프로젝트를 이해하려면 영상 재생 기능만이 아니라 요청을 받아 적절한 페이지로 연결하는 흐름을 볼 필요가 있다.
추가로 연 검색 라우트는 빈 검색, 일반 검색어, 붙여 넣은 URL을 서로 다르게 다룬다.
라우트는 웹 요청 주소에 맞춰 처리 함수를 선택하는 부분이다.
같은 검색창이라도 입력의 종류에 따라 처리 경로가 달라진다는 것을 작은 파일에서 확인할 수 있다.[2]

## 검색·구독·접근 경로의 분리

README의 구독은 Google 계정과 독립된 방식으로 소개되며, YouTube·NewPipe·FreeTube 등의 자료 가져오기나 내보내기 기능도 나열한다.
여기서 독립적이라는 말은 각 원본 서비스의 계정이나 서버가 Invidious로 자동 이전된다는 뜻이 아니다.
무엇을 옮기는 기능인지, 예를 들어 구독 목록과 시청 이력 중 어느 자료인지 구분해서 읽어야 한다.[1]

음성 전용 모드, 모바일의 백그라운드 재생, 테마와 홈페이지 사용자화 등은 화면 경험을 조정하는 기능이다.
개발자 API와 임베드 지원은 다른 프로그램이나 웹페이지에서 접근할 수 있는 경로를 제공한다.
이 기능들을 한데 묶어 '동영상을 내려받는 도구'라고만 부르면 계정·검색·표시의 역할이 사라진다.
반대로 다운로드가 가능하다는 어떤 설명도 저작물 사용 권한을 대신하지 않는다.[1]

검색 구현은 GET 요청의 쿼리와 다른 방식으로 제출된 본문 입력을 구별한 뒤, 요청의 지역 값 또는 사용자 설정의 지역 값을 선택한다.
이어 `Invidious::Search::Query`를 만든다.
검색어를 화면에서 읽는 일과 실제 검색을 수행하는 일은 다른 층으로 나뉘며, 이 라우트는 검색 모델에 처리를 위임한다.
따라서 이 파일만으로 상위 서비스에 보내는 모든 네트워크 요청을 확인했다고 말하지 않는다.[2]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
사용자가 공개 학습 영상을 찾기 위해 검색창에 주제를 입력한다고 하자.
검색 라우트는 입력과 지역 설정을 묶은 Query를 만들고, 비어 있지 않으며 URL도 아닌 일반 검색어로 처리한다.
로그인한 사용자 정보가 있으면 그 사용자를 전달하고, 없으면 사용자 없이 `query.process`를 호출하도록 분기한다.
검색 이용에 항상 계정 객체를 전제하는 코드는 아니라는 점을 확인할 수 있다.[2]

검색 처리에서 채널 관련 예외가 나면 채널을 찾을 수 없다는 오류 페이지로, 그 외 예외는 다른 오류 페이지로 연결한다.
결과가 생기면 현재 페이지와 검색 조건을 이용해 페이지 이동 링크를 구성한 뒤 검색 템플릿을 렌더링한다.
템플릿은 결과 자료를 HTML 화면으로 배치하는 틀이다.
결과 개수에 따라 다음 페이지 표시를 결정하는 조건도 있지만, 이는 검색 결과 전체가 몇 개라는 확정 집계가 아니라 화면 탐색을 위한 조건으로 읽어야 한다.[2]

같은 창에 검색어 대신 URL을 붙여 넣은 경우에는 일반 검색 호출 전에 URL 정리기를 거쳐 해당 페이지로 이동시키는 경로를 탄다.
입력이 비어 있으면 검색 홈 화면을 보여 준다.
사람이 확인할 부분은 자신이 지금 검색 결과를 보고 있는지, 붙여 넣은 주소로 이동한 것인지, 오류가 입력 문제인지 상위 자료 조회 문제인지다.
이번에는 어떤 공개 인스턴스에도 요청을 보내 영상 재생이나 검색 결과를 확인하지 않았다.[2]

이 사례는 사용자 화면의 단순함과 내부 처리의 차이를 보여 준다.
하나의 검색창이 여러 진입점 역할을 하지만, 검색 라우트는 사용자 설정·요청 형식·오류를 명시적으로 나누고 있다.
작동하는 화면을 보았다는 사실만으로 모든 경로의 예외 처리까지 검증되는 것은 아니므로, 코드와 실제 서비스 관찰도 서로 다른 근거로 다루어야 한다.

## 프라이버시 소개와 실제 운영 조건

README는 공식 YouTube API를 사용하지 않는다고 명시한다.
이는 API 키를 필요로 하는 공식 연동 제품과 다르다는 설명이지만, 상위 서비스에 대한 의존성이 없다는 뜻은 아니다.
대체 프런트엔드가 원래 서비스의 모든 변화나 접근 제한에도 항상 동작한다고 가정할 근거는 이번 자료에 없다.
기능 소개를 지속적 가용성 보장으로 바꾸지 않았다.[1]

광고·추적 없음이라는 소개도 프로젝트의 설계 목표와 제공 기능에 관한 설명이다.
특정 공개 인스턴스의 실제 로그 정책, 배포한 코드, 네트워크 운영을 이번에 감사한 것은 아니다.
접속하는 서버의 운영 주체와 자료 처리 정책은 사용자가 별도로 판단해야 한다.
직접 호스팅을 선택하면 그만큼 설정·업데이트·저장 자료의 보호 책임을 스스로 맡게 된다.[1]

프로젝트는 관련 법규를 따를 것을 권고하고 불법 다운로드 같은 부적절한 사용에 대한 책임을 거부한다.
이 글의 사례도 공개 학습 자료의 탐색에 한정하며 접근 권한이나 콘텐츠 이용 조건을 무시하는 방법을 설명하지 않는다.
라이선스 표기는 AGPLv3이므로 수정된 서비스를 제공하거나 코드를 재배포하려는 경우 기능 소개와 별개로 라이선스 조건을 확인해야 한다.[1]

## 정리

Invidious는 영상 검색·구독·표시를 다른 웹 인터페이스로 제공한다.
원본 영상 서비스와 독립된 모든 기능을 보장하는 것은 아니며, 공개 인스턴스의 신뢰와 콘텐츠 이용 권한은 별도로 확인해야 한다.[1][2]
