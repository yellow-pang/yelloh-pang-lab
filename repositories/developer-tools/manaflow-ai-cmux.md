## 여러 코딩 세션을 구별하는 터미널 작업 공간

cmux는 libghostty로 터미널을 렌더링하고 세로 탭·분할 화면·브라우저·알림을 묶은 macOS 앱이다.
README는 Ghostty 자체의 fork가 아니라 렌더링 라이브러리를 활용한 별도 앱이라고 설명한다.
AI 코딩 도우미가 일할 화면을 제공하지만 자체 언어 모델이나 모든 개발 과정을 대신 결정하는 단일 에이전트는 아니다.
터미널에서 실행하는 기존 도구를 작업 공간 안에 배치하고 제어하는 역할이다.[1]

여러 세션이 동시에 돌아가면 어느 창이 입력을 기다리는지, 어떤 폴더에서 작업 중인지, 브라우저에 보이는 서버가 어느 세션의 것인지 헷갈릴 수 있다.
cmux의 사이드바는 작업 경로·브랜치·관련 PR·열린 포트·최근 알림을 보여 주는 방식으로 이 맥락을 보조한다.
작업 자체의 정답을 판단하기보다 사람이 돌아가야 할 위치를 찾는 문제를 다룬다.[1]

## 화면 구성과 자동화 인터페이스

작업 공간에는 터미널이나 브라우저 surface가 놓이고, 이를 가로·세로로 나눌 수 있다.
surface는 개별 화면 면을 가리키는 단위로 이해하면 된다.
CLI와 Unix socket API는 작업 공간 생성, 분할, 입력 전달과 브라우저 제어를 제공한다.
사람이 누르는 화면과 자동화 도구가 다루는 대상이 같은 구성 단위로 연결되는 셈이다.[1]

내장 브라우저는 접근성 트리나 DOM 스냅샷을 보고 요소를 클릭하거나 입력하는 API를 제공한다.
README는 agent-browser에서 가져온 API를 소개한다.
이 기능은 코딩 도우미가 자신이 바꾼 웹 화면을 확인할 수 있는 통로지만, 브라우저가 열려 있다는 사실만으로 올바른 검증이 수행되는 것은 아니다.
어떤 요소와 상태를 확인할지는 그 도우미의 작업과 사용자의 검토 범위에 달려 있다.[1]

알림은 표준 터미널 제어 시퀀스인 OSC 9/99/777이나 CLI·도우미 훅을 통해 들어온다.
훅은 특정 작업 순간에 외부 명령을 연결하는 기능이다.
README는 알림 링, 사이드바의 읽지 않은 표시, 알림 패널과 최근 미확인 위치로 이동하는 단축키를 설명한다.
화면에 메시지를 더하는 것뿐 아니라 알림의 출처를 작업 공간과 면에 연결하는 것이 중요하다.[1]

## 알림을 화면에 보내기 전의 정책

추가로 확인한 `AgentNotificationDelivery.swift`는 사용자 설정에서 권한 요청, 턴 종료 방식, 유휴 알림 관련 값을 읽는다. `enqueue`는 작업 공간 ID와 surface ID, 제목·본문·범주·대기 여부 등을 받은 뒤 `allows`로 허용 여부를 검사한다.
허용되지 않으면 false를 반환하고 알림을 넣지 않는다.
모든 이벤트를 무조건 표시하는 단순 전달 함수가 아니라 정책 판단을 앞에 둔다.[2]

허용된 이벤트는 공유 mutation bus로 전달된다.
여기서 bus는 화면 상태 변경을 공통 경로로 보내는 통로다.
도우미 종류와 하위 에이전트 여부, 세션 ID 같은 문맥도 함께 담길 수 있다.
코드 주석은 종류와 하위 여부가 이 게이트 자체의 판정에는 영향을 주지 않고 사용자 정책 훅에 전달되는 정보라고 명시한다.
알림 속성으로 보인다고 전부 표시 허용 조건으로 쓰이는 것은 아니다.[2]

태그 없는 이전 형식의 알림은 호환성을 위해 agent 문맥을 만들지 않는 분기도 있다.
범주가 없는 알림을 허용하는 처리 역시 같은 파일에 보인다.
이 세부사항은 새로운 분류 알림과 기존 일반 알림을 같이 지원하면서, 불필요하게 훅 입력을 바꾸지 않으려는 구조로 읽을 수 있다.
최종 정책 계산 함수의 모든 내부 규칙까지 이 파일에서 확인한 것은 아니다.[2]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
사용자가 두 프로젝트를 나란히 열고 각각의 터미널에서 코딩 도우미를 실행한다고 하자.
한 도우미가 권한 승인을 기다리며 훅을 통해 알림을 보낸다.
알림에는 화면에 보일 문구뿐 아니라 어느 작업 공간과 surface에 속하는지도 담긴다.
사람이 필요한 세션으로 이동하려면 이 출처 연결이 있어야 한다.[1][2]

코드의 전달 흐름에서는 먼저 범주와 pending 상태를 설정값에 비추어 허용할지 판단한다.
통과한 이벤트만 공유 버스에 들어가며, 제목·본문·응답 형태·세션 문맥 등이 함께 전달된다.
README가 설명하는 UI에서는 해당 pane의 링과 탭 표시, 알림 목록을 통해 사용자가 주의를 기울일 위치를 찾는다.
실제로 알림을 띄워 본 것은 아니므로 모든 훅과 운영체제 알림 권한 조합에서 표시를 검증했다고 쓰지 않는다.[1][2]

사용자는 최근 읽지 않은 알림으로 이동해 요청 내용을 확인하고 필요한 판단을 내린다.
이때 알림 자체는 작업 성공의 증거가 아니다.
입력을 기다린다는 상태와 코드가 올바르다는 평가는 다르며, 어떤 명령을 승인할지와 수정 결과를 어떻게 검토할지는 여전히 별도다.
여러 창을 놓치지 않게 돕는 기능과 에이전트의 행동을 신뢰할 수 있게 만드는 검증 절차를 나누어야 한다.

## 복원되는 화면과 살아 있는 프로세스

README의 세션 복원은 창·작업 공간·분할 배치, 경로, 가능한 범위의 터미널 기록과 브라우저 이력을 재구성하는 기능이다.
임의의 실행 중 프로세스 상태를 체크포인트로 저장하지 않는다고 명시한다.
따라서 종료 전 화면이 다시 보이는 것과 그 안의 셸·편집기·명령이 같은 상태로 계속 살아 있다는 것은 다르다.[1]

지원 도우미는 훅이 저장한 자체 세션 ID를 이용해 재개할 수 있지만, 이는 해당 도우미의 resume 명령을 다시 실행하는 방식이다.
사용자 정의 재개 명령도 신뢰·승인 정책에 따라 자동 실행 여부가 달라진다.
문서는 민감한 환경 키를 저장 전 제외하고 승인 접두어를 경로·환경 값에 묶는다고 설명한다.
이 소개를 모든 비밀 정보가 모든 기록에서 완전히 지워진다는 감사 결과로 해석하지 않는다.[1]

브라우저 쿠키·세션 가져오기와 소켓을 통한 입력 제어는 편리한 만큼 권한 범위를 가진다.
로그인된 브라우저나 터미널에 자동화가 접근할 수 있으므로 세션 분리와 명령 신뢰를 검토해야 한다.
macOS 네이티브 데스크톱 앱이라는 범위와 별도 iOS 베타 안내도 나누어 읽는다.
소스 라이선스는 GPL-3.0-or-later이며 특정 부분의 상업 조건 안내가 제3자 자료까지 다시 허가한다는 뜻은 아니다.[1]

## 정리

cmux는 코딩 도구를 감싸는 터미널 작업 공간과 제어 통로다.
세션의 위치와 요청을 놓치지 않게 돕지만, 알림은 성공 증명이 아니고 화면 복원은 임의 프로세스의 생존 보장이 아니다.[1][2]
