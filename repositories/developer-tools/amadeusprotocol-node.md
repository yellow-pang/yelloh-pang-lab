## 네트워크 노드와 계약 예제를 함께 읽는 저장소

`amadeusprotocol/node`는 AMA Protocol의 노드 운용 안내와 스마트 계약 예제를 담은 공개 저장소다.
README는 `amadeusd`로 로컬 테스트넷을 실행하고 계약을 배포·호출하는 흐름을 제시한다.
추가로 확인한 `DOCS.md`는 프로토콜을 Privacy Layer 1과 행렬 곱 기반 Useful Proof of Work라는 용어로 소개하고 계약 형식을 WASM으로 명시한다.
이 소개는 프로젝트가 주장하는 정체이며, 성능이나 프라이버시 보장을 이번 조사에서 검증한 것은 아니다.[1][2]

노드는 네트워크에 참여해 상태와 요청을 처리하는 실행 프로그램이고, 스마트 계약은 정해진 호출에 따라 상태를 읽거나 바꾸는 프로그램이다.
이 둘을 구분하면 저장소를 읽기 쉬워진다. `node`라는 이름이 JavaScript 실행 환경인 Node.js를 뜻한다고 추정해서는 안 된다.
README의 호출 예제는 Elixir 형태의 REPL 코드를 사용하고, 별도 AssemblyScript 파일은 WASM 계약으로 작성할 예제를 보여 준다.[1][3]

블록체인을 처음 보는 독자에게는 네트워크 전체의 경제적 의미보다 작은 상태 하나가 어떻게 변하는지 살펴보는 편이 구체적이다.
이 저장소의 counter 예제는 이름으로 저장한 숫자를 읽고, 입력값을 받아 변경하며, 결과를 반환한다.
웹 화면이나 지갑의 편의 기능이 아니라 계약의 입력·저장·출력을 직접 드러내는 예제다.[3]

## 실행 환경과 계약 인터페이스의 분리

README의 Testnet 절은 로컬 실행 환경을 준비하고, REPL에서 계정 키를 얻어 전송이나 계약 호출을 하는 순서다.
REPL은 명령을 입력하고 즉시 결과를 확인하는 대화형 실행 창을 말한다.
문서는 `trainer_pk`와 `trainer_sk`를 가져오는 예제를 제시하므로 공개 식별자와 서명에 쓰는 비밀 키의 역할을 혼동하지 않아야 한다.
문서에 나온 로컬 시험용 계정 사용 흐름을 실제 자산 운용의 안전 절차로 일반화할 수는 없다.[1]

`DOCS.md`에는 WASM 계약, SDK, 지갑 연결, 노드 실행, 테스트넷·메인넷의 자료 경로가 분리되어 있다.
WASM은 다른 언어에서 만든 프로그램을 일정한 실행 형식으로 전달하는 기술이며, 이 저장소에서는 계약 형식으로 제시된다.
SDK는 계약이나 외부 프로그램이 사용할 기능을 묶은 개발 도구다.
링크가 존재한다는 사실과 각 연결 대상이 현재 정상 동작한다는 사실은 다르므로, 여기서는 확인한 문서의 구획만 설명한다.[2]

추가로 연 `0_counter.ts`는 `sdk`를 통해 저장 공간과 상호작용한다. `init`은 배포 시 호출된다는 로그와 함께 `inited` 키를 저장하고, `get`은 `the_counter`를 읽어 정수로 바꾼 다음 반환한다.
이 구현은 계약의 상태가 함수의 지역 변수로만 남는 것이 아니라 이름 붙은 저장 항목을 통해 이어진다는 점을 보여 준다.
다만 키가 처음에 없을 때의 해석은 이 파일이 호출하는 SDK 쪽에 있으므로 여기서 임의의 초기값을 단정하지 않는다.[3]

계약끼리 호출하는 함수도 있다. `increment_another_counter`는 대상 계약 식별자를 메모리에서 읽고, 그 계약의 `increment`를 호출한 뒤 결과를 반환한다.
한 계약이 다른 계약을 호출할 수 있다는 구조는 확인되지만, 수수료·실패 전파·원자성 같은 세부 보장은 이 짧은 예제만으로 설명할 수 없다.
파일에서 직접 보이는 동작과 프로토콜 전체의 규칙을 나누어 읽어야 한다.[3]

## 예시로 따라가는 흐름

공식 README는 counter 계약 파일을 배포한 뒤 `get`을 호출하고, 이어 `increment`에 문자열 `"2"`를 넘기는 예를 제시한다.
이를 소스와 대조하면 이름만으로는 놓치기 쉬운 세부 동작이 나타난다. `increment`는 입력 포인터에서 문자열을 읽어 `the_counter`에 한 번 더하고, 그 다음 줄에서 같은 키에 `1`을 다시 더한다.
반환하는 값은 두 번째 증가 호출의 결과다.
따라서 이 예제를 단순히 '입력값만큼 한 번 증가하는 함수'라고 요약하면 실제 코드를 잘못 설명하게 된다.[1][3]

입력은 계약 주소와 함수 이름, 인자이며 처리는 SDK의 메모리 읽기와 키-값 저장 변경을 통해 이루어진다.
출력은 `sdk.ret`로 돌려주는 증가 후 값이다.
여기서는 초기 저장 상태와 SDK의 변환·오류 규칙을 모두 확인하지 않았으므로 특정 숫자가 출력되었다고 쓰지 않는다.
직접 배포하거나 호출한 결과도 아니다.
사람이 먼저 확인해야 할 것은 README에서 부른 함수가 실제 예제의 어느 함수인지, 문자열 인자가 어떤 경로로 해석되는지, 한 번의 호출 안에서 상태 변경이 몇 차례 일어나는지다.[3]

이 흐름은 '문서의 함수 이름을 믿고 결과를 예상하는 읽기'와 '함수 본문의 상태 변경을 따라가는 읽기'의 차이를 보여 준다.
특히 다른 counter를 호출하는 예제도 결국 이 `increment` 함수로 이어지므로, 바깥 호출의 인자만 보고 최종 변경량을 설명하지 않아야 한다.
작은 계약이라도 입력, 저장 키, 반환 위치를 함께 확인하는 것이 핵심이다.[3]

## 로컬 시험 안내를 그대로 운영 설정으로 옮기지 않기

README는 시험한 환경으로 Linux Kernel 6.8과 Ubuntu 24.04를 적고 있다.
이는 모든 Linux 배포판이나 다른 운영체제의 호환성을 보장하는 표현이 아니다.
또한 테스트넷 안내에는 브라우저 인증서·웹 보안 검사를 비활성화하는 선택지, 로컬 호스트 매핑, 낮은 포트 사용을 위한 시스템 변경이 포함되어 있다.
이런 부분은 격리된 시험 맥락에서 이해해야 하며 일상 브라우저와 운영 환경에 그대로 적용할 절차로 소개하지 않는다.[1]

서비스 예제에는 root 실행, 자동 업데이트, 네트워크 버퍼와 자원 제한 수정도 보인다.
편의상 제시된 명령이 최소 권한이나 안전한 운영 구성을 입증하지는 않는다.
특히 비밀 키를 다루는 노드의 변경과 업데이트는 문서 읽기와 실제 운영을 분리해서 검토할 사안이다.
이번 작업에서는 시스템 설정을 바꾸거나 네트워크에 접속하는 노드를 실행하지 않았다.[1]

README의 면책 문구는 교육·정보 목적의 실험적 연구 프로젝트이며 보증 없이 제공된다고 설명한다.
지역 법률과 제재 관련 제한도 명시한다.
이를 투자 수익, 자산 보관의 안전성, 실서비스 안정성을 뒷받침하는 자료로 사용해서는 안 된다.
루트 문서와 계약 예제를 읽었다는 범위 안에서만 정체와 구조를 설명할 수 있다.[1]

## 정리

이 저장소는 AMA 노드의 시험·운용 입구와 계약 상태 변경 예제를 제공한다.
작은 counter 코드에서도 문서상의 이름보다 실제 저장 호출을 따라가야 하며, 실험용 실행 안내는 자산 운용이나 시스템 보안의 보장이 아니다.[1][3][2]
