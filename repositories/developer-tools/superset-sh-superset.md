## 한 줄 요약

Superset은 CLI 코딩 에이전트, 터미널, 코드 변경 검토, 브라우저 미리보기를 작업 공간 단위로 모으는 개발 도구다.
에이전트는 요청을 받아 코드 수정과 도구 실행을 수행하는 프로그램을 뜻한다.
Superset 자체를 새 언어 모델로 보는 대신 Claude Code·Codex 같은 기존 도구의 작업을 배치하고 검토하는 환경으로 이해하면 역할이 분명해진다.[1]

## 병렬 작업에서 잃어버리기 쉬운 것

한 개인 프로젝트에서 화면 수정과 테스트 보완을 동시에 진행하면 터미널마다 어느 변경을 다루는지 헷갈릴 수 있다.
두 에이전트가 같은 폴더를 수정하면 상대의 중간 변경까지 읽을 수 있고, 다른 폴더로 나누어도 결과를 검토할 곳은 필요하다.
Superset의 README는 각 작업에 별도 Git worktree와 브랜치, 터미널을 주고 결과를 병합 전에 검토하는 구성을 안내한다.[1]

Worktree는 하나의 Git 저장소에서 별도의 작업 파일 묶음을 사용하는 방식이다.
변경 중인 파일을 분리하는 데 쓰이지만 프로그램 실행 권한을 격리하는 보안 장치는 아니다.
README는 worktree가 프로세스를 샌드박스화하지 않으며 병합 충돌도 막지 않는다고 직접 명시한다.
폴더를 나누는 것과 충돌 없는 최종 결과를 얻는 것을 같은 약속으로 읽어서는 안 된다.[1]

## 실행보다 검토를 중심에 두는 구성

`Changes`와 내장 diff 화면은 에이전트가 바꾼 코드를 전후 비교하도록 돕는다.
Diff는 파일의 어느 줄이 추가·삭제·수정되었는지를 보여주는 표현이다.
README의 시작 안내도 요청을 보내는 데서 끝나지 않고 패치를 살피고 관련 테스트를 실행하며 앱을 미리 본 뒤 커밋하라고 설명한다.
에이전트의 완료 표시와 변경 내용의 승인 사이에 사람의 판단 단계를 둔 것이다.[1]

브라우저 패널은 실행 중인 개발 서버를 미리 보여주고 작업 공간별 포트를 감지한다.
Design 모드에서는 화면 요소를 선택해 그 정보와 수정 요청을 에이전트에 전달할 수 있다.
화면에서 본 문제를 긴 말로 다시 설명하는 대신 요소 문맥을 붙이는 통로다.
다만 포트 감지가 서버를 안전하게 격리하거나 테스트의 정답을 대신 결정하는 기능은 아니다.[1]

PR의 코드 줄을 선택해 의견을 실행 중이거나 새 에이전트 세션으로 보내는 흐름도 있다.
README는 GitHub에 의견을 게시하는 것은 선택사항이라고 구분한다.
즉 코드를 보고 에이전트에 수정 요구를 전달하는 행위와 외부 PR에 댓글을 공개하는 행위가 반드시 같은 작업은 아니다.
검토를 반복하는 과정에서 전달 대상과 공개 범위를 확인할 이유가 여기에 있다.[1]

공식 저장소의 `docs/cookbook/README.md`는 WIP, 즉 작성 중인 병렬 코딩 안내다.
이 문서는 계획을 먼저 다듬고 구현 담당에게 전달한 뒤 검토 담당의 의견을 다시 반영하는 순서를 제시한다.
기능별 PR을 나누고, 포트가 충돌하지 않도록 환경 변수에 기반한 매핑을 두라는 팁도 있다.
문서에 실린 생산성·비용 주장은 작성자의 설명이며 이번 조사에서 측정한 성능으로 받아들이지 않았다.[2]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
개인 웹 앱의 설정 화면 간격을 고치는 작업과 날짜 입력 테스트를 보완하는 작업을 나누어 보자.
첫 입력은 막연한 '앱 개선'이 아니라 각각 수정 범위와 확인 조건을 적은 작은 요청이다.
두 작업 공간을 만들고 각 에이전트가 별도의 worktree에서 일하게 하면 중간 파일 변경을 한 폴더에 섞지 않을 수 있다.[1]

화면 작업은 브라우저 패널에서 대상 요소를 골라 수정 요구와 문맥을 전달하고, 코드 결과는 Changes에서 확인한다.
테스트 작업은 별도 터미널에서 진행 상황을 보되 완료 알림을 테스트 통과 증거로 대신하지 않는다.
README의 흐름에 따라 실제 관련 테스트 결과와 패치를 함께 확인해야 한다.
같은 파일을 각 작업이 서로 다르게 수정했다면 worktree가 나뉘어 있어도 합칠 때 조정이 필요하다.[1]

중간 검토에서 간격은 맞지만 좁은 화면이 깨진다면 그 문제를 다시 전달할 수 있다.
Cookbook이 설명하는 계획→구현→검토→피드백 반복과 연결되는 부분이다.
마지막 결과는 두 에이전트가 동시에 끝났다는 상태가 아니라 사람이 승인할 수 있는 변경 묶음이다.
병합을 별도 작업으로 다루라는 문서의 조언처럼, 독립적으로 진행한 수정이 함께 놓였을 때도 맞는지 확인하는 과정은 남는다.[2]

## 데스크톱과 부가 기능의 조건

조회한 README는 macOS를 주 대상으로 안내하고 Linux AppImage를 실험적이라고 표시하며 Windows는 아직 제공하지 않는다고 밝힌다.
Git이 필요하고 PR 흐름을 위한 `gh`는 선택사항으로 설명한다.
선택한 에이전트의 로그인·구독·권한은 Superset의 작업 공간 기능과 별도로 확인할 조건이다.
기존 구독을 유지할 수 있다는 안내를 무제한 무료 모델 사용으로 바꾸어 읽을 수는 없다.[1]

원격 접속, 정기 실행, CLI·SDK·MCP를 통한 작업 공간 관리도 소개한다.
하지만 모바일은 Superset Pro, iOS 26 이상, 컴퓨터의 Remote Access 활성화라는 조건을 명시한다.
로컬 데스크톱 사용과 휴대폰에서 같은 세션에 접근하는 구성을 구분해야 하며, 원격 기능을 켠다는 것은 접속 범위와 작업 권한을 다시 검토할 계기다.[1]

라이선스는 Elastic License 2.0이다.
전문에는 주요 기능을 제3자에게 호스팅·관리 서비스 형태로 제공하는 행위, 라이선스 키 기능의 우회, 고지 제거 등에 대한 제한이 있다.
소스 열람이 가능하다는 사실과 모든 재배포·서비스 제공 방식이 허용된다는 주장은 다르다.
구체적인 배포를 판단할 때는 전문의 적용 조건을 확인해야 한다.[3]

## 정리

Superset은 여러 코딩 도구를 작업 공간에 배치하고 변경을 다시 검토하는 통로를 모은다.
worktree 분리는 병렬 진행의 수단이지 보안 격리나 품질 보증이 아니다.
결과를 읽고 시험하고 합치는 책임은 각 작업 공간 밖에서도 계속된다.
