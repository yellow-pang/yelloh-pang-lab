## 콘텐츠를 소유하는 서비스가 아닌 검색·재생 화면

LunaTV 저장소의 README는 프로젝트를 MoonTV라는 이름으로 소개한다.
여러 영상 정보 제공처를 검색하고 결과를 재생 화면, 즐겨찾기, 이어 보기 기능에 연결하는 웹 애플리케이션이다.
중요한 전제는 배포 직후에는 재생원과 실시간 방송원이 내장되지 않은 빈 앱이라는 점이다.
설치만으로 합법적인 영상 콘텐츠 이용권이나 완성된 자료 목록이 생기는 서비스는 아니다.[1]

여러 출처에 흩어진 공개·허가된 영상 정보를 같은 화면에서 찾아보고, 다른 기기에서도 보던 위치를 이어가고 싶은 상황을 떠올릴 수 있다.
이때 검색 인터페이스, 재생 기술, 사용자의 시청 기록은 서로 다른 문제다.
LunaTV는 이를 하나의 앱에서 연결하지만 영상 제공처의 접근 가능성이나 권리 관계까지 해결하지는 않는다.
검색과 재생을 합친다는 말은 콘텐츠 자체를 제공한다는 뜻과 다르다.[1]

## 검색원·플레이어·기록 저장소의 역할

검색원은 관리자가 설정하는 `api_site`에 정의된다.
README는 API 주소, 화면에 표시할 이름, 필요할 때 사용하는 상세 페이지 주소를 구분하고, 표준 Apple CMS V10 API 형식을 지원한다고 설명한다.
API는 다른 프로그램이 구조화된 데이터를 요청하는 접점이다.
여기서는 검색어를 받아 제목·에피소드 같은 정보를 돌려주는 외부 접점이므로, 그 주소가 유효하고 사용할 권한이 있는지가 먼저 확인되어야 한다.[1]

재생 화면에는 ArtPlayer와 HLS.js가 사용된다.
HLS는 동영상을 여러 조각으로 나눠 전달하는 스트리밍 방식이며 HLS.js는 이를 웹 브라우저에서 다루는 구성 요소다.
상세 정보·에피소드 선택과 실제 영상 스트림 재생은 관련되지만 동일한 처리 단계는 아니다.
검색 결과가 표시돼도 영상 주소가 만료되거나 접근 조건이 맞지 않으면 재생까지 보장되지는 않는다.[1]

즐겨찾기와 이어 보기에는 Kvrocks, Redis, Upstash 같은 별도 저장소를 연결한다.
README는 이 저장소들을 재생 기록·즐겨찾기 보관 방식으로 제시하고 기기 간 진행 상황 동기화를 설명한다.
이는 영상을 서버에 복사해 두는 기능과 구분해야 한다.
Redis 배포 예시에는 지속 보관 설정이 없으면 업그레이드나 재시작 후 데이터가 사라질 수 있다는 경고도 있다.[1]

PWA는 웹 앱을 기기의 홈 화면 등에 추가해 앱처럼 접근하게 하는 구성이다.
README에 오프라인 캐시가 언급되지만, 이를 모든 영상을 내려받아 오프라인으로 재생할 수 있다는 뜻으로 확대해서는 안 된다.
화면 자원 캐시, 사용자 기록 저장, 외부 영상 데이터 접근은 각각 다른 저장·통신 경로다.[1]

## 검색 API에서 확인되는 처리 방식

실제 `src/app/api/search/route.ts`는 요청의 인증 정보부터 확인한다.
사용자 이름이 없으면 인증되지 않은 요청으로 응답하고, 검색어 `q`가 없으면 빈 결과를 반환한다.
유효한 검색 요청에서는 해당 사용자에게 허용된 API 사이트 목록을 얻어 각 사이트에 질의를 보낸다.
따라서 아무 외부 사이트나 검색하는 범용 검색 엔진이라기보다 설정과 사용자 권한 안에서 작동하는 집계 경로다.[2]

각 외부 검색에는 시간 제한이 걸리며, 실패한 사이트는 빈 배열로 처리된다.
완료된 결과들을 합친 뒤 설정에 따라 분류명에 포함된 특정 단어를 걸러내고 JSON 응답을 만든다.
이 파일의 필터는 분류명 문자열에 대한 검사이지 영상의 실제 내용을 판독하는 기능이 아니다.
또한 일부 검색원이 실패해도 나머지 결과는 모일 수 있으므로, 화면에 결과가 있다는 사실만으로 모든 검색원이 정상이라고 판단할 수 없다.[2]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
관리자가 이용 허가를 확인한 공개 교육 영상 API를 등록하고, 로그인한 사용자가 특정 강의 제목을 검색한다고 가정하자.
설정에는 제공처의 API 주소와 표시 이름이 들어 있고, 검색어는 `q`로 검색 경로에 전달된다.
서버는 인증 정보와 사용자에게 사용 가능한 제공처 목록을 먼저 확인한 뒤, 각 제공처에 같은 검색어를 보내는 구조로 읽을 수 있다.[1][2]

한 제공처는 응답하고 다른 제공처는 시간 안에 응답하지 못하는 경우를 생각해 보자.
소스에서는 실패한 요청을 빈 목록으로 바꾸고 나머지 결과를 합치기 때문에 사용자는 일부 검색 결과만 볼 수 있다.
이때 검색 결과가 적은 이유는 해당 제목의 부재일 수도 있고 제공처 실패일 수도 있다.
관리자는 결과 수만 보지 말고 제공처 설정과 실패 기록을 함께 확인해야 한다.
이는 실제 발생을 보고한 것이 아니라 오류 처리 코드가 갖는 의미를 설명한 것이다.[2]

사용자가 허가된 영상을 선택하면 상세 정보와 재생 화면을 통해 감상하고, 이어 보기 정보를 설정한 기록 저장소에 남기는 것이 README가 설명하는 전체 사용 흐름이다.
여기서 영상이 정상 재생되는지, 선택한 회차가 맞는지, 다른 기기의 기록이 일치하는지는 별도 확인 지점이다.
검색 API를 읽었다고 재생·동기화의 실제 동작까지 검증한 것으로 취급하지 않는다.[1]

## 배포보다 먼저 확인할 조건

README는 Docker 또는 Docker 기반 플랫폼 배포를 안내하며 관리자 이름·암호·저장소 유형을 필수 환경 변수로 제시한다.
강한 암호, 공개 가입 제한, 개인 사용 범위도 강조한다.
외부에 공개된 검색·재생 앱을 운영하는 일은 로컬 화면을 읽는 것과 다르며, 연결한 API와 저장소의 접근 정보 역시 보호 대상이다.[1]

라이선스는 CC BY-NC-SA 4.0으로 명시되어 있다.
README는 상업화 금지, 파생 프로젝트의 출처·저작자 표시와 같은 조건의 공유를 요구하고 공개 서비스 제공도 하지 말라고 안내한다.
프로젝트에는 별도의 홍보·수록 제한 요청도 적혀 있으므로 재배포나 공개 소개를 준비할 때 원문 조건을 확인해야 한다.
영상의 저작권은 앱의 라이선스와 별도로 판단할 문제이며, 접근 가능한 주소가 곧 이용 허가를 뜻하지는 않는다.[1]

실험적 광고 조각 건너뛰기 기능 역시 README의 기능 설명일 뿐 안정성을 검증한 결과가 아니다.
이 글에서는 무단 배포 출처, 접근 통제 우회, 영상 확보 절차를 제공하지 않는다.
핵심은 합법적으로 사용할 수 있는 출처와 개인 기록 관리 구조를 구분해서 읽는 것이다.

## 정리

LunaTV는 등록된 영상 정보원을 모아 검색·재생·개인 기록을 연결하는 웹 앱이다.
실제 콘텐츠의 공급과 이용 권리는 외부에 있으며, 빈 앱의 설정·저장소 관리·출처 권리 확인이 사용의 전제다.
