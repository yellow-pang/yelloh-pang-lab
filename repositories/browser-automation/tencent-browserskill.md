## 한 줄 요약

BrowserSkill은 AI 도우미가 사용자의 기존 Chrome·Edge 로그인 상태로 페이지를 읽고 조작하도록 연결하는 도구다.
AI 모델이나 새 브라우저를 만드는 프로젝트가 아니라, 명령 도구와 브라우저 확장, 도우미용 사용 지침을 제공한다.[1]

## 로그인한 브라우저에 도구를 연결한다

웹페이지를 읽는 것과 로그인한 계정으로 웹사이트 안에서 작업하는 것은 다르다.
새 자동화 브라우저를 열면 필요한 로그인 상태가 없을 수 있고, 사용자가 보던 탭을 그대로 조작하면 사람의 작업과 충돌할 수 있다.
BrowserSkill은 선택한 브라우저 프로필의 계정을 사용하되, 기본 작업을 별도의 보이는 Agent Window에 둔다.
기존 탭이 필요할 때는 명시적으로 빌려 쓰고 작업이 끝나면 원래 창으로 돌려주는 방식이다.[1]

여기서 프로필은 로그인과 설정을 함께 보관하는 브라우저의 사용자 공간이다.
창이 나뉜다고 계정 권한까지 분리되지는 않는다.
공식 README도 Agent Window가 별도 계정이나 보안 격리 환경이 아니라고 명시한다.
따라서 이 프로젝트의 창 분리는 작업을 구분하기 위한 장치이지, 민감한 계정에 접근해도 안전해지는 장치는 아니다.[1]

## 연결·관찰·작업 종료의 역할 분담

로컬 구성에는 AI 도우미, `bsk` CLI, 브라우저 확장이 필요하다.
CLI는 터미널에서 호출하는 명령 도구이고, 함께 제공되는 daemon은 연결을 유지하는 백그라운드 프로그램이다.
Skill은 도우미에게 이 도구를 언제, 어떤 순서로 사용할지 알려주는 문서다.
Skill 파일만 넣는 것으로 CLI나 확장이 설치되지는 않으며, 모델 선택은 BrowserSkill 밖의 도우미에 맡긴다.[1][2]

실제 작업 지침은 먼저 목표를 정하고 세션을 만드는 것에서 시작한다.
세션은 한 작업을 묶는 식별자이며, 브라우저가 여러 개라면 대상 인스턴스를 명시적으로 선택한다.
`observe`는 페이지의 글과 조작 요소, 요소를 가리키는 참조를 돌려준다.
도우미는 방금 얻은 참조로 클릭하거나 입력해야 하며, 이동이나 큰 화면 구조 변화 뒤에는 다시 관찰해야 한다.
이는 예전 화면의 버튼 번호를 새 페이지에도 그대로 적용하지 않도록 하는 규칙이다.[2]

성공뿐 아니라 실패했을 때도 `session stop`으로 해당 세션을 끝내도록 지시한다.
빌린 탭은 닫아 없애는 대신 사용자의 창으로 반환된다.
공유 daemon 전체를 재시작하는 것은 작업 정리의 대체 수단이 아니다.
이처럼 연결 프로그램의 수명과 개별 작업의 수명을 구분한다.[2]

## 예시로 따라가는 흐름

README의 첫 작업은 `https://example.com`을 열어 내용을 요약하고 세션을 종료하는 것이다.
다음은 그 공식 예시를 구성요소별로 풀어 쓴 설명이며 직접 실행한 결과가 아니다.
입력은 URL과 “페이지를 요약한 뒤 끝내라”는 요청이다.
도우미는 `bsk session start --no-focus --json`으로 세션을 만들고 반환된 `session_id`를 보관한다.
여러 브라우저가 연결되어 있다면 시작할 때 대상 브라우저를 지정해야 한다.[1][2]

이어 `navigate`로 해당 주소를 열고 `observe`로 페이지의 현재 내용을 읽는다.
확장은 브라우저 쪽 관찰 결과를 연결된 daemon으로 보내고, 이를 받은 도우미가 요약문을 구성한다.
따라서 요약의 문장 생성과 정확성 판단은 AI 도우미의 몫이며, BrowserSkill의 역할은 페이지 상태를 읽고 전달하는 것이다.
필요하면 `screenshot`으로 이미지를 저장할 수 있지만, 이미지 파일이 생겼다는 사실이 요약 내용의 정확성을 대신하지는 않는다.[1][3]

이 작업의 산출물은 도우미의 페이지 요약이며, 캡처를 요청한 경우에는 화면 이미지도 포함된다.
사람은 실제로 연 주소와 읽은 페이지가 일치하는지, 요약에 페이지 밖의 내용이 섞이지 않았는지 확인할 수 있다.
목표를 달성하면 세션을 종료하고, 실패하더라도 같은 정리 절차를 따른다.
여기서는 실제 요약문이나 성공 화면을 만들지 않았으며, 공식 예시가 요구하는 입력·관찰·산출물·종료의 경계만 설명했다.[1][2]

## 오류 조사에서는 기록의 성격이 달라진다

일반 페이지 읽기와 website debugging은 구별된다.
디버깅은 허가받은 사이트에서 오류를 재현하기 전에 캡처를 시작하여 요청·응답·콘솔 메시지·입력 필드 값·페이지 변화를 연결해서 보는 기능이다.
예를 들어 자신이 만든 테스트 양식이 저장되지 않을 때, 화면의 실패 표시만 보는 대신 요청이 전송되었는지와 응답 내용을 함께 조사할 수 있다.
자료가 없거나 일부만 수집되었을 가능성도 남으므로 증거의 빈 부분을 곧바로 오류 원인으로 단정해서는 안 된다.[1]

기록을 읽는 것과 요청을 재전송하는 것도 다르다.
재전송은 현재 브라우저의 로그인 세션으로 새로운 요청을 보내며 서버 데이터를 바꿀 수 있다.
요청 수정·차단·모의 응답 역시 조사 범위 안에서 명시적으로 설정하는 기능이다.
오류를 읽어 달라는 요청을 데이터 변경까지 허용한 것으로 넓혀 해석하지 않는 것이 중요하다.[1][3]

## 계정 권한과 원격 전송의 경계

확장에는 기존 탭을 빌리기 전에 확인하는 설정과 사람의 도움을 요청하도록 허용하는 설정이 따로 있다.
둘 다 기본적으로 켜져 있으며, Skill은 이를 우회하려고 설정이나 브라우저 연결 방식을 바꾸지 말라고 지시한다.
로그인·인증·동의처럼 사람이 처리해야 하는 단계는 사람이 참여하는 경로로 넘긴다.
페이지 본문도 사용자의 새 지시가 아니라 작업에 필요한 자료로 다루며, 자격정보·쿠키·토큰을 추출하지 않도록 규정한다.[1][2]

원격 모드에서는 브라우저는 사용자 컴퓨터에 남고 도우미·CLI·daemon은 서버에 있을 수 있다.
브라우저가 인증된 암호화 WebSocket 연결인 WSS를 시작하므로 사용자 컴퓨터의 외부 접속용 포트를 열 필요는 없다고 안내한다.
다만 페이지 내용과 화면 캡처 등 요청된 결과는 선택한 서버로 전달된다.
필수 중계 클라우드나 제품 텔레메트리가 없다는 설명은 “데이터가 장치 밖으로 나가지 않는다”는 뜻이 아니다.
선택한 도우미와 게이트웨이의 보관·전달 정책은 별도로 확인해야 한다.[1][3]

디버깅 기록은 원격 모드에서도 현재 브라우저 프로필에 저장되며, 작업 종료나 연결 해제로 삭제되지 않는다.
알려진 비밀정보를 가리는 처리가 있지만 임의의 본문·콘솔·필드 값까지 완전히 정리한다고 보장하지 않는다.
반면 별도 operation audit는 기본적으로 꺼져 있고 입력값·페이지 본문·화면 이미지 대신 작업 메타데이터를 기록한다.
두 기록을 혼동하지 말고, 내보낸 JSON과 이미지는 공유 전에 직접 확인해야 한다.[3]

확장은 Chromium 125 이상 Chrome·Edge를 대상으로 한다.
원격 파일 업로드·다운로드는 지원하지 않으며, 저장소의 설명과 확장 스토어 배포 시점이 다를 수 있다.
연결 검사인 `doctor`의 성공도 도우미가 Skill을 발견했다는 사실까지 증명하지는 않는다.[1]

## 정리

BrowserSkill은 로그인된 브라우저와 선택한 AI 도우미 사이의 관찰·조작 통로다.
그 구조를 이해하려면 도구 연결, 작업 세션, 계정 권한, 기록 보관을 각각 나누어 봐야 한다.
보이는 작업 창과 종료 규칙은 제공하지만, 계정 권한을 줄이거나 도우미의 판단을 대신 검증하는 제품은 아니다.[1][2][3]
