## 한 줄 요약

backend-interview-question은 신입 백엔드 개발자를 위한 한국어 면접 질문과 짧은 답변을 하나의 README에 모은 자료다.
실제로 받은 질문, 학습한 내용, 예상 가능한 질문을 선별했다고 밝히며, 정답을 채점하는 서비스나 모든 기술을 깊이 설명하는 교과서는 아니다.
작성자는 답변을 자신의 설명 예로 받아들이고 더 깊은 질문에 대비해 별도 학습을 하도록 안내한다.[1]

## 긴 지식을 짧게 설명하는 연습

백엔드는 사용자의 요청을 받아 자료를 처리하고 저장하는 서버 쪽 역할을 말한다.
이 일을 설명하려면 네트워크, 운영체제, 데이터베이스뿐 아니라 사용하는 언어와 프레임워크까지 연결해야 한다.
이 저장소는 넓은 범위를 하나의 질문 목록으로 정리하여 어느 부분에서 설명이 막히는지 확인하게 한다.
답변을 가능하면 간단히 구성하는 것이 명시된 목표다.[1]

README는 질문을 보고 음성메모로 대답한 뒤 다시 들어보는 방법을 제안한다.
이는 자동 평가 기능이 아니라 독자가 자기 설명을 점검하는 사용법이다.
답안이 짧다는 점도 작성자가 직접 제한으로 밝힌다.
누락하거나 덜어낸 부분이 있고, 정답이 하나로 정해지지 않는 질문도 있으므로 문장을 그대로 외우는 것과 개념을 이해하는 일을 구별해야 한다.[1]

자료 범위는 균일하지 않다.
작성자는 Java를 주로 사용한다고 설명하며 언어별 지식의 차이를 밝힌다.
실제 목차에도 Java와 Spring, JPA 항목이 구체적으로 이어지고 다른 언어·주제의 질문에는 비어 있는 답안이 있다.
어떤 질문이 존재한다는 사실을 그 질문의 완성된 해설까지 제공한다는 뜻으로 받아들이지 않는 것이 중요하다.[1]

## 하나의 README가 만드는 탐색 방식

본문은 면접 전 정보, CS 관련 지식, 언어, 기타 주제와 조언으로 이어진다.
CS는 컴퓨터 과학의 기초 지식을 뜻하며 여기서는 요청 전달, 프로세스·스레드, 데이터 저장, 자료구조 같은 바탕을 다룬다.
각 질문은 `details`와 `summary`로 답변을 접고 펼치는 구조다.
따라서 목차로 큰 영역을 고른 뒤 질문 제목만 보고 설명을 시도하고, 필요한 항목을 펼치는 방식으로 읽을 수 있다.[1]

예를 들어 Java 영역의 자원 해제 질문은 `try-with-resources`를 다룬다.
자원은 파일처럼 사용 후 닫아야 하는 외부 대상을 연결한 객체로 이해하면 된다.
README는 `finally`에서 직접 닫는 코드의 누락·중복 문제를 설명하고, `try`의 자원 선언에 넣으면 종료 시 닫기 처리가 이루어지는 문법으로 연결한다.
질문의 목적, 문제 상황, 언어 기능이 한 덩어리로 나타나는 대표 항목이다.[1]

다만 이 저장소에는 README 외의 별도 기능 구현 파일이 없다.
따라서 대표 질문을 실제 언어의 공식 예제와 대조하는 것이 보강에 적합하다.
Java Tutorials의 `try-with-resources` 안내는 파일 첫 줄을 읽는 예제와, 읽기 또는 닫기에서 예외가 발생하는 경우를 함께 설명한다.
간단한 답에서 생략된 종료 순서와 예외 처리를 확인할 수 있다.[2]

## 예시로 따라가는 흐름

대표 사례는 README의 “try-with-resource에 대해서 설명해주세요”라는 질문에서 시작한다.
먼저 “파일을 읽은 뒤 왜 닫아야 하는가”, “읽다가 실패해도 닫는가”를 자신의 설명에 포함할 수 있는지 확인한다.
이는 질문을 읽는 연습 사례이며 Java 코드를 직접 실행한 결과가 아니다.
README의 답변을 펼치면 자동 자원 반납이라는 핵심과 Java 버전별 문법 차이를 만날 수 있다.[1]

여기서 공식 Java Tutorials의 파일 읽기 예제로 이동한다.
예제 입력은 파일 경로이고, `FileReader`와 이를 감싸는 `BufferedReader`를 `try` 자원 선언에 넣은 뒤 `readLine()`을 호출한다.
정상 경로의 반환 대상은 파일 첫 줄이며, 읽기 도중 예외가 발생해도 선언한 자원을 닫는 흐름이 이어진다.
실제 파일 내용이나 반환 문자열은 이번에 준비하거나 만들어내지 않았다.[2]

그 다음은 예외라는 후속 질문이다.
블록의 처리와 자원 닫기에서 모두 예외가 생기면 무엇이 바깥으로 전달되는가?
공식 설명은 블록에서 난 예외를 유지하고 닫기 과정의 예외는 suppressed exception으로 다룬다고 설명한다.
이는 실패 정보를 주 예외에 딸린 정보로 보존하는 방식이다.
여러 자원은 만들어진 순서의 반대로 닫힌다는 점도 나와 있다.
단순히 “자동으로 닫아준다”에서 멈추지 않고 어떤 실패 정보와 종료 순서가 남는지까지 설명을 확장할 수 있다.[2]

읽기 결과는 긴 코드를 암기한 답변이 아니라, 핵심 한 문장과 뒤따르는 조건의 구분이다.
사람은 닫을 수 있는 객체의 조건인 `AutoCloseable`, 정상 종료와 예외 종료, 여러 자원의 닫기 순서를 확인하면 된다.
이 흐름은 질문 모음이 기술 명세를 대신하는 것이 아니라 공식 자료로 들어가는 출발점이 될 수 있음을 보여준다.[1][2]

## 짧은 답변과 이용 조건에서 주의할 부분

저장소의 기술 답변에는 일반화하거나 특정 환경을 생략한 표현이 있을 수 있으며, 작성자도 오류 가능성을 인정한다.
동일성·동등성, 예외와 트랜잭션, 네트워크의 흐름처럼 실행 환경에 따라 세부 조건이 달라지는 항목은 원문만으로 결론 내리지 않아야 한다.
이번에 대조한 Java 예제 외의 답변을 모두 정확하다고 인증한 것은 아니다.[1]

테스트 코드나 설계 방법을 묻는 일부 질문에는 작성자의 견해가 포함된다.
이런 답변을 사용자의 경험이나 의견으로 바꾸어 써서는 안 된다.
경험을 묻는 질문에는 실제로 수행한 일과 확인한 결과가 필요하며, 질문 목록에 적혀 있다는 이유만으로 자신이 해본 사례처럼 말할 수는 없다.
이 원고는 개인 경험과 채용 성과를 추가하지 않는다.[1]

라이선스 표기도 확인할 불확실성이다.
README의 Information에는 CC BY-NC-SA라고 적혀 있지만, 이어지는 배지와 링크 문구는 저작자표시-비영리 2.0 대한민국, 즉 CC BY-NC를 가리킨다.
동일조건변경허락 여부와 버전 표기가 일치하지 않으므로 이를 임의로 하나로 정리하지 않았다.
공개 재배포나 상업적 사용을 고려한다면 어떤 조건이 적용되는지 권리자에게 확인할 필요가 있다.
공개된 질문 모음이라는 이유만으로 자유로운 복제 허락을 추정하지 않아야 한다.[1]
