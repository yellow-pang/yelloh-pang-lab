## 한 줄 요약

OpenMAIC는 주제나 자료를 받아 슬라이드·퀴즈·상호작용 장면과 AI 교사·동료를 갖춘 수업을 만드는 플랫폼이다.
이미 검증된 교재를 전달하는 자료실이나 사람 교사를 대신하는 자격 인증 서비스는 아니다.
생성된 학습 내용과 평가 피드백은 사람이 정확성과 수준을 확인해야 한다.[1]

## 설명을 읽는 것에서 장면을 다루는 것으로

어떤 개념을 배우려면 설명문뿐 아니라 그림을 보고 조건을 바꾸거나 문제에 답하는 과정이 필요할 수 있다.
OpenMAIC는 고전적인 생성 경로에서 먼저 입력을 수업 개요로 만들고, 각 개요 항목을 슬라이드·퀴즈·HTML 상호작용·프로젝트 활동 같은 장면으로 변환한다고 설명한다.
장면은 한 페이지의 그림에 그치지 않고 학습자가 수행할 행동을 포함할 수 있다.[1]

AI 교사와 동료는 서로 다른 역할의 에이전트다.
질문에 답하거나 토론하고 화이트보드에 그림·수식을 표현하는 기능이 소개되지만, 여러 역할이 이야기한다는 사실만으로 내용의 사실성이 서로 독립적으로 검증되지는 않는다.
PBL은 Project-Based Learning의 약자로 목표·단계·산출물을 가진 프로젝트를 따라 배우는 방식이다.[1]

Pro workbench는 한 번 생성하고 끝내는 경로와 구별된다.
대화로 교육과정을 계획하고 페이지를 만들거나 수정하며, 서버에 보관되는 세션에서 취소·재개·방향 변경을 다루는 기능으로 소개된다.
자료 입력도 문서뿐 아니라 설정된 추출기를 통한 음성·영상과 웹 검색을 포함할 수 있다.[1]

## 서비스와 에이전트 Skill의 차이

`skills/openmaic/SKILL.md`는 외부 에이전트가 서비스를 설정하고 호출하도록 안내하는 절차다.
그 파일만 읽는다고 수업 생성 서버가 생기는 것은 아니다.
공식 호스팅 서비스, 로컬 실행, SDK를 활용한 확장 경로를 나누며 서버의 모델·제공자 설정을 사용하도록 규정한다.[2]

특히 외부 에이전트 자신의 모델이나 키가 OpenMAIC에도 그대로 사용된다고 가정하지 말라고 명시한다.
키를 대화에 붙여 달라고 요구하는 대신 사용자가 로컬 설정을 직접 편집하도록 안내하고, 요청 시점의 임의 모델 덮어쓰기에 의존하지 않는다.
수업 내용 입력과 서버 운영 설정의 경계를 나누는 규칙이다.[2]

## 예시로 따라가는 흐름

공식 Generate Flow에는 “고등학생을 위한 양자역학 입문 교실을 만들어 달라”는 요구 문장이 예로 나온다.
여기서는 실제 수업을 생성하지 않고 요청이 완성된 수업 링크가 되기까지를 설명한다.
서비스가 정상이고 제공자 설정이 준비되면 `requirement`에 요구를 담아 생성 작업을 제출한다.
PDF를 기반으로 할 때는 허가를 받고 파일을 읽어 먼저 해석한 뒤 텍스트와 이미지 목록을 정해진 구조로 전달한다.[3]

선택 기능을 켜기 전에는 health 응답의 `capabilities`를 확인한다.
웹 검색, 이미지·영상 생성과 TTS가 서버에서 가능한지 확인한 뒤 해당 옵션을 보낸다.
TTS는 글을 음성으로 만드는 기능이다.
옵션을 생략하면 기본적으로 false이며, 수업을 요청했다고 모든 미디어가 자동으로 활성화되는 것은 아니다.[3]

제출 직후 응답은 완성 결과가 아니라 `jobId`와 상태 조회 주소를 가진 작업 접수다. `queued`나 `running`이면 같은 작업을 기다리고 `succeeded` 또는 `failed`로 끝날 때 판단한다.
한 번 조회가 실패했다고 새 작업을 또 제출하면 중복 생성이 될 수 있어 같은 조회 주소로 이어 확인하도록 문서가 지시한다.[3]

최종 성공에서도 수업 링크만 보면 부족하다. `warning`과 `ttsCoverage`를 읽어 일부 내레이션이 만들어지지 않았는지 확인해야 한다.
교실 URL은 사용 가능하지만 음성이 불완전할 수 있기 때문이다.
학습자가 볼 내용에서는 물리 개념·수식·퀴즈 정답·난이도를 별도로 대조해야 한다.
이처럼 기술적 작업 성공과 교육 자료의 완성도는 서로 다른 검사 항목이다.[3]

## 내보내기와 보관의 범위

README는 편집 가능한 PowerPoint, 상호작용 HTML과 교실 ZIP을 서로 다른 출력으로 소개한다.
ZIP은 수업 구조와 미디어를 보관·공유하는 경로이고, 서버 저장을 켜면 가져온 자산을 서버 자산 풀에 넣어 다른 브라우저에서도 찾을 수 있다고 설명한다.
슬라이드 파일만 내보내는 일과 전체 상호작용 수업을 보관하는 일을 혼동하지 않아야 한다.[1]

기본 실행은 데이터베이스 없이 브라우저 저장소를 쓰며 서버 지속성을 선택하면 PostgreSQL과 자산 저장 구성이 추가된다.
“세션이 재시작 후에도 유지된다”는 기능 소개를 모든 기본 구성에 적용하지 말고 어떤 보관 모드가 켜졌는지 확인해야 한다.
브라우저 캐시와 서버 자산 보관은 데이터의 접근·백업 경계가 다르다.[1]

## 실행 전에 확인할 제약

공유 배포에서는 `ACCESS_CODE`가 중요하다.
README는 설정하지 않은 기본 상태에서 일치하는 앱·API 경로가 열리고 두 번째 강제 지점이 없다고 설명한다.
인증 시도 제한도 신뢰할 수 있는 역방향 프록시와 `TRUST_PROXY_HEADERS` 설정을 전제로 한다.
배포 버튼이 있다고 공개 접근·사용량 보호까지 준비되는 것은 아니다.[1]

모델과 선택적 검색·이미지·음성 제공자에는 별도 설정과 비용이 따른다.
입력 자료의 이용 권한과 외부 전송 허용 여부도 확인해야 한다.
UI에 여러 언어가 있다는 설명과 Generate Flow의 API `language` 계약은 다른 층이다.
이번에 읽은 API 문서는 `zh-CN`·`en-US` 외 값이 중국어 기본값으로 돌아간다고 하므로 화면의 한국어 지원을 모든 생성 endpoint의 한국어 매개변수 보장으로 확대하지 않는다.[1][3]

루트 라이선스는 MIT지만 함께 포함된 `mathml2omml` 패키지는 LGPL-3.0-or-later라고 README가 별도로 밝힌다.
전체를 재배포할 때는 각 포함 패키지의 조건도 확인해야 한다.
그림·시뮬레이션의 표현력이 곧 교육 효과라는 독립 검증 결과는 이번 조사에 포함되지 않았다.[1]

## 정리

OpenMAIC는 자료를 상호작용 수업으로 조립하고 수정·배포할 수 있게 한다.
생성 완료, 미디어 완성, 내용의 정확성과 배포 보안은 각각 별도의 확인이 필요한 경계다.
