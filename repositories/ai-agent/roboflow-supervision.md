## 한 줄 요약

Supervision은 컴퓨터 비전 모델의 결과를 다루는 Python 도구 모음이다.
객체를 인식하는 모델 자체가 아니라, 모델 출력의 공통 표현, 시각화, 데이터셋 처리와 영역·선 통과 집계처럼 애플리케이션에서 반복되는 부분을 제공한다.[1]

## 모델이 상자를 그린 다음에 필요한 일

영상 속 물체를 찾는 모델이 있어도 활용 프로그램이 완성되지는 않는다.
결과를 화면에 표시하고, 필요한 종류만 남기고, 프레임 사이의 같은 물체를 이어서 세어야 한다.
객체 탐지는 한 장의 이미지에서 위치와 종류를 찾는 작업이고, 추적은 여러 장에서 같은 물체의 정체성을 유지하는 작업이다.
Supervision을 읽을 때 이 둘을 구별하면 집계 도구가 요구하는 입력이 분명해진다.[1][2]

README는 특정 모델에 묶이지 않는 구성을 설명한다.
Ultralytics, Transformers, MMDetection, Inference 등의 출력 연결 기능이 있고, `rfdetr`처럼 처음부터 `sv.Detections`를 반환하는 연동도 소개한다.
공통 컨테이너를 사용하면 뒤쪽의 시각화나 집계가 각 모델의 고유 출력 형식을 매번 알아야 하는 부담을 줄일 수 있다.[1]

## 공통 검출 결과, 표시, 데이터셋

`Detections`는 검출된 대상의 좌표와 관련 정보를 묶는 표현이다.
README의 예에서는 모델이 이미 만든 검출 결과를 `BoxAnnotator`에 전달해 이미지 복사본에 상자를 그린다.
annotator는 결과를 그림으로 표시하는 구성요소이며, 상자를 예쁘게 표시했다고 모델의 판단이 더 정확해지는 것은 아니다.[1]

데이터셋 도구는 COCO, YOLO, Pascal VOC 같은 이미지 주석 형식을 읽고 저장하는 예제로 설명된다.
주석은 이미지 속 물체의 위치나 종류를 기록한 자료다.
형식 변환 외에도 분할과 병합을 제공하고, 예제의 이미지 접근은 필요할 때 로딩한다고 명시한다.
이것은 학습 데이터를 다루는 보조 기능이며 새 모델을 학습시키는 전체 훈련 절차와는 역할이 다르다.[1]

선 통과 집계의 대표 구현은 `LineZone`이다.
시작점과 끝점으로 기준선을 정하고, 검출 상자의 어느 지점을 기준으로 판단할지 anchor를 설정한다.
기본 anchor는 네 모서리다.
한 대상이 선의 어느 쪽에 있었는지 기록한 뒤 반대쪽으로 넘어간 것이 확인될 때 들어옴·나감을 센다.
한 프레임에 몇 개가 보였는지 합산하는 방식이 아니다.[2]

`minimum_crossing_threshold`는 반대편에 연속해서 관찰되어야 하는 정도를 정한다.
상자가 잠깐 흔들리거나 선에 걸쳐 있을 때 즉시 왕복 이동으로 세지 않도록 설계되어 있다.
구현은 처음 관찰한 쪽을 기준으로 삼고, 너무 오래 보이지 않는 추적 ID의 상태를 제거한다.
따라서 추적의 안정성과 장면 조건이 집계의 전제가 된다.[2]

## 예시로 따라가는 흐름

공식 `LineZone` 문서 문자열에는 수평선과 하나의 추적 ID를 사용하는 작은 예가 있다.
이는 직접 실행한 결과가 아니라 코드에 포함된 예제의 설명이다.
입력은 시작점 `(0, 100)`, 끝점 `(200, 100)`으로 정의한 선과 `tracker_id`가 1인 검출 상자다.
첫 관찰에서 상자는 선의 한쪽에 있으므로 이전 위치에서 넘어온 이동이 아직 없다.
다음 관찰은 같은 ID의 상자가 반대편에 놓이도록 구성한다.[2]

`trigger()`는 각 검출이 이번에 안쪽 또는 바깥쪽으로 넘어왔는지를 나타내는 두 불리언 배열을 반환하고 누적 카운터를 갱신한다.
불리언은 참과 거짓으로 된 표시다.
공식 예제는 이 위치 변화에서 카운터가 바뀌는 모습을 제시하지만, 이는 실제 영상의 탐지·추적 품질을 측정한 결과가 아니다.
예제는 신원과 좌표가 정확히 제공되었을 때 집계기가 어떤 의미로 동작하는지 보여 준다.[2]

사람이 확인할 부분은 같은 물체가 계속 같은 ID를 받는지, 기준선 방향이 원하는 들어옴·나감과 맞는지, 상자가 선 양쪽에 걸칠 때 무엇을 세는지다.
실제 영상으로 확장할 때는 모델 출력 뒤에 추적 단계가 먼저 필요하다.
ID가 없다면 `LineZone`은 경고를 내고 집계를 건너뛰며, 음수 ID는 아직 확정되지 않은 추적으로 취급해 세지 않도록 되어 있다.
검출이 보인다는 사실만으로 통과 횟수가 생기지 않는 이유다.[2]

## 도구가 책임지지 않는 정확도

README의 설치 조건은 Python 3.10 이상이며, 모델 예제에 필요한 `pillow`, `rfdetr`는 선택 의존성으로 별도 안내된다.
Inference를 사용하는 다른 예는 API 키가 필요하다.
Supervision 패키지 설치와 모든 모델 연결의 준비를 같은 일로 보면 안 된다.[1]

집계기의 상태 관리가 있어도 가려짐, 잘못된 상자, 추적 ID 변경을 모두 해결한다는 보장은 없다.
코드에서도 음수 ID 제외와 오래된 기록 정리 같은 입력 경계가 드러난다.
결과의 정확도를 평가하려면 실제 영상의 정답과 비교하는 별도 검증이 필요하며 이 글은 그러한 성능 수치를 제시하지 않는다.[2]

데이터셋 변환 또한 파일을 읽고 쓸 수 있다는 기능과 변환 후 의미가 동일하다는 검토를 구분해야 한다.
클래스 이름과 좌표, 분할의 의도가 유지되는지는 사용한 자료에서 확인할 일이다.
README 예제의 검출 개수와 데이터 분할 숫자는 설명용 예시이며 어떤 입력에도 성립하는 결과로 재사용하지 않았다.[1]

## 정리

Supervision은 모델 뒤의 반복 작업을 재사용 가능한 부품으로 만든다.
시각화와 집계를 얻기 전에 어떤 검출·추적 정보를 제공해야 하는지 확인하는 것이 사용 범위를 이해하는 핵심이다.
