## 한 줄 요약

ai-agent-book은 AI Agent의 설계 원리와 구현을 설명하는 책의 본문, 번역, 전자책과 장별 실험 코드를 함께 제공하는 학습 저장소다.
완성된 하나의 에이전트 서비스라기보다 개념 설명과 작은 구현을 연결해 읽는 교재다.
README는 `Agent = LLM + 上下文 + 工具`, 즉 언어 모델·문맥·도구의 결합을 책 전체의 출발점으로 제시한다.[1]

## 모델을 호출한 뒤 무엇이 더 필요한가

질문을 모델에 보내 답을 받는 예제와, 자료를 찾고 계산하며 오류를 수정하는 에이전트 사이에는 여러 단계가 있다.
모델이 지난 도구 결과를 볼 수 있는지, 다음 행동에 어떤 정보를 전달하는지, 마지막 답이 실제로 맞는지 확인하는 구조가 필요하다.
이 책은 문맥, 기억과 지식, 도구, 코딩 에이전트, 상호작용, 평가와 학습, 여러 에이전트의 협업으로 주제를 나누어 그 구성 요소를 설명한다.[1]

여기서 문맥은 모델이 현재 판단할 때 받는 요청과 이전 대화, 도구 관측 등의 정보다.
도구는 모델 밖에서 파일 읽기나 계산 같은 일을 수행하는 기능이다.
책의 공식을 모든 에이전트에 대한 유일한 정의로 받아들이기보다, 무엇을 바꾸어 결과 차이를 관찰할지 정하는 교재의 설계 틀로 읽으면 각 장과 실험의 연결이 보인다.[1][2]

## 본문·실험·검증 상태를 나누어 읽는다

README는 장별 본문과 실험 안내를 별도로 연결하며, 중국어 원문과 커뮤니티 번역의 위치를 구분한다.
번역은 원문보다 늦을 수 있다고 안내한다.
PDF나 웹 문서를 읽을 때도 언어와 판본이 같은지 확인해야 장 번호나 실험 설명의 차이를 잘못 해석하지 않는다.
자료를 읽는 것만으로 실습 환경을 설치할 필요는 없다.[1]

실험 코드에는 모델 호출, 도구 결과, 평가 조건을 직접 볼 수 있는 파일이 있다.
대표로 확인한 `chapter1/context/main.py`는 문맥 정보를 일부 빼는 ablation study를 구성한다.
Ablation은 구성 요소를 하나씩 제외해 어떤 차이가 생기는지 비교하는 방법이다.
이 파일은 전체 문맥을 기준으로 과거 기록, 추론 과정, 도구 호출 정보, 도구 결과가 없는 조건을 구분해 실행하도록 되어 있다.[2]

특히 이 코드에서는 응답을 끝냈다는 `completed`와 과제를 올바르게 수행했다는 판단을 구분한다.
이전 결과를 읽기 위한 `success` 이름이 남아 있지만, 주석은 이를 완료 여부의 호환용 별칭이라고 설명하고 과제 정답 판정은 별도로 미확정 상태에 둔다.
요약 표에 성공처럼 보이는 값이 있어도 어떤 의미로 계산된 지표인지 먼저 읽어야 하는 사례다.[2]

또한 모델에 실제 전송된 메시지에서 관측 수치를 모아, 최종 답변의 숫자가 어떤 근거를 가졌는지 검사하는 흐름이 들어 있다.
도구는 실행했지만 결과를 모델에게 보여 주지 않는 조건에서는 모델이 본 관측과 실행기가 가진 결과가 다를 수 있기 때문이다.
코드가 이를 구분하려는 구조는 확인했지만, 그 검사 함수의 정확도나 모든 수치 추론을 판별하는 능력까지 검증한 것은 아니다.[2]

## 예시로 따라가는 흐름

대표 파일의 기본 과제는 여러 지역의 지출을 한 통화로 합치고, 총액·평균·비중 등을 설명하는 예제다.
입력에는 지역별 금액과 통화, 읽을 PDF 주소와 계산 요청이 함께 들어 있다.
이번 글은 해당 코드의 흐름을 읽어 설명하는 것이며 직접 실행한 결과가 아니다.
환율이나 계산 결과를 여기서 만들어 제시하지 않는다.[2]

실험은 같은 과제를 전체 문맥과 정보가 빠진 조건에 각각 전달한다.
각 조건은 `ContextAwareAgent`를 생성해 과제를 실행하고, 수행 시간, 반복 횟수, 도구 호출 횟수, 최종 답변 유무 같은 기록을 결과에 담는다.
이후 실제 요청 메시지로부터 모델이 볼 수 있었던 도구 관측을 추려 답변의 수치 근거 검사에 넘긴다.
산출물은 조건별 기록과 분석용 지표이지, 한 번의 답변만 보고 내리는 전반적인 모델 등급이 아니다.[2]

사람이 볼 부분은 두 가지다.
먼저 정보를 제거한 조건이 실제로 의도한 정보를 모델에게서 가렸는지 확인한다.
그다음 답변 완료와 과제의 정답 여부를 분리한다.
예를 들어 필요한 환율 자료가 없다고 답한 경우와, 근거 없는 환율을 말하며 계산을 끝낸 경우는 모두 대화를 마칠 수 있지만 같은 결과로 평가하면 안 된다.
확인한 코드의 `_outcome`은 근거 없는 수치를 낸 결과를 별도로 표시한다.
다만 이것만으로 통화 처리의 경제적 의미나 전체 계산의 정답을 모두 판정했다고 볼 수는 없다.[2]

## 교재 코드가 의미하는 검증의 범위

README는 실험별 요구 조건을 확인하도록 하며 모델 API 자격 증명, 브라우저와 CUDA 같은 별도 시스템 의존성이 필요한 경우를 구분한다.
로컬 모델도 각 실험의 문서나 명령 옵션에 명시된 경우에 사용하도록 안내한다.
하나의 설치 옵션이나 예제를 확인했다고 모든 장이 같은 환경에서 실행된다고 판단하면 안 된다.[1]

또한 README는 실행 상태와 증거, 남은 검증 항목을 별도 문서로 관리한다고 명시하고, 소스를 가져오거나 설치한 것이 실험 완료를 뜻하지 않는다고 설명한다.
외부 구현을 재현하는 실험과 저장소 안의 코드를 실행하는 실험도 섞여 있으므로, 본문의 설명과 해당 실험의 현재 구현 범위를 함께 읽어야 한다.[1]

모델 응답은 제공자와 설정에 영향을 받고 API 비용도 따를 수 있다.
교재에 실험 코드가 있다는 사실은 성능 결과의 보증이 아니다.
이번에 확인한 대표 파일은 문맥 조건을 비교하고 기록을 남기는 설계를 보여 주며, 과제별 채점 기준이 없는 상태를 코드 안에서 명시한다.
이런 구분을 이해하는 것이 출력 표의 숫자를 곧바로 정답률로 읽는 것보다 먼저다.[1][2]

## 정리

이 저장소는 에이전트의 구성 요소를 책과 실험 코드로 연결한다.
대표 문맥 실험은 어떤 정보를 모델에게 보여 주는지와 결과를 어떤 기준으로 기록하는지를 함께 읽게 한다.
교재와 코드의 공개, 실제 환경의 실행, 과제 정답 검증은 각각 다른 단계다.
