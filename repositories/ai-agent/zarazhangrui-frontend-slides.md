## 한 줄 요약

Frontend Slides는 코딩 에이전트가 브라우저에서 보는 HTML 프레젠테이션을 만들도록 안내하는 Skill이다.
독립적인 슬라이드 편집기나 새로운 생성 모델이 아니다.
README는 새 발표 자료 작성, 기존 PowerPoint 변환을 제시하며 Claude Code 플러그인 패키지와 다른 코딩 에이전트가 읽을 수 있는 핵심 `SKILL.md`를 구분한다.
결과물은 CSS와 JavaScript를 포함하는 단일 HTML 파일을 지향한다.[1]

## 디자인 취향을 말로 설명하기 어려울 때

‘깔끔하게 만들어 달라’는 요청은 사람마다 의미가 다르다.
글자 크기, 여백, 색과 움직임을 단어만으로 합의하려면 반복 수정이 늘어날 수 있다.
이 Skill은 전체 자료를 먼저 만드는 대신 서로 다른 스타일의 작은 미리보기를 생성하고 사용자가 보고 선택하도록 한다.
디자인 용어를 많이 알아야 시작할 수 있는 흐름이 아니라 비교할 화면을 먼저 만드는 방식이다.[1][2]

내용의 목적도 구분한다.
공식 Skill은 발표자가 말로 설명하는 낮은 밀도의 자료와 독자가 혼자 읽는 높은 밀도의 자료인지 묻는다.
전자는 한 장에 한 가지 생각을 크게 전달하고 후자는 표·주석·카드로 더 많은 정보를 자체적으로 설명한다.
같은 원고라 해도 페이지 수와 글자 크기, 배치가 달라지는 이유를 사용 목적에서 찾는다.[2]

## 브라우저 문서지만 반응형 웹페이지와는 다르다

공식 지침은 1920×1080 고정 무대에서 슬라이드를 작성하고 창 크기에 맞춰 전체를 동일 비율로 축소하도록 한다.
화면 비율은 16:9를 유지하며 휴대전화라고 해서 내용을 세로로 다시 배치하지 않는다.
일반적인 웹페이지의 반응형 재배치보다 프레젠테이션의 구도를 보존하는 설계다.
창이 좁아지면 여백이 생길 수 있으며 ‘휴대전화에서 열림’과 ‘작은 화면에서도 모든 글이 편안히 읽힘’은 구별해야 한다.[2]

`viewport-base.css`의 규칙을 결과물에 포함하고 슬라이드 전환은 지정된 가시성·투명도·포인터 처리로 제어하도록 한다.
단순히 `display` 값을 바꾸면 뒤에 추가된 레이아웃 스타일 때문에 모든 슬라이드가 한꺼번에 보일 수 있다는 구체적인 경고도 있다.
애니메이션 장식만 권하는 것이 아니라 화면 크기와 전환 상태가 깨지는 원인을 예방하는 지침이 함께 있다.[2]

스타일 자료는 한 번에 모두 읽지 않는다.
가벼운 스타일 색인과 미리보기 카드부터 보고 사용자가 선택한 템플릿의 전체 설계 문서를 나중에 읽는 점진적 로딩을 요구한다.
이는 선택하지 않은 스타일의 상세 규칙이 모델 입력을 차지하거나 최종 디자인을 뒤섞는 것을 줄이려는 구성이다.
확정되지 않은 방향과 확정된 구현 지침을 나누는 절차라고 이해할 수 있다.[2]

## 예시로 따라가는 흐름

공개 강연용 슬라이드를 만들기 위해 간단한 원고와 직접 만든 그림을 제공한다고 가정하자.
이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
Skill의 첫 단계는 목적, 길이, 준비된 내용, 정보 밀도를 함께 묻는다.
그림이 있으면 파일을 살피고 무엇을 보여주는지와 사용할 수 있는지 판단해 원고와 이미지가 함께 개요를 결정하도록 한다.
이미 정한 슬라이드에 그림을 나중에 억지로 끼워 넣는 흐름이 아니다.[2]

그 다음 서로 다른 세 가지 단일 슬라이드 미리보기를 만들어 글꼴, 색, 움직임과 분위기를 비교한다.
사용자가 방향을 고르면 필요한 템플릿의 상세 문서를 읽고 전체 HTML 자료를 만든다.
결과를 확인할 때에는 스타일이 선택과 맞는지뿐 아니라 텍스트가 카드 밖으로 넘치는지, 패널이 겹치는지, 슬라이드가 계속 16:9인지 살핀다.
공식 지침은 수정 뒤 일반 화면과 휴대전화 화면의 캡처를 확인하도록 한다.
내용이 많으면 글자를 계속 줄이는 대신 슬라이드를 나눠야 한다.
따라서 예제의 완료 기준은 HTML 파일이 있다는 사실이 아니라 원고가 빠지지 않고 지정된 화면 안에서 읽히는 상태다.[2]

## 생성물의 가벼움과 제작 환경의 조건

README의 Zero Dependencies는 결과 HTML에 npm이나 빌드 프레임워크가 필요 없다는 지향을 설명한다.
이것을 제작 에이전트까지 파일·셸 접근이나 변환 보조 도구가 전혀 필요 없다는 뜻으로 확대하면 안 된다.
다른 코딩 에이전트는 핵심 Skill과 필요한 지원 파일을 읽어 사용할 수 있지만 Claude Code 플러그인의 호출 명령 체계를 그대로 사용하지는 않는다고 README가 명시한다.[1]

PowerPoint 변환 소개는 이미지와 내용을 보존한다고 설명하지만 이 조사에서는 실제 파일의 복잡한 도형·애니메이션·서식 변환을 시험하지 않았다.
변환을 선택할 때는 원본과 결과의 내용 대응을 직접 검토해야 한다.
브라우저 발표 자료를 만든다는 것과 원래 편집 프로그램의 모든 기능을 동일하게 재현한다는 것은 다른 목표다.[1]

또한 Skill의 디자인 원칙은 작성 지시이지 출력 품질의 보증서가 아니다.
접근성, 글자 크기, 움직임 감소 설정과 화면 넘침 규칙이 있어도 에이전트가 실제로 지켰는지는 렌더링으로 확인해야 한다. `prefers-reduced-motion` 지원은 움직임에 민감한 사용자가 시스템 설정을 통해 애니메이션을 줄이도록 하는 배려다.
시각적으로 화려한 결과와 읽기 편한 자료를 별도 기준으로 검토할 필요가 있다.[2]

## 정리

Frontend Slides는 디자인 선택을 화면 비교로 바꾸고 고정 비율의 HTML 발표 자료를 만드는 작업 지침이다.
핵심은 시각적 탐색과 내용 밀도 관리이며 실제 읽기 품질은 생성 뒤 화면 검토로 확인해야 한다.
