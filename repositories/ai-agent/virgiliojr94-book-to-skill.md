## 한 줄 요약

book-to-skill은 책이나 여러 문서를 에이전트가 필요할 때 찾아 읽는 구조화된 Skill로 바꾸는 도구와 작업 지침의 조합이다.
새로운 언어 모델을 훈련하는 프로젝트도, 책 내용을 자체 제공하는 전자책 서비스도 아니다.
Python 추출기가 문서에서 텍스트와 메타데이터를 얻고 호스트 에이전트가 `SKILL.md`의 생성 절차를 따라 지식 파일을 만드는 두 부분으로 설명된다.[1]

## 요약 한 장으로는 다시 찾기 어려운 지식

책에서 읽었던 특정 개념을 다시 묻고 싶은데 정확한 장이나 표현을 기억하지 못하는 상황이 출발점이다.
전체 PDF를 매번 모델에 넣으면 관련 없는 내용도 함께 읽게 된다.
반대로 짧은 요약만 저장하면 개념의 조건과 예외가 사라질 수 있다.
프로젝트는 핵심 개념과 장별 색인을 작은 진입 문서에 두고 자세한 장 파일은 질문과 관련될 때 읽는 방식으로 이 문제를 다룬다.[1]

여기서 Skill은 에이전트가 상황에 맞게 불러오는 지침과 참고 자료의 묶음이다.
생성 결과에는 중심 문서 `SKILL.md`, 장별 파일, 용어집, 패턴 모음, 빠른 판단표가 포함된다.
본문 전체를 압축한 독후감보다는 ‘어떤 문제에서 어떤 원칙을 찾아볼지’ 설명하는 길잡이에 가깝다.
공식 지침도 요약보다 프레임워크, 실행 가능한 원칙, 기법과 피해야 할 패턴을 추출하라고 강조한다.[1][2]

## 추출과 해석을 분리하는 절차

추출은 파일 형식에 맞는 도구가 맡는다.
README는 PDF, EPUB, DOCX, HTML과 일반 텍스트 등에서 도구를 순서대로 시도한다고 설명한다.
기술 문서처럼 표·코드·수식이 중요한 경우와 산문 중심 문서를 구분하며 전자에서는 구조를 보존하는 방식을 선택하도록 한다.
글자가 들어 있는 PDF와 페이지 이미지뿐인 스캔 PDF도 다르다.
후자는 먼저 OCR, 즉 이미지의 글자를 텍스트로 인식하는 처리가 필요하다.[1]

이후 에이전트의 해석 단계가 목차, 제목, 저자와 핵심 주제를 찾는다.
공식 Skill은 추출된 앞부분에서 구조를 확인하고 목차로 전체 장을 지도화하도록 지시한다.
책이 말하는 기법의 고유 명칭도 보존하도록 한다.
고유한 프레임워크 이름을 일반적인 표현으로 바꿔 놓으면 나중에 원문과 대조하기 어려워지기 때문이다.[2]

모든 요청이 곧 파일 생성으로 이어지지는 않는다.
전체 변환 외에 분석만 수행하는 모드는 추출 보고서를 내고 멈춘다.
이미 있는 분석으로 생성하거나 새 자료를 기존 Skill에 합치는 경로도 별도다.
기존 이름의 Skill이 있으면 갱신, 덮어쓰기, 이름 변경을 선택하도록 하므로 자료 추가와 기존 지식의 전면 교체는 구별된다.[2]

## 예시로 따라가는 흐름

자신이 작성한 공개 Markdown 안내서 묶음을 Skill로 만드는 상황을 생각해 보자.
이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
입력은 문서 폴더와 원하는 Skill 이름이다.
변환기는 지원되는 파일을 찾고 해당 내용이 표와 코드 중심인지 산문 중심인지 확인한 다음 텍스트와 구조를 추출한다.
이때 ‘분석만’ 요청했다면 프레임워크, 원칙, 기법과 장 구조를 보고서로 정리하고 파일 생성 전에 멈추는 것이 공식 절차다.[2]

전체 변환을 선택했다면 사용 목적을 묻는다.
특정 개념을 빨리 찾는 것이 목표인지, 원칙을 적용하고 이해하는 것이 목표인지에 따라 장별 설명의 깊이가 달라진다.
결과는 중심 색인과 장별 파일, 용어와 판단 규칙의 모음이다.
이후 개념을 질문하면 에이전트는 해당 장을 읽을 수 있지만 사람이 확인할 것은 파일 개수보다 원문 장과의 대응, 조건과 예외의 누락, 저자가 쓰지 않은 규칙의 추가 여부다.
생성물이 문법상 올바른 Skill이라는 사실과 내용을 충실히 옮겼다는 사실은 별개다.
공식 README의 질문 예시도 이 구조를 보여줄 뿐 이 조사에서 응답 정확도를 시험한 것은 아니다.[1][2]

## 로컬 처리와 저작권을 함께 읽기

README는 추출과 분석의 로컬 처리를 강조하면서도 사용하는 에이전트의 모델이 클라우드에 있으면 전달한 텍스트는 제공자의 데이터 조건을 따른다고 명시한다.
추출기가 파일을 직접 업로드하지 않는다는 설명과 전체 작업에서 데이터가 외부로 전혀 나가지 않는다는 주장은 다르다.
자료의 공개 범위와 모델 요청 경로를 별도로 확인해야 한다.[1]

프로젝트는 책 내용을 배포하지 않으며 사용자가 권리를 가진 사본을 입력하도록 안내한다.
결과를 개인 공부용 노트로 다루고 타인의 저작물을 바탕으로 만든 Skill을 공개 배포하면 권리를 침해할 수 있다고 경고한다.
생성 절차에 게시 선택지가 있거나 비공개 저장소를 기본값으로 삼더라도 원자료의 재배포 허락을 얻는 것은 아니다.
공개 라이선스 문서도 해당 조건을 따라야 한다.[1]

README의 토큰 절감 수치와 ‘환각 없음’ 같은 표현은 프로젝트의 주장이다.
여기서는 성능 보고서를 재현하지 않았으며 모델이 해석하고 재구성하는 단계가 있으므로 생성물의 정확성을 보장한다고 쓰지 않는다.
호스트마다 Skill을 발견하는 위치와 권한 요구가 달라 같은 파일 형식을 사용한다는 사실만으로 모든 설치 경로가 같다고 가정할 수도 없다.[1][2]

## 정리

book-to-skill은 긴 문서를 반복해서 활용할 수 있는 탐색 구조로 바꾸는 변환 작업이다.
구조화는 검색과 재사용을 돕지만 원문 충실도·모델 전송·재배포 권리의 검토를 대신하지 않는다.
