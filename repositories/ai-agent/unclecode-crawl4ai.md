## 한 줄 요약

Crawl4AI는 웹 페이지를 가져와 Markdown이나 구조화된 자료로 바꾸는 크롤러·스크레이퍼다.
크롤러는 여러 URL을 찾아 방문하고, 스크레이퍼는 페이지에서 필요한 내용을 추출한다.
자체 언어 모델이나 답변 정확성을 보장하는 검색 엔진은 아니며, Python 라이브러리·자체 서버와 별도 호스팅 서비스의 범위를 나누어 읽어야 한다.[1]

## 웹 화면과 모델 입력 사이

브라우저에서 읽기 쉬운 페이지에도 메뉴·광고·바닥글이 섞여 있다.
모델에게 페이지를 전달하거나 검색 자료로 저장하려면 핵심 본문과 링크, 표 같은 구조를 보존하면서 불필요한 반복을 줄일 필요가 있다.
Crawl4AI는 브라우저로 동적 페이지를 처리하고 Markdown을 만들며, 필요한 경우 원하는 필드만 JSON으로 추출하는 기능을 제공한다.[1]

RAG는 검색한 외부 자료를 모델 답변의 근거로 붙이는 방식이다.
“LLM-ready Markdown”은 이런 후속 작업에 전달하기 좋은 입력 형식을 가리키지, 페이지의 주장이나 최신성을 자동 검증했다는 뜻이 아니다.
수집 시각·원문 URL·내용 누락 여부는 후속 자료 관리에서도 남겨야 한다.[1]

## 가져오기·거르기·필드 추출을 나누기

기본 Python 예의 `AsyncWebCrawler`는 브라우저 수집을 맡고 `CrawlerRunConfig`는 한 번의 수집에서 적용할 설정을 담는다.
비동기 처리는 페이지를 기다리는 동안 다른 작업도 진행할 수 있게 하는 방식이며, 많은 URL의 동시 처리는 별도 `arun_many` 경로로 소개된다.
동시 실행 가능성이 대상 사이트에 과도한 요청을 보낼 권한을 의미하지 않는다.[1]

Markdown의 raw 버전과 fit 버전은 목적이 다르다. `PruningContentFilterLXML` 같은 필터는 메뉴·반복 내용을 줄이는 데 쓰고, BM25는 검색어에 관련된 내용을 고르는 데 사용된다.
짧아진 결과가 항상 더 완전한 결과는 아니므로 중요한 조건이나 각주까지 제거되지 않았는지 원문과 비교해야 한다.[1]

구조가 일정한 페이지라면 CSS·XPath 스키마로 모델 없이 필드를 가져올 수 있다.
CSS 선택자는 HTML에서 원하는 요소를 지정하는 규칙이다.
반면 자연어 지시와 JSON 스키마를 함께 쓰는 `LLMExtractionStrategy`는 모델 제공자 호출을 포함한다.
같은 “추출”이라도 비용, 데이터 전송과 오류 성격이 다르다.[1]

## 예시로 따라가는 흐름

README의 공식 예는 스크롤할수록 인용문이 추가되는 `quotes.toscrape.com/scroll`에서 문장·저자·태그를 가져온다.
이 글은 예제를 읽었으며 수집을 직접 실행하지 않았다.
입력에는 URL과 `div.quote`라는 반복 단위, 그 안의 `span.text`, `small.author`, `a.tag`에 대응하는 필드 정의가 있다.
원하는 데이터의 구조를 먼저 적고 그 규칙에 맞는 HTML 내용을 가져오는 방식이다.[1]

브라우저가 페이지를 연 뒤 `scan_full_page`와 스크롤 대기 설정으로 아래쪽 자료가 나타나도록 하고, `JsonCssExtractionStrategy`가 각 반복 요소를 문장·저자·태그 목록으로 변환한다.
결과는 `extracted_content`에서 JSON으로 읽는 구조다.
여기서는 인용문 개수나 실제 반환 데이터를 만들어 제시하지 않는다.
예제의 캐시 우회 설정은 저장된 예전 결과 대신 새 페이지를 요청하는 선택이며 모든 상황의 기본 요구는 아니다.[1]

사람은 페이지 끝까지 실제로 로딩되었는지, 같은 인용문이 중복되지 않았는지, 저자가 빈 값인 항목이 없는지 확인해야 한다.
화면의 HTML 클래스가 바뀌면 선택자가 맞지 않을 수 있고, 페이지 방문 성공과 필드 추출 성공은 별개의 문제다.
LLM을 쓰지 않는다는 점은 모델 호출 비용을 줄이는 설계 특성이지만 원문 구조 변화까지 자동으로 해결한다는 의미는 아니다.[1]

## 오래 도는 수집은 상태도 산출물이다

대표 추가 파일 `deep_crawl_crash_recovery.py`는 여러 페이지를 따라가는 작업의 중단·재개를 보여 준다.
BFS는 시작 페이지에서 가까운 링크부터 너비 우선으로 방문하는 전략이다.
예제는 최대 깊이와 페이지 수를 제한하고 각 URL 처리 뒤 `on_state_change`로 상태를 저장한다.
저장에는 방문한 URL, 대기 항목, 깊이와 처리 수 같은 필드가 포함된다.[2]

재개 경로는 파일에서 읽은 상태를 `resume_state`로 다음 전략에 전달한다.
이는 어디까지 방문했는지의 복구 예이지 이전에 추출한 모든 문서 본문을 영구 보관하는 완성된 데이터 파이프라인은 아니다.
실제 자료 저장, 실패 URL 관리와 재수집 정책은 별도로 설계해야 한다.[2]

예제의 중복 확인 메시지도 엄격한 독립 검증으로 확대할 수 없다.
구현은 재개 단계의 목록을 이미 방문한 URL 집합을 뺀 새 URL로 만든 뒤 이전 집합과 교집합을 비교한다.
따라서 출력상 중복이 없다는 메시지만으로 실제 네트워크 요청이 한 번씩만 일어났음을 입증하지는 않는다.
공식 예제도 어떤 상태를 측정하는지 읽어야 하는 사례다.[2]

## 수집할 수 있음과 수집해도 됨

라이브러리·자체 서버는 사용자가 브라우저 자원과 세션·프록시를 관리하고, Cloud는 별도 키와 사용량 과금으로 제공된다.
README의 웹 검색·직접 답변 API는 Cloud 항목에 있으므로 이를 모두 로컬 라이브러리 기능으로 옮겨 적지 않는다.
외부 모델 추출과 클라우드 이용에는 전달할 자료와 제공자 조건을 확인해야 한다.[1]

로그인이 저장된 브라우저 프로필은 쿠키·세션 같은 민감한 정보를 가진다.
접근 가능한 페이지라도 수집·재배포 권리가 자동으로 생기지 않으며 사이트 약관, robots 정책, 요청 빈도와 개인정보를 고려해야 한다.
차단을 만났을 때 이 글은 접근 통제나 CAPTCHA 우회 절차를 제공하지 않는다.[1]

현재 Docker 안내는 API 토큰이 필요하고 토큰이 없으면 컨테이너 내부에서만 응답한다고 설명한다.
그러나 자신의 설정과 공개 포트·저장 디렉터리의 보호까지 대신 확인해 주지는 않는다.
라이선스는 Apache 2.0으로 안내되며 README의 별도 출처 표기 절도 재사용 전에 함께 읽을 필요가 있다.[1]

## 정리

Crawl4AI는 웹 화면을 후속 분석에 쓸 자료로 바꾸는 기반이다.
수집 성공, 내용 완전성, 추출 정확성과 이용 권한은 각각 확인해야 하며 상태 복구 예제도 완성된 자료 보관 체계를 대신하지 않는다.
