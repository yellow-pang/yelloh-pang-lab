## 한 줄 요약

last30days-skill은 최근의 공개 논의와 자료를 여러 플랫폼에서 모아 AI가 근거 있는 브리프로 정리하도록 만드는 조사용 Skill과 스크립트 모음이다.
하나의 검색 사이트나 새 언어 모델이 아니라, 에이전트가 주제를 해석하고 검색 엔진을 실행한 뒤 자료를 묶어 설명하는 작업 흐름이다.
README는 실행 규약의 기준 문서로 `skills/last30days/SKILL.md`를 지정한다.[1]

## 최근 정보를 찾는 질문은 한 종류가 아니다

어떤 도구의 최근 변화를 알고 싶은 경우, 공식 발표만으로는 사용자가 어디서 어려움을 겪는지 알기 어렵다.
반대로 커뮤니티 게시물만 보면 인기 있는 불만과 실제 기능 변경이 섞일 수 있다.
이 프로젝트는 Reddit, X, YouTube, Hacker News, GitHub와 웹 등 성격이 다른 자료를 모아 관련성·신선도·반응을 함께 살피는 흐름을 제시한다.[1]

여기서 ‘최근 30일’은 요청의 시간 범위이며 모든 플랫폼이 동일한 과거 범위를 제공한다는 보장이 아니다.
README에는 X의 특정 공식 API 경로가 계정 권한에 따라 최근 일주일 정도의 검색에 제한될 수 있다고 적혀 있다.
이름만 보고 전체 30일을 빠짐없이 검색했다고 받아들이면, 자료가 없었던 것과 접근할 수 없었던 것을 혼동하게 된다.[1]

## 주제 해석, 병렬 수집, 이야기별 묶음

공식 흐름은 주제를 받은 뒤 관련 계정, 저장소, 커뮤니티 등을 먼저 확인하는 데서 시작한다.
제품 이름과 일반 명사가 겹치거나 사람 이름이 여럿에게 쓰이는 경우에는 검색어를 그대로 반복하기보다 대상을 좁혀야 한다.
Skill에는 사용자 의도 해석과 사전 검색 계획, 대상별 식별자를 확인하는 절차가 별도로 나뉘어 있다.[1][2]

그 다음 여러 소스를 병렬로 검색하고 게시물의 반응, 관련성, 시점을 고려한다.
동일한 사건이 다른 플랫폼에서 반복되면 플랫폼별 목록으로만 보여 주지 않고 이야기나 주제 단위의 cluster로 묶는다.
Cluster는 같은 서사를 가리키는 자료들의 묶음이다.
다만 여러 URL이 있다는 사실과 독립된 증거가 여러 개라는 판단은 같지 않으므로 종합 단계에서 출처 성격을 살펴야 한다.[1][2]

출력은 화면의 짧은 답뿐 아니라 로컬 연구 파일로 남길 수 있다.
README는 저장 위치 조정, 구조화된 JSON 출력, 이전 연구 검색, 감시 목록과 브리핑을 구분한다.
기본 스냅샷 생성과 지속적 모니터링은 다른 동작이다.
기록을 보관한다는 설명을 자동으로 주기 실행하거나 외부로 게시한다는 의미로 확대해서는 안 된다.[1]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
‘공개 코딩 도구의 최근 사용자 불편과 업데이트를 정리해 달라’는 요청을 생각해 보자.
에이전트는 먼저 정확한 제품과 공식 저장소, 관련 커뮤니티를 확인한다.
검색 계획은 업데이트 발표와 사용 경험을 구분해 확장하고, 사용할 수 있는 플랫폼만 대상으로 수집한다.
YouTube 자막이나 게시물 댓글이 확보되면 제목만 보고 결론을 내리는 대신 실제 내용과 날짜, 반응 정보를 함께 읽는 것이 README가 설명하는 흐름이다.[1][2]

검색 후에는 같은 업데이트에 대한 발표와 논의를 한 묶음으로 모으고, 특정 플랫폼에서만 발견된 주장에는 그 불확실성을 남겨야 한다.
결과가 적은 소스는 실제 논의가 적은 것인지 인증·도구 조건이 충족되지 않은 것인지 구분한다.
대표 Skill은 외부 웹 검색 보충 자료도 저장된 연구 원문에 덧붙여 나중에 어떤 자료가 종합에 영향을 주었는지 추적하도록 요구한다.
사람은 최종 요약의 링크와 원문, 기간, 자료 범위를 확인해야 한다.
여기에는 실제 조사 없이 만든 최신 게시물, 좋아요 수, 업데이트 사실을 채워 넣지 않는다.[2]

이 흐름에서 인기 지표는 사람들이 무엇에 반응했는지 보여 주는 단서다.
추천 수가 많다고 기술적 주장이 참이 되는 것은 아니고, 예측 시장의 값도 확정된 미래 사건을 뜻하지 않는다.
README의 홍보 표현과 실제 자료가 지지하는 결론을 나누어 읽는 것이 필요하다.[1]

## 외부 접근과 로컬 저장의 경계

플랫폼별 조건은 서로 다르다.
일부 공개 소스는 별도 키 없이 사용할 수 있지만 다른 소스는 API 키, 설치된 CLI나 로그인 세션이 필요하다.
Skill의 보안 설명은 여러 API에 검색어를 보내며, 브라우저 쿠키는 명시적 설정이나 동의가 있을 때만 접근한다고 밝힌다.
도구 설치가 곧 계정 세션 사용 허가라고 해석해서는 안 된다.[1][2]

또한 첫 실행 설정은 필요한 도구를 설치하는 경로를 포함할 수 있다.
읽기만 하려는 조사와 실제 Skill 호출은 부수 효과가 다르므로, 설정과 스크립트를 먼저 살펴야 한다.
Skill은 플랫폼에 글을 게시하거나 좋아요를 누르는 도구가 아니라고 설명하지만, 연구 라이브러리의 호스팅 공개는 별도 명시적 선택 기능으로 존재한다.
공개 기본값을 이해하지 않은 채 연구 파일을 게시하지 않도록 구별해야 한다.[2]

README의 기능 소개와 버전 설명, 매우 긴 Skill 문서는 서로 다른 부분에서 조건을 반복한다.
이 글에서는 모든 플랫폼의 현재 접근 가능성을 시험하지 않았고, 광고성 비교 문구를 다른 검색 서비스의 실제 한계로 재인용하지 않는다.
실제 사용 시에는 소스별 진단과 오류, 수집 범위를 결과의 일부로 남기는 편이 누락을 숨기지 않는다.[1][2]
