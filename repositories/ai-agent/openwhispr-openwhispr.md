## 한 줄 요약

OpenWhispr는 말한 내용을 글로 바꾸어 현재 커서 위치에 입력하는 데스크톱 음성 앱이다.
받아쓰기뿐 아니라 음성 비서, 회의 전사와 노트 관리까지 연결하지만, 음성 인식 모델 자체를 새로 만드는 저장소는 아니다.
로컬 모델과 클라우드 제공자를 골라 음성 입력을 처리하는 사용자 애플리케이션에 가깝다.[1]

## 녹음 파일을 옮기지 않고 글을 쓰려면

메모를 말로 남긴 뒤 녹음 파일을 따로 열어 전사하고, 결과를 복사해 원래 앱으로 돌아오는 과정은 여러 단계를 요구한다.
OpenWhispr의 기본 사용 흐름은 전역 단축키를 누르고 말하면 현재 입력 위치에 글이 나타나는 방식이다.
전역 단축키는 앱 화면을 앞으로 가져오지 않아도 사용하는 키 조합이며, 자동 붙여넣기가 음성 인식 결과와 실제 작성 중인 문서를 연결한다.[1]

이 과정에서 받아쓰기와 명령 전달을 구별할 필요가 있다.
README의 Voice Assistant 단축키는 말한 내용을 비서 명령으로 보내며, 선택된 텍스트가 있으면 그 자리에서 편집하는 경로를 설명한다.
일반 전사와 달리 문장을 해석해 답하거나 바꾸는 단계가 포함될 수 있다.
말한 그대로 적는 기능과 AI가 다듬어 만든 결과를 같은 출력으로 취급하면 원문 확인이 어려워진다.[1]

## 음성 인식 위치를 선택하는 구조

로컬 전사는 기기 안의 음성 인식 모델로 음성을 글로 바꾸는 방식이다.
README는 Whisper, Parakeet 등의 선택지를 소개하며 오프라인 처리 경로에서는 오디오가 기기를 떠나지 않는다고 설명한다.
클라우드를 선택하면 외부 처리 경로가 사용된다.
BYOK는 사용자가 자신의 API 키를 넣는 방식을 뜻하며, 무료로 공개된 앱이라는 사실과 외부 API 비용은 별개다.[1]

대표 구현인 `transcriptionRoute.ts`는 받아쓰기·재시도·파일 업로드의 일괄 전사 경로를 공통으로 결정한다.
설정을 받아 로컬 처리, 중계 처리, HTTP 일괄 요청 또는 오류 같은 결과를 돌려준다.
실제 음성을 전사하는 모델 코드가 아니라 어느 처리기로 보내야 하는지를 정하는 파일이다.
실시간 스트리밍 제공자 선택은 다른 녹음 구성요소에 남겨 두었다는 주석도 있어 범위를 분명히 한다.[2]

이 파일은 단지 모델 이름만 고르지 않는다.
자체 호스팅 주소가 유효한지, 사용자가 선택한 제공자가 파일 업로드를 지원하는지, 필요한 인증 방식이 무엇인지도 구분한다.
반환되는 경로에는 비밀 키 값 대신 `auth.keyRef`라는 키 보관 위치의 참조를 넣고, 실제 실행기가 키를 찾아 쓰도록 작성되어 있다.
주소 결정과 비밀정보 접근의 책임을 나눈 것이다.[2]

회의 전사와 노트는 그 위에 놓인 별도 사용 흐름이다.
화자 분리란 한 녹음 안에서 누가 말한 구간인지를 구별하는 일이며, 전사 문장의 정확성과 같은 문제는 아니다.
README는 기기 내 화자 라벨링과 음성 지문, 노트 검색과 선택적 동기화 등을 소개한다.
단순한 한 문장 받아쓰기보다 데이터 보관과 공유 설정을 함께 살펴야 하는 기능들이다.[1]

## 예시로 따라가는 흐름

개인 독서 메모를 작성하던 중 짧은 생각을 말로 넣는 상황을 가정해 보자.
이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
커서가 메모 입력란에 있는 상태에서 받아쓰기 단축키로 음성을 입력하면 선택한 전사 경로가 오디오를 텍스트로 바꾸고, 앱은 결과를 그 위치에 붙여넣는 흐름을 제공한다.
사람은 인명이나 책 제목처럼 틀리기 쉬운 표현, 문장부호와 현재 입력 위치를 먼저 확인해야 한다.[1]

이때 일괄 처리 설정이 로컬 엔진을 사용하도록 해석되면 대표 라우터는 `transport: local`을 반환한다.
반면 self-hosted 모드에서는 저장된 서버 주소를 정규화하고 유효성을 확인한 뒤 HTTP 경로를 만든다.
주소가 빠졌거나 지원하지 않는 형태이면 오류를 돌려주는 분기도 있다.
로컬로 생각하고 녹음했는데 설정 때문에 외부로 가는 상황을 막으려면 화면의 모델 이름만이 아니라 처리 모드와 목적지를 확인하는 것이 중요하다.[2]

이미 녹음한 파일을 다시 전사하려는 경우에는 제공자별 지원 범위가 더 직접적으로 드러난다.
소스는 Deepgram과 AssemblyAI를 해당 경로의 실시간 전용 제공자로 분류하고, 파일 업로드·재시도 요청에서는 오류로 멈추도록 한다.
주석은 그렇지 않으면 기본 제공자로 잘못 넘어가 오디오가 의도하지 않은 곳에 전송될 수 있음을 설명한다.
따라서 이 사례의 정상 결과는 언제나 텍스트 한 장이 아니라, 지원하지 않는 조합에서 명확히 중단하는 상태일 수도 있다.
실제 파일 업로드나 전사 정확도 측정은 수행하지 않았다.[2]

## 개인정보 문구는 선택한 경로와 함께 읽는다

README의 오프라인 개인정보 설명은 로컬 처리 경로에 관한 것이다.
같은 README에 클라우드 처리, 노트 동기화, 웹 공유, 선택적 화면 캡처 전달도 등장한다.
따라서 앱을 설치했다는 이유만으로 모든 기능이 오프라인이라고 단정하지 말아야 한다.
전사와 AI 후처리, 노트 공유는 각각 어떤 자료를 어디로 보내는지 다른 질문이 된다.[1]

플랫폼 제한도 있다.
README는 Intel Mac에서 의존 런타임 문제로 실시간 화자 식별과 음성 지문을 사용할 수 없으며, 노트 검색은 의미 검색 대신 키워드 검색으로 대체된다고 적는다.
회의 녹음과 전사는 계속 가능하다는 설명도 있어, 특정 기능 제한을 앱 전체 미지원으로 확대하지 않는 것이 중요하다.[1]

회의나 타인의 음성이 포함된 파일에는 당사자의 동의와 공개 범위 확인이 필요하다.
로컬 처리도 잘못 공유한 노트까지 막아주는 것은 아니다.
한편 라우터에서 오류 차단 조건을 확인했다고 전체 프로그램의 비밀정보 관리나 네트워크 전송이 안전하다고 인증할 수는 없다.
이번에 확인한 것은 한 경로 결정 모듈과 공식 기능 설명이다.

## 정리

OpenWhispr는 음성을 작성 중인 텍스트와 연결하고, 필요하면 비서·회의·노트 기능으로 확장한다.
핵심 선택은 모델 이름뿐 아니라 처리 위치와 사용 흐름이며, 전사 결과의 정확성과 자료 공유 범위는 사람이 확인해야 한다.
