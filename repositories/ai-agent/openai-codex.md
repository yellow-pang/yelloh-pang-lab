## 대답을 넘어 작업 폴더에 손을 대는 도구

Codex CLI는 사용자 컴퓨터에서 실행되는 OpenAI의 코딩 에이전트다.
여기서 에이전트란 질문에 답하는 데서 끝나지 않고, 주어진 작업을 위해 파일을 읽고 수정하거나 명령을 실행하는 프로그램을 뜻한다.
이 저장소의 README는 로컬 CLI와 코드 편집기 연동, 데스크톱 앱, 클라우드에서 동작하는 Codex Web을 구분한다.
따라서 `openai/codex`를 AI 모델의 학습 데이터나 모델 자체를 내려받는 저장소로 이해하면 실제 사용 방식과 어긋난다.[1][2]

작은 프로그램에서 오류를 고칠 때도 해야 할 일은 여러 가지다.
오류와 관련된 파일을 찾고, 기존 코드의 의도를 읽고, 수정한 다음 문제가 사라졌는지 확인해야 한다.
웹 채팅에 코드를 붙여 넣는 방식에서는 이 연결 작업을 사람이 반복한다.
Codex CLI는 작업 디렉터리에서 파일 읽기·편집·명령 실행을 이어 갈 수 있게 하지만, 허용되는 행동은 샌드박스와 승인 설정에 따라 달라진다.[2]

## 코드 변경과 권한을 나누어 이해하기

### 파일 변경은 설명문이 아니라 실제 작업이다

저장소에는 `apply-patch`라는 파일 편집 구성 요소가 있다.
패치(patch)는 파일 전체를 다시 설명하는 대신 어느 부분을 지우고 무엇을 넣을지 적은 변경 지시다.
해당 구현은 파일 추가·삭제·수정을 서로 다른 변경으로 다루며, 수정에는 변경 전후의 차이와 새 내용이 포함된다.
즉, “이렇게 고치세요”라는 문장과 디스크의 파일을 바꾸는 동작이 분리되어 있다.[3]

함께 수록된 `gpt_5_codex_prompt.md`에는 단일 파일 편집에 `apply_patch`를 우선 고려하고, 사용자가 이미 수정한 내용을 임의로 되돌리지 말라는 지침이 있다.
이는 저장소에 포함된 특정 모델용 지침의 예이며, 모든 모델과 버전에서 같은 문장이 적용된다는 뜻은 아니다.
파일을 바꿀 수 있는 도구와 기존 작업을 보호하기 위한 행동 지침을 함께 제공한다는 점을 읽을 수 있다.[4]

### 샌드박스와 승인은 서로 다른 질문에 답한다

샌드박스(sandbox)는 프로그램이 접근하거나 변경할 수 있는 범위를 기술적으로 제한하는 장치다.
반면 승인 정책은 어떤 행동 전에 사용자에게 물을지 정한다.
공식 문서는 이 둘을 별개의 통제로 설명한다.
작업 폴더 안의 편집을 허용하면서 폴더 밖 수정에는 승인을 요구하는 식으로 조합할 수 있다.[2]

예를 들어 `workspace-write`와 `on-request`를 사용하는 Auto 설정에서는 작업 영역 안의 읽기·편집·명령 실행이 자동으로 진행될 수 있다.
읽기와 계획만 필요하면 `read-only` 모드를 선택할 수 있다.
승인 창이 없다는 이유만으로 “파일을 바꿀 수 없다”거나 “아무 제한이 없다”고 판단해서는 안 된다.
실제로 무엇이 허용되는지는 승인 정책과 샌드박스를 함께 봐야 한다.[2]

### 로컬 실행과 오프라인 AI는 같은 말이 아니다

README는 ChatGPT 계정으로 로그인하는 방법과 API 키를 사용하는 방법을 안내한다.
보안 문서도 로컬 명령의 네트워크 제어와 클라이언트의 모델·인증 요청을 구분한다.
따라서 “내 컴퓨터에서 실행된다”는 설명을 모든 추론과 데이터 처리가 컴퓨터 안에서 끝난다는 보장으로 읽으면 안 된다.
코드에 민감한 내용이 있다면 사용하는 계정과 서비스의 데이터 처리 조건을 별도로 확인해야 한다.[1][2]

## 예시로 따라가는 흐름

파일 수정이 무엇을 뜻하는지 가장 작은 실제 사례로 보자.
`apply-patch/src/lib.rs`의 `test_update_file_hunk_modifies_content` 테스트에는 `update.txt`의 두 번째 줄을 바꾸는 예가 있다.
아래는 공식 테스트 코드를 읽어 설명한 흐름이며, 이 조사에서 테스트를 직접 실행한 결과는 아니다.[3]

입력 파일은 첫째 줄이 `foo`, 둘째 줄이 `bar`인 텍스트다.
테스트는 `foo`는 유지하고 `bar`를 제거한 뒤 `baz`를 넣는 패치를 구성한다.
패치에서 `-`로 시작하는 줄은 지울 내용, `+`로 시작하는 줄은 새로 넣을 내용이다.
주변의 변하지 않는 줄은 어느 부분을 수정하려는지 알려 주는 문맥이 된다.[3]

이 패치를 `apply_patch` 함수에 넘긴 뒤 테스트는 두 종류의 결과를 확인한다.
하나는 변경된 파일을 알리는 출력과 오류 출력이고, 다른 하나는 파일을 다시 읽은 실제 내용이다.
기대하는 내용은 `foo`와 `baz` 두 줄이다.
“수정했다는 메시지가 나왔다”와 “원하는 내용으로 바뀌었다”를 따로 검사하도록 작성되어 있다는 점이 중요하다.[3]

사용자가 맡기는 오류 수정도 이런 작은 변경들의 조합으로 생각할 수 있다.
다만 위 테스트는 **이미 정해진 패치를 적용하는 기능**의 예이지, AI가 올바른 수정안을 찾아내는 능력을 검증한 시험은 아니다.
텍스트 교체가 정확하더라도 프로그램의 논리가 옳아졌는지는 별도의 문제다.
공식 보안 문서 역시 결과를 다른 코드 변경 제안처럼 다루고, 변경 차이를 검토하고 필요한 검증을 수행하도록 권한다.[3][2]

사람이 마지막으로 볼 것은 “에이전트가 완료라고 말했는가”보다 “어떤 파일이 왜 바뀌었는가”다.
원래 문제를 고치는 데 필요한 변경인지, 다른 기능을 깨뜨리지 않았는지, 시험하지 못한 부분은 무엇인지가 검토 대상이다.
이 관점은 설명을 잘하는 도구와 검증된 결과물을 같은 것으로 취급하지 않게 해 준다.

## 어디까지 맡기고 무엇을 남겨 두어야 하나

Codex CLI에 작업을 맡기기 전에는 편집할 디렉터리와 허용할 명령 범위를 먼저 정하는 편이 좋다.
공식 문서는 버전 관리된 작업을 이용해 변경을 분리하고 되돌릴 수 있도록 준비하라고 안내한다.
또한 샌드박스와 승인을 모두 우회하는 설정은 권장하지 않는다.
테스트나 빌드를 실행할 수 있다는 것은 프로젝트에 포함된 스크립트도 실제로 작동할 수 있다는 뜻이므로, 낯선 코드에는 특히 범위 제한이 필요하다.[2]

외부 웹 자료를 읽게 할 때는 프롬프트 인젝션도 고려해야 한다.
이는 문서 속 악의적인 문장을 에이전트가 작업 지시로 잘못 받아들이는 문제다.
공식 문서는 웹 검색 결과를 신뢰할 수 없는 입력으로 취급하라고 설명한다.
샌드박스는 피해 범위를 줄이는 수단이지, 결과의 정확성과 모든 외부 입력의 안전성을 보증하는 장치는 아니다.[2]

사용 조건도 소스 공개와 구분해야 한다.
README의 Apache-2.0 라이선스 안내는 저장소 코드에 관한 것이며, 모델 사용이 무제한 무료라는 뜻은 아니다.
ChatGPT 플랜을 통한 이용과 API 키를 통한 이용은 별도 안내를 따른다.
이 원고에서는 특정 플랜의 사용량이나 가격을 확인하지 않았으므로 수치로 비교하지 않는다.[1]

## 정리

Codex CLI의 핵심은 AI의 제안을 작업 폴더의 읽기·수정·명령 실행으로 연결하는 데 있다.
패치를 적용하는 기능, 행동을 제한하는 권한, 수정 결과를 받아들일지 판단하는 검토는 서로 다른 역할이다.
권한을 넓히는 것과 코드의 정확성을 높이는 것을 같은 일로 보지 않는 것이 이 도구를 이해하는 출발점이다.[3][2]
