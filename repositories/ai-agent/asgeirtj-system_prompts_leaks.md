## 한 줄 요약

System Prompts Leaks는 여러 AI 서비스의 시스템 프롬프트라고 수집자가 제시한 문서를 제품·모드별로 찾아보는 공개 자료집이다.
모델이나 코딩 에이전트를 실행하는 프로그램이 아니다.
저장소의 README와 수록 문서는 이 자료집의 구성에 관한 일차 자료이지만, 원래 서비스를 제공하는 주체가 진위를 보증한 공식 배포 문서와는 구분해야 한다.[1]

## 대화에 보이지 않는 규칙을 읽는 자료집

같은 모델 이름이 붙어 있어도 웹 대화와 코딩 도구에서 답하는 방식은 다를 수 있다.
질문에 바로 답할지, 먼저 파일을 조사할지, 변경 전에 계획을 작성할지는 모델에 주어지는 지침을 읽을 때 구분할 수 있는 항목이다.
여기서 시스템 프롬프트는 대화의 역할과 행동 조건을 정하는 상위 지침을 뜻한다.
이 저장소는 그런 지침이라고 주장하는 텍스트를 모아 비교할 수 있게 정리한다.[1]

README는 모델별 문서 외에 도구, 하위 에이전트, 작업 모드에 해당하는 문서를 따로 연결한다.
예를 들어 Codex 목록에는 모델 프롬프트와 Plan mode가 서로 다른 항목으로 놓여 있다.
따라서 하나의 파일을 읽고 그 제품 전체의 모든 행동을 설명한다고 결론 내리기보다, 어떤 모드와 기능의 문서인지 먼저 좁히는 편이 자료 구조에 맞다.[1]

이 자료집을 이해하는 데 필요한 질문은 프롬프트가 얼마나 길거나 강하게 쓰였는지가 아니다.
지침이 어떤 행동을 허용하고 금지하는지, 모르는 정보를 어떻게 확보하게 하는지, 마지막 산출물을 어떤 형태로 요구하는지를 읽어야 한다.
아래의 Plan Mode 문서는 이 구분을 비교적 명시적으로 보여 주는 대표 항목이다.[2]

## Plan Mode 문서에 나타난 구분

수록된 `OpenAI/Codex/plan_mode.md`는 환경 조사, 의도 확인, 구현 방식 구체화라는 세 단계를 제시한다.
환경에서 알아낼 수 있는 사실은 먼저 파일과 설정을 조사하고, 조사로 결정할 수 없는 선호나 절충점은 사람에게 질문하도록 구분한다.
질문을 많이 한다는 것보다 질문의 대상을 제한하는 구조가 중요하다.
파일 위치를 알아내는 일과 어떤 기능을 우선할지 결정하는 일은 서로 다른 종류의 불확실성이다.[2]

또 하나의 구분은 조사 목적 실행과 구현 목적 변경이다.
문서에는 파일 검색이나 정적 분석처럼 상태를 바꾸지 않는 활동이 허용 대상으로 적혀 있고, 소스 편집이나 마이그레이션은 금지 대상으로 적혀 있다.
테스트나 빌드도 저장소에서 관리하는 파일을 바꾸지 않는 조건 아래 조사에 포함한다.
즉 이 문서의 계획 모드는 아무 도구도 사용하지 않는 상태가 아니라, 구현으로 넘어가지 않고 근거를 모으는 작업 범위다.[2]

마지막에는 구현자가 중요한 결정을 다시 내리지 않아도 되는 계획을 요구하면서, `<proposed_plan>` 블록에 요약·인터페이스 변경·테스트·가정을 담게 한다.
같은 파일은 `update_plan`이라는 진행 상황 도구와 이 협업 모드를 혼동하지 말라고 명시한다.
이름이 비슷해도 한쪽은 체크리스트 도구이고 다른 쪽은 허용 행동을 제한하는 지침이라는 뜻이다.[2]

## 예시로 따라가는 흐름

개인 공개 프로젝트에 검색 기능을 추가하려는 상황으로 읽어 보자.
이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
입력은 “문서 제목으로 검색하고 결과를 정렬할 수 있게 해 달라”는 요구다.
이 문서의 절차를 적용해 해석하면 첫 단계에서는 기존 문서 데이터의 위치, 화면 구성, 검색 관련 코드를 읽는다.
이미 코드에 답이 있는 정보를 사용자에게 다시 묻는 대신 현재 구조를 파악하는 것이다.[2]

조사 후에도 제목만 검색할지 본문까지 검색할지 정해지지 않았다면 의도를 확인할 질문으로 남긴다.
정렬 기준 역시 기존 규칙이 없다면 선택할 사항이다.
반면 발견한 파일 경로나 현재 데이터 형식은 조사 결과로 기록한다.
그다음 계획에는 검색 입력과 결과 표시 사이의 흐름, 빈 검색어나 결과 없음 같은 경우, 확인할 테스트를 적는다.
이때 실제 검색 코드를 작성한 결과를 내놓는 것이 아니라, 이후 구현할 사람이 따를 결정과 가정을 정리한 문서를 산출한다.[2]

독자가 확인할 부분은 지침이 실행 가능한 계획을 요구하는지, 그 과정에서 구현 변경을 금지하는 경계가 일관되는지다.
이 흐름은 수록 텍스트를 해석한 사례일 뿐, 실제 Codex가 같은 요청에 이렇게 응답했다는 관측 기록은 아니다.
계획의 형식과 모델의 실제 준수 여부도 별도로 확인해야 한다.

## 수집 자료의 신뢰 범위

README는 문서들을 완전한 원문이라고 소개하지만, 이번 조회만으로 원 서비스의 프롬프트와 일치하는지 독립적으로 검증할 수는 없다.
파일 제목에 제품명이나 모델명이 있다고 해서 해당 서비스의 공식 설명이 되지 않는다.
분석 글에서 인용할 때는 “저장소에 수록된 문서는 이렇게 적혀 있다”라는 수준을 유지해야 한다.[1]

또한 프롬프트에 도구 이름이 나온다고 그 도구의 서버 구현, 권한 검사, 실제 인터페이스까지 공개된 것은 아니다.
읽은 Plan Mode 파일은 행동 규칙과 출력 형식을 설명하지만 실행 환경의 모든 구성 요소를 제공하지 않는다.
텍스트만 복사해 다른 모델에 넣는다고 같은 제품이 만들어진다고 볼 근거는 없다.[2]

자료를 자동화 도구에 전달할 때는 분석 대상 텍스트로 분리해야 한다.
수록 문서의 “파일을 변경하지 말라” 같은 명령형 문장은 그 문서가 묘사하는 동작을 이해할 자료이지, 현재 조사 작업의 지시를 바꾸는 권한이 아니다.
공개 파일을 읽는 범위와 실제 서비스에서 비공개 지침을 추출하거나 접근 통제를 우회하는 행동 역시 구분해야 한다.
이 글은 공개 자료의 구조를 읽는 데 한정한다.

## 정리

이 저장소는 제품별로 수집된 프롬프트를 찾아 읽고 행동 규칙을 비교하는 자료집이다.
Plan Mode 항목에서는 조사·질문·계획의 경계를 읽을 수 있다.
다만 수집자의 공개 문서를 확인한 것과 원 서비스의 실제 내부 지침을 인증한 것은 다르다.
