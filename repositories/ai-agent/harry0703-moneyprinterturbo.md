## 주제를 짧은 영상으로 조립하는 작업 흐름

MoneyPrinterTurbo는 주제나 키워드를 받아 대본, 음성, 영상 소재, 자막, 배경음악을 연결해 짧은 영상을 만드는 프로그램이다.
하나의 동영상 생성 모델을 공개한 저장소가 아니라 여러 모델 서비스와 편집 단계를 묶은 자동화 도구다.
README는 AI Agent, 웹 화면, API, CLI를 이용하는 진입로와 각 단계에 사용자가 준비한 내용을 넣는 방법을 소개한다.[1]

짧은 설명 영상을 만들 때도 원고 작성과 녹음, 장면 찾기, 화면 비율 맞추기, 자막 시간 조정은 서로 다른 일이다.
MoneyPrinterTurbo는 이 작업들을 하나의 처리 흐름으로 잇는다.
텍스트를 생성한 다음 무조건 그 글을 화면에 띄우는 것이 아니라, 대본으로부터 소재 검색어를 만들고 음성 길이와 자막을 준비한 뒤 장면을 합친다는 점이 전체 목적을 이해하는 열쇠다.[1][2]

## 대본·소재·음성은 교체할 수 있는 단계다

대본에는 외부 언어 모델을 이용하거나 직접 작성한 글을 넣을 수 있다.
소재 역시 준비된 로컬 이미지·영상, 온라인 스톡 영상, 외부 생성 서비스 등 여러 경로를 갖는다.
같은 대본을 사용하더라도 어떤 소재 경로를 선택했는지에 따라 요구되는 키와 비용, 실제 화면의 성격이 달라진다.
README의 지원 목록은 하나의 서비스가 모든 결과를 공급한다는 뜻이 아니다.[1]

음성 합성은 글을 소리로 읽어 주는 기능이다.
README에는 자동 음성, 업로드한 음성, 음성 없는 방식이 소개되어 있다.
자막은 TTS의 시간 정보를 쓰는 기본 경로와 로컬 `faster-whisper`로 음성을 전사하는 경로가 구분된다.
두 경로를 알아야 자막 문제가 대본 내용 때문인지, 읽기 속도나 시간 정보 때문인지 나누어 볼 수 있다.
글꼴·위치·색상과 배경음악 음량은 마지막 표현을 조정하는 요소다.[1]

대표 구현인 `app/services/task.py`에서는 `_run_pipeline`이 흐름을 관리한다.
공급자 키와 FFmpeg 사용 가능 여부 등을 먼저 확인한 다음 대본, 검색어, 음성, 자막, 소재, 완성 영상으로 진행한다.
FFmpeg는 오디오와 비디오 파일을 처리하는 프로그램이다.
대본과 검색어 단계만 요청할 때는 해당 검사에서 제외하지만 음성·영상 처리를 하려면 필요하다는 분기가 코드에 보인다.[2]

## 중간 결과와 실패 위치를 따로 남긴다

이 구현에는 `stop_at`으로 대본이나 음성 같은 중간 단계에서 끝내는 분기가 있다.
최종 영상만 받는 것과 중간 산출물을 받는 것은 같은 작업이 아니다.
예를 들어 대본 생성이 잘못되었을 때 모든 소재를 다시 내려받기 전에 원고를 먼저 검토할 수 있는 구조다.
각 단계에서는 진행 상태를 갱신하고 결과가 없으면 해당 단계의 실패로 기록한다.[2]

영상 생성과 외부 플랫폼 게시도 구별된다.
코드는 완성 영상 상태를 먼저 기록한 뒤, 게시 서비스가 설정되고 자동 업로드가 켜져 있으며 대상 플랫폼이 있을 때 별도 게시 작업을 예약한다.
따라서 파일 생성 완료와 업로드 완료는 서로 다른 상태다.
화면에 성공이 보였다는 이유만으로 공개 게시까지 성공했다고 판단하거나, 반대로 게시 실패가 곧 영상 파일 손실이라고 해석해서는 안 된다.[2]

## 예시로 따라가는 흐름

README의 Agent 요청 예시는 ‘인공지능이 보통 사람의 일상을 어떻게 바꾸는가’라는 영상 주제다.
이 입력을 실제 처리 구조에 맞춰 읽으면 먼저 선택한 대본 생성 경로가 설명 문장을 만들고, 로컬 소재가 아닌 경우 영상 검색어를 추출한다.
다음으로 음성 파일과 길이를 준비하고 그 음성을 기준으로 자막을 만든다.
소재 단계가 준비한 영상은 음성·자막과 함께 최종 합성에 전달된다.
마지막 반환 정보에는 영상 경로뿐 아니라 대본, 검색어, 음성, 자막, 소재와 경고도 포함된다.[1][2]

이것은 문서의 요청과 구현을 따라간 설명이며 직접 실행한 결과가 아니다.
사람은 대본에서 과장되거나 근거 없는 주장을 먼저 걸러야 하고, 검색된 화면이 해당 설명을 실제로 보여 주는지 확인해야 한다.
‘AI’라는 검색어가 들어갔다고 모든 장면이 대본의 사례를 뒷받침하지는 않는다.
완성 파일에서는 발음, 자막의 줄바꿈과 표시 시간, 배경음악에 가려지는 음성, 세로 화면에서 잘린 부분을 확인하는 것이 필요하다.
게시를 원하지 않는 시험이라면 파일 생성과 자동 게시 설정을 분리해서 확인해야 한다.

## 비용과 권리는 합성 과정 밖에 있다

README는 GPU가 필수는 아니라고 설명하지만 이는 모든 경로가 같은 자원을 쓴다는 뜻이 아니다.
클라우드 언어 모델과 음성 서비스를 이용하면 네트워크와 API 설정이 필요하고, 로컬 전사 모델을 쓰면 모델 다운로드와 실행 자원이 필요하다.
배치 생성은 입력 한 개의 성공 여부만으로 자원과 비용을 예측할 수 없다.
여러 공급자를 연결할 때 각각의 이용 조건을 확인해야 한다.[1]

미디어 권리도 중요하다.
README는 기본 배경음악이 YouTube 영상에서 왔으며 권리 문제가 있으면 삭제하라는 안내를 남긴다.
저장소를 받을 수 있다는 사실이 모든 포함 음악과 외부 소재의 배포 권한까지 보장하지 않는다.
업로드한 음성이나 복제하려는 목소리에도 사용 허가가 필요하며, 자동 게시 전에 완성물의 내용과 권리를 사람이 확인하는 경계가 남는다.[1]
