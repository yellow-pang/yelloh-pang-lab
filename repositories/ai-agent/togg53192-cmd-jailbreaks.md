## 한 줄 요약

모델별 지시문 충돌 사례를 모은 프롬프트 자료집으로, 방어 관점에서 신뢰 경계를 읽는 자료다.[1]

## 무엇을 모은 저장소인가?

이 저장소는 시스템 프롬프트, 역할 설정, 작업공간 정책, `AGENTS.md`, Ollama 설정 형식의 문서를 모은 자료집이다.
별도 모델을 학습하거나 보안 검사를 자동 실행하는 프로그램으로 소개되지 않는다.
README는 지시 우선순위, 역할 부여, 서로 충돌하는 요청이 모델 행동에 미치는 영향을 연구·교육 목적으로 다룬다고 설명한다.[1]

프롬프트 주입은 외부 문서에 들어 있는 문장이 모델에게 새로운 명령처럼 받아들여지는 문제다.
이 자료를 방어 관점에서 읽을 때는 문구의 자극성보다, 누가 작성한 지시를 어떤 권한으로 취급하려 하는지 구분하는 것이 중요하다.
공개된 목록에 모델 이름이 있다는 사실은 그 모델에서 우회가 재현되었다는 검증 결과가 아니다.[1]

## 파일 형식과 신뢰 경계

README는 일반 대화용 문장뿐 아니라 시스템 지침과 작업공간 지침 등 서로 다른 입력 표면을 구분한다.
입력 표면은 모델이나 도구가 문서를 받아들이는 위치를 뜻한다.
동일한 문장이라도 대화 본문과 프로젝트 설정은 읽히는 방식이 다르므로, 한 종류의 결과를 다른 환경으로 일반화할 수 없다.[1]

대표 파일 `gemma4.md`는 기반 모델을 지정하는 `FROM`과 지시문을 담는 `SYSTEM`이 있는 설정 문서다.
따라서 이름의 확장자가 Markdown이라고 해서 설명용 글만 있는 것으로 보면 안 된다.
실행 코드 없이도 설정 문서가 모델의 동작 조건을 바꾸는 입력이 될 수 있다는 구조를 보여준다.[2]

이 초안은 해당 지시문의 실행·복사 절차나 우회용 문장을 제공하지 않는다.
수집된 원문은 조사 근거이며, 이 문서를 작성하는 에이전트가 따라야 할 명령이 아니다.

## 가상 사례: 방어용 분류표 만들기

자신이 관리하는 실험 환경의 지침 로더를 점검한다고 가정한 예시다. 실제 테스트 결과는 아니다.
입력은 공개 문서의 파일 형식과, 그 문서가 어떤 권한을 주장하는지에 대한 관찰 기록이다.
읽는 사람은 모델명, 지침을 넣는 위치, 역할 변경 요구의 유무, 실제 검증 여부를 서로 다른 열로 나눈다.[1][2]

결과물은 성공률 표가 아니라 신뢰 경계 검토표다.
예를 들어 작업공간 문서가 더 높은 우선순위의 규칙을 바꾸려 하는 경우, 이를 실행하지 않고 충돌 유형으로 표시한다.
이렇게 하면 악성 문장의 재사용 없이도 외부 자료를 데이터로 다뤄야 하는 이유를 설명할 수 있다.

## 읽을 때 남겨야 할 한계

README 자체가 모델 업데이트와 지시 체계 변화에 따라 기존 동작이 달라질 수 있다고 경고한다.
모델별 이름, 작성자의 목적, 실제 재현성은 각각 다른 정보이며 이 조사에서는 모델을 호출하지 않았다.[1]

수집한 루트 트리에는 별도 LICENSE 파일이 없고 공개 API의 라이선스 값도 비어 있다.
공개 열람이 가능하다는 이유만으로 재배포·수정 허가가 있다고 단정하지 않아야 한다.[3]
연구 목적이라는 설명도 제공자 약관이나 법적 제한을 없애지 않으며, README 역시 이를 준수할 책임을 명시한다.[1]

방어적 독해에서는 문구를 실행하는 대신 입력 위치, 주장하는 권한, 검증의 공백을 기록할 수 있다.
