## 한 줄 요약

Garden Skills는 웹 디자인, 발표용 웹 화면, 이미지 생성과 자료 정리를 위한 AI 에이전트용 작업 지침 모음이다.
자체 언어 모델이나 하나의 디자인 편집기가 아니라, `SKILL.md`와 참조 문서·스크립트·자산을 호스트 에이전트가 읽는 형태다.
각 Skill이 만드는 결과와 필요한 실행 도구가 다르다.[1]

## 보기 좋은 결과 이전에 결정해야 할 것

글을 영상 설명으로 옮길 때 원고를 화면마다 잘라 붙이는 것만으로는 충분하지 않다.
한 화면에 얼마나 설명할지, 어떤 순서로 보여줄지, 그림과 음성은 언제 확정할지 정해야 한다.
Garden의 발표 Skill은 내용 작성, 계획 합의, 웹 구현, 선택적 음성 합성, 녹화의 단계를 나눈다.
화면을 만드는 코드만이 아니라 협업 절차까지 포함하는 셈이다.[2]

웹 디자인 Skill은 제품 맥락과 디자인 방향을 정하고 초기 화면을 보여준 다음 전체 구현으로 이어지는 구조로 소개된다.
이미지 Skill은 프롬프트를 작성하는 일과 실제 이미지를 생성하는 일을 구분한다.
공통적으로 “결과를 만들어 달라”는 요청을 작은 결정과 확인 단계로 나누지만, 모든 Skill이 같은 입력과 산출물을 공유하지는 않는다.[1][3]

## 발표는 영상 파일이 아니라 움직이는 웹 프로젝트다

`web-video-presentation`의 주된 산출물은 Vite·React·TypeScript 기반 웹 프로젝트다.
이 기술들은 브라우저 화면을 개발하고 실행하는 도구와 언어다.
고정 비율 무대를 화면 크기에 맞게 표시하고 클릭이나 키보드로 설명 단계를 넘기므로, 녹화할 수 있는 발표 화면을 만든다는 설명이 정확하다.
요청 한 번으로 완성된 편집 영상 파일을 보장하는 기능으로 읽으면 범위가 달라진다.[1][2]

원문은 `article.md`, 말할 원고는 `script.md`, 장별 개발 계획은 `outline.md`로 나뉜다.
원문은 세부 정보의 근거라서 원고를 만든 뒤에도 보존한다.
특히 `narrations.ts`를 단계 수와 음성 텍스트의 기준으로 삼고, 화면 코드의 단계 수가 이 배열 길이와 맞도록 요구한다.
그림을 늘렸는데 음성이 예전 순서에 머무는 불일치를 막으려는 규칙이다.[2]

계획 확인에서는 원고·outline·테마·소재·개발 모드를 함께 맞춘다.
첫 장은 기준이 되는 완성본으로 만들고 사용자의 확인을 거쳐야 나머지 장으로 진행한다.
장별 개발을 병렬화할 수 있다는 설명보다 이 기준 화면과 승인 지점이 어떤 역할을 하는지 먼저 읽어야 한다.[2]

## 이미지 Skill의 세 실행 경로

`gpt-image-2`는 환경에 따라 로컬 스크립트 실행, 호스트의 이미지 도구 위임, 프롬프트 작성만 수행하는 세 모드를 구분한다.
Garden 모드는 활성화 변수와 API 키를 요구하고, 생성·편집 스크립트를 통해 프롬프트와 이미지를 저장한다.
여기서 로컬은 스크립트가 동작하는 위치를 뜻하며 모델이 인터넷 없이 기기 안에서 실행된다는 뜻은 아니다.[3]

호스트 도구를 쓰는 모드는 프롬프트 지침만 재사용하고 이미지의 저장 위치는 호스트가 정한다.
이미지 도구가 없는 advisor 모드는 프롬프트를 전달할 뿐 이미지를 생성했다고 말해서는 안 된다고 명시한다.
실행 실패 시에도 성공한 척하지 않고 오류와 대체 경로를 확인하도록 되어 있다.
같은 Skill 이름이어도 환경에 따라 최종 산출물이 이미지 또는 텍스트로 달라지는 이유다.[3]

## 예시로 따라가는 흐름

공개된 개인 학습 글을 짧은 설명 화면으로 바꾸는 이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
입력은 원문 글과 전달할 대상, 녹화 목적이다.
발표 Skill의 절차를 따르면 원문을 보존한 상태로 말하기용 원고와 장별 outline을 만든다.
outline은 정보량과 진행 리듬을 정하고, 실제 화면의 애니메이션을 미리 모두 고정하는 문서로 쓰지 않는다.[2]

다음에는 사용자가 원고와 소재, 테마, 개발 방식을 한 번에 검토한다.
첫 장의 실제 화면이 준비되면 그 장을 기준으로 글자 크기와 진행 속도, 시각 표현을 확인한 뒤 나머지 장을 작성한다.
각 장의 단계는 `narrations.ts`와 일치해야 한다.
이후 음성이 필요한지 다시 확인하고, 필요한 경우에만 공급자를 사용해 장별 오디오를 만든다.
마지막 녹화와 후편집은 웹 화면 제작 다음 단계다.
사람은 원문의 의미가 축약 과정에서 바뀌지 않았는지, 화면 한 단계와 내레이션 한 단위가 맞는지, 공개할 소재의 권리가 있는지 점검한다.
웹 프로젝트가 생성된 사실과 영상·음성이 완성된 사실을 구분해야 한다.[2]

## 지침의 이식성과 실행 조건은 다르다

README는 여러 에이전트의 Skill 디렉터리와 플러그인 설치 경로를 소개한다.
하지만 Markdown을 읽을 수 있다는 조건만으로 웹 프로젝트 빌드, 화면 확인, 음성·이미지 API 호출 능력까지 갖춰지지는 않는다.
특히 이미지와 음성 기능은 선택한 공급자의 키, 접근 가능 모델, 한도와 비용을 따로 확인해야 한다.[1][2][3]

발표 지침은 원문이나 원고가 없고 주제만 있으면 재료를 먼저 요청하도록 한다.
입력이 부족한 상태에서 내용을 임의로 만들어 제작을 계속하는 역할은 아니다.
또한 산출물별 점검에서 실패한 항목을 수정한 다음 보고하도록 요구한다.
이런 문서 규칙이 있다는 사실과 모든 호스트가 언제나 이를 준수한다는 보장은 구별된다.[2]

자료에는 버전을 고정한 배포 파일과 체크섬을 확인하는 경로가 소개된다.
재현할 때는 움직이는 최신 브랜치와 특정 배포본을 구분할 수 있다.
다만 이 글은 공개 문서를 읽은 기록이며, 호환성 표의 “테스트됨” 표시를 독립적으로 다시 검증한 것은 아니다.[1]

## 정리

Garden Skills는 창작 요청을 자료 준비와 합의, 구현, 검토로 나누는 지침과 보조 자산을 제공한다.
화면 제작과 영상 완성, 프롬프트 작성과 이미지 생성의 경계를 구분하면 실제로 맡길 수 있는 일을 이해하기 쉽다.
