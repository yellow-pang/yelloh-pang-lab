## 한 줄 요약

ai-memory는 서로 다른 코딩 에이전트가 같은 프로젝트의 작업 맥락을 이어받도록 만드는 장기 기억 서버다.
Rust 단일 바이너리를 중심으로 동작하며 원본 기억은 Markdown 위키에, 검색용 파생 정보는 SQLite에 둔다.
새로운 코딩 모델이나 모든 대화를 대신 수행하는 에이전트가 아니라 여러 도구 사이의 기록·검색·인계를 담당한다.[1][2]

## 도구를 바꿀 때 사라지는 설명을 줄이기

한 에이전트와 오류를 조사하다 다른 CLI를 열면 현재 구조, 실패한 시도, 아직 남은 질문을 다시 설명해야 할 수 있다.
README는 이 상황을 “중간에 도구를 바꾸어도 작업을 이어가기”라는 문제로 제시한다.
기억을 특정 CLI 안에만 두지 않고 별도 서버와 프로젝트별 위키에 모아 여러 에이전트와 컴퓨터가 참조하게 한다.[1]

기억을 공유한다는 말에는 두 층이 있다.
프로젝트의 지식 페이지를 검색하는 일과 현재 작업의 인계 내용을 받는 일이다.
README는 지식은 프로젝트별로 공유하되 개인 인계는 개인에게 남기며, handoff를 형식과 소유자가 있는 한 번 수령하는 프로토콜로 다룬다고 설명한다.
따라서 모든 사용자의 대화를 무조건 하나로 섞는 단순 로그 저장소와는 목적이 다르다.[1]

## 수집에서 다음 세션까지

첫 단계는 lifecycle hook이다.
훅은 세션 시작·종료, 사용자 요청, 도구 사용처럼 정해진 시점에 호출되는 연결 장치다.
Architecture 문서는 훅 이벤트가 서버에 들어오면 정제 과정을 거쳐 관찰 기록으로 분류되고 쓰기 처리 경로에 전달된다고 설명한다.
에이전트가 기억하라고 매번 명시하지 않아도 작업 자체를 수집하려는 설계다.[2]

진짜 SessionEnd가 들어오면 규칙 기반의 세션 요약 Markdown을 만들고 다음 에이전트를 위한 인계 행을 연다.
기본 경로는 LLM 호출 없이 작동하며, 제공자를 설정하면 요약을 더 오래 쓸 개념·결정·주의사항 페이지로 정리하는 선택 경로가 추가된다.
기본 기록과 모델 기반 재작성은 비용과 데이터 전송 조건이 다르므로 구분해서 읽어야 한다.[1][2]

검색은 전문 검색, 단어 기반 개체 정보, 링크 관계와 선택적인 벡터를 조합한다.
벡터는 문장의 의미를 숫자로 표현해 유사성을 찾는 수단이지만 필수 저장 형식은 아니다.
Markdown이 원본이고 SQLite는 재구축할 수 있는 색인이라는 설명은, 검색 서버의 내부 형식과 사용자가 소유하는 기록을 분리한다는 뜻이다.[1][2]

## 예시로 따라가는 흐름

README의 대표 상황은 Claude Code에서 하던 작업을 같은 디렉터리의 Codex로 이어가는 것이다.
문서를 따라 흐름을 풀면 첫 에이전트의 입력과 도구 활동이 훅으로 관찰되고, 종료 시 세션 요약과 인계 상태가 생긴다.
새로운 에이전트는 제한된 분량의 brief와 검색을 통해 이전 시도와 남은 질문을 받는다.
저장소 전체와 모든 과거 대화를 매번 한꺼번에 프롬프트에 넣는 방식으로 설명되어 있지는 않다.[1][2]

여기서 중요한 중간 판단은 “세션이 실제로 끝났는가”다.
Architecture 문서는 신뢰할 수 있는 종료 훅이 없는 클라이언트에는 명시적 종료 작업이 필요하다고 설명한다.
또 종료 재전송과 중단 복구에서 관찰 기록을 중복 추가하지 않도록 식별자와 처리 상태를 사용한다.
기록을 캡처했다는 사실, 요약 페이지를 만들었다는 사실, 인계가 수령되었다는 사실은 각각 확인해야 한다.[2]

사람이 받을 결과는 기억이 좋아졌다는 추상적 점수가 아니라 읽을 수 있는 페이지와 열린 질문, 다음 작업자가 확인할 맥락이다.
이전 코드 상태와 노트가 어긋났는지, 민감한 도구 출력이 포함되었는지, 실패한 접근이 성공한 결정처럼 요약되지는 않았는지 검토할 수 있다.
이 글에서는 실제 두 CLI를 연결하지 않았으며, 어떤 인계가 성공적으로 수령되었다는 실행 결과를 제시하지 않는다.[1][2]

## 오래 남기는 기능에는 삭제와 접근의 문제가 따른다

기억의 노화와 압축은 기록을 무조건 영구 보관하거나 즉시 삭제하는 두 선택 사이를 다룬다.
README는 실제 사용된 기억의 보존을 늘리는 동작과, 재작성·중복 축소처럼 내용을 바꾸는 선택 기능을 구분한다.
원래 버전은 Git과 버전 체인에 남아 복원할 수 있다는 설명도 있다.
이는 되돌리기에 유리하지만 민감한 내용의 완전 삭제와는 다른 문제다.[1]

기본 Docker 빠른 시작은 인증 없이 loopback에 바인딩하는 경로다.
loopback은 같은 컴퓨터 안에서만 접속하는 주소를 뜻한다.
이를 외부 네트워크에 공개할 때는 토큰과 접근 통제를 다시 구성해야 하며, 로컬 예시를 그대로 공용 서버 설정으로 옮겨서는 안 된다.
여러 사용자에게 공유할수록 프로젝트 범위와 개인 인계 경계도 중요해진다.[1]

Architecture에는 모델 제공자를 설정한 경우 완료 세션을 검토하는 auto-improvement 스케줄러와 기본 승인 경로도 설명되어 있다.
관리자가 스케줄을 끄거나 `require_approval`을 설정해 제안을 대기시킬 수 있다.
모든 고급 기능이 동일한 기본값을 갖는다고 생각하지 말고 “LLM 없이 쓰는 기본 경로”와 “제공자를 추가한 이후의 백그라운드 변경”을 나누어 확인할 필요가 있다.[2]

## 정리

ai-memory는 에이전트 교체를 넘어 살아남는 프로젝트 기록과 명시적인 작업 인계를 제공한다.
기억이 존재한다고 현재 코드와 자동으로 일치하는 것은 아니며, 자동 수집의 범위·서버 접근·백그라운드 변경 정책을 함께 관리해야 한다.
