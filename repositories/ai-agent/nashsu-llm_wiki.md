## 한 줄 요약

LLM Wiki는 가져온 자료를 AI가 읽고 서로 연결된 위키로 유지하는 데스크톱 애플리케이션이다.
README가 출발점으로 드는 LLM Wiki 패턴은 방법론이며, 이 저장소는 그 패턴을 화면·검색·파일 관리가 있는 앱으로 구현한다.
추상적 지침 파일이나 언어 모델 자체와 구별할 필요가 있다.[1]

## 질문할 때마다 처음부터 읽는 대신

문서를 모아 두어도 매번 같은 배경을 다시 설명해야 한다면 지식이 축적되기 어렵다.
LLM Wiki는 원본을 그때그때 검색해 답하는 방식에 더해, 원본에서 개념·대상·요약 페이지를 만들고 새 자료가 들어오면 연결을 갱신하는 방식을 제시한다.
질의 결과뿐 아니라 다음 질의가 참고할 중간 지식 구조를 파일로 남기는 것이 중심이다.[1]

기본 구조는 원본 자료, AI가 만든 위키, 구성 규칙으로 나뉜다.
`purpose.md`는 어떤 질문과 범위를 위해 위키를 만드는지 적는 곳이며 `schema.md`는 페이지 구조와 형식을 정하는 곳이다.
원본과 생성 문서를 분리하면 AI의 해석을 원자료 자체와 혼동하지 않고 되돌아가 확인할 수 있다.
README는 사람이 자료를 선별하고 LLM이 유지한다는 역할 분담을 명시한다.[1]

## 가져오기, 연결하기, 다시 찾기

문서 ingest는 먼저 자료를 분석하고 그 다음 위키 파일을 생성하는 두 단계로 설명된다.
분석에서는 개념과 기존 지식의 연결·충돌을 찾고, 생성에서는 원본 요약과 개념 페이지, 색인과 작업 기록, 사람이 판단할 항목을 만든다.
생성 페이지의 `sources` 필드는 어떤 원본을 바탕으로 했는지 추적하는 연결이다.
출처 필드가 있다는 사실과 문장 내용이 정확하다는 판단은 여전히 별개다.[1]

파일 내용이 바뀌지 않았으면 해시를 이용해 재처리를 피하는 캐시와, 중단 뒤 이어갈 수 있는 대기열도 안내된다.
지식 그래프는 페이지 사이의 직접 링크, 공통 출처, 공통 이웃과 유형 같은 신호로 관계를 표현한다.
그래프의 가까움은 문서 사이 연결의 정도이지 내용의 참·거짓이나 중요도를 자동 판정하는 점수는 아니다.[1]

검색은 단어 검색과 연결 확장을 기본으로 하고, 의미 검색용 벡터 기능을 선택적으로 붙인다.
벡터는 문장의 의미적 특성을 숫자 배열로 표현한 것이며, 같은 단어가 없더라도 관련 내용을 찾기 위한 보조 수단이다.
README는 이 기능이 기본 비활성이며 별도 모델·엔드포인트 설정을 가진다고 설명한다.
앱을 설치하면 모든 자료가 자동으로 외부 임베딩 서비스에 전송된다고 단정하지 않는다.[1]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
공개 읽기 자료들을 프로젝트에 넣고 특정 개념의 위키 페이지를 생성한 뒤, 그 페이지를 수정해 검색 색인을 갱신하는 상황을 생각해 보자.
문서 가져오기는 원본 분석과 위키 생성을 거쳐 `sources`가 있는 페이지를 남긴다.
선택적 벡터 검색을 쓰는 경우 읽어 본 `page_embedding.rs`의 단일 페이지 경로가 그 위키 Markdown을 다시 색인할 수 있다.
이 경로는 먼저 임베딩이 활성화되어 있고 모델이 지정되어 있는지, 파일이 프로젝트의 `wiki/` 안에 있는 Markdown인지 검사한다.[1][2]

다음으로 파일 내용과 임베딩 설정을 반영한 지문을 이전 색인과 비교한다.
달라진 것이 없고 강제 실행이 아니라면 `unchanged`를 돌려주며 새 벡터를 쓰지 않는다.
바뀌었다면 제목과 문단 조각을 만들고 공급자에게 임베딩을 요청한 뒤 결과를 검사하여 페이지 색인을 교체한다.
구현 주석은 공급자 실패로 기존 정상 색인을 먼저 없애지 않도록 모든 벡터를 준비한 뒤 교체한다고 설명한다.
사람은 페이지 파일이 갱신된 것과 검색 색인이 갱신된 것을 구별하고, `indexed` 또는 오류 상태를 확인해야 한다.
새 문장이 검색된다고 해서 원본과의 사실 대조까지 끝난 것은 아니다.[2]

## 자동 생성 이후에 남는 검토

README의 Review 화면은 모델이 사람의 판단이 필요한 항목을 표시하는 통로다.
질문에 원본만 사용하도록 하는 Read Sources Only 모드도 소개되어 있다.
이는 AI가 정리한 위키를 읽을지 원자료를 직접 근거로 삼을지 선택할 수 있다는 차이다.
중요한 결론을 확인할 때는 위키의 매끄러운 설명만 보는 대신 연결된 원본과 충돌 항목을 살펴야 한다.[1]

또한 데스크톱 앱이라고 해서 모든 모델 처리가 로컬이라는 뜻은 아니다.
README는 여러 외부 공급자와 로컬 모델 연결, 선택적 웹 검색, 클라우드 또는 로컬 문서 분석을 구별한다.
사용자가 선택한 경로에 따라 자료가 외부로 나가고 비용이 생길 수 있다.
파일이 로컬에 보관되는 위치와 모델 요청이 처리되는 위치는 별개의 설정이다.[1]

원본 삭제는 관련 요약·색인·링크 정리로 이어지는 기능으로 설명된다.
여러 출처를 공유하는 개념 페이지를 보존하는 규칙도 있지만, 자동 정리 기능의 존재를 백업 대체 수단으로 볼 수 없다.
프로젝트 내보내기와 원본 보존 범위를 확인할 필요가 있다.
확인한 임베딩 코드도 파일 크기·조각 수 제한과 집계 페이지 제외 조건을 갖고 있어 모든 파일을 무조건 색인하지 않는다.[1][2]

공식 README는 코드의 라이선스를 GNU GPL v3.0으로 명시한다.
로컬에 위키를 저장하는 방식과 앱 코드를 수정·재배포할 때의 조건은 별개다.
소스 공개를 제한 없는 재배포 허가로 받아들이지 말고, 다른 프로그램과 묶거나 수정본을 나눌 때에는 해당 라이선스 원문을 확인해야 한다.[1]

## 정리

LLM Wiki는 자료를 일회성 답변으로 소비하는 대신 출처가 연결된 위키 파일로 누적하는 앱이다.
자동 생성·검색·검토를 연결하지만, 원문 정확성 확인과 모델 전송 경로, 삭제·백업 책임까지 사라지는 것은 아니다.
