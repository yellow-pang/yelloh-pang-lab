## 한 줄 요약

OpenCode는 프로젝트 파일과 실행 도구를 사용해 개발 작업을 진행하는 공개 소스 AI 코딩 에이전트다.
터미널 인터페이스를 중심으로 제공되며 README에는 별도의 데스크톱 앱도 beta로 소개되어 있다.
모델 자체나 프롬프트 모음이 아니라 모델의 판단을 파일 탐색·편집 같은 작업에 연결하는 프로그램이다.[1]

## 설명을 듣는 단계와 수정하는 단계

낯선 프로젝트에서 “이 기능을 고쳐 줘”라고 요청하면 먼저 구조를 이해해야 한다.
구조를 읽는 동안 파일이 바뀌면 무엇을 확인했고 무엇을 고쳤는지 구분하기 어렵다.
OpenCode README는 이 두 의도를 `plan`과 `build`라는 기본 에이전트로 나누어 소개한다.
plan은 분석·코드 탐색, build는 개발 작업의 기본 역할이며 Tab으로 전환할 수 있다.[1]

여기서 에이전트는 독립된 사람이나 별도 학습 모델을 뜻하지 않는다.
같은 프로그램 안에서 프롬프트, 허용 도구, 모델 선택과 역할을 묶은 설정 단위다.
실제 `agent.ts`의 Info 구조에는 이름·설명·mode·권한·모델·프롬프트·옵션이 들어 있다.
역할 이름만 보는 것보다 어떤 도구를 어떤 규칙으로 쓸 수 있는지 함께 보는 것이 중요하다.[2]

## 역할 정의는 권한 규칙과 합쳐진다

추가로 읽은 구현은 기본 권한, 사용자 전역 권한, 에이전트별 설정을 병합한다.
build 설명도 “설정된 권한에 따라 도구를 실행하는 기본 에이전트”라고 되어 있다.
README의 full-access라는 짧은 표현을 운영체제의 모든 보호를 우회한다는 의미로 읽어서는 안 된다.
실제 허용 범위는 설정과 도구 실행 환경을 함께 보아야 한다.[1][2]

plan의 편집 설정은 전체에 deny를 두되 `.opencode/plans/*.md`와 계획 파일 경로에는 allow 예외가 있다.
즉 “계획 역할은 어떤 파일도 한 글자도 쓰지 않는다”는 절대적인 설명보다 코드 변경을 막고 계획 산출물은 허용하는 구조로 읽는 편이 정확하다.
README는 bash 실행 전 허락을 묻는다고 소개하지만, 이 파일에서는 기본값과 사용자 권한 병합까지 확인되므로 모든 설치의 명령 승인 상태를 여기서 보장할 수 없다.[1][2]

일반 보조 역할인 `general`은 복잡한 조사와 여러 단계 작업을 맡는다.
구현에는 파일·키워드를 찾는 `explore`, 문맥 압축·제목·요약을 위한 숨겨진 역할도 보인다.
주요 사용자 역할과 내부 보조 처리가 같은 선언 구조로 정리되어 있지만, 모두가 동일한 도구 권한을 받는 것은 아니다.
예를 들어 explore는 허용 도구를 명시적으로 열어 둔 형태다.[2]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
공개 프로젝트의 검색 화면이 어떻게 데이터를 가져오는지 알고 싶다고 가정하자.
처음 입력은 “고쳐라”가 아니라 관련 파일과 요청 흐름을 설명하라는 조사 요청이다.
사용자는 plan 역할에서 출발해 코드 읽기와 탐색 결과를 받으며, 이 단계에서 수정할 요구사항과 확인할 동작을 구분한다.
README가 plan을 낯선 코드베이스 탐색에 적합하다고 설명하는 이유가 이 순서에 있다.[1]

조사가 끝난 뒤 변경을 승인하면 build로 전환해 실제 수정을 요청하는 흐름을 구성할 수 있다.
이때 결과는 답변 문장만이 아니라 편집된 파일과 실행한 확인 작업이어야 한다.
사람은 에이전트가 찾은 호출 관계가 맞는지, 요청하지 않은 파일을 바꾸지 않았는지, 테스트 결과가 실제 명령에서 나온 것인지 검토해야 한다.
이 글은 특정 프로젝트에서 그러한 변경이 성공했다고 주장하지 않는다.[1][2]

대표 구현을 읽으면 계획 모드에서도 계획 파일의 쓰기 예외가 있고 사용자 설정이 나중에 병합됨을 알 수 있다.
따라서 “plan이니까 안전하다”는 이름의 인상에만 의존하지 말고 적용되는 권한을 확인해야 한다. `.env` 계열 파일의 읽기에 ask 규칙을 두고 예제 환경 파일에는 allow를 두는 기본값도 보인다.
비밀 설정을 읽는 동작과 일반 코드 읽기를 같은 범주로 다루지 않는 사례다.[2]

## 실행 권한을 이름만으로 판단하지 않기

코딩 에이전트가 파일 편집과 명령 실행을 할 수 있으면 오류도 실제 작업 공간에 남는다.
계획·실행 역할의 분리는 유용한 경계이지만 격리된 운영체제나 테스트 환경을 자동 제공한다는 뜻은 아니다.
특히 설정에서 모델과 권한을 바꾸면 기본 소개와 다른 행동을 만들 수 있다.
조회한 코드도 에이전트 비활성화와 사용자 정의 역할, 권한 덮어쓰기를 처리한다.[2]

데스크톱 배포는 README에서 beta로 표시되며 운영체제별 패키지가 안내되어 있다.
설치 경로와 릴리스 형태의 존재만으로 모든 플랫폼에서 동일하게 안정적이라고 평가할 수는 없다.
또한 코드가 모델에 제공되는 사용 방식에서는 선택한 모델 제공자, 프로젝트에 포함된 민감한 파일, 외부 도구의 접근 범위를 별도로 살펴야 한다.
이 조사에서는 인증 설정이나 실제 전송 내용을 확인하지 않았다.[1][2]

“OpenCode”를 이름에 포함한 주변 프로젝트가 모두 공식 제품은 아니다.
README는 관련 프로젝트가 공식 개발팀과 관계없다면 이를 명시하도록 요청한다.
자료를 읽을 때 이 저장소의 실행 프로그램과 외부 대시보드·확장 프로그램의 지원 범위를 섞지 않는 것이 필요하다.[1]

## 정리

OpenCode는 모델과 개발 도구를 연결하고 조사·구현·보조 역할을 나누는 코딩 환경이다.
실제 행동 범위는 역할 이름보다 병합된 권한과 설정에서 결정되며, 코드 변경의 검증은 별도로 필요하다.
