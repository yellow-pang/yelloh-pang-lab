## 한 줄 요약

openai/skills는 Codex가 반복되는 작업을 수행할 때 참고할 지침·스크립트·자료를 폴더 단위로 모은 Agent Skills 카탈로그다.
다만 조사 시점의 README 맨 앞에는 이 저장소가 폐기 예정이 아니라 이미 deprecated된 경로라는 안내가 있다.
현재 예제는 다른 공식 플러그인 저장소와 제작 안내를 보도록 유도하므로, 이 글은 남아 있는 스킬 구성과 동작 지침을 읽는 기록이지 최신 배포 경로를 추천하는 글이 아니다.[1]

## 기능 이름보다 반복 절차를 담는 단위

에이전트에게 “리뷰 의견을 처리해 줘”라고 말하는 것과, 어떤 의견을 찾고 언제 사용자에게 선택을 받아야 하는지까지 정한 절차를 주는 것은 다르다.
README는 스킬을 에이전트가 발견하고 사용할 수 있는 지침·스크립트·자원 폴더로 정의한다.
따라서 스킬은 독립된 언어 모델이나 계속 실행되는 서버가 아니라, 실행 주체에게 특정 과제를 반복 가능한 방식으로 수행하도록 설명하는 묶음이다.[1]

이 구분은 파일을 열었을 때 특히 명확해진다.
대표 항목인 `gh-address-comments/SKILL.md`에는 코드 리뷰를 처리하는 역할, 필요한 인증 확인, 댓글을 수집하는 스크립트 이름, 사용자의 선택을 받은 뒤 수정하는 순서가 적혀 있다.
저장소에 그 문서가 있다는 사실만으로 댓글을 자동 수집하거나 변경을 완료한 것은 아니다.
Codex의 도구, 네트워크 접근, 인증 상태와 실제 호출이 있어야 지침이 행동으로 이어진다.[2]

## 발견 정보와 행동 경계를 함께 읽기

대표 `SKILL.md`의 앞부분에는 `name`, `description`, 짧은 설명 메타데이터가 있다.
이는 어떤 상황에 이 스킬을 쓸지를 알려주는 표지다.
여기서 description은 현재 브랜치의 열린 GitHub PR에 있는 리뷰·이슈 댓글을 처리하고, 먼저 `gh` 인증을 확인하라고 설명한다.
PR은 변경안을 검토받는 단위이며, `gh`는 GitHub 작업을 터미널에서 다루는 도구다.[2]

본문은 그 표지를 실제 작업 순서로 풀어준다.
먼저 댓글과 리뷰 스레드를 모으고, 각 항목에 번호를 붙여 필요한 수정을 짧게 요약한다.
그다음 사용자가 어떤 번호를 처리할지 물으며, 선택된 댓글에만 수정을 적용하도록 한다.
이 흐름에서 중요한 구별점은 “댓글이 존재한다”와 “수정을 승인했다”를 같은 사건으로 취급하지 않는다는 것이다.[2]

또 하나는 배포 단위와 출처의 구분이다.
README에는 기본 제공 `.system`, 선별 `.curated`, 실험 `.experimental`이라는 폴더 구분 및 스킬 설치자를 통한 도입 방식이 남아 있다.
이름으로 설치하거나 GitHub 폴더 URL을 지정하는 예도 있지만, 맨 앞의 deprecated 안내를 제외하고 과거 설치 설명만 현재 권장 절차처럼 인용해서는 안 된다.
저장소를 읽는 순서 자체가 해석에 영향을 준다.[1]

라이선스도 카탈로그 전체에 하나의 권한을 막연히 적용하지 않도록 작성되어 있다.
README는 각 스킬 디렉터리의 `LICENSE.txt`에서 개별 라이선스를 찾으라고 한다.
필요한 항목을 복사하거나 수정·재배포하려면 바로 그 항목의 파일을 확인해야 하며, 목록에 함께 실려 있다는 이유만으로 같은 조건이라고 단정할 수 없다.[1]

## 예시로 따라가는 흐름

공식 `gh-address-comments` 지침을 읽는 사례를 보자.
입력은 현재 브랜치의 열린 PR과 거기에 달린 검토 의견이다.
지침상 에이전트는 먼저 `gh` 인증 상태를 확인하고, `scripts/fetch_comments.py`를 이용해 댓글과 리뷰 스레드를 수집한다.
여기까지는 수정 대상의 후보를 알아내는 단계다.
지침은 곧바로 코드를 바꾸는 대신 의견에 번호를 붙이고 각 의견을 반영하려면 무엇을 해야 하는지 요약하도록 한다.[2]

예를 들어 공개 개인 프로젝트의 PR에 설명 보완과 테스트 추가 의견이 함께 있는 상황을 생각할 수 있다.
이 부분은 이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
스킬의 절차를 따르면 사용자는 정리된 후보 중 이번에 처리할 항목을 고르고, 에이전트는 선택된 항목의 수정에 집중한다.
기대하는 산출물은 무조건 모든 댓글을 닫는 결과가 아니라, 사용자 선택과 연결되는 변경이다.
사람이 확인할 부분은 요약이 원래 리뷰의 의미를 보존했는지, 선택하지 않은 범위를 바꾸지 않았는지, 인증 문제를 작업 성공으로 오해하지 않았는지다.
자료에는 인증·호출 제한 문제가 나면 다시 인증을 요청하라는 안내도 있지만, 이 글에서는 로그인이나 PR 조회, 변경 적용을 수행하지 않았다.[2]

이 예제는 스킬의 지침을 읽은 것이며 보조 스크립트 내부까지 분석한 것은 아니다.
따라서 댓글 페이지네이션이나 예외 처리의 완전성을 주장하지 않는다.
명시된 단계와 실제 스크립트 구현이 같은 범위인지 확인하는 일은 별도의 코드 검토가 필요하다.

## 지침은 실행 환경의 권한을 대체하지 않는다

대표 스킬은 네트워크 접근과 인증 권한에 관한 환경별 지침을 담고 있다.
이러한 문장을 다른 에이전트 환경에 옮기면 도구 이름이나 승인 방식이 맞지 않을 수 있다.
스킬 포맷이 재사용을 지향한다고 해서 모든 실행기에서 동일한 권한 요청이 통한다는 뜻은 아니다.
실제 환경의 승인 규칙을 따르고, 접근이 막히면 사용자 확인을 거쳐야 한다.[2]

또한 스킬은 모델이 따라야 할 절차를 설명하지만 그 자체가 수정 범위를 강제하는 보안 장치나 자동 검증기가 아니다.
이 예제에 사용자 선택 단계가 들어 있다는 것은 확인할 수 있으나, 모든 실제 실행이 그 단계를 지킨다는 성능·안전 보장은 문서를 읽는 것만으로 할 수 없다.
에이전트가 만드는 변경은 별도로 검토해야 한다.

저장소 상태는 가장 큰 현재성 제약이다.
이번에 확인한 대표 파일은 스킬 설계를 이해하는 자료로 사용할 수 있지만, 신규 구성에 필요한 최신 플러그인 방식까지 이 저장소 하나로 설명할 수는 없다.
README가 제시한 이전 안내의 존재와 그 대상 문서를 실제 분석했다는 주장을 구분해야 한다.[1]

## 정리

이 저장소가 보여주는 것은 AI 능력을 새로 학습시키는 방식이 아니라 반복 작업의 발견 정보와 수행 절차를 묶는 방식이다.
대표 스킬에서는 사용자 선택이 중요한 경계이며, 현재 사용 경로는 저장소의 deprecated 안내를 먼저 고려해야 한다.
