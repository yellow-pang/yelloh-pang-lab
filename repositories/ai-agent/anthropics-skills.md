## 한 줄 요약

anthropics/skills는 Claude가 전문 작업에서 참고하는 Skill의 공개 예제와 구현을 모은 저장소다.
Skill은 지침·스크립트·보조 자료를 담은 폴더이며 필요할 때 동적으로 읽힌다.
모델 가중치를 새로 학습시키는 자료나 독립 실행 프로그램이라기보다, 기존 에이전트가 반복 가능한 방식으로 일하도록 전달하는 작업 지식이다.[1]

## 매번 긴 설명을 다시 쓰지 않기

웹 화면을 시험하거나 문서를 편집할 때에는 목표만큼 순서가 중요하다.
어떤 입력을 먼저 확인하고 어떤 도구를 쓰며 완료를 어떻게 증명할지 매번 다시 설명하면 절차가 달라질 수 있다.
이 저장소는 창작, 개발, 문서 작업 등 서로 다른 예제를 통해 그 절차를 파일로 묶는 방법을 보여준다.[1]

README는 Agent Skills 표준과 이 저장소를 구분한다.
이곳은 Claude용 구현이며 표준 자체에 관한 안내는 별도 사이트로 연결한다.
따라서 여기 있는 모든 스크립트와 도구 가정이 다른 에이전트에서도 그대로 작동한다고 결론 내릴 수 없다.
포맷을 읽을 수 있는 것과 실제 실행 환경이 준비되어 있는 것은 다른 조건이다.[1]

## 작은 입구와 작업에 필요한 도구

기본 Skill의 입구는 `SKILL.md`다.
앞부분 YAML에는 고유 이름인 name과 언제 무엇을 하는지 설명하는 description이 필요하고, 그 아래에 지침·예제·가이드가 들어간다.
호스트는 설명을 보고 관련 작업에 이 Skill을 선택할 수 있다.
문서 제목을 멋지게 붙이는 것보다 호출 조건이 구체적인지가 중요해지는 구조다.[1]

대표로 읽은 `webapp-testing`은 로컬 웹 애플리케이션을 Playwright로 상호작용·시험하는 지침이다.
Playwright는 브라우저를 프로그램으로 조작하는 도구다.
Skill에는 정적 HTML인지 동적 웹 앱인지, 서버가 이미 떠 있는지에 따라 경로를 나누는 의사결정 흐름이 있다.
정적 파일을 직접 읽는 일과 JavaScript 실행 뒤의 화면을 확인하는 일을 구분한다.[2]

동적 페이지에서는 먼저 접속·대기하고 화면 또는 DOM을 조사한 뒤 선택자를 찾고 행동한다.
DOM은 브라우저가 구성한 페이지 요소 구조이고 선택자는 버튼·입력창 등 특정 요소를 가리키는 기준이다.
존재하지 않는 버튼 위치나 이름을 추측해 클릭하는 대신 실제 렌더링 상태에서 대상을 찾도록 하는 절차가 중심이다.[2]

## 예시로 따라가는 흐름

공식 예제는 `with_server.py`가 개발 서버의 생명주기를 관리하고 별도 Python Playwright 스크립트가 브라우저 작업을 수행하는 구성을 보여준다.
입력은 실행할 서버 명령·포트와 자동화 스크립트다.
여러 서버가 필요한 경우 백엔드와 프런트엔드를 각각 지정할 수 있도록 되어 있다.
이 글에서는 그 명령을 실행하지 않았고 구조만 읽었다.[2]

브라우저 스크립트는 headless Chromium을 열고 로컬 주소에 접속한 다음 페이지 로딩 상태를 기다린다.
이어 스크린샷, `page.content()`, 버튼 목록 등으로 현재 화면을 조사하고 발견한 선택자를 이용해 행동한다.
결과로 남길 수 있는 증거는 화면과 DOM, 브라우저 로그이며 어떤 기능을 검증할지는 요청에 맞춰 스크립트에 정의해야 한다.
예제의 주석 자리에 실제 검증 논리를 넣지 않고 “테스트가 있다”고만 하면 동작을 증명할 수 없다.[2]

사람은 클릭 자체가 성공했는지보다 클릭 뒤 기대 상태가 나타났는지 확인해야 한다.
서버 준비와 브라우저 준비는 다른 단계이고, 화면이 정적으로 보이는 것과 JavaScript가 만든 요소를 조사한 것도 구별된다.
Skill은 작업이 끝나면 브라우저를 닫도록 안내한다.
이 절차는 테스트가 남긴 증거와 자원 정리까지 작업의 일부로 보는 사례다.[2]

## 지침에 포함된 가정도 검토 대상

webapp-testing은 동적 앱을 조사하기 전에 `networkidle`을 기다리라고 강조한다.
이는 이 예제의 안내이며, 해당 대기만으로 모든 비동기 동작과 사용자 기대 상태가 완료되었다는 보장이 되지는 않는다.
파일도 필요에 따라 선택자 대기를 사용하도록 설명한다.
실제 앱에서는 검사할 요소나 결과 조건을 명확하게 정해야 한다.[2]

보조 스크립트를 먼저 `--help`로 확인하고 일반적인 작업은 내부 소스를 모두 읽기보다 호출하라고 권한다.
목적은 맥락을 큰 스크립트로 채우지 않고 이미 준비된 도구를 재사용하는 데 있다.
그러나 이 원고는 사용 실행이 아닌 자료 조사이므로 도구를 설치하거나 도움말을 실행하지 않았다.
지침 파일의 존재를 의존성 설치와 실행 성공의 증거로 삼지 않는다.[2]

라이선스는 특히 구분해야 한다.
README는 많은 예제가 Apache 2.0이라고 설명하면서 `docx`, `pdf`, `pptx`, `xlsx` 문서 Skill은 source-available이며 오픈소스는 아니라고 명시한다.
소스를 읽을 수 있다는 사실과 자유로운 재배포 허락은 같지 않다.
해당 폴더의 조건을 개별 확인해야 하며 저장소 전체에 하나의 허용 범위를 적용하면 안 된다.[1]

README는 시연·교육 목적의 자료이고 실제 Claude 제품 동작과 다를 수 있으며 중요한 작업에 의존하기 전 환경별 시험을 하라고 밝힌다.
이는 예제를 완성된 품질 보증 체계로 과장하지 말라는 경계다.
Skill의 절차, 호스트 기능, 실행 도구, 실제 산출물의 검증을 따로 확인할 필요가 있다.[1]

## 정리

anthropics/skills는 작업 방법을 선택 가능한 폴더로 전달하는 예제집이다.
