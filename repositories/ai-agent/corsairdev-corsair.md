## 한 줄 요약

Corsair는 애플리케이션 사용자의 외부 계정을 연결하고 여러 서비스의 API를 일정한 형태로 호출하도록 돕는 통합 플랫폼이다.
AI 에이전트에만 한정된 MCP 서버가 아니라, 에이전트·백엔드·사용자 대시보드가 같은 통합 계층을 활용하는 구성을 지향한다.
README는 REST API 기반이라는 점과 서비스별 어댑터를 공통 문법 뒤에 두는 점을 강조한다.[1]

## 외부 서비스가 늘면 연결 코드도 늘어난다

개인 앱에서 이슈 목록을 보여주고 알림을 보내려면 서비스마다 인증과 요청 형식, 응답 처리 코드를 준비해야 한다.
사용자가 여러 명이면 누구의 인증정보로 호출하는지도 구분해야 한다.
Corsair는 이런 반복 연결 코드를 통합하고, 사용자별 계정과 데이터의 범위를 나누는 층을 제공한다.[1][2]

서비스의 차이를 완전히 없애는 것은 아니다.
메시지를 보내는 데 필요한 채널과 이슈를 만드는 데 필요한 프로젝트 정보는 여전히 다르다.
공통화하는 부분은 연결을 구성하고 기능에 접근하는 방식이다.
실제 최소 예제에서도 메시지는 `messages.post`, 이슈는 `issues.create`를 쓰며 각각 다른 인자를 받는다.[3]

## 플러그인, 테넌트, 데이터베이스

`createCorsair`는 데이터베이스와 암호화 키, 플러그인을 받아 인스턴스를 만든다.
플러그인은 외부 서비스의 기능을 연결하는 구성 요소다.
빠른 시작은 서비스별 `@corsair-dev/*` 패키지를 선택하도록 안내하며, GitHub 플러그인으로 OAuth 연결 흐름을 설명한다.[2]

테넌트는 데이터와 인증정보를 구분하는 사용자 또는 이용 단위다. `multiTenancy: true`를 켠 예제에서는 `withTenant`로 범위를 정한 인스턴스를 얻는다.
이후 같은 API 문법을 사용하더라도 선택한 테넌트의 연결을 기준으로 동작하는 구조다.
이 범위를 앱의 로그인 사용자와 정확히 연결하는 일은 서비스 개발자가 확인해야 한다.[2][3]

빠른 시작의 데이터베이스 구조에는 통합, 계정, 엔터티, 이벤트, 권한 테이블이 나온다.
엔터티는 외부 서비스에서 가져와 저장하는 이슈 같은 데이터 항목이다.
API 응답을 데이터베이스에 저장해 후속 읽기에 사용하는 경로도 소개한다.
따라서 원격 API 호출과 로컬 저장 데이터를 읽는 호출을 같은 것으로 다루면 안 된다.[2][3]

## Hub의 연결 화면과 자격 증명 보관

공식 빠른 시작은 Hub가 OAuth 연결·승인·웹훅 표면을 제공하는 경로를 사용한다.
OAuth는 앱이 사용자의 비밀번호를 직접 받는 대신 허용받은 범위의 접근을 연결하는 방식이고, 웹훅은 외부 서비스의 이벤트를 앱으로 전달하는 요청이다.
이 안내에서는 자격 증명을 암호화해 사용자의 데이터베이스에 보관하며 Hub에는 저장하지 않는다고 설명한다.[2]

이때 KEK는 저장된 자격 증명에 접근하기 위한 암호화 키다.
문서는 이 키를 잃으면 저장된 자격 증명에 접근할 수 없다고 경고한다.
자체 데이터 보관이라는 장점만 볼 것이 아니라 백업과 키 관리 책임도 함께 읽어야 한다.
자체 호스팅과 Hub 사용은 README가 소개하는 서로 다른 운영 선택지다.[1][2]

## 예시로 따라가는 흐름

대표 자료는 `demo/minimal/corsair.ts`의 공식 코드다.
처음에 데이터베이스와 KEK, 메시지·이슈·메일 관련 플러그인을 넣어 Corsair를 만들고, 예시 테넌트 식별자로 범위를 정한다.
이어 정해진 채널에 메시지를 보내고, 별도의 이슈 서비스에는 제목과 팀 식별자, 설명을 전달한다.
응답에서는 메시지의 시각 식별자와 채널, 이슈의 식별자와 제목 같은 필드를 읽는다.[3]

마지막에는 원격 이슈 생성 API가 아니라 `tenant.linear.db.issues.list()`로 데이터베이스의 이슈 목록을 조회하고 제목과 우선순위를 읽는다.
이 순서가 보여주는 것은 설정 → 사용자 범위 지정 → 외부 행동 → 저장 데이터 읽기의 연결이다.
TypeScript의 타입은 인자와 응답 필드의 형태를 확인하도록 돕지만, 채널이나 팀이 사용자가 의도한 실제 대상인지는 사람이 따로 점검해야 한다.
예제의 식별자를 자기 계정의 값으로 검증하지 않고 사용하면 안 되며, 이 코드는 읽기 전용 샘플이 아니라 메시지와 이슈를 만드는 행동을 포함한다.
이 글에서는 코드를 실행하거나 메시지·이슈를 생성하지 않았다.[3]

## 문서와 예제의 시점을 구분한다

최소 예제는 통합 함수를 `corsair`에서 함께 가져오지만 현재 quick-start는 서비스별 패키지를 안내한다.
또한 demo README의 파일 안내에는 실제 조회한 폴더 목록과 다른 이름이 포함되어 있다.
이 차이를 임의로 맞춰 “그대로 실행 가능”이라고 판단하지 않고, 예제는 호출 구조 설명에 사용하고 도입 시점에는 선택한 버전의 설치·import 경로를 다시 확인해야 한다.[2][3][4]

공통 문법은 외부 API의 접근 권한이나 한도까지 없애지 않는다.
읽기와 쓰기 권한, 테넌트 선택, 토큰 보관, 웹훅 전달과 재처리 조건은 각각 확인할 대상이다.
Hub의 연결 상태 표시가 정상이라는 것만으로 모든 플러그인 호출의 결과까지 검증된 것은 아니다.
빠른 시작도 연결 페이지와 API 호출을 별도 단계로 구분한다.[2]

README는 Apache 2.0 라이선스를 안내한다.
여기서 확인한 것은 공개 문서와 예제의 설계이며, 모든 어댑터의 데이터 동기화 정확도나 운영 안정성, 인증 격리를 실험한 결과는 아니다.
서비스를 추가할 때는 해당 플러그인의 지원 범위를 따로 읽어야 한다.[1][2]

## 정리

Corsair는 여러 외부 서비스를 사용자별 연결과 일정한 호출 구조로 묶는다.
연결 화면, 인증정보 저장, 외부 쓰기 작업과 로컬 데이터 읽기는 서로 다른 층이며, 운영자는 키와 사용자 범위를 명확히 관리해야 한다.
