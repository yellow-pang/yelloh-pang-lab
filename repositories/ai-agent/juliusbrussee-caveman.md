## 답변을 줄이는 Skill과 입력을 줄이는 실행 계층

Caveman은 AI Agent의 불필요한 설명을 줄이는 Skill에서 출발해 도구 결과를 압축하는 프록시와 응용 프로그램용 미들웨어까지 제공하는 프로젝트다.
토큰은 모델이 읽고 쓰는 텍스트를 처리하는 단위다.
답변이 짧아지는 것과 모델에 보내는 입력이 줄어드는 것은 비용과 동작에 영향을 주는 서로 다른 경로이므로 구별해서 읽어야 한다.[1]

README의 Skill은 Agent가 말하는 방식을 바꾸고, 프록시는 Agent와 모델 제공자 사이에서 로그·테스트 출력·JSON·diff 같은 입력을 줄이는 것으로 설명된다.
미들웨어는 개발자가 자신의 코드에서 모델 호출을 감쌀 때 쓰는 경로다.
따라서 기존 초안처럼 ‘동굴 사람 말투로 토큰을 줄이는 문서’만으로 소개하면 현재 저장소의 범위를 모두 설명하지 못한다.[1]

## 짧게 말해도 보존해야 할 정보

대표 `skills/caveman/SKILL.md`는 장황한 도입과 반복, 장식적 표현을 없애되 기술적 내용은 보존하라고 지시한다.
코드, 명령, 경로와 오류 문자열은 그대로 두고 숫자와 단위, not·only·except처럼 의미를 바꾸는 조건도 삭제하지 않는다.
출력 모드는 lite, full, ultra와 문언문 계열로 나뉘지만 명료함과 압축이 충돌하면 명료함을 우선하는 규칙이 있다.[2]

자주 쓰이지 않는 축약어를 새로 만드는 것도 금지한다.
짧아 보이는 철자가 토크나이저에서 반드시 적은 단위로 나뉘는 것은 아니고 독자의 해독 부담만 늘 수 있기 때문이다.
한 문장에 한 가지 생각, 일관된 용어, 명확한 주어와 참조 대상을 유지하라는 설명이 함께 있다.
즉 목적은 일부러 문법을 망가뜨리는 것이 아니라 읽는 사람에게 필요한 사실을 더 적은 군더더기로 전달하는 것이다.[2]

한국어처럼 작은 조사가 문장 성분의 역할을 표현하는 언어에서는 영어 관사 삭제 규칙을 그대로 적용하지 말라고 적혀 있다.
사용자의 언어를 유지하고 예시가 다른 언어라는 이유로 전환하지 않는다는 규칙도 있다.
줄여야 하는 것은 언어 자체가 아니라 불필요한 정중 표현과 반복이라는 구분이다.[2]

## 예시로 따라가는 흐름

README와 Skill의 React 예시는 컴포넌트가 다시 렌더링되는 이유를 묻는 상황이다.
긴 답변에서는 매번 새로운 객체 참조가 만들어지고 얕은 비교에서 다른 값으로 취급되어 다시 렌더링된다는 설명을 풀어 쓴다.
압축된 예시는 새 객체 참조, 인라인 객체 prop, 재렌더링의 관계와 `useMemo`라는 제안을 짧게 남긴다.
입력 질문과 진단·제안의 핵심을 유지하면서 도입 문장을 덜어 내는 사례다.[1][2]

이 예시는 모든 React 재렌더링의 원인이나 처방을 보증하지 않으며 여기서 실제 코드를 진단한 것도 아니다.
사람은 압축 전후에 조건과 인과관계가 보존됐는지 확인해야 한다.
특히 ‘항상’과 ‘일부 조건에서’가 뒤섞이면 짧아진 문장이 더 위험해질 수 있다.
공식 지침은 보안 경고, 되돌릴 수 없는 동작 확인, 순서가 혼동될 여러 단계 작업, 사용자가 다시 설명을 요청하는 경우 정상 문장으로 돌아가도록 한다.
따라서 성공 기준은 가장 짧은 글자 수가 아니라 필요한 판단과 경고가 남아 있는 답변이다.[2]

## 채팅 스타일과 저장되는 문서를 분리한다

Skill의 Boundaries는 코드·주석·커밋·문서·이슈와 PR 본문·외부 메시지·기억 파일처럼 채팅 밖에 남기는 내용을 일반적인 문장으로 쓰도록 한다. `/caveman-compress`는 별도 예외로 언급된다.
대화에서 짧게 말하는 모드를 켰다는 이유로 공개 문서와 다른 사람에게 전달할 메시지까지 불완전한 문장으로 바꾸는 기능은 아니다.[2]

README는 기억 파일 압축에서 원본을 백업하고, 프록시가 줄인 바이트도 원본을 보관해 Agent가 다시 가져올 수 있다고 설명한다.
원문 회수는 압축이 내용을 생략할 수 있다는 사실을 보완하는 장치다.
백업이 있다는 사실만으로 모델이 모든 중요한 줄을 자동으로 다시 읽는 것은 아니므로, 결정적인 오류나 테스트 실패가 생략되지 않았는지 확인해야 한다.[1]

프록시와 미들웨어는 Skill보다 훨씬 넓은 자료를 다룬다.
로컬 실행이라고 해도 Agent의 모델 제공자 통신 자체가 없어지는 것은 아니다.
무엇을 압축하고 어디에 원본을 남기는지, 보관된 로그에 비밀값이나 개인정보가 있는지 검토할 필요가 있다.
실제 비용 감소는 출력 비중과 도구 사용량, 모델 과금 방식에 따라 달라진다.

## 절감 수치와 라이선스의 범위

README에는 여러 측정과 비교 수치가 있지만 이 글에서는 동일 조건으로 재현하지 않았다.
Skill의 출력 절감과 프록시의 입력 절감, 전체 세션의 금액 변화를 하나의 비율로 합쳐 일반화하면 안 된다.
README도 자신의 작업에서 비교 실험을 하라는 경로를 제공하고 측정할 수 없는 상태를 숨기지 않도록 설명한다.[1]

라이선스도 나뉜다.
README는 Skill과 CLI·SDK 등 채택을 위한 부분은 MIT, 엔진과 프록시 등 연결된 런타임은 BSL-1.1이라고 밝힌다.
런타임은 정해진 전환 날짜 전에는 OSI 오픈소스가 아닌 source-available이며 제삼자 대상 호스팅은 상업 라이선스가 필요하다는 설명이 있다.
무료 Skill의 조건을 전체 프록시 서비스 배포에 그대로 적용해서는 안 된다.[1]
