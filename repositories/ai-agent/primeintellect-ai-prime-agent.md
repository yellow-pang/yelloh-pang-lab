## 한 줄 요약

Prime Agent는 코딩과 조사, 오래 이어지는 작업을 수행하는 에이전트 실행 환경이다.
자체 언어 모델을 뜻하지 않는다.
모델이 지속되는 Python 환경에서 도구와 하위 에이전트를 코드로 조합하고, 별도의 호스트가 세션과 실행 수명을 관리하는 구조다.[1][2]

## 긴 대화보다 오래 남는 작업 상태

여러 파일을 조사하고 검사를 기다리는 작업에서는 다음 대화 차례에도 중간 결과가 필요하다.
모든 파일 내용을 계속 대화에 붙이면 입력이 커지고, 터미널 연결이 끊기면 진행 상태를 잃기 쉽다.
Prime Agent는 Python 변수에 작업 자료를 두고 백그라운드 세션과 목표를 유지하는 방식으로 이 문제를 다룬다.[1]

README의 RLM은 Recursive Language Model이라는 프로그래밍 모델이다.
여기서는 긴 자료를 대화문으로만 취급하지 않고 변수로 다루며, 하위 에이전트 호출을 함수 호출처럼 조합한다는 의미가 중요하다.
REPL은 코드를 입력하고 결과를 확인하며 상태를 유지하는 대화형 실행 환경이다.
모델의 사고를 무한히 확장한다는 뜻보다, 자료와 도구를 다루는 인터페이스를 바꾼 설계로 이해할 수 있다.[1][2]

## Python 표면과 TypeScript 호스트의 분업

RLM 문서에 따르면 기본 내장 모델 도구는 `ipython`이며 파일 읽기, 셸 명령, 결과 변환과 위임이 지속되는 커널에서 시작된다.
커널은 Python 코드와 변수 상태를 보관하는 실행 주체다.
변수·함수·파싱 결과는 도구 호출과 대화 압축 이후에도 남도록 설계되어 있어, 다음 단계에서 이미 정리한 자료를 재사용할 수 있다.[2]

반면 제공자 호출, 대화 저장, 자식 에이전트 수명, 일정과 안전 정책은 TypeScript 호스트가 관리한다.
문서의 host bridge는 Python 쪽 요청을 호스트가 검증하고 권위 있는 상태 변경을 맡는 통로다.
모든 기능을 Python에서 호출한다고 인증 정보나 세션 저장까지 모델 코드가 직접 소유하는 것은 아니다.[2]

`rlm.spawn()`은 별도 문맥을 가진 하위 에이전트를 만든다.
중요한 점은 반환값이 답변이 아니라 접수된 작업의 handle이라는 것이다.
handle은 하위 작업 ID, 이름, 세션 디렉터리와 모델을 가리키는 참조다.
실제 결과는 명시적인 에이전트 메시지나 파일로 돌아온다.
위임 요청 성공과 작업 완료를 구분하는 규칙이 인터페이스에 드러난다.[2]

Continual Harness는 반복 작업에서 얻은 보조 지침·기억·Skill 설명 등을 지속 상태로 남기는 또 다른 축이다.
README는 `/refine`이 근거 있는 작은 수정과 되돌리기용 기록을 만들 수 있지만, 변경 불가능한 기본 시스템 프롬프트를 다시 쓰지는 않는다고 설명한다.
따라서 “자기 개선”은 모델 가중치가 자동으로 학습된다는 뜻이 아니라 보조 실행 지침을 검토·조정하는 범위로 읽어야 한다.[1]

## 예시로 따라가는 흐름

공식 RLM 문서에는 공개 API 검토, 테스트 범위 검토, 느린 통합 점검을 서로 다른 이름의 하위 에이전트에 맡기는 예제가 있다.
이를 읽는 순서는 세 요청을 독립 작업으로 구분한 뒤 각각 `rlm.spawn()`을 호출하고, 접수 handle을 보관하는 것이다.
이는 예제를 설명한 것이며 실제 검토나 테스트를 실행한 결과가 아니다.
부모는 handle이 돌아왔다고 검사가 통과했다고 말할 수 없다.[2]

자식 에이전트는 독립 문맥에서 지정된 과제를 처리하고 `agent_message.send()`로 부모에게 응답하거나 결과 파일을 남긴다.
부모는 보고된 문제와 실제 산출물을 모아 요청한 API와 테스트의 관계를 확인한다.
새 회귀 테스트가 추가되었다면 유지된 자식에게 그 변경을 다시 점검하도록 메시지를 보낼 수 있다.
하위 에이전트가 남아 있다는 성질은 반복 검토의 문맥을 이어 주지만, 수정된 코드에 대한 이전 검사 결과를 자동으로 새 결과로 바꾸지는 않는다.[2]

같은 문서의 `bash()` 예는 긴 명령을 기다리는 방식도 분리한다.
동기적으로 결과를 기다리거나 실행 handle을 보관한 채 차례를 끝낼 수 있고, 완료 알림 뒤 저장된 결과를 다시 읽는다.
사람이 최종 확인할 것은 세 작업이 모두 반환되었는지, 어떤 명령의 종료 상태인지, 검토 범위가 원래 목표를 덮는지다.
병렬 작업 수 자체는 완료 근거가 아니다.[2]

## 지속 실행은 보안 격리가 아니다

README와 RLM 문서는 모두 모델이 만든 Python과 프로젝트 명령이 사용자 또는 worker의 운영체제 권한으로 실행된다고 경고한다.
worker와 kernel의 분리는 실행 수명과 복구를 위한 것이며 보안 샌드박스가 아니다.
신뢰하지 않는 저장소·지침·Python Skill은 외부 격리 환경에서 다루어야 한다.[1][2]

자율 모드도 무제한 성공 장치가 아니다.
차례 수·토큰·시간 예산을 두고 품질 검사를 연결할 수 있지만, 제한에 도달했다고 작업이 완성된 것은 아니라는 설명이 있다.
검사 통과는 그 검사가 확인한 범위에만 해당한다.
백그라운드 실행을 선택하면 남은 프로세스와 모델 사용량, 유지되는 목표와 일정도 관리 대상이 된다.[1]

실행 전에는 제공자 인증과 되돌릴 수 있는 작업 디렉터리가 필요하다.
README가 깨끗한 작업 복사본이나 확인 가능한 체크포인트를 권하는 이유는 실제 명령과 파일 수정 권한이 있기 때문이다.
이 글에서는 해당 설치나 인증을 수행하지 않았다.[1]

## 정리

Prime Agent는 코드로 도구를 조합하고 상태와 하위 작업을 장기간 유지하는 harness다.
핵심은 긴 작업의 재개 가능성이며, 접수·완료 보고·검증과 권한 경계를 분리해서 이해해야 한다.
