## 한 줄 요약

OpenSEO는 키워드 조사, 순위 추적, 사이트 점검과 검색 관련 데이터를 웹 화면과 AI 에이전트에서 사용하는 SEO 도구다.
SEO는 검색 서비스가 페이지를 이해하고 사용자가 필요한 정보를 찾도록 사이트와 콘텐츠를 개선하는 작업이다.
이 프로젝트는 자체 호스팅 경로와 MCP 연결, 작업별 Skill을 함께 제공하지만 외부 데이터 비용까지 사라지는 무료 검색 데이터베이스는 아니다.[1]

## 검색량 하나로 글 주제를 고르기 어려운 이유

개인 사이트에 어떤 글을 쓸지 정할 때 많이 검색되는 단어만 모으면 실제 사이트와 맞지 않는 주제가 섞일 수 있다.
같은 단어도 구매 의도인지 사용법을 찾는 의도인지에 따라 필요한 페이지가 달라진다.
OpenSEO의 키워드 조사 Skill은 씨앗 주제에서 후보를 찾되 사이트 목적·검색 의도·경쟁 난도·현재 결과 화면을 함께 보도록 한다.[2]

검색량, 난도, 클릭당 광고 비용 같은 지표는 서로 다른 신호다.
검색량이 크다는 이유만으로 만들기 쉬운 페이지이거나 방문자가 목표 행동을 한다고 단정할 수 없다.
Skill은 실질적인 주제 적합성과 의도를 우선하며 값이 없으면 `unknown`으로 쓰라고 명시한다.[2]

## 앱, MCP, Skill의 역할

README는 키워드 연구 외에도 순위, 경쟁 사이트, 외부 링크, 사이트 감사와 AI 노출 관련 흐름을 나열한다.
여기서 이 목록은 제공 범위를 소개하는 자료이며 각 항목의 정확도나 지원 세부를 모두 검증한 결과는 아니다.
대표 기능은 별도의 키워드 조사 지침으로 더 구체적으로 확인했다.[1][2]

MCP 서버는 에이전트가 데이터 기능을 호출하는 연결 입구이고, Skill은 어떤 순서로 호출하고 결과를 해석할지 정하는 작업 지침이다.
웹 화면과 에이전트가 같은 프로젝트 맥락을 공유하도록 하는 도구가 있으며, 키워드 조사도 `projectId`를 기준으로 시작한다.
프로젝트가 빠졌으면 목록을 먼저 확인하도록 한다.[1][2]

`get_project_context`로 사이트 설명과 목표를 읽고, 필요한 정보가 비어 있으면 최소한의 질문이나 확인으로 채운다.
모든 설정 인터뷰를 앞에 몰아넣는 대신 이번 조사에 필요한 맥락부터 확보하는 방식이다.
종료 시에는 오래 유지할 가치가 있는 요약과 조사 기록을 저장하도록 안내한다.[2]

## 조사와 저장을 분리하는 절차

키워드 발굴 도구는 씨앗 주제에서 후보를 찾고, 지표 조회 도구는 이미 정한 단어에 검색량·난도·의도·추세를 붙인다.
Search Console이 연결된 경우에는 사이트가 이미 노출되는 검색어를 출발점으로 삼는 경로도 있다.
SERP는 실제 검색 결과 페이지를 뜻하며, 의도가 모호하거나 유망한 후보에 대해 이 결과를 확인하도록 한다.[2]

중복된 최근 조사가 있다면 다시 유료 요청을 하기 전에 로그를 보고 재사용한다.
추천한 단어를 저장하는 행동도 자동으로 하지 않고 명시적 확인을 요구한다.
자료 조사와 영구 목록 변경, 비용이 발생하는 호출을 각각 다른 결정으로 취급하는 부분이다.[2]

결과물은 짧은 우선순위 목록과 더 긴 후보 표, 각 추천의 근거, 위험과 다음 행동으로 구성된다. `seo-report` Skill을 통해 보고서를 전달하도록 하며 그 Skill이 없으면 HTML을 작성하기 전에 중단하라고 한다.
키워드 지침 하나만 확보했다고 전체 보고서 경로가 독립적으로 완성되는 것은 아니다.[2]

## 예시로 따라가는 흐름

개인 사진 촬영 학습 사이트에서 “실내 사진”을 중심으로 글 주제를 정하는 이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
입력은 해당 프로젝트와 주제, 대상 언어·지역이다.
먼저 프로젝트 설명과 현재 목표를 확인하고 최근에 같은 범위를 조사했는지 기록을 읽는다.
지역이나 언어가 지표에 영향을 주는데 불분명하면 사용자에게 확인한다.[2]

이후 씨앗 주제를 서로 다른 조사 각도로 나누고 후보 키워드를 얻는다.
이미 Search Console 데이터가 연결되어 있다면 노출이 생긴 검색어도 검토한다.
후보에 지표를 붙인 뒤 사이트와 맞지 않거나 중복된 단어를 제외하고, 검색 의도가 불분명한 경우 실제 결과 페이지를 살핀다.
출력은 어느 글에 연결할지와 추천 이유를 담은 표이며, 데이터가 없는 칸은 모르는 상태로 남긴다.
사람은 지표가 자기 시장과 언어에 해당하는지, 결과가 촬영 방법인지 장비 구매인지, 제안한 페이지를 실제로 작성할 수 있는지 확인한다.
유망한 단어라도 저장 전에는 별도 확인을 받고, 검색 순위가 올랐다고 주장하지 않는다.
이 원고에서는 키워드를 조회하거나 비용을 사용하지 않았다.[2]

## 자체 호스팅의 비용과 인증

README는 데이터 취득에 DataForSEO API 키가 필요하며 자체 호스팅에서는 해당 공급자에게 직접 비용을 지불한다고 설명한다.
호스팅 서비스의 구독·요청 과금 설명도 따로 있으므로 “구독 없음”이라는 소개 문구를 모든 배포 경로가 무비용이라는 뜻으로 읽으면 안 된다.
요금은 도입 시점의 공식 가격 정보를 다시 확인할 항목이다.[1]

Docker 안내는 기본적으로 `AUTH_MODE=local_noauth`, 즉 앱 인증 검사가 꺼진 로컬 관리자로 실행된다고 명시한다.
인터넷에 공개하려면 자체 인증이 있는 프록시나 보호된 터널·사설망 뒤에 두어야 한다.
호스트 이름 허용 설정은 접근 인증을 대신하지 않으며, 개인 컴퓨터에서 화면이 열린다는 것과 공개 서버 운영 준비가 된 것은 다르다.[3]

일부 AI 기능에는 OpenRouter 키도 별도로 필요하다.
따라서 SEO 데이터 API와 모델 호출 비용을 구분해야 한다.
Docker 문서는 집계 사용 이벤트의 텔레메트리와 끄는 설정도 설명한다.
자체 호스팅이라고 모든 외부 통신이 자동으로 없어지는 것은 아니며, 키·요청 데이터·관찰 이벤트의 경로를 각각 확인해야 한다.[3]

## 정리

OpenSEO는 검색 데이터를 사이트별 작업과 에이전트 호출로 연결한다.
후보를 추천하는 것과 실제 검색 성과를 얻는 일은 다르며, 데이터 비용과 저장 승인, 자체 호스팅 인증을 별도 경계로 관리해야 한다.
