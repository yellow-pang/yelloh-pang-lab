## 한 줄 요약

확인한 기본 브랜치의 YuE는 YuE2 음악 생성 모델과 추론 코드, 예제 및 에이전트용 지침을 제공한다.
가사와 스타일 설명으로 멜로디·화음 계획을 만든 뒤 보컬과 반주가 있는 오디오로 구현하는 흐름이 중심이다.
원래 YuE의 코드와 문서는 별도 `YuE-v1` 브랜치에 보존되어 있다고 README가 안내한다.[1]

## 완성된 소리 앞에 편집 가능한 계획을 두기

음악 생성 결과가 오디오 파일 하나뿐이면 마음에 드는 선율은 유지하면서 화음만 바꾸고 싶을 때 무엇을 고쳐야 하는지 분명하지 않다.
YuE2는 중간에 읽고 수정할 수 있는 악보 형태의 계획을 드러낸다.
README의 white-box라는 표현은 모델 내부의 모든 판단이 투명하다는 뜻보다, 의도한 작곡 내용을 사람이 검사하고 바꿀 인터페이스가 있다는 의미다.[1][2]

여기서 ABC notation은 음표·길이·박자·템포와 화음 등을 텍스트로 나타내는 악보 표현이다.
에이전트가 바꾸는 대상은 이 텍스트 계획과 가사·스타일 입력이며, 실제 소리를 만드는 모델은 YuE2다.
에이전트가 존재한다는 이유만으로 별도 음악 모델이 추가되는 것은 아니며, README도 음악 생성과 편집에서 같은 생성 체크포인트를 사용한다고 설명한다.[1]

## 계획에서 오디오까지 나누어진 단계

Python API는 `plan()`에서 계획을 만들고 `generate_semantic()`, `synthesize()`, `decode()`로 진행하는 단계를 노출한다.
초보 독자에게는 곡의 구조를 정한 뒤, 음악 내용을 모델 내부 표현으로 만들고, 이를 실제 들을 수 있는 신호로 바꾸는 흐름으로 이해할 수 있다.
중간 산출물을 남기면 완성 오디오만 볼 때보다 입력과 출력의 관계를 추적하기 쉽다.[1]

설정도 목적별로 다르다. `cot="full"`은 멜로디와 화음 계획을 만들고, `cot="melody"`는 멜로디를 조건으로 두면서 반주에 더 자유를 주는 경로다.
사용자가 직접 ABC를 제공할 수도 있고, 계획 없이 가사와 스타일에서 생성하는 모드도 있다.
이 옵션들은 같은 결과를 얻는 단순한 속도 설정이 아니라 무엇을 명시적으로 제어할지 달리한다.[1]

커버 경로에서는 원본 녹음에서 SheetSage2로 선율을 옮겨 적은 뒤 악보를 검토하고 스타일을 바꾼다.
README는 SheetSage2가 별도 환경에서 실행된다고 설명하며, MERT2 특징 추출은 일반 YuE2 생성의 필수 별도 다운로드가 아니라고 구별한다.
같은 소개 페이지에 등장하는 모델들을 모두 한 번에 필요한 하나의 제품으로 묶어 이해하지 않는 것이 중요하다.[1]

## 예시로 따라가는 흐름

공식 편집 안내의 화음 수정 예제는 원본 `score.abc`와 `score-jazz.abc`를 비교한다.
후자는 화음 기호를 seventh chord로 바꾸되 멜로디, 가사 순서, 박자, 템포, 스타일과 seed를 고정하는 사례다.
Seed는 생성 과정의 무작위 선택을 통제하기 위한 입력이다.
문서는 먼저 두 악보를 검사하고 비교한 뒤 각각 별도 출력 폴더로 오디오를 만들도록 안내한다.
여기서는 해당 명령을 실행하거나 두 음원을 생성한 것이 아니라 공식 절차를 읽었다.[2]

비교 도구가 확인하는 것은 음표와 타이밍, 박자·템포 같은 악보의 불변 조건이다.
화음 차이는 의도적으로 허용하므로 이 비교가 일치한다고 해서 두 곡이 같은 소리라는 뜻은 아니다.
이후 사람은 두 결과를 직접 듣고 바꾼 화음이 실제로 들리는지, 선율이 의도한 대로 유지되는지 확인해야 한다.
원문은 지원하는 ABC 문법이 제한적이어서 도구가 악보를 거부해도 곧바로 음악적 오류라고 판단하지 말라고 경고한다.
기호 검사와 청취 검사가 서로 다른 문제를 확인하는 구조다.[2]

마지막으로 편집은 기존 오디오 일부만 고쳐 붙이는 방식이 아니라 새 녹음 전체를 생성한다.
악보의 변경되지 않은 부분이 같아도 노래 목소리, 음색, 파형이 동일하다고 보장하지 않는다.
원본을 보존하고 출력 폴더를 분리하며 곡이 잘렸는지까지 살피라는 안내는 버전 비교가 필요한 이유를 보여 준다.[2]

## 하드웨어와 이용 조건을 분리해서 읽기

README의 빠른 시작은 Linux, Python 3.12, BF16 지원 NVIDIA GPU와 24GB VRAM을 조건으로 제시한다.
따라서 소스가 공개되어 있다는 사실만으로 일반 노트북에서 같은 경로를 바로 사용할 수 있다고 판단할 수 없다.
처음 사용할 때 모델 파일을 받는 과정도 있으며, 이 조사에서는 실제 메모리 사용량이나 생성 시간을 측정하지 않았다.[1]

코드와 모델 가중치의 라이선스도 다르다.
README는 코드·Skill·문서는 Apache 2.0, 모델 가중치는 CC BY-NC 4.0에 추가 창작자 허가를 붙인 조건으로 설명한다.
개인 창작자의 결과물 수익화와 조직의 상업적 모델 사용을 구별하므로 ‘전부 Apache 2.0’이라고 요약하면 중요한 조건이 빠진다.
원본 녹음이나 가사의 권한, 목소리 사용 동의와 결과물의 적법성도 사용자가 확인할 별도 문제다.[1]

성능 표는 저자들이 지정한 데이터와 후보 선택, 디코더로 평가한 결과다.
README 자체도 지표별 순위가 다르고 작은 평균 차이가 통계적 유의성을 뜻하지 않는다고 적는다.
숫자 하나로 모든 장르·언어·편집 요청에서 우월하다고 결론 내리지 않는다.[1]

## 정리

YuE2의 특징은 가사와 스타일에서 소리를 만드는 중간에 수정 가능한 작곡 계획을 드러내는 데 있다.
계획을 유지했다는 검증, 오디오가 의도대로 들린다는 검증, 모델을 사용할 권리는 각각 따로 확인해야 한다.
