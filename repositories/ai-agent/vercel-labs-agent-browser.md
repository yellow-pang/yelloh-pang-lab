## 한 줄 요약

agent-browser는 AI 에이전트가 웹페이지를 읽고 조작하도록 만든 브라우저 자동화 명령줄 도구다.
스스로 사용자의 목표를 판단하는 AI 모델이 아니라, 외부 에이전트가 호출하는 실행 수단이다.
현재 README는 Rust CLI와 Rust 데몬이 직접 CDP로 브라우저를 제어하는 구성을 설명한다.
CDP는 Chromium 계열 브라우저를 외부 프로그램에서 관찰하고 제어하는 통신 규약이다.[1]

## 긴 HTML 대신 조작할 대상을 보여주기

웹페이지에는 메뉴, 버튼, 숨겨진 영역과 스크립트가 섞여 있다.
원시 HTML 전체를 모델에 건네면 클릭할 대상보다 관계없는 내용이 더 많아질 수 있다.
agent-browser의 대표 접근은 접근성 트리 스냅샷이다.
접근성 트리는 화면의 요소를 ‘버튼’, ‘입력칸’, ‘제목’처럼 역할과 이름으로 표현한 구조다. `snapshot -i`는 상호작용 가능한 요소를 추리고 각 대상에 `@e1` 같은 짧은 참조를 붙인다.[1][2]

이 참조는 사용자가 기억해야 할 페이지의 고정 번호가 아니다.
에이전트는 현재 화면을 읽고 참조로 클릭하거나 값을 넣은 뒤, 이동이나 내용 변경이 있으면 다시 관찰해야 한다.
공식 Skill은 페이지 열기, 스냅샷, 참조로 조작, 변화 후 재관찰이라는 반복을 제시한다.
사이트의 DOM 구조를 미리 추측해서 긴 선택자를 만드는 방식과 구별되는 부분이다.[2]

## 읽기와 실행, 세션을 분리하는 구성

명령을 입력할 때마다 완전히 새로운 브라우저를 여는 것은 아니다.
README에 따르면 데몬은 첫 명령에서 시작하고 후속 명령 사이에 유지된다.
CLI는 명령을 해석해 데몬에 전달한다.
따라서 검색어 입력 후 다음 명령에서 결과를 클릭하는 동작을 같은 브라우저 상태에서 이어갈 수 있다.
기본 유휴 종료나 복원 설정에 따라 상태 보존 범위는 달라지며, 임시 탭과 인증 상태가 언제나 저장되는 것은 아니다.[1]

공식 Skill은 작업마다 이름 있는 세션을 사용할 것을 강조한다.
이름 없는 기본 세션은 다른 에이전트와 공유될 수 있어, 한쪽의 페이지 이동이 다른 쪽 작업을 바꿀 수 있기 때문이다.
세션 분리는 단순한 출력 이름이 아니라 어떤 브라우저 상태를 조작하는지 정하는 문제다.
동시에 여러 조사를 진행할 때 ‘검색 결과가 갑자기 다른 사이트로 바뀌는’ 혼선을 피하려면 이 경계를 먼저 이해해야 한다.[2]

또한 `read`와 `snapshot`은 목적이 다르다.
문서 내용을 소비하는 것이 목표라면 `read`로 텍스트를 얻을 수 있고, 버튼과 폼을 조작하려면 참조가 있는 스냅샷이 필요하다.
URL을 명시한 읽기는 브라우저를 띄우지 않고 HTTP 자료를 읽는 경로가 있으며, URL을 생략하면 활성 탭의 렌더링된 내용을 읽는다.
로그인 상태가 필요한 화면과 공개 문서 읽기를 같은 동작으로 취급하면 필요한 정보가 빠질 수 있다.[2]

## 예시로 따라가는 흐름

공식 Skill의 검색 예제는 DuckDuckGo 페이지를 열고 ‘agent-browser cli’를 검색한 다음 결과를 클릭해 스크린샷을 남긴다.
처음 입력은 주소와 검색어다.
도구는 페이지를 연 뒤 `snapshot -i`로 검색칸을 드러내고, 에이전트는 관찰된 참조에 값을 채운 다음 Enter를 보낸다.
문서의 `@e1`은 예시 화면의 참조이므로 다른 시점의 페이지에서 동일한 검색칸이라고 가정하면 안 된다.[2]

검색 후에는 검색어가 나타날 때까지 기다리고 스냅샷을 다시 얻는다.
새로 관찰한 결과 링크를 클릭한 뒤 결과 페이지의 이미지를 저장하는 것이 문서의 마지막 단계다.
여기서 산출물은 검색 결과에 대한 주장 자체가 아니라 도구가 읽은 화면과 캡처 파일이다.
사람은 URL과 제목이 의도한 페이지인지, 배너가 내용을 가렸는지, 검색 광고를 본문 결과로 오인하지 않았는지 확인해야 한다.
이 설명은 공식 예제를 읽은 흐름이며 직접 실행한 검색 결과를 제시하는 것이 아니다.
스크린샷 생성 성공과 원하는 정보의 정확성은 별도 검증이라는 점도 중요하다.[2]

## 브라우저 권한을 자동 판단 권한으로 바꾸지 않기

README는 다른 요소가 클릭 위치를 가리면 클릭이 일찍 실패할 수 있다고 설명한다.
동의 배너나 모달이 있을 경우 가리는 요소를 처리한 뒤 새 스냅샷을 얻어야 한다.
클릭 명령을 반복하는 것보다 화면 상태가 왜 달라졌는지 읽는 것이 우선이다.
숨김 실행의 스크린샷에서는 스크롤바 표시도 옵션에 따라 달라질 수 있으므로 캡처가 사람이 보는 환경과 완전히 같다고 단정할 수 없다.[1]

Skill에는 WebMCP라는 페이지 제공 도구를 우선 활용할 수 있는 경로도 있다.
다만 해당 도구가 사용자가 허용한 작업과 맞는지, 입력 구조와 효과가 무엇인지 확인하도록 명시한다.
웹사이트가 보내는 메타데이터는 신뢰할 수 없는 사이트 데이터이지 새로운 지시나 권한이 아니다.
페이지에 도구가 노출됐다는 이유로 계정 변경이나 외부 전송을 자동 승인해서는 안 된다.[2]

도메인 허용 목록은 탐색과 페이지의 네트워크 통신을 제한하는 수단이지만 운영체제 방화벽은 아니다.
공식 Skill은 기존 CDP 세션이나 일부 플랫폼처럼 같은 수준의 초기 차단을 보장할 수 없는 연결에서 옵션을 거부한다고 설명한다.
브라우저 설치 요구사항, 선택한 연결 방식, 로그인 쿠키와 저장 상태의 민감성을 따로 살펴야 한다.
이 프로젝트를 도입했다는 사실만으로 웹 자동화의 개인정보·권한 문제가 해결되지는 않는다.[2]

## 정리

agent-browser의 핵심은 웹페이지를 짧은 관찰 결과와 실행 가능한 참조로 바꾸는 것이다.
도구는 브라우저를 조작하지만 목적 판단과 작업 승인, 변경 후 확인은 이를 호출하는 에이전트와 사람의 몫이다.
