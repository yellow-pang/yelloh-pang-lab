## 한 줄 요약

OpenResearch는 기존 코딩 에이전트를 문헌 조사와 실험 수행에 연결하는 로컬 우선 연구 작업 공간이다.
에이전트 세션, Git 기반 실험 트리, 계산 실행과 결과 자료를 한 프로젝트 안에서 관리한다.
논문 검색기만도 아니고 새로운 언어 모델도 아니며, 여러 연구 방향의 코드와 증거가 섞이지 않게 조직하는 실행 환경에 가깝다.[1]

## 실험을 많이 하는 것보다 비교 가능하게 남기기

학습률을 바꾸거나 전처리 코드를 수정해 결과를 비교할 때, 어느 코드가 어느 로그를 만들었는지 모르면 좋은 수치가 나와도 이유를 설명하기 어렵다.
병렬 에이전트를 쓰면 같은 파일을 서로 수정할 위험도 더해진다.
README는 방향마다 독립된 세션과 Git worktree를 주고 실험 변형을 트리로 기록한다고 설명한다.
worktree는 같은 저장소의 서로 다른 작업 상태를 별도 디렉터리에서 다루는 방식이다.[1]

실행은 기록된 커밋의 변경 불가능한 아카이브를 받는다.
코드가 뒤에서 바뀌더라도 이미 실행한 입력과 현재 편집 상태를 구분하려는 설계다.
로그·diff·파일·결과·산출물을 그것을 만든 작업에 연결한다는 설명은 연구 보고서의 문장뿐 아니라 실험의 계보를 보존하겠다는 뜻이다.[1]

## 실험 노드와 실행 기록은 다르다

공식 `SKILL.md`는 프로젝트 ID, 실험 ID, 실행 ID를 섞지 말라고 강조한다.
프로젝트는 전체 주제와 실행 계약을, 실험 노드는 특정 가설을 가진 코드 변형을, run은 그 노드를 실제 계산한 기록을 가리킨다.
로그를 읽으려면 실행 ID를, 실험 트리를 보려면 프로젝트 ID를 찾아야 하는 이유가 여기에 있다.[2]

이 Skill의 핵심 규칙은 결과를 얻은 노드를 다시 수정하지 않는 것이다.
기대에 못 미친 결과도 결과이므로 고정하고, 새 가설은 자식 노드에서 시험한다.
아직 기준선이나 가설에 답하지 못한 provisional 노드에서는 의존성 수정 같은 준비 작업을 할 수 있지만, 실험을 완료한 노드를 나중에 고쳐 과거 결과의 의미를 바꾸면 안 된다.[2]

실행 명령과 환경은 노드 사이에서 고정된 계약으로 취급한다.
매번 명령행 인자나 환경변수로 조건을 바꾸는 대신 커밋된 코드·설정에 변형을 기록하도록 요구한다.
이는 명령 문자열까지 함께 비교해야 하는 숨은 차이를 줄이기 위한 절차다.
실험 트리도 루트에서 끝없이 가지를 뻗기보다 한 비교 라운드의 결과를 바탕으로 선택한 방향 아래로 내려가도록 안내한다.[2]

## 예시로 따라가는 흐름

이해를 위한 가상 예시로 공개된 학습 코드의 설정을 비교한다고 가정하자.
직접 실행한 결과가 아니다.
먼저 기준 프로젝트와 실행 명령을 정하고 기준선 노드를 실행한다.
그 실행이 가설에 답하는 결과를 냈다면 좋든 나쁘든 노드를 고정한다.
다음에는 서로 다른 설정을 커밋한 자식 노드를 만들어 동일한 실행 계약 아래 비교한다.
변경점은 설명만이 아니라 각 가지의 코드에 남아야 한다.[2]

에이전트는 실행을 시작한 뒤 프로젝트의 run 목록에서 실제 실행 ID를 찾고 로그를 읽는다.
계산이 끝났다는 알림과 유효한 결과를 얻었다는 판정은 다르다.
의존성 문제로 아무 질문에도 답하지 못했다면 준비 상태를 고치는 경로, 비교할 다른 후보가 필요하면 같은 라운드의 형제를 보충하는 경로, 충분한 근거가 있으면 다음 자식으로 내려가는 경로, 중단하는 경로를 구분하도록 Skill이 설명한다.[2]

사람이 확인할 결과는 선택된 숫자 하나보다 입력 커밋, 실행 환경, 로그, 가설과 결론의 연결이다.
README의 autoresearch는 아이디어 제안·코드 수정·실행·증거 확인·다음 시도 결정을 반복하는 기능이지만, 자동 반복이 과학적 타당성을 자동으로 부여하지는 않는다.
어떤 지표를 목표로 삼았는지와 비교 조건이 유지되었는지는 별도 검토해야 한다.[1][2]

## 로컬 소유권과 원격 실행의 경계

README는 프로젝트·대화·실험·로그·코드·산출물을 로컬에 보관하고, 프로젝트 생성이나 실행이 코드를 공개하지 않는다고 설명한다.
계산은 로컬 외에도 SSH와 여러 백엔드를 사용할 수 있다.
다만 원격 자원을 쓴다는 것은 해당 환경의 계정·권한·자원 조건이 필요하다는 의미이며, 같은 소스 스냅샷만으로 하드웨어 차이까지 사라지는 것은 아니다.[1]

원격 작업 공간의 서비스는 loopback에 바인딩하지만 애플리케이션 수준 인증이 없어서 해당 호스트의 다른 사용자가 접근할 수 있다고 README가 경고한다.
또한 공식 릴리스 빌드는 익명 설치 ID에 연결된 사용 이벤트를 opt-out 방식으로 전송한다.
문서상 코드·프롬프트·파일 내용은 포함하지 않지만, 로컬 우선이 네트워크 활동 없음과 동의어는 아니다.
모델 제공자와 관리형 compute 사용도 따로 검토해야 한다.[1]

계정은 로컬 프로젝트와 실행에 필수인 것으로 설명되지 않는다.
Skill도 로컬 명령과 관리형 compute·계정 관련 인증 요구를 구분한다.
따라서 시작 안내의 로그인 명령을 보고 모든 기능이 계정 없이는 불가능하다고 결론 내리지 않아야 한다.[1][2]

## 정리

OpenResearch의 중심은 연구 에이전트를 더 많이 띄우는 것보다 실험 변형과 실행 증거의 관계를 유지하는 데 있다.
자동 탐색을 사용할 때도 노드 동결, 고정 실행 계약, 원격 접근 경계를 지켜야 비교의 의미가 남는다.
