## 한 줄 요약

Atlas는 여러 코딩 에이전트의 실행 기록과 코드 변경을 함께 살피는 데스크톱 개발 도구다.
커밋에 남는 변경 결과뿐 아니라 그 결과를 만든 세션의 요청과 도구 호출을 연결하는 체크포인트, 에이전트 사이의 공유 메모리가 중심이다.
기존 Git을 대체하는 새로운 분산 버전 관리 체계나 단일 AI 모델로 보는 것과는 다르다.[1]

## 변경은 남았는데 이유를 찾기 어려울 때

코드 변경 파일은 남아 있어도 어떤 요청을 받고 왜 그 방식을 선택했는지는 긴 대화 기록에 흩어질 수 있다.
README는 에이전트 전환 시 맥락을 다시 설명해야 하는 문제와 노트·지침·개별 에이전트 이력이 따로 존재하는 문제를 제시한다.
Atlas는 프로젝트 안의 자료와 실행 기록을 함께 모아 이후 질문과 검토에 연결하려 한다.[1]

체크포인트는 이 목적에 맞춘 연결 기록이다.
README 설명에서 커밋, 그것을 만든 세션, 프롬프트와 도구 호출, 파일 변경을 함께 추적한다.
세션은 대화와 실행의 단위이고 커밋은 코드 이력의 단위이므로 둘은 같은 것이 아니다.
코드 변경이 없는 조사 세션도 의미가 있다는 점은 대표 구현에서도 확인된다.[1][2]

## 에이전트 연결과 공유 맥락

Atlas는 외부 에이전트를 ACP라는 Agent Client Protocol을 통해 하위 프로세스로 실행하는 경로와 자체 에이전트를 앱 내부 엔진으로 실행하는 경로를 구별한다.
ACP는 앱과 에이전트가 요청·응답을 주고받는 약속이다.
공식 아키텍처 문서는 상위 화면이 두 실행 방식을 같은 연결 인터페이스로 다룬다고 설명한다.[3]

단, 목록에 지원 이름이 보이는 것과 처음 설치했을 때 실행 준비가 끝났다는 것은 다르다.
아키텍처 문서는 새 설치에는 외부 ACP 에이전트가 없고 Marketplace에서 사용자가 설치해야 실행 대상으로 등록된다고 밝힌다.
PATH에서 프로그램을 발견하는 것은 사용자에게 제안할 근거이지 자동 실행 허가가 아니라고 명시한다.
README의 “여러 에이전트를 나란히 실행”이라는 소개를 이 조건과 함께 읽어야 한다.[3]

공유 맥락은 메시지를 보내기 전 조립된다.
README에는 파일·노트 등의 `@` 참조, 계획과 결정·실패 기록, 기기 내부 임베딩 검색, 첫 메시지에서의 세션 인계 자료가 나온다.
임베딩은 글을 의미 비교에 쓸 수 있는 수치 표현으로 바꾸는 방식이다.
파일과 폴더 참조는 전체 본문을 항상 붙이는 대신 경로를 보내 필요할 때 읽도록 하는 구분도 있다.[1]

화면과 실제 상태의 소유자도 나뉜다.
React 화면은 Rust 백엔드에 명령을 보내고 사건을 받아 표시하며, 파일 접근과 프로세스 실행은 백엔드를 거친다.
아키텍처는 채팅 로그, 터미널 데이터와 편집기 본문을 화면용 상태 저장소에 모두 복제하지 말고 해당 실행부가 관리하도록 설명한다.
이는 여러 실행 흐름을 같은 창에 보여주는 것과 그 상태를 한 덩어리로 섞는 것이 다르다는 설계다.[3]

## 예시로 따라가는 흐름

공식 체크포인트 모듈의 `binding.rs`를 따라 프로젝트 등록 과정을 보자.
입력은 작업 디렉터리와 프로젝트 식별자, 저장 모드다. `detect`는 디렉터리가 Git 저장소인지, 커밋이 있는지, 얕은 복제인지와 원격 주소 등 알 수 있는 정보를 수집한다.
하지만 파일 첫 주석은 이 정보를 증거이지 진입 차단 조건이 아니라고 설명한다.
원격이 없는 저장소나 이력이 다시 작성된 저장소도 정상적인 사용 사례이기 때문이다.[2]

`bind`는 감지 결과를 저장하고 이미 등록된 프로젝트라면 두 번째 등록을 만드는 대신 정보를 갱신한다.
로컬 모드에서는 이 함수가 네트워크나 계정을 요구하지 않는다고 주석에 명시되어 있다.
Git이 없는 디렉터리도 세션은 기록할 수 있지만 커밋과 연결되는 체크포인트는 만들지 않는다는 차이도 설명된다.
이후 첫 커밋이 생기는 상황을 위해 감지 정보를 다시 읽는 함수가 존재한다.[2]

이를 공개 개인 코드의 변경 이유를 되짚는 상황에 연결할 수 있다.
이 부분은 이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
개발자는 처음에는 조사 세션만 기록하고, 나중에 실제 변경을 커밋한 뒤 연결된 세션에서 어떤 요청과 도구 호출이 있었는지 살핀다.
확인할 것은 “에이전트가 했다고 표시되었는가”만이 아니라 올바른 프로젝트·커밋과 연결되었는지, 기록 누락 상태가 있는지다.
README는 이력을 합쳐 연결이 모호해진 경우 추측 대신 고아 상태로 둔다고 설명한다.
따라서 체크포인트는 변경 이유를 찾는 자료이지 인과관계를 무조건 확정하는 증서가 아니다.[1]

## 로컬 기본값과 원격 통신의 구분

Atlas의 로컬 기록은 계정 없이 사용할 수 있지만 모든 통신이 없다고 단정하면 부정확하다.
README는 익명 사용 분석이 기본 활성화라고 밝히고, 별도 `TELEMETRY.md`는 더 구체적인 계정 연결 조건을 설명한다.
이 문서는 0.2.4부터 로그인 시 사용 데이터를 계정에 연결하고 이전 기기 이력도 합칠 수 있다고 명시한다.
따라서 README의 익명이라는 단어만 인용해 영구 익명을 보장하면 안 된다.[4]

공식 분석 문서에는 전체 전송을 제어하는 Share usage data와 계정 연결만 제어하는 별도 설정이 설명되어 있다.
계정 연결을 끄거나 로그아웃해도 이미 합쳐진 이력을 되돌리지는 않는다는 점도 있다.
로컬 코드·세션 보관, 선택적 동기화, 사용 분석, 연결한 에이전트의 모델 요청은 각각 별도 데이터 경로로 보아야 한다.
이번 조사는 문서 읽기이며 실제 네트워크 감사를 수행한 것은 아니다.[1][4]

플랫폼 지원도 README는 macOS와 Windows를 명시하고 Linux는 같은 Tauri 코드에서 빌드 가능하지만 미시험이라고 구별한다.
긴 꼬리의 ACP 등록 에이전트에 대한 QA도 진행 중이라고 적혀 있다.
여러 에이전트를 같은 코드베이스에서 쓸 수 있다는 소개가 충돌 없는 동시 수정을 보장하는 것은 아니므로, 변경 범위와 결과 검토는 별도로 필요하다.[1]

## 정리

Atlas는 에이전트가 만든 코드와 작업 맥락 사이의 연결을 보존하려는 도구다.
세션 기록, 커밋 연결, 공유 메모리를 구분하고, 외부 에이전트 설치 상태와 데이터 전송 설정까지 읽어야 전체 동작을 이해할 수 있다.
