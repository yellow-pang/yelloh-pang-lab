# Tencent/AI-Infra-Guard

## 한 줄 요약

AI-Infra-Guard, 줄여서 A.I.G는 AI 서비스와 에이전트 구성 요소의 보안 위험을 점검하는 플랫폼이다.
실행 중인 AI 인프라, MCP 서버·Skill 소스, 에이전트 작업 흐름과 모델의 안전 응답을 서로 다른 검사 대상으로 다룬다.
모든 문제를 찾아 고치거나 안전한 운영을 보장하는 방화벽과는 역할이 다르다.[1]

## 대상이 다르면 검사도 달라진다

AI 앱의 위험은 모델 답변에만 있지 않다.
취약한 서버 구성 요소, 외부 도구의 코드, 에이전트에게 전달되는 지침과 자격 증명 사용도 확인 대상이다.
레드팀 평가는 허가된 범위에서 시스템이 잘못된 행동을 하는지 시험해 방어를 개선하는 활동이며, 이 글은 자기 소유 또는 명시적 허가를 받은 환경의 방어적 점검 관점으로 한정한다.[1]

README는 인프라 스캔의 입력을 GitHub 링크가 아니라 실제 실행 중인 서비스 주소로 구분한다.
서비스 특징을 보고 구성 요소와 버전을 파악하는 fingerprinting 뒤 알려진 취약점 규칙과 대조하는 흐름이다.
반대로 MCP·Skill 검사에는 저장소 URL이나 소스 압축파일을 입력할 수 있다.
주소 입력란이 있다고 두 유형에 같은 대상을 넣는 것은 아니다.[1]

MCP는 모델이 외부 도구를 호출하는 연결 규약이고, Skill은 에이전트가 읽는 절차·자료 묶음이다.
전자는 도구 연결과 구현, 후자는 자연어 지침과 함께 포함된 코드의 위험을 보아야 한다.
Jailbreak 평가는 대상 모델의 API와 자료 집합을 사용해 안전 경계가 유지되는지 살피는 별도 기능으로 소개된다.
이 기능 구분이 특정 악용 절차를 실행할 허가를 주지는 않는다.[1]

## 대표 하위 프로젝트: Skill 정적 감사

추가로 읽은 `skill-scan` 문서는 실행하지 않고 소스와 지침을 읽는 정적 감사 도구라고 정의한다.
언어 모델을 활용하며 기본 경로는 Code Audit을 수행하고 첫 결론이 `suspicious`일 때만 Verdict Review를 추가한다. `normal`과 `malicious` 결론은 빠른 경로를 유지한다.
모든 결과를 항상 같은 횟수로 재검토하는 구조는 아니다.[2]

플랫폼 연동용 `--aig-mode`는 정보 수집, 코드 감사, 취약점 검토의 세 단계로 나뉜다.
화면에 진행 상태를 보여 주는 구조화 로그와 내부 JSON을 쓰기 위한 경로이며, 독립 CLI 기본 모드와 출력 계약이 다르다.
단독 사용에서는 기본 결과가 SARIF 2.1.0 형식이라고 문서화되어 있다.[2]

SARIF는 정적 분석 도구가 발견 내용·규칙·파일 위치를 교환하기 위한 JSON 형식이다.
위험 분류, 심각도와 파일·줄 정보를 담지만 줄 위치는 모델이 반환한 선택적 필드에 의존한다.
위치를 결정하지 못하면 경로가 `.`으로 대체된다고 문서가 설명한다.
결과 파일이 생겼다는 것만으로 모든 문제에 정확한 코드 위치가 붙었다고 할 수 없다.[2]

## 예시로 따라가는 흐름

공식 Quick Start가 사용하는 로컬 Skill 디렉터리 입력을 방어적 검토 상황으로 읽어 보자.
직접 검사를 실행한 결과가 아니다.
검토자는 공개된 Skill을 자신의 격리된 조사 폴더에 두고 어떤 파일을 점검할지와 사용할 모델 API를 정한다.
입력은 대화 프롬프트 하나가 아니라 지침과 관련 스크립트를 포함한 프로젝트이며, 출력 언어와 보고서 파일 형식도 선택 대상이다.[2]

기본 감사는 프로젝트 요약과 문자 인코딩·바이트코드 등 사전 점검 정보를 바탕으로 코드 감사를 진행하는 구조로 소개된다.
결론이 의심 상태일 때는 그 결론을 집중 재검토하고, 결과를 `malicious`, `suspicious`, `normal`로 구분한다.
문서에서 `malicious`는 명확한 공격 의도, `suspicious`는 취약하지만 명확한 공격 의도가 없는 상태를 뜻한다.
취약점의 존재와 작성자의 의도를 같은 말로 처리하지 않는 구분이다.[2]

결과를 SARIF로 받았다면 검토자는 위험 코드, 심각도, 근거 설명과 실제 해당 파일을 나란히 확인한다.
경로가 모호한 항목은 원문을 더 읽어야 하며, 위험 점수만 보고 배포를 승인하지 않는다.
문서의 점수는 심각도별 감점을 합산하는 규칙이지 안전할 확률이 아니다.
수정 뒤 같은 범위로 다시 확인하고 누락·오탐 여부를 사람이 판단하는 단계가 남는다.
이 예시는 악성 Skill 제작이나 타인의 시스템 공격 방법을 다루지 않는다.[2]

## 검사 결과를 믿기 전에 볼 경계

루트 README는 플랫폼에 인증 기제가 없으며 공개 네트워크에 배포하지 말라고 명시한다.
보안을 점검하는 도구라고 해서 그 관리 화면 자체가 인터넷 공개에 적합한 것은 아니다.
Docker 실행 예제의 존재와 운영 환경의 접근 통제·격리는 별도 문제다.[1]

Skill 감사에는 언어 모델 API 키와 제공자 연결이 필요하다.
비공개 코드나 비밀 값이 포함된 폴더를 무심코 입력하면 외부 모델로 보내는 자료의 범위가 문제가 될 수 있으므로 입력을 최소화하고 데이터 정책을 확인해야 한다.
키는 환경 변수로 제공하라는 안내가 있으며, 이 글에서는 키를 등록하거나 외부 모델에 자료를 전송하지 않았다.[2]

README의 정확도·재현율 표는 프로젝트가 특정 평가와 모델 조합으로 발표한 결과다.
다른 Skill, 다른 언어 모델과 실제 서비스의 모든 취약점으로 일반화할 근거는 아니다.
알려진 규칙 기반의 인프라 검사도 규칙에 없거나 버전을 정확히 식별하지 못하는 위험을 모두 해결한다고 볼 수 없다.[1]

라이선스는 Apache 2.0으로 안내되며 문서는 재배포·파생물의 출처 표기도 별도로 요구한다.
실제 포함·재배포 시에는 LICENSE와 NOTICE를 함께 읽어야 한다.
이번 글은 공개된 사용 설명의 범위만 정리하며 법적 적합성이나 방어 효과를 인증하지 않는다.[1][2]

## 정리

A.I.G는 대상별로 다른 보안 검사를 한 플랫폼에 모은다.
검사 범위의 허가, 관리 화면의 비공개 운영과 모델 기반 판정의 재검토는 스캐너 바깥에서 계속 책임져야 하는 일이다.
