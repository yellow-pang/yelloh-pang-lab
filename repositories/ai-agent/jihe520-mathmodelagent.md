## 수학적 문제를 모델·코드·논문 산출물로 연결하기

MathModelAgent는 수학적 모델링 문제의 분석, 코드 작성과 그림 생성, 논문 작성 및 검증을 연결하는 프로젝트다.
모델링은 현실의 질문을 변수와 관계, 제약조건으로 표현하고 답을 구하는 방법을 정하는 일이다.
이 저장소는 수학 정리의 증명 정확성을 보장하는 시스템이 아니라, 언어 모델과 실행 도구가 그 과정을 수행하도록 단계와 결과 파일을 정하는 자동화 흐름이다.[1]

README에는 데스크톱 앱, 기존 웹·백엔드 구성, 외부 Agent 환경에서 사용하는 Skill 경로가 함께 남아 있다.
현재 설명은 앞으로 Skill 계층을 중심으로 개선한다고 밝힌다.
따라서 기존 백엔드의 기능 목록과 Skill 기반 경로, 데스크톱에 포함된 실행 환경을 하나의 동일한 구현으로 뭉뚱그리면 안 된다.
이 글은 추가로 확인한 Skill 진입점을 중심으로 동작을 설명한다.[1][2]

## 문제 풀이와 논문 작성 사이의 파일 경계

`1start-mathmodel/SKILL.md`는 전체 진입점이며 후속 Skill을 대신하지 않는다고 명시한다.
먼저 조판 엔진, 대회 종류, 논문 언어, 하위 문제 수처럼 흐름을 실질적으로 바꾸는 조건을 묻고, 선택한 내용을 `plan.md`에 남긴다.
Typst와 LaTeX는 수식과 그림이 포함된 문서를 조판하는 도구다.
논문 형식 결정이 마지막 장식이 아니라 필요한 템플릿과 컴파일 경로를 정하는 입력이다.[2]

그다음 `todo.md`에 단계별 상태를 기록하며 분석·모델링, 코드·데이터 그림, 개념도, 논문, 검증 순서로 진행한다.
분석 보고서는 변수·제약·평가지표와 해법을, 결과 보고서는 코드 실행에서 얻은 산출물을 전달한다.
최종 논문은 이 자료를 참조해야 하며 작성 Skill이 숫자 결론을 만들어 내면 안 된다는 규칙이 명시되어 있다.[2]

데이터 그림과 개념도도 구분된다. `3coding-visual`은 계산 결과를 바탕으로 한 그래프를 맡고 `4drawio`는 흐름도와 구조도처럼 수치에 의존하지 않는 그림을 맡는다.
글을 쓰는 단계는 이미 만든 그림을 어느 위치에 넣을지 결정한다.
비슷하게 생긴 그림이라도 계산을 검증할 근거인지 설명을 돕는 도식인지 역할이 다른 것이다.[2]

## 예시로 따라가는 흐름

공식 시작 Skill은 문제 수에 따라 `problem1.py`, `problem2.py` 같은 코드와 보고서, 결과 폴더를 구성하는 예시를 제공한다.
이를 여러 대안의 비용과 성능을 비교하는 공개 연습 문제에 대입해 볼 수 있다.
이 주제는 이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
입력에는 문제 문장과 제공 데이터, 원하는 문서 형식이 필요하고, 첫 분석에서는 비용·성능을 어떤 변수로 나타낼지와 비교 제약을 정해야 한다.[2]

코드 단계가 그 모델을 계산하고 결과 표와 데이터 그림을 만들면 논문 단계는 결과 보고서에서 값을 가져와 설명한다.
개념도가 필요하면 계산 순서를 도식화하되 수치 그래프를 임의로 다시 그리지 않는다.
마지막 검증 단계의 산출물은 `VERIFY_REPORT.md`이며 재현성, 일관성, 파일 완비 여부와 형식을 확인하도록 되어 있다.
사람은 입력 단위가 같은지, 선택한 모델이 질문의 조건을 실제로 반영하는지, 논문의 수치가 계산 결과와 같은지 살펴야 한다.
PDF가 컴파일된 사실은 문제의 수학적 가정이나 해법이 타당하다는 증거가 아니고, 제출 형식이 맞는 것과 연구 내용이 좋은 것도 별개의 판단이다.

## README 안의 상충하는 설명을 읽는 법

기능 소개에는 인터넷 검색, RAG 지식 검색, 사람 승인과 여러 단계의 실패 복구가 열거되어 있다.
하지만 같은 README의 계획 부분에는 일부 기능이 미완성이거나 설정만 있고 핵심 로직이 없다는 주석이 있다.
예를 들어 RAG는 핵심 검색 로직 미구현, HIL은 워크플로 통합 미완료, Tavily 검색 계획은 현재 OpenAlex로 대체되었다고 적혀 있다.
이 때문에 위 목록을 모두 검증된 지원 기능으로 소개하지 않는다.[1]

Skill 경로도 ‘자동 완료’ 문구만 보고 무제한으로 실행해서는 안 된다.
README의 사용 예시는 Agent의 승인 우회를 포함하고, 대표 Skill의 허용 도구에는 셸과 파일 쓰기, 웹 조회 등이 들어 있다.
이러한 권한은 코드 실행과 외부 요청, 여러 파일 생성으로 이어질 수 있다.
연습 환경에서도 허용할 폴더와 입력 데이터, API 비용, 결과 검토 지점을 먼저 정하는 편이 안전하다.[1][2]

프로젝트는 실험적 개발 단계이며 버그가 남아 있다고 설명하고, AI 생성은 참고용이라는 면책 문구도 둔다.
‘바로 제출할 논문’이나 시간 절감·수상 수준에 관한 표현은 프로젝트의 지향이나 홍보 문구이지 이번 조사에서 확인한 성과가 아니다.
대회나 교육기관의 AI 사용·표절·데이터 이용 규칙은 사용자가 별도로 준수해야 한다.[1]

또한 README의 저작권 안내는 개인 무료 사용과 비상업 범위를 적고 상업 이용은 저자에게 연락하라고 한다.
앞부분의 무료·공개 표현만으로 일반적인 상업 사용 허가를 추정할 수 없다.
이 글은 공개된 문서의 범위를 설명하며 별도의 권리 허가를 제공하지 않는다.[1]
