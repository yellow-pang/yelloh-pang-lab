## 문서를 검색 가능한 근거로 바꾸는 RAG 엔진

RAGFlow는 문서를 읽고 검색한 자료를 언어 모델의 답변 근거로 전달하는 RAG 엔진이며 Agent 작업 흐름도 제공한다.
RAG는 검색 증강 생성의 줄임말로, 모델이 기억한 지식만으로 답하게 하지 않고 질문과 관련된 자료를 찾아 함께 주는 방법이다.
저장소 자체가 새로운 언어 모델을 학습한 결과물은 아니다.
문서 처리, 검색, 모델 연결과 인용 추적을 하나의 흐름으로 구성하는 쪽에 가깝다.[1]

스캔한 자료나 표가 많은 PDF는 복사한 텍스트만으로 읽기 어렵다.
머리말이 본문 사이에 끼거나 표의 숫자와 열 제목이 떨어지면 검색 결과가 있어도 잘못 해석할 수 있다.
RAGFlow가 강조하는 출발점은 문서의 내용뿐 아니라 구조를 읽고, 사람이 확인할 수 있는 조각으로 만드는 일이다.
입력이 잘못되면 답변 모델을 바꾸는 것만으로 해결하기 어렵다는 문제를 다룬다.[1][2]

## 문서의 구조를 먼저 읽는 DeepDoc

대표 공식 자료인 `deepdoc/README.md`는 시각 인식과 파서라는 두 부분을 설명한다.
파서는 파일 내용을 프로그램이 다룰 수 있는 구조로 해석하는 도구다.
OCR은 이미지 속 글자를 추출하고, 레이아웃 인식은 본문·제목·그림·표·머리말·꼬리말처럼 역할이 다른 영역을 구분한다.
두 과정은 문자를 읽는 것과 그 문자가 어디에 속하는지 이해하는 일의 차이다.[2]

표 구조 인식은 열, 행, 열 제목, 투영된 행 제목, 여러 칸에 걸친 셀을 구분한다.
DeepDoc은 표 내용을 언어 모델이 이해하기 쉬운 문장으로 다시 구성한다고 설명한다.
스캔 문서의 표가 돌아간 경우 OCR 신뢰도를 비교해 방향을 정하는 자동 회전 기능도 문서에 소개되어 있다.
다만 이는 처리 방식의 설명이며 이번 조사에서 회전된 표 인식률을 측정한 것은 아니다.[2]

PDF 파서의 출력에는 페이지 번호와 사각형 좌표가 붙은 텍스트 조각, 잘라낸 표 이미지와 문장으로 변환된 내용, 그림과 캡션 및 그림 속 글자가 포함된다고 한다.
이 위치 정보는 답변의 근거를 원문에서 다시 찾는 데 중요하다.
원문 추적은 문장 옆에 링크를 붙이는 일만이 아니라 추출한 내용과 실제 문서의 관계를 보존하는 일이다.[2]

## 조각 만들기와 검색을 연결한다

메인 README는 템플릿 기반 chunking, 조각 시각화와 사람의 개입, 관련 참조의 빠른 확인을 소개한다.
Chunk는 검색과 모델 입력에 쓰도록 나눈 문서의 일부다.
문서마다 제목과 문단 구조가 다르므로 어디에서 나누는지가 검색 결과의 의미에 영향을 준다.
표의 제목과 값이 다른 조각으로 떨어지면 관련 숫자를 찾고도 어떤 조건의 값인지 알기 어려울 수 있다.[1]

또한 모델 설정에서 언어 모델과 임베딩 모델을 구분하고, 여러 검색 결과를 모아 다시 순서를 정하는 재순위화도 설명한다.
임베딩은 문장이나 자료를 의미 비교에 쓸 숫자 표현으로 바꾸는 방식이다.
이 구조에서는 ‘자료를 읽는 모델’, ‘관련 자료를 고르는 과정’, ‘최종 문장을 만드는 모델’이 한 가지 판단으로 합쳐지지 않는다.[1]

## 예시로 따라가는 흐름

표가 포함된 공개 안내 PDF에서 특정 항목의 조건을 묻는 상황을 생각해 볼 수 있다.
이는 이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
입력 문서를 DeepDoc 경로로 처리하면 OCR과 레이아웃 분석으로 본문과 표 영역을 나누고, 표의 행·열 관계를 해석해 내용과 위치가 있는 자료를 준비한다.
이후 적절한 분할 방식으로 조각을 만들고 질문에 관련된 조각을 검색한 뒤 모델에 전달하는 흐름이다.[1][2]

답변 단계의 기대 결과는 조건을 설명하는 문장과 되짚어 볼 근거다.
그러나 사람은 답변의 인용이 실제 질문과 같은 항목을 가리키는지, 표에서 단위와 예외 조건이 빠지지 않았는지, 다른 페이지의 비슷한 이름을 혼동하지 않았는지를 원문으로 확인해야 한다.
잘못 읽힌 숫자는 검색에서 높은 관련성을 보여도 틀린 근거다.
따라서 문제가 생겼을 때 답변 문장만 바꾸기보다 원문 추출, 조각 경계, 검색된 참조를 순서대로 점검하는 것이 이 엔진의 구성에 맞는 읽기 방식이다.

## 자가 호스팅은 문서 업로드 이상의 작업이다

README의 자가 호스팅 전제에는 여러 CPU 코어, 메모리와 디스크, Docker·Compose 등의 조건이 명시되어 있다.
제공 Docker 이미지가 x86용이며 ARM64에서는 별도 빌드 안내를 따라야 한다는 주의도 있다.
이름이 Python 패키지처럼 보이더라도 전체 서비스의 저장·검색·웹 구성까지 포함하면 작은 스크립트를 실행하는 것과는 다르다.[1]

코드 실행기 기능에는 gVisor가 필요한 것으로 안내된다.
gVisor는 프로그램 실행을 격리하는 기반이며, 문서 검색만 하는 기능과 외부 코드를 실행하는 기능의 위험은 다르다.
코드 실행, 외부 데이터 동기화, 모델 API를 선택할 때는 각각 필요한 권한과 데이터 전송 범위를 별도로 확인해야 한다.[1]

README의 정확도와 ‘환각 감소’ 표현은 프로젝트의 목표와 설명이지 모든 문서에 대한 보증이 아니다.
특히 DeepDoc의 이력서 설명에는 파서 자체는 아직 공개하지 않았다는 주의가 있다.
문서에서 특정 분야를 언급했다는 사실만으로 전체 특수 파서가 제공된다고 확장해 해석해서는 안 된다.[2]

## 정리

RAGFlow는 복잡한 문서를 모델이 사용할 근거로 바꾸는 처리·검색·인용 흐름을 제공한다.
답변의 신뢰성은 모델만이 아니라 추출 구조와 조각, 검색된 자료에 함께 달려 있으며 원문 확인은 여전히 필요하다.
