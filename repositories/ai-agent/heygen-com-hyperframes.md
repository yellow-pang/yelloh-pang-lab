## 웹 화면을 시간에 따라 그려 영상으로 바꾸기

HyperFrames는 HTML, CSS, 미디어와 특정 시간으로 이동할 수 있는 애니메이션을 MP4 영상으로 바꾸는 프레임워크다.
HTML은 화면 요소의 구조, CSS는 모양과 배치를 표현한다.
이미지나 동영상 생성 모델 자체가 아니라, 이렇게 작성한 화면을 정해진 시각마다 그려 영상 파일로 묶는 렌더링 도구다.
CLI로 직접 사용하거나 코딩 Agent의 Skill과 연결할 수 있다.[1]

제품 소개 영상에서 제목이 언제 나타나고 배경 영상은 얼마나 재생되며 음악은 어느 구간에 흐르는지 정해야 한다.
일반 웹페이지의 애니메이션은 페이지가 열린 순간부터 시간이 흐르는 경우가 많지만, 영상 제작에서는 ‘특정 시각의 화면’을 다시 정확히 얻는 것이 중요하다.
HyperFrames는 브라우저에서 재생되는 화면에 시간 정보를 선언하고 렌더러가 각 프레임의 시각으로 이동하도록 구성한다.[1]

## 구성 요소와 시간을 분리해 적는다

README의 HTML 예시는 `data-composition-id`로 장면을 식별하고 `data-width`, `data-height`로 화면 크기를 정한다.
영상과 제목에는 시작 시각과 지속 시간을 붙이며, 음악에도 재생 구간과 음량을 적는다.
GSAP 같은 애니메이션 도구의 일시정지된 타임라인을 등록하면 렌더러가 원하는 시간으로 이동해 요소의 상태를 계산할 수 있다.
마지막에는 화면 없는 Chrome으로 프레임을 얻고 FFmpeg로 인코딩한다.[1]

대표 자료인 `hyperframes-core/SKILL.md`는 일반 웹 코딩과 다른 약속을 명시한다.
장면 ID와 `window.__timelines`의 키가 일치해야 하고, 최상위 HTML과 하위 장면의 `<template>` 형식은 서로 바꾸어 쓸 수 없다.
장면 전체의 길이가 명시되어 있으면 애니메이션이 더 길어도 잘릴 수 있다.
이런 규칙은 화면이 한 번 보이는지만 확인해서는 찾기 어려운 시간축 오류를 줄이기 위한 것이다.[2]

트랙 역시 영상 편집기의 줄과 비슷하게 보이지만, `data-track-index`는 Studio 표시 영역이지 시간을 자동으로 비우는 제약이 아니라고 설명한다.
겹치면 안 되는 요소는 작성자가 시작 시각과 지속 시간을 맞춰야 한다.
미디어의 재생과 clip의 표시 여부는 프레임워크가 관리하므로 작성한 애니메이션이 같은 속성을 동시에 제어하면 충돌할 수 있다.[2]

## 예시로 따라가는 흐름

공식 README의 작은 장면은 `intro.mp4`를 배경에 놓고 ‘Launch day’ 제목을 뒤이어 나타내며 `music.wav`를 함께 재생한다.
작성자는 영상과 제목의 시작·종료 구간을 선언하고, 제목이 아래에서 올라오며 나타나는 효과를 일시정지된 GSAP 타임라인에 등록한다.
렌더러는 실제 시간이 지나기를 기다리는 대신 각 시각으로 이동해 화면을 얻는 방식으로 이 장면을 영상으로 바꾼다.[1]

이 예시를 읽을 때는 README의 짧은 코드가 현재의 모든 검증 규칙을 만족하는 완성 템플릿이라고 가정하지 않는 것이 중요하다.
추가로 확인한 Core Skill은 모든 오디오에 ID가 있어야 하고, 이름을 지정한 글꼴에는 로컬 글꼴 파일을 연결하는 규칙이 있다고 안내한다.
따라서 예시의 개념을 이해한 뒤 실제 작성 시점의 계약과 검사 결과를 대조해야 한다.
여기서는 영상을 렌더링하지 않았다.
사람이 확인할 대상은 제목이 보이는지뿐 아니라 마지막 프레임에서 잘리지 않는지, 음악이 실제 믹서에 포함되는지, 다른 시각으로 이동해도 같은 화면이 나오는지다.[2]

## 재현성을 얻으려면 입력도 고정해야 한다

README는 같은 입력으로 같은 영상을 얻는 결정적 렌더링을 목표로 설명한다.
그러나 이것이 아무 웹페이지나 넣으면 언제나 같은 결과를 얻는다는 뜻은 아니다.
Core Skill은 렌더링 중 시계, 고정되지 않은 난수, 네트워크, 입력 상태에 의존하지 말라고 명시한다.
반복 효과도 무한 반복 대신 유한한 횟수를 사용해야 한다.
변화하는 외부 데이터나 다운로드가 장면 중간에 들어오면 프레임 재현성을 해칠 수 있기 때문이다.[1][2]

검증 결과의 의미도 주의할 부분이다.
Core Skill에 따르면 lint 오류가 있으면 레이아웃과 대비 검사가 실행되지 않아 표본 수가 0으로 나타날 수 있다.
따라서 0건이라는 숫자만 보고 시각적 검사를 통과했다고 말할 수 없다.
문서는 오류를 먼저 없애고 중간 시각의 스냅샷을 눈으로 확인하며, 사용자의 승인을 받은 뒤 렌더링하도록 안내한다.[2]

Agent용 제작 과정과 렌더링 엔진은 역할이 다르다.
Skill은 기획·HTML 작성·미디어 준비·검사를 가르치고, 엔진은 정해진 장면을 영상으로 만든다.
설치한 제작 워크플로와 외부 미디어의 출처, 로컬 렌더링 환경은 따로 확인해야 한다.
소스가 Apache 2.0으로 공개된 것과 넣은 음원·사진의 이용 권리는 같은 문제가 아니다.[1]

## 정리

HyperFrames는 HTML 화면을 시간에 따라 재현하고 영상으로 출력하는 기반이다.
웹 문법을 쓴다는 친숙함 뒤에는 프레임 단위 이동, 고정된 입력, 미디어 소유권이라는 별도의 제작 규칙이 있다.
