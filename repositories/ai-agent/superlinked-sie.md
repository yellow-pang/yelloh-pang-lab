## 한 줄 요약

SIE는 Superlinked Inference Engine의 약자로, 검색·정보 추출·문서 변환·생성 등 서로 다른 모델 작업을 한 API와 배포 기반에서 제공하는 추론 서버다.
추론은 이미 학습된 모델에 입력을 주어 결과를 얻는 과정이며, 이 저장소 자체가 모든 과제용 모델을 새로 학습하는 프로젝트는 아니다.[1]

## 에이전트 뒤에 필요한 여러 모델

문서를 읽는 에이전트는 글을 생성하는 모델 외에도 PDF를 텍스트로 바꾸거나, 관련 문서를 찾거나, 특정 이름을 추출하는 모델을 사용할 수 있다.
각각 별도 서버로 운영하면 호출 형식과 메모리 관리, 배포 구성이 늘어난다.
SIE는 이런 작업을 여러 모델이 공존하는 서버와 클러스터로 모으고 필요한 모델을 요청에 따라 로딩하는 방식으로 소개된다.[1]

클러스터는 여러 실행 자원을 묶어 요청을 처리하는 구성이며, 단일 서버의 기능과 운영 배포 구성을 구분해야 한다.
README에는 OpenAI 호환 API와 Python·TypeScript SDK뿐 아니라 Kubernetes·Helm, 게이트웨이, 자동 확장과 대시보드 설정도 안내된다.
이 파일들의 존재가 어떤 환경에서도 곧바로 같은 처리량을 낸다는 뜻은 아니다.[1]

## 작업의 의미와 모델의 이름을 구분하기

검색에서 embedding은 문장을 숫자 벡터로 바꾸는 과정이고, rerank는 이미 얻은 후보들을 질문과의 관련성으로 다시 정렬하는 과정이다.
README의 `encode`와 `score` 예제를 나란히 보면 두 기능이 다름을 알 수 있다.
검색용 벡터를 만드는 호출과 후보 문서의 순서를 매기는 호출은 서로 다른 입출력 계약을 갖는다.[1]

정보 추출은 문장 속 사람·조직 같은 항목을 찾거나 지정한 구조의 JSON을 만드는 작업으로 소개된다.
구조가 유효한 JSON이라는 것은 필드와 형식이 요구 조건을 만족한다는 뜻이지, 추출된 내용이 항상 원문과 맞다는 뜻은 아니다.
문서 변환, 이미지, 음성 등도 모델 설정에 따라 별도 작업으로 묶인다.[1]

모델 설정의 `sie_id`는 SDK에 전달하는 이름이고 `hf_id`는 가중치를 받을 Hugging Face 저장소 이름이라고 README가 설명한다.
두 값이 보통 같아도 언제나 같다고 가정할 수는 없다.
처음 호출할 때 모델 가중치를 다운로드하고 이후에는 재다운로드를 피하며, LRU eviction으로 최근 덜 사용한 모델을 내려 메모리를 관리하는 구성이 소개된다.[1]

## 예시로 따라가는 흐름

대표 공식 예제 `examples/rerank`는 같은 주제의 규제 문서 중 확정된 규칙과 제안 단계 문서를 구별해 우선순위를 바꾸는 사례다.
입력은 질문과 후보 문단, 그리고 무엇을 관련 있다고 볼지 적은 instruction이다.
예제는 같은 제목의 최종 규칙·제안 규칙과 인접 주제의 후보를 함께 사용하므로, 제목 단어가 비슷하다는 것만으로 원하는 문서를 고르기 어렵게 구성되어 있다.[2]

질문과 후보를 그대로 둔 채 “이미 채택된 규칙” 또는 “아직 제안인 규칙”이라는 기준을 바꾸어 모델의 순위를 비교한다.
정답 기준은 모델의 해석이 아니라 Federal Register의 `type` 필드에서 미리 만든다.
출력의 `item_id`, `score`, `rank`를 통해 어떤 후보가 앞에 놓였는지 살피는 구조이며, 이 점수는 확률이 아니라고 예제가 명시한다.
여기서는 원저자의 기록된 사례를 설명할 뿐 직접 호출한 결과나 새 정확도 수치를 제시하지 않는다.[2]

확인 경로도 분리되어 있다. `fetch.py`는 고정된 데이터 버전을 받고 무결성을 확인하고, `score.py`는 기록된 응답에서 결과를 계산하며, `run.py --check`는 입력에서 요청을 다시 구성하는 경로다.
실제 모델로 새 기록을 만드는 `--record`는 SDK와 API 키, 비용이 필요한 별도 단계다.
사람이 확인할 것은 질문별 기록이 빠지지 않았는지, 같은 후보 집합인지, 요청과 응답이 정확히 연결되는지다.
기록 재계산과 현재 서버의 실시간 추론 검증은 같은 일이 아니다.[2]

## 지시로 해결할 수 있는 것과 없는 것

rerank 예제는 작은 시연이며 일반 벤치마크가 아니라고 분명히 제한한다.
특히 후보 문장 자체가 채택·제안의 차이를 표현할 때만 지시를 적용할 수 있고, 원문에 없는 최신 상태 메타데이터는 instruction으로 만들어 낼 수 없다고 설명한다.
따라서 “관련성 규칙을 넣을 수 있다”와 “모든 검색 의도를 올바르게 수행한다”를 구분해야 한다.[2]

다운로드한 파일의 digest는 손상이나 잘림을 찾는 데 쓰지만 출처의 진위를 보장하는 신뢰 사슬은 아니라고 예제가 밝힌다.
원저자의 기록을 재현하는 절차가 정교해도 새 자료나 다른 모델의 성능까지 보증하지는 않는다.
이 글도 그 예제의 주장을 SIE 전체의 우월성으로 확장하지 않는다.[2]

배포에서는 모델 계열의 의존성 차이가 중요하다.
README는 Docker 이미지를 bundle별로 나누어 서로 호환되지 않는 모델 의존성을 격리하며 기본 이미지가 일부 모델 계열을 의도적으로 광고하지 않는다고 설명한다.
네이티브 경로의 Python 요구 조건, GPU·CPU·Apple Silicon 경로와 첫 다운로드 비용을 함께 확인해야 한다.[1]

OpenAI 호환이라는 표현도 필요한 endpoint와 모델별 과제가 맞는지 확인한 뒤 받아들여야 한다.
데이터가 클러스터로 들어가는 위치, 가중치 다운로드와 API 키가 필요한 서비스, 응답 지연은 모델·하드웨어·배치 크기에 따라 달라진다.
이번 조사는 실행 성능이나 개인정보 격리를 시험하지 않았다.[1]

## 직접 읽어볼 자료

- [README의 Tasks와 Quickstart](https://github.com/superlinked/sie/blob/main/README.md)
  `encode`, `score`, `extract`를 비교해 같은 서버에서도 입력과 결과의 의미가 어떻게 달라지는지 확인한다.
  모델 ID와 가중치 출처 ID의 구분도 여기서 읽을 수 있다.
- [공식 rerank 예제](https://github.com/superlinked/sie/blob/main/examples/rerank/README.md)
  같은 후보와 질문에서 relevance rule만 바꾸는 실험 구성을 읽는다.
  정답 필드와 모델이 반환한 순위를 다른 출처로 보관하는 이유를 확인할 자료다.
- [rerank 예제의 What this does NOT establish](https://github.com/superlinked/sie/blob/main/examples/rerank/README.md)
  기록된 결과의 재계산, 실제 새 추론, 범용 성능 주장을 나누어 읽는다.
  점수가 확률이 아니라는 제한과 원문에 없는 정보는 지시로 보충할 수 없다는 설명이 중요하다.

## 정리

SIE는 에이전트가 호출하는 여러 모델 작업의 서버 운영을 공통화한다.
API를 통일해도 모델별 입력 의미와 배포 의존성은 남으며, 대표 예제의 결과를 실제 자료 전체의 성능으로 일반화해서는 안 된다.
