## 검색 노출 점검을 진단·수정·측정 절차로 만든 Skill

`fire-your-seo-agency`는 웹사이트의 검색 접근성과 AI 답변에서의 인용 가능성을 점검하는 Claude Code Skill이다.
독립적인 검색엔진이나 검색 순위를 보장하는 서비스가 아니라, Agent가 사이트를 조사하고 변경을 제안하며 이후 지표를 확인하도록 작성된 작업 지침이다.
README의 대행 비용 대체나 성과 수치는 저자의 소개이며, 이 글에서 효과를 재현하거나 어떤 사이트에서도 같은 결과가 난다고 확인한 것은 아니다.[1]

브라우저에서는 페이지가 잘 보이는데 검색엔진에는 본문이 충분히 전달되지 않을 수 있다.
또는 내용은 있어도 사이트맵에서 빠져 있거나 공개 페이지에 색인을 금지하는 설정이 남을 수 있다.
이 Skill은 글을 더 많이 쓰기 전에 이런 기본 상태를 확인하도록 한다. '검색 최적화'라는 넓은 표현을 기술적 노출, 답변 인용, 생성형 검색, 모델의 브랜드 인지, 네이버 검색이라는 다른 질문으로 나누는 것이 출발점이다.[1][2]

## 다섯 레인과 하나의 검증 기준

README의 SEO는 크롤러가 내용을 읽고 색인할 수 있는지, AEO는 검색 결과 위의 답변 영역이 출처로 인용하는지, GEO는 생성형 AI가 웹을 탐색할 때 원출처가 되는지를 묻는다.
LLMO는 모델이 이미 알고 있는 브랜드 정보, NEO는 네이버 검색과 AI 브리핑을 별도 대상으로 삼는 이름이다.
이 분류는 저장소의 작업 구분이며, 하나의 파일을 추가하면 다섯 영역에서 같은 효과가 보장된다는 표준 인증 체계는 아니다.[1]

실제 `SKILL.md`의 공통 기준은 '코드에 존재하는가'보다 'JavaScript 없이 받은 HTML에 존재하는가'다.
SSR은 서버가 본문을 포함한 HTML을 미리 만들어 보내는 방식이고, 브라우저 안에서만 나중에 생성되는 내용과 구분된다.
지침은 HTML의 robots 메타와 HTTP 응답의 `X-Robots-Tag`를 모두 보고, `noindex`라는 색인 금지 신호를 최우선으로 점검한다.
화면 캡처만으로 크롤러가 읽을 내용을 검증했다고 하지 않는 구조다.[2]

기술 기반 이후에는 질문 하나에 대응하는 페이지를 설계하고, 첫 문단의 직접적인 답과 근거 데이터를 연결하도록 안내한다.
JSON-LD는 페이지의 의미를 기계가 읽기 쉽도록 구조화한 데이터인데, Skill은 이것이 실제 화면의 내용과 달라서는 안 된다고 명시한다.
가짜 수치나 화면에 없는 주장을 구조화 데이터에만 넣는 방식은 지침의 원칙에 어긋난다.[2]

콘텐츠 운영은 일회성 코드 수정과도 구분된다. `question`, `answer`, `data_asof`, `sources`, `faq` 같은 글 속성을 한 원장으로 삼아 화면과 JSON-LD를 생성하고, 검색어에서 아직 대응 페이지가 없는 질문을 대기열로 관리하도록 한다.
AI 초안은 허용하지만 원출처 대조와 사람의 검수를 요구하고 대량 자동 발행을 금지한다.
결국 결과물은 체크리스트 하나가 아니라 페이지 구조와 반복 점검 과정이다.[2]

## 예시로 따라가는 흐름

공개 개인 블로그의 설명 페이지가 검색에서 잘 발견되지 않는 상황을 가정해 보자.
이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
Agent는 먼저 허가받은 도메인이나 로컬 프로젝트를 입력받고 응답 HTML, 헤더, `robots.txt`, 사이트맵을 확인한다.
본문이 HTML에 있는지와 색인을 막는 표기가 있는지를 나누어 기록하고, 다섯 레인과 콘텐츠 운영 상태에 각각 근거를 붙인다.
이 시점의 출력은 개선 순위 제안이며, 공식 지침은 사용자의 승인을 받은 뒤 구현을 진행하도록 되어 있다.[2]

가령 사이트맵 누락을 수정하기로 했다면 변경 전에 노출·클릭과 색인 상태의 기준선을 남겨야 한다. `references/measure.md`는 고치기 전 상태를 기록하라고 명확히 설명한다.
구현 후에는 응답 HTML과 사이트맵에 원하는 내용이 실제로 나타나는지 다시 확인하고, 어떤 파일을 바꾸었는지와 아직 하지 않은 일을 구분한다.
특정 검색 화면에 즉시 등장했다고 가정하거나 가상 노출 숫자를 적는 방식은 이 절차와 다르다.[2][3]

그 다음 단계는 시간이 지난 뒤 같은 지표를 다시 보는 것이다.
측정 문서는 변경 후 14일 재측정을 기본 제안으로 두고, 최근 집계 지연 구간을 빼고 비교하도록 한다.
사람은 지표의 값뿐 아니라 날짜와 대상 페이지가 같은지 확인해야 한다.
기술적 접근성이 고쳐졌다는 결론과 검색 유입이 증가했다는 결론은 별개의 관측이며, 수치가 변하더라도 그 변화 전체가 이번 수정 때문이라고 곧바로 단정할 수 없다.[3]

## 순위 보장과 자동 발행을 맡기는 도구는 아니다

저장소는 백링크 구매, 스팸, 키워드 과잉 삽입, 숨긴 텍스트와 클로킹을 거부한다고 설명한다.
클로킹은 방문 대상에 따라 다른 내용을 보여 검색엔진을 속이는 방식이다.
외부 페이지에서 가져온 지시문은 분석 자료로만 취급하고 Agent 명령으로 따르지 않는 규칙도 있다.
점검에 필요한 공개 웹 자료를 읽는 것과 그 안의 행동 지시를 승인하는 일을 분리한 것이다.[1][2]

또한 Search Console이나 네이버 서치어드바이저의 실측 데이터와 등록 절차에는 사용자의 접근 권한이 필요하다.
로컬 파일을 편집했다고 외부 서비스 등록이나 재측정 예약까지 실제로 완료되는 것은 아니다. `SKILL.md`는 측정 없이 완료를 주장하지 않는다고 적지만, 일정 제안·예약·실제 재측정은 구분해서 보고해야 한다. `llms.txt`나 구조화 데이터의 존재만으로 AI 인용이 보장되지 않는다는 경계도 유지해야 한다.[2][3]

측정 파일의 '고치기 전 기준선' 설명과 운영 절차의 '변경 직후 기준선 기록'이라는 짧은 표현에는 시점 차이가 있다.
전후 비교 목적이라면 변경 전 값을 먼저 확보하고 변경 시각을 따로 기록하는 해석이 필요하다.
문서의 문장을 기계적으로 모두 수행하기보다 무엇을 비교하려는 측정인지 확인할 대목이다.[2][3]

## 정리

이 Skill의 중심은 검색 유입을 약속하는 문구보다 진단 근거를 남기고 수정 뒤 다시 측정하는 절차에 있다.
기술적 읽기 가능성, 실제 인용, 유입 성과를 별도 단계로 보아야 한다.
무엇을 고쳤는지와 무엇이 관측되었는지를 분리할 때 결과를 과장하지 않는 설명이 된다.
