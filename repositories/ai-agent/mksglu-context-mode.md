## 한 줄 요약

Context Mode는 AI 코딩 도구가 읽는 원시 출력을 줄이고 작업 상태를 이어 가도록 돕는 MCP 서버와 연결 장치다.
MCP는 AI 도구와 외부 기능이 요청·응답을 주고받는 규약이다.
이 프로젝트는 모델의 최대 입력 크기를 늘리는 기술이 아니라, 제한된 입력 공간에 무엇을 넣을지 관리한다.[1]

## 긴 로그를 읽고 정작 질문을 잃는 문제

AI가 파일, 웹 문서, 테스트 로그를 많이 읽으면 정작 필요한 부분보다 원문 전체가 대화 공간을 차지할 수 있다.
여기서 context window는 모델이 한 번에 참고하는 입력의 범위다.
공간이 부족해 이전 대화를 줄이는 compaction이 일어나면 현재 작업과 결정이 충분히 남지 않을 수도 있다.
Context Mode는 출력의 선별과 세션 상태 보존을 함께 해결 대상으로 삼는다.[1]

접근 방식은 모델이 모든 줄을 눈으로 읽는 대신, 필요한 분석을 코드로 표현하게 하는 것이다.
파일별 개수나 조건에 맞는 항목을 찾을 때 프로그램이 원문을 처리하고 결과만 출력하면 대화에는 작은 답만 들어간다.
README의 절감률과 세션 시간 수치는 프로젝트가 제시한 사례다.
여기서는 같은 데이터와 조건으로 재현하지 않았으므로 보편적 성능 수치로 인용하지 않는다.[1]

## 실행, 색인, 복원은 다른 일이다

`ctx_execute`는 코드를 별도 프로세스에서 실행하고 표준 출력만 대화에 전달한다. `ctx_execute_file`은 파일을 처리하는 경로다.
`ctx_index`와 `ctx_search`는 문서를 저장해 필요한 부분을 다시 찾는 역할을 한다.
색인은 검색하기 쉽게 문서를 나누고 정리하는 작업이며, README는 SQLite FTS5와 BM25 순위를 설명한다.
BM25는 질문에 등장하는 단어와 문서의 단어 분포를 바탕으로 관련 부분을 정렬하는 방식이다.[1]

긴 출력과 검색 의도가 함께 주어지면 전체 출력을 색인한 뒤 관련 부분을 돌려주는 경로도 설명되어 있다.
이는 문서를 무조건 앞에서부터 잘라 버리는 것과 다르다.
질문에 따라 필요한 위치가 뒤쪽일 수도 있기 때문이다.
한편 `src/truncate.ts`는 화면과 스냅샷용 문자열에 크기 제한을 적용하는 실제 유틸리티다.
검색으로 의미 있는 부분을 고르는 일과, 최종 전달량의 상한을 지키는 일이 분리되어 있다.[1][2]

세션 연속성은 hook에 의존한다.
Hook은 도구 호출 전후나 대화 압축 시점에 실행되는 연결 동작이다.
파일 편집, 작업, 오류, 사용자 결정을 기록하고 압축 이후 필요한 상태를 복원하는 역할이지만, 클라이언트마다 지원하는 hook과 복원 범위가 다르다.
따라서 MCP 도구를 등록한 것만으로 모든 플랫폼의 자동 라우팅과 기억 복원이 동일하게 작동한다고 볼 수 없다.[1]

## 예시로 따라가는 흐름

공식 README의 TypeScript 파일 줄 수 집계 예제를 읽어 보면 역할 분리가 분명하다.
요청은 소스 폴더에 있는 파일들을 읽어 각 파일의 줄 수를 알려 달라는 것이다.
에이전트가 파일 전체를 여러 번 대화에 넣는 대신, 실행 도구에 파일 목록을 순회하고 내용을 나누어 개수를 출력하는 JavaScript를 전달한다.
대화에 돌아오는 것은 원문 코드 전체가 아니라 파일명과 집계 결과다.
이 문단은 공식 코드의 의도를 설명하며 실제 파일을 대상으로 실행한 결과가 아니다.[1]

이때 결과 출력 자체가 커질 수도 있다.
확인한 `truncateJSON` 구현은 JSON으로 직렬화한 값이 지정된 바이트 한도를 넘으면 잘린 표시를 덧붙인다.
UTF-8 경계와 일부 문자의 쌍이 깨지지 않도록 접두부를 줄이는 처리가 있으며, 잘린 결과는 유효한 JSON이라고 보장하지 않는다는 주석이 있다.
사람은 출력이 전체 목록인지 표시용 일부인지부터 확인해야 한다.
집계 결과와 생략 표식을 구별하지 않으면 작은 출력이 정확한 전체 결과라는 잘못된 결론에 도달할 수 있다.
필요한 항목은 원문을 다시 검색하거나 범위를 나누어 조회하는 판단이 남는다.[2]

## 샌드박스라는 이름의 정확한 범위

README는 자식 프로세스의 메모리와 상태를 분리한다고 설명하지만, 보안 절에서는 코드 실행 도구가 프로세스의 파일 접근 권한을 상속하며 완전한 운영체제 샌드박스가 아니라고 분명히 적는다.
따라서 ‘대화에 원문을 넣지 않는다’는 데이터 전달 규칙과 ‘파일이나 네트워크에 접근할 수 없다’는 보안 격리는 다른 문제다.
실행 도구의 승인은 임의 코드 실행에 대한 승인으로 보고 호스트 수준의 제한을 유지해야 한다.[1]

파일 전용 도구의 프로젝트 경계 검사와 네트워크 주소 제한도 별도 항목이다.
특히 로컬·사설 네트워크 주소는 기본 허용이라고 설명되어 있어 공유 서비스와 개인 개발 환경의 판단이 같지 않다.
README의 개인정보 문구도 외부 URL을 가져오는 기능이나 별도 호스팅 대시보드 안내와 구별해서 읽어야 하며, 모든 기능이 네트워크를 쓰지 않는다는 뜻으로 확대할 수 없다.[1]

라이선스는 README에서 Elastic License 2.0의 source-available로 설명한다.
소스를 볼 수 있다는 사실만으로 MIT와 같은 사용 조건이라고 분류하면 안 된다.
또한 색인된 문서의 캐시와 세션 기록은 보존·정리 규칙이 있으므로, 장기 자료 보관소나 원본 백업을 대신한다고 생각해서는 안 된다.[1]

## 정리

Context Mode의 핵심은 원시 자료를 대화 밖에서 처리하고 필요한 결과와 상태를 되돌려주는 것이다.
작은 출력이 전체 근거를 대신하지는 않으며, 프로세스 분리·출력 절감·보안 권한은 각각 별도로 판단할 대상이다.
