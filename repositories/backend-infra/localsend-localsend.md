## 한 줄 요약

LocalSend는 같은 로컬 네트워크의 가까운 기기 사이에서 파일과 메시지를 주고받는 앱이다.
인터넷상의 중앙 저장소에 먼저 업로드하는 방식이 아니라 기기끼리 통신하는 경로를 제공하며, 여러 운영체제용 앱과 터미널용 CLI를 포함한다.[1]

## 가까운 두 기기에 파일을 옮기는 문제

노트북과 휴대전화가 같은 네트워크에 있는데 파일 하나를 옮기려고 외부 계정에 로그인하고 다시 내려받는 과정은 불필요할 수 있다.
LocalSend는 이런 근거리 전송을 대상으로 한다.
인터넷이 필요 없다는 말은 네트워크 자체가 필요 없다는 뜻이 아니다.
두 기기가 서로 통신할 수 있는 로컬 연결은 있어야 한다.[1]

README는 REST API와 HTTPS 기반 통신을 설명한다.
REST API는 기기가 정해진 요청·응답 방식으로 정보를 주고받는 접점이며, HTTPS는 전송 중 데이터를 보호하는 통신 방식이다.
각 기기에서 인증서를 생성한다는 설명도 있다.
다만 “암호화를 사용한다”는 말만으로 잘못 고른 수신자에게 보내는 실수까지 막힌다고 보아서는 안 된다.[1]

## 발견, 전송 준비, 파일 업로드

CLI 안내는 파일과 디렉터리를 선택하고 발견된 기기 목록에서 대상을 고르는 흐름을 보여 준다.
별칭 또는 IP 주소를 직접 지정하는 방식도 있다.
별칭은 발견된 기기를 하나로 특정할 수 있어야 하며, IP를 지정하면 기본 포트의 HTTPS로 직접 확인한다.
기기 발견과 실제 전송 가능 여부가 같은 문제는 아니라는 점을 알 수 있다.[1]

대표 구현인 `cli/src/send_task.rs`는 파일을 바로 보내기 전에 `prepare_upload`를 호출한다.
이 요청에는 송신 기기의 정보와 제안하는 파일 목록이 들어간다.
응답에는 세션 식별자와 받아들인 파일들이 있고, 코드는 수신 측이 수락한 파일만 순서대로 업로드한다.
수신자가 일부만 허용할 수 있다는 사실이 데이터 구조와 로그 처리에 반영되어 있다.[2]

전송 진행률도 제안한 전체 파일과 수락된 파일을 구분해 계산한다.
파일 본문은 조각을 읽어 보내는 stream으로 만들고 누적 바이트를 갱신한다.
취소가 수신자에게서 시작되었는지 로컬에서 시작되었는지 구분하며, 로컬 취소나 업로드 실패 때는 상대에게 세션 취소를 알리는 경로가 있다.
파일 전송이 단 한 번의 HTTP 요청이 아니라 준비와 여러 업로드, 종료 처리를 가진다는 점이 드러난다.[2]

## 예시로 따라가는 흐름

공식 CLI 안내의 예는 `report.pdf`, `photo.jpg`, `project-backup` 디렉터리를 함께 전송하는 것이다.
입력으로 파일과 폴더 경로를 넘기면 발견된 기기 목록이 열리고 목적지를 선택하는 흐름이다.
디렉터리는 재귀적으로 파일을 모으며, 선택한 루트 이름과 내부 경로를 수신 측에 보존한다고 README는 설명한다.
빈 디렉터리는 파일 항목이 아니므로 전송되지 않는다는 예외도 명시되어 있다.[1]

확인한 송신 코드에 이어 보면, 선택한 파일 목록은 먼저 전송 준비 요청으로 상대에게 제안된다.
수신자가 일부 파일만 수락하면 그 결과를 알리고 수락한 항목들의 크기로 세션을 준비한다.
이어 파일명 기준으로 순서를 정해 각 파일의 세션·식별자·토큰과 본문을 업로드한다.
파일 경로를 선택한 순간 모든 내용이 무조건 보내지는 구조는 아니다.[2]

사용자는 목적지 별칭과 실제 기기가 일치하는지, 일부 수락이나 취소가 발생했는지, 수신 폴더의 구조가 의도와 맞는지 확인해야 한다.
README 예제를 그대로 실행한 기록은 아니며 전송 시간이나 성공 로그를 새로 만들어 제시하지 않는다.
특히 백업이라는 이름의 폴더를 보냈다고 백업 정책과 복구 가능성까지 검증되는 것은 아니다.
빈 디렉터리 보존이 필요한 작업이라면 이 파일 중심 전송 방식의 경계를 고려해야 한다.[1][2]

## 네트워크 조건과 앱별 차이

README의 문제 해결 안내는 방화벽, 공유기의 AP isolation, 운영체제의 로컬 네트워크 권한과 VPN을 확인하도록 한다.
AP isolation은 같은 무선망의 기기끼리 직접 통신하지 못하게 하는 기능이다.
같은 Wi-Fi 이름으로 접속했다는 사실만으로 서로 발견할 수 있다고 단정할 수 없는 이유다.
직접 IP로 보내기가 된다면 발견 경로와 통신 경로를 나누어 조사할 단서가 된다.[1]

공식 송신 코드에는 CLI가 PIN을 요구하는 응답을 처리할 때 지원하지 않는다는 메시지가 들어 있다.
따라서 그래픽 앱에서 가능한 전송 경험과 CLI의 지원 범위를 동일하게 보아서는 안 된다.
코드는 HTTP와 HTTPS 채널을 구분하고 HTTPS에서는 예상 fingerprint를 넘기는 구조도 보인다.
fingerprint는 인증서를 식별하는 값이며, 이 분기를 근거로 모든 설정에서 무조건 암호화된다고 일반화하지 않는다.[2]

앱에는 자체 자동 업데이트가 없으므로 README는 앱 스토어나 패키지 관리자를 통한 다운로드를 권장한다.
소스로 빌드하는 경우에는 지정된 Flutter 버전과 시스템 설치 버전의 불일치가 문제를 만들 수 있다고도 안내한다.
완성 앱을 이용하는 절차와 개발 환경을 만드는 절차는 별도로 읽는 것이 좋다.[1]

## 정리

LocalSend는 로컬 기기 사이의 파일 전달을 위한 앱이며, 송신 구현은 준비 요청과 수락된 파일의 개별 업로드를 구분한다.
수신자 확인, 네트워크 접근 조건과 CLI의 지원 한계를 함께 읽어야 전송 기능의 실제 범위를 이해할 수 있다.[1][2]
