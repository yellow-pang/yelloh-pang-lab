## 한 줄 요약

Escrcpy는 scrcpy를 그래픽 인터페이스로 다루어 Android 기기의 화면을 컴퓨터에 표시하고 조작하는 데 초점을 둔 앱이다.
Android를 컴퓨터 안에서 새로 실행하는 에뮬레이터가 아니라 연결된 실제 기기를 다룬다.
README는 scrcpy 기반의 화면 미러링과 여러 기기 관리, 입력 매핑 등의 기능을 소개하며 일부 고급 기능은 별도 유료 확장에서 제공한다고 밝힌다.[1]

## 기기 연결과 화면 조작을 한곳에서 보기

휴대전화의 화면을 큰 화면에서 보거나 키보드·마우스로 조작하려는 상황에서는 화면을 전송하는 기능 외에도 어느 기기를 연결했는지, 어떤 모드로 열지, 연결을 어떻게 승인할지가 필요하다.
Escrcpy의 그래픽 인터페이스는 기기 목록과 조작 항목을 통해 이런 선택을 드러낸다.
화면 미러링, 녹화, 카메라·오디오 기록은 문서에서 서로 다른 모드로 분리돼 있다.[1][2]

ADB는 컴퓨터와 Android 기기 사이의 디버깅·제어 통로다.
공식 시작 안내는 개발자 모드와 USB 디버깅을 켜고, 기기에서 디버깅 승인 요청이 나오면 허용하는 절차를 제시한다.
따라서 케이블을 꽂거나 앱을 켰다는 사실만으로 모든 기기를 조작할 수 있는 구조가 아니다.
연결 통로와 사용자의 승인이 화면 미러링에 앞선다.[3]

## 화면·입력·여러 기기의 구분

미러링은 기기의 화면을 컴퓨터에서 보게 하는 기능이고 입력 제어는 그 화면에 대응하는 조작을 보내는 기능이다.
README의 Inset Mirror는 앱 안에 포함된 별도 화면과 해상도·방향 맞춤을, Keyboard Mapping은 터치·스와이프·스크롤 등의 입력 매핑을 설명한다.
화면을 본다는 것과 입력을 보낸다는 것을 구분하면 단순 발표용 표시와 실제 기기 조작의 범위 차이를 이해할 수 있다.[1]

여러 기기를 함께 다루는 기능은 편의뿐 아니라 대상 선택의 문제도 만든다.
README는 한 창에서 여러 기기를 조작하고 입력을 방송하거나 여러 기기의 스크린샷과 APK 설치를 일괄 처리할 수 있다고 소개한다.
APK는 Android 앱 설치 파일이다.
공식 Operation 문서도 일괄 미러링, 파일 관리, 스크립트 실행 등을 별도 목록으로 둔다.
한 기기에 보내려던 입력이 여러 기기에 적용되지 않는지 대상과 모드를 구별해야 한다.[1][2]

무선 연결은 USB 연결을 단순히 없앤다는 뜻이 아니다.
시작 문서는 QR 코드 페어링과 IP 주소·포트 입력을 서로 다른 연결 방식으로 설명한다.
초기 연결이 실패하면 무선 페어링이 필요할 수 있다고도 적는다.
페어링은 두 장치가 연결을 승인하고 사용할 수 있도록 짝을 맺는 과정이다.
같은 네트워크에 있다는 조건과 제어가 승인됐다는 조건은 다르다.[3]

## 예시로 따라가는 흐름

공식 Quick Start의 USB 연결 절차를 따라 읽어보면 입력은 사용자가 소유하거나 조작 허가를 받은 Android 기기와 컴퓨터다.
먼저 기기의 개발자 모드에서 USB 디버깅을 활성화한다.
그 다음 Escrcpy를 열고 기기를 연결한다.
전화기에 디버깅 승인 창이 나오면 사용자가 요청을 확인해야 한다.
이 글에서는 기기를 연결하거나 승인을 누르지 않았으며, 문서의 순서만 설명한다.[3]

연결된 기기가 목록에 나타나면 사용자는 해당 항목을 선택해 미러링을 시작한다.
예상되는 사용 흐름은 기기의 화면을 앱에서 보고 필요한 조작을 선택하는 것이지만, 실제 화면이 나타났다고 이 글에서 검증한 것은 아니다.
여러 기기를 연결한 경우에는 이름과 연결 상태를 확인해 대상을 구분하는 단계가 중요하다.
단순 미러링을 원한다면 녹화나 스크립트 실행을 같은 동작으로 취급해서는 안 된다.[1][3][2]

문제가 생겼을 때도 확인 순서가 달라진다.
목록에 기기가 없다면 연결과 디버깅 승인부터 살펴야 하고, 화면을 표시하는 단계에서 문제가 생기면 scrcpy 의존성과 실행 환경을 확인해야 한다.
제어 막대에는 홈·뒤로 가기·회전·볼륨·파일 관리·앱 설치 등 성격이 다른 조작이 있다.
결과를 확인하는 사람은 원하는 기기에서 의도한 작업만 일어났는지 봐야 한다.
앱 설치나 파일 변경은 화면 보기보다 큰 부작용을 갖는 작업이다.[3][2]

## 공개 기능과 배포 조건의 경계

README는 Escrcpy를 안정적인 통합 기반으로 설명하며 일부 고급 기능은 비공개 확장 EscrcpyX에서 유료로 제공한다고 명시한다.
따라서 README의 전체 기능 목록을 이 공개 저장소만으로 모두 사용할 수 있다는 보장으로 옮기지 않았다.
Copilot과 시각적 자동화가 목록에 있어도 구체적인 모델 연결, 과금과 배포 범위는 사용하려는 배포본의 조건을 추가 확인해야 한다.[1]

플랫폼 의존성 안내에는 시간에 따른 문구가 함께 남아 있다.
Quick Start는 macOS·Linux에 scrcpy를 수동 설치해야 한다는 안내와, Escrcpy 1.27.1 이후 바이너리가 예비 통합됐다는 설명을 나란히 싣는다.
이 때문에 모든 현재 배포본에서 별도 설치가 필요하다거나 전혀 필요 없다고 단정하지 않았다.
역테더링 도구 Gnirehtet은 Windows·Linux에 포함되고 macOS에는 수동 설치가 필요하다는 구분도 따로 있다.[3]

역테더링은 컴퓨터의 네트워크 연결을 Android 기기가 쓰게 하는 방향의 공유다.
화면 표시와는 다른 기능이며, 시작 안내에서도 기기를 연결한 다음 제어 막대에서 켜는 항목으로 다룬다.
실제 기기와 파일, 앱을 다루는 도구인 만큼 자신의 기기나 명시적으로 허가받은 기기로 범위를 제한해야 한다.
문서의 저지연·고성능 표현은 여기서 측정한 결과가 아니다.[1][3]

  미러링·입력 매핑·다중 기기 제어를 구별해 읽고, 기능 목록 위의 유료 확장 안내를 놓치지 않는다.
  공개 앱의 정체와 소개된 전체 기능의 제공 범위를 분리하는 자료다.[1]
- [Quick Start](https://github.com/viarotel-org/escrcpy/blob/main/docs/en/guide/started.md):

  USB 승인에서 기기 목록 확인, 미러링 시작까지 먼저 따라 읽는다.
  이후 QR 코드와 IP 연결을 비교하고, 운영체제별 scrcpy·Gnirehtet 안내가 자신의 배포본과 맞는지 확인한다.[3]
- [Device Operation](https://github.com/viarotel-org/escrcpy/blob/main/docs/en/guide/operation.md):

  Batch Processing, Control Model, Device Interaction Bar를 순서대로 본다.
  여러 기기에 적용하는 기능인지, 보기·녹화 모드인지, 기기에 변경을 일으키는 명령인지를 나눠 확인하는 짧은 기능 지도다.[2]

## 정리

Escrcpy는 Android 화면 전송과 제어 기능을 기기 중심의 그래픽 인터페이스로 묶는다.
연결 승인, 대상 기기, 제어 모드와 기능 제공 범위를 구별해야 하며, 자동화나 일괄 조작이 권한 확인을 대신하지는 않는다.[1][3][2]
