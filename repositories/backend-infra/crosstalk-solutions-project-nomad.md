## 한 줄 요약

Project NOMAD는 인터넷 연결이 없을 때도 지식 자료와 교육 콘텐츠, 로컬 AI 도구에 접근하도록 준비하는 브라우저 기반 서버다.
백과사전이나 언어 모델을 새로 만드는 프로젝트가 아니라, 여러 도구를 설치하고 관리하는 Command Center와 API가 중심이다.[1]

## 오프라인 사용은 사전 준비에서 시작된다

연결이 끊긴 뒤 백과사전을 검색하거나 문서에 질문하려면 자료와 실행 도구가 이미 기기에 있어야 한다.
NOMAD의 offline-first는 이 준비 과정을 묶는 방향이다.
초기 설치와 추가 자료 다운로드에는 인터넷이 필요하며, 어떤 콘텐츠를 얼마나 보관할지는 사용자가 정한다.
관리 화면이 열린다고 필요한 지식이 전부 들어 있는 것은 아니다.[1]

Command Center는 Docker 컨테이너로 제공되는 도구의 설치·설정·갱신을 조정한다.
컨테이너는 각 프로그램과 그 실행에 필요한 환경을 묶는 단위다.
서버 자체에 데스크톱 화면이 없어도 다른 기기의 브라우저로 접근할 수 있다.
따라서 서버가 맡는 일과 접속하는 화면이 맡는 일을 나누어 이해할 수 있다.[1]

## 자료 열람과 AI 검색의 다른 경로

Kiwix는 오프라인 백과사전과 전자책을 열람하는 역할을 맡고, Kolibri는 교육 콘텐츠와 학습 진행 기록을 담당한다.
ProtoMaps 기반 지역 지도, CyberChef 데이터 처리 도구, FlatNotes 메모도 안내된다.
이들은 모두 같은 종류의 AI 기능이 아니라 각기 다른 자료와 작업을 제공하며, NOMAD는 접근과 관리를 한곳에 모은다.[1]

AI 채팅에는 Ollama 또는 OpenAI 호환 API를 연결할 수 있고, 업로드한 문서를 의미로 검색하는 데 Qdrant를 사용한다.
RAG는 질문과 관련된 문서를 찾아 모델 답변의 참고 자료로 제공하는 방식이다.
모델이 모든 문서를 학습해서 기억하게 만드는 절차와는 다르다.
어떤 자료를 보관했는지와 검색 단계가 무엇을 돌려주는지가 답변의 근거 범위를 결정한다.[1][2]

확인한 `rag_service.ts`는 이 검색 계층을 더 구체적으로 보여 준다.
Qdrant 연결을 준비하고 컬렉션을 확인하며, 검색용 모델이 있는지 검사한다.
질문에는 `search_query:` 접두어를 붙여 임베딩을 만든다.
임베딩은 문장의 의미를 검색에 사용할 수 있는 숫자 배열로 바꾸는 표현이다.
그런 다음 Qdrant에서 가까운 문서 조각을 가져온다.[2]

검색 결과를 그대로 반환하는 것만으로 끝나지는 않는다.
코드에는 의미 유사도와 키워드를 이용한 재정렬, 같은 자료에 결과가 몰리는 것을 줄이기 위한 처리, 반환 개수 제한이 보인다.
이것은 검색 결과를 구성하는 방법이지 정답의 정확성을 보증하는 장치는 아니다.
지식 기반이 비어 있거나 필요한 모델이 없을 때 빈 결과를 반환하는 경로도 있으므로, 채팅 화면의 존재만으로 문서 검색 준비가 끝났다고 볼 수 없다.[2]

## 예시로 따라가는 흐름

이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
인터넷이 없는 곳에서 개인 장비 설명서를 찾아보려는 상황을 생각할 수 있다.
먼저 연결이 있을 때 필요한 도구와 모델을 준비하고, 허용된 설명서 파일을 지식 기반에 넣는다.
NOMAD의 문서 업로드와 RAG 기능은 이 자료를 나중에 질문과 함께 활용하는 경로를 제공한다.
백과사전을 내려받는 일과 이 개인 파일을 검색 가능하게 만드는 일은 별도 준비로 보아야 한다.[1][2]

사용자가 설명서의 특정 설정을 묻는 질문을 입력하면 검색 계층은 Qdrant 상태와 문서 조각의 존재를 확인한다.
질문을 전처리하고 길이를 제한한 뒤 검색용 임베딩을 만들어 관련 조각을 조회한다.
후보는 키워드와 의미 유사도 등을 바탕으로 다시 정렬되고, 상위 결과가 문서 텍스트와 점수·메타데이터 형태로 반환된다.
이 파일에서 확인한 것은 답변을 만들기 전의 자료 검색 흐름이다.[2]

사람이 확인할 부분은 질문에 맞는 설명서가 실제 포함되었는지, 잘린 문맥이 중요한 조건을 빠뜨리지 않았는지, 답변이 원문과 일치하는지다.
검색 점수는 사실 확인 도장이 아니다.
아무 문서도 검색되지 않았다면 모델의 일반 답변을 업로드 자료에서 검증된 내용으로 오해하면 안 된다.
최종 설명이 필요한 경우에는 원문 페이지를 다시 열어 대조하는 단계가 남는다.[1][2]

## 관리 화면과 실행 자원의 경계

README의 최소 요구사항은 관리 앱 자체에 관한 것이고 AI 도구의 요구사항과는 다르다.
선택한 모델과 자료에 따라 메모리, GPU와 저장 공간 수요가 커진다.
외부 호스트의 Ollama나 호환 API를 사용할 수도 있지만, 그 서버를 준비하고 모델을 내려받는 책임까지 자동으로 사라지는 것은 아니다.[1]

보안 면에서 가장 중요한 제약은 기본 인증 기능이 없다는 점이다.
README는 인터넷에 직접 노출하도록 설계되지 않았다고 밝히고, 다른 기기와 공유할 때 네트워크 수준의 접근 통제를 권한다.
오프라인용이라는 이름이 모든 접속을 자동으로 안전하게 만든다는 뜻은 아니다.
설치 스크립트가 관리자 권한을 요구한다는 사실도 배포 전에 확인해야 한다.[1]

인터넷 사용도 구체적으로 읽어야 한다.
자료 다운로드 외에 연결 상태 확인용 외부 요청이 설명되어 있으며, 자동 업데이트는 선택적으로 켜는 기능이다.
완전히 외부 통신이 없어야 하는 환경과 “연결 없이도 준비된 자료를 쓴다”는 목표는 동일하지 않다.
연결 확인 주소의 설정 방법과 업데이트 정책을 따로 검토할 필요가 있다.[1]

## 정리

NOMAD는 준비된 콘텐츠와 도구를 오프라인에서도 쓰도록 묶는 관리 계층이다.
사용할 자료, 모델 실행 장소, 접속 허용 범위를 사람이 미리 정해야 하며, 검색 기반 답변은 원문 검토를 대신하지 않는다.[1][2]
