## 한 줄 요약

Motrix는 HTTP·FTP·BitTorrent·magnet 링크 등을 처리하는 다운로드 관리자다.
다운로드할 콘텐츠를 제공하거나 파일을 검색해 주는 서비스가 아니라 사용자가 지정한 자료의 전송과 작업 상태를 관리한다.
확인한 README는 Motrix Turbo를 v2로 소개하며 데스크톱 앱과 화면 없이 실행하는 headless 서버가 같은 핵심 코드를 공유한다고 설명한다.
서버에는 NAS나 개인 서버에서 사용할 웹 UI도 포함된다.[1]

## 창을 닫아도 작업의 상태는 남아야 한다

여러 파일을 받다가 프로그램을 다시 시작하거나, 브라우저에서 고른 다운로드를 다른 기기로 넘기고 싶은 상황에서는 주소 하나를 여는 것보다 많은 관리가 필요하다.
Motrix는 작업 목록, 속도 제한, 완료 알림과 SQLite 기반 세션 복원을 제공한다.
SQLite는 별도의 큰 데이터베이스 서버 없이 파일에 구조화된 데이터를 보관하는 도구다.[1]

실제 전송 엔진은 앱에 포함된 Motrix 관리 aria2 fork다.
사용자 화면은 React·Electron으로 구성하고 작업·설정·플러그인·외부 연결을 맡는 core와 엔진 adapter를 나눈다.
adapter는 앱의 요청을 실제 전송 엔진이 이해하는 호출로 바꾸는 연결층이다.
같은 core를 데스크톱과 서버에서 쓴다는 설명은 모든 운영체제의 알림·비밀 저장 방식이 같다는 뜻이 아니라 그 차이를 별도 구현으로 감싼다는 의미다.[1]

## 브라우저와 CLI는 다른 입구다

브라우저 확장은 브라우저의 다운로드를 Motrix로 넘기고, CLI는 터미널에서 작업 추가·목록·진행 상태를 다룬다.
두 입구는 MDXP라는 공개 연결 규약을 이용한다.
MDXP는 JSON-RPC 2.0 기반으로 요청과 응답을 주고받는 방식이다.
따라서 터미널에 CLI를 설치하는 것과 실제 파일을 내려받을 Motrix 실행 환경을 준비하는 것은 구별해야 한다.[1]

원격 서버 연결에는 device-code pairing이 쓰인다.
사람이 특정 기기의 연결 코드를 확인해 승인하는 흐름으로, 주소를 알고 있다는 사실만으로 클라이언트를 신뢰하지 않도록 한다.
README는 인터넷 접근에서 TLS 역방향 프록시와 원래 포트 주변의 방화벽 규칙을 요구한다.
로컬에서 쓰는 앱을 원격 제어할 수 있게 만들면 접근 권한이 추가로 중요해진다.[1]

## 다운로드 전후를 확장하는 플러그인

Motrix의 플러그인은 `beforeCreate`, `beforeFinalize`, `afterComplete`, `onError` 같은 hook에 연결된다.
hook은 특정 시점에 추가 동작을 실행하는 지점이다.
예를 들어 작업 생성 전에 URL을 해석하거나 저장 전에 파일명을 바꾸고 완료 뒤 알림을 처리할 수 있다.
공식 README는 파일명 템플릿과 페이지 링크 추출 등을 내장 플러그인의 예로 든다.[1]

플러그인은 QuickJS 샌드박스에서 실행하고 Node.js API나 직접 파일·네트워크 접근을 주지 않는다고 안내한다.
필요한 기능과 URL별 접근 권한을 선언하고 사용자가 승인하는 구성이다.
그렇다고 설치 가능한 플러그인이 모두 신뢰할 만해지는 것은 아니다.
공식 hook 규격도 서명, 설치 동의와 권한 부여를 별도 관문으로 남겨 둔다.[1][2]

## 예시로 따라가는 흐름

배포자가 내려받도록 공개한 자료의 URL을 입력하고 저장 전에 파일명 템플릿을 적용하는 상황을 가정하자.
이해를 위한 가상 예시이며 직접 실행한 결과가 아니다.
입력은 파일 URL과 저장 위치, 활성화한 플러그인이다.
hook 규격은 입력 검증 뒤 조건에 맞는 플러그인을 찾고 역할과 ID 순으로 실행한다고 정의한다.
뒤 플러그인은 앞에서 검증해 받아들인 변경이 포함된 문맥을 보지만 실패한 변경이나 다른 작업의 문맥을 받아서는 안 된다.[2]

`beforeFinalize`가 끝나면 원본 결과물과 최종 경로·메타데이터 변경을 담은 `HookPlan`을 만들고, host가 파일과 작업 상태를 반영한다.
guest 플러그인이 반환한 효과는 데이터이며 그 자체가 저장 완료를 뜻하지 않는다.
사람은 실제 파일 경로와 이름, 완료 상태 및 다른 파일을 덮어쓰지 않았는지 확인해야 한다.
규격은 저장 디렉터리 밖으로 완료하거나 무관한 기존 경로를 덮어쓰는 것을 허용하지 않는다.
완료 뒤 알림 같은 외부 행동은 최소 한 번 전달 방식이므로 재시도에서 중복이 생길 수 있다.
플러그인은 안정적인 delivery ID로 중복을 구분해야 하며 다운로드 한 건에 외부 알림도 반드시 정확히 한 번만 발생한다고 주장할 수 없다.[2]

## 재시작 복원과 베타 이전은 다르다

세션 복원을 제공한다는 것과 오래된 버전의 데이터를 안전하게 이전한다는 것은 다른 기능이다.
확인한 README는 v2가 베타이고 v1 데이터 이전은 아직 검증하지 않았다고 명시한다.
기존 데이터와 다운로드를 백업하고 가능한 경우 별도 계정·장치·Docker 데이터 디렉터리로 시험하도록 안내한다.
현재 베타 패키지도 남은 배포 관문을 통과한 뒤 배포한다는 조건이 있으므로 문서에 버전명이 있다는 이유로 모든 플랫폼의 즉시 설치 가능성을 확정하지 않는다.[1]

다운로드 재개 여부와 전송 속도는 서버·프로토콜·파일 상태와 환경에도 영향을 받는다.
여러 연결이나 속도 제한 설정이 있어도 어떤 네트워크에서든 더 빠르다고 입증된 것은 아니다.
이 조사에서는 전송·중단·재개와 파일 무결성을 시험하지 않았다.
BitTorrent나 magnet 지원은 자료를 받을 기술적 경로일 뿐 해당 자료의 배포 권한을 대신하지 않는다.

LICENSE는 MIT이지만 같은 파일이 제3자 자산은 MIT 적용 대상이 아닐 수 있다고 별도로 경고한다.
수정·배포 시에는 고지 보존과 함께 제3자 조건도 확인해야 한다.
플러그인과 다운로드한 자료 역시 앱 코드와 같은 라이선스라고 가정하면 안 된다.[3]

## 정리

Motrix는 여러 경로의 다운로드를 작업 상태와 확장 기능으로 관리한다.
v2의 공통 core와 hook 설계를 읽을 수 있지만 베타 데이터 이전, 원격 권한과 자료별 이용 조건은 별도 검토가 필요하다.
