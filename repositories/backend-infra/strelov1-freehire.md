## 한 줄 요약

freehire는 여러 채용 출처의 공고를 하나의 형식으로 모아 검색하고, 이력서와 지원 이력까지 연결하는 오픈소스 서비스다.
새 채용 모델을 학습시키는 프로젝트가 아니라 수집 파이프라인·검색 API·웹 화면을 함께 제공한다.[1]

## 흩어진 공고를 같은 기준으로 읽기

채용 사이트마다 직무명, 지역, 근무 방식이 다르고 같은 공고가 여러 경로에 나타난다.
freehire는 출처별 데이터를 정규화하고 안정적인 키로 중복을 줄인 뒤 조건별 검색에 사용한다.
README의 ‘원출처 직결’이라는 소개와 달리, 실제 Sources에는 ATS뿐 아니라 집계 사이트와 Telegram도 포함된다.
따라서 모든 결과가 기업 채용 페이지에서 직접 수집되었다고 단정하지 않는 것이 정확하다.[1]

## 수집 작업과 검색 서버를 나누는 구조

`cmd/`에는 서버와 독립 워커, `migrations/`에는 SQL 스키마, `web/`에는 SvelteKit 화면이 배치된다.
HTTP 서버는 요청을 처리하고 수집·보강·색인은 실행 후 종료하는 워커가 담당한다.
PostgreSQL은 저장소, Meilisearch는 전문 검색과 조건 필터, Redis는 제한·실시간 전달 등에 쓰인다.[1]

`docs/architecture.md`의 검색 흐름은 색인 문서에 공개 응답 형태를 담는 이유를 설명한다.
일반 검색 결과 본문은 Meilisearch에서 반환하므로 매 결과를 PostgreSQL에서 다시 조립하지 않는다.
다만 공고 신뢰 신호는 별도로 조회하며, 그 조회가 실패하면 배지를 생략하도록 설명한다.
색인에는 설명을 줄여 담고 상세 API에는 전문을 남기므로 목록과 상세의 정보량은 같지 않다.[2]

기업을 추가할 때는 이미 지원하는 ATS라면 `boards` 카탈로그에 등록하고, 새로운 ATS라면 어댑터가 필요하다.
ATS는 기업이 지원자를 관리하는 채용 시스템이다. 회사 하나를 추가하는 일과 새 수집 방식을 구현하는 일을 분리한 설계다.
운영 사전은 모르는 직무·기술 분류를 억지로 추측하기보다 비워 두도록 설명한다.[2]

## 가상 시나리오: 원격 Go 공고 모으기

공개 공고를 대상으로 원격 근무와 Go 기술 조건을 조합하는 상황을 가정한다.
먼저 수집 워커가 게시판을 읽고 정규화한 데이터를 저장하며, 색인 작업이 검색용 문서를 갱신한다.
사용자가 필터를 선택하면 웹 화면이 API를 호출하고 API는 Meilisearch 조건으로 바꾸어 결과를 반환한다.[1][2]

검색 결과를 원문과 대조한 뒤 관심 공고를 지원 관리 화면에 연결할 수 있다.
이 흐름의 산출물은 검색 가능한 공고와 관리 기록이지, 공고의 진위나 채용 성공을 보증하는 판단이 아니다.
프로젝트도 공고 신호가 고용주의 의도를 관찰한 결과는 아니라고 경계를 둔다.[2]

## 운영 전에 확인할 경계

자체 호스팅은 웹 서버 하나만 켜는 구성이 아니다. 저장소·색인·워커와 필요한 환경변수를 함께 준비해야 한다.
`JWT_SECRET`은 필수이고 OAuth·LLM 자격증명이 없으면 관련 기능은 비활성화된다.[1]
새 필터를 코드에 먼저 배포하고 색인 설정을 늦게 바꾸면 검색 오류가 생길 수 있으므로 갱신 순서가 중요하다.[2]
README의 볼륨 재생성 예시는 기존 데이터 삭제를 동반할 수 있어 일반적인 업데이트 명령으로 복사하면 안 된다.[1]
코드는 MIT이며 저작권·허가 고지를 유지해야 한다. 이 조건이 수집 대상 사이트의 이용 조건까지 대신하지는 않는다.[3]
