## 한 줄 요약

RustFS는 파일을 버킷이라는 묶음에 객체로 저장하고 S3 방식의 API로 접근하게 하는 Rust 기반 분산 저장소이다.[1]

## 이 Repository는 무엇인가?

단일 노드와 여러 노드에 걸친 배포를 지원하며, 웹 콘솔이나 S3 호환 클라이언트로 객체를 업로드하고 내려받는다.[1]

일반 프로그램에 끼워 쓰는 파일 라이브러리가 아니라 별도로 운영하는 저장소 서버이며, S3 호환 범위는 지원표로 관리한다.[1]

## 주요 기능

- 객체 버전 관리, 보존 기간 중 변경을 제한하는 Object Lock, 수명주기 관리와 서버 측 암호화를 제공한다.[1]
- 버킷·사이트 복제, 데이터 손상 검사와 복구, 저장 공간 확장 및 축소 관련 기능을 제공한다.[1]
- 사용자 권한 정책, 웹 관리 콘솔, 감사 로그와 이벤트 알림을 제공하며 일부 추가 프로토콜은 선택 빌드 기능이다.[1]

## 어떻게 동작하는가?

```text
쓰기 가능한 데이터 경로와 인증 정보를 갖춘 서버를 준비한다.
↓
콘솔에서 버킷을 만들거나 S3 호환 도구로 객체를 업로드한다.
↓
저장된 객체를 내려받고 필요한 보존·복제·접근 정책으로 관리한다.
```

이는 README의 기본 접근 흐름이며, 분산 배치에서는 드라이브 구성과 복구용 중복 데이터 설정에 따른 제약을 별도로 따른다.[1]

### 확인한 파일 구성

- `Cargo.toml`은 `rustfs` 본체와 여러 crate, 즉 Rust 모듈 패키지를 묶은 작업 공간을 정의한다.[2]
- manifest 주석은 `crates/ecstore`를 오류 정정 저장 구현, `crates/iam`을 접근 권한 관리, `crates/scanner`를 데이터 무결성 검사 영역으로 설명한다.[2]

## 어떤 기술을 사용하는가?

- `Rust`는 서버 구현 언어이고 `Cargo`는 내부 패키지와 공통 의존성을 관리한다.[2]
- `S3 API`는 객체 저장소 클라이언트의 연결 방식이며, `Docker`와 Kubernetes용 Helm 배포 경로도 안내한다.[1]

## 실제로 어디에 사용할 수 있는가?

- 개인 실습 환경에서 버킷 생성·객체 업로드·버전 관리 등 객체 저장소의 기본 개념을 학습할 수 있다.[1]
- 복제·암호화·권한 정책이 파일 보관에 어떻게 결합되는지 공개 구성과 API 범위를 살펴볼 수 있다.[1]

## 왜 주목할 만한가?

학습 관점에서는 저장 엔진뿐 아니라 권한·키 관리·검사·알림을 별도 패키지로 나눈 구성이 관찰점이다.[2]

## 장점

- 웹 콘솔과 S3 API를 함께 제공하므로 수동 관리와 프로그램 접근을 같은 저장소에서 다룰 수 있다.[1]
- 공식 표에서 사용 가능 기능과 Preview를 구별하고 호환성의 제한을 문서로 연결한다.[1]

## 단점 / 주의점

- Apache 2.0 라이선스이며, S3 Tables와 MinIO 디스크 형식 호환은 Preview이고 MinIO가 암호화한 객체는 읽지 못한다.[1]
- 단일 노드·단일 드라이브 배치는 제자리 확장이 불가능하며, 컨테이너의 데이터 경로 권한과 초기 계정 설정도 확인해야 한다.[1]
- KMS의 Local·Static 백엔드는 개발·시험용으로 한정되며, 웹훅의 TLS 검증을 끄면 보안 위험이 발생한다고 명시한다.[1]

## 정리

RustFS는 객체 저장 API와 관리·보호 기능을 묶은 분산 저장소 서버이다.[1] 모든 S3 동작이나 기존 저장 형식과의 무조건적인 호환을 뜻하지 않으며, 기능별 지원표와 배포 구성의 제약을 함께 확인해야 한다.[1]
