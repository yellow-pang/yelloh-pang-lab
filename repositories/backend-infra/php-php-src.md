## 한 줄 요약

php-src는 PHP 프로그램을 실행하는 인터프리터의 소스 저장소다. 웹 페이지를 만드는 PHP 애플리케이션이나 프레임워크 예제가 아니라, 그 코드를 실행할 언어 처리계 자체를 개발한다. 일반 사용자는 미리 빌드된 패키지를 사용할 수 있고 소스 빌드는 다른 작업 경로다.[1]

## 언어를 사용하는 코드와 언어를 실행하는 코드

PHP로 조건문과 함수를 작성하면 실행기는 그 의미를 실제 동작으로 옮겨야 한다.
php-src를 읽는 목적은 웹 화면을 빨리 만드는 법보다 언어 실행, 확장 기능과 회귀 테스트의 구조를 이해하는 데 가깝다.
README는 기본 빌드 도구와 선택한 기능에 필요한 라이브러리, 테스트 실행 경로를 나누어 설명한다.[1]

확장은 기본 실행기에 기능을 추가하는 구성 요소다. README는 함께 포함된 확장과 외부 확장 설치 경로를 구분하므로 언어 실행기만 빌드했다고 모든 기능이 포함되는 것은 아니다.[1]

## Zend 엔진의 실행 코드는 어떻게 준비되는가

`Zend/README.md`는 메모리 관리와 가상 머신의 내부 구조를 설명한다. 여기서 가상 머신은 별도 운영체제를 켜는 컴퓨터가 아니라, opcode라는 내부 명령을 처리하는 실행 장치다. opcode 처리기는 피연산자 종류에 맞게 특수화할 수 있다고 문서가 설명한다.[2]

`zend_vm_gen.php`는 `zend_vm_def.h`와 `zend_vm_execute.skl`을 입력으로 실행 관련 헤더를 생성한다. 결과인 `zend_vm_opcodes.h`는 명령 정의를, `zend_vm_execute.h`는 실행기 코드를 담는다고 안내한다.
생성되는 파일과 사람이 고치는 정의 파일을 구분하는 것이 소스 탐색의 중요한 단서다.[2]

문서 안에는 과거 엔진 버전의 성능 설명도 남아 있다.
그 수치를 현재 PHP 전체의 속도 향상이나 데이터베이스 중심 앱의 성능으로 그대로 옮기지 않아야 한다.[2]

## 라이선스와 아주 작은 언어 테스트

조사 시점의 루트 README와 `LICENSE`는 BSD-3-Clause를 안내한다.
이 과거와 달라질 수 있는 조건은 기억에 의존하지 않고 현재 확인한 파일을 기준으로 기록한다.
재배포 시 고지 보존과 저작권자 이름을 승인 없이 보증에 사용하지 않는 조건 등을 확인해야 한다.[1][3]

`tests/lang/001.phpt`는 간단한 if 조건 테스트다.
`--FILE--` 구역에는 양수인지 검사해 Yes를 출력하는 PHP 코드가 있고, `--EXPECT--`에는 기대 출력이 있다.
테스트 목적·실행 입력·기대 결과를 한 파일에 모으는 형식을 확인할 수 있다.[4]

## 가상 예시: 조건문 변경의 회귀 확인

다음은 PHP를 빌드하거나 테스트한 실제 기록이 아니다.
언어 실행부를 변경한 개발자가 기본 조건문 동작이 깨지지 않았는지 확인한다고 가정한다.
작은 PHPT 파일에서 기대 동작을 읽고, 빌드된 실행기로 관련 테스트 디렉터리를 검사하는 흐름을 생각할 수 있다.[1][4]

하나의 테스트 통과는 전체 언어 호환성이나 모든 확장의 안전성을 증명하지 않는다.
원인을 좁히는 최소 사례와 전체 회귀 검사 사이의 차이를 구분해야 한다.

## 빌드와 설치의 경계

README는 `make test`와 `make install`을 별도 단계로 설명하며 설치에는 권한이 필요할 수 있다고 안내한다.
소스 분석을 위해 시스템 PHP를 교체할 필요는 없으며, 개발 빌드와 실제 사용하는 실행 환경을 분리하는 편이 안전하다.[1]

## 직접 읽어볼 자료

- 루트 README에서 소스 빌드·테스트·설치가 구분된 순서를 읽는다.[1]
- `Zend/README.md`의 생성기 입력과 출력을 따라가며 실행기 파일의 역할을 파악한다.[2]
- `tests/lang/001.phpt`에서 테스트 이름, PHP 코드, 기대 출력을 비교한다.[4]

## 정리

php-src는 PHP 앱의 기능을 만드는 저장소가 아니라 PHP 언어 동작을 구현하고 검증하는 기반이다.
실행기 생성 구조와 최소 언어 테스트를 함께 읽으면 거대한 소스에서 출발할 지점을 잡을 수 있다.[1][2][4]
